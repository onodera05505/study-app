# 読む段の指摘を反映する（セルフフィードバックの「直す」段。ロードマップ型）

「読む」段（`scripts/prompts/self_review.md`）で出た指摘を、担当バンドルの教材と確認問題に反映する。
**直すのは担当バンドルの 2 ファイルだけ。** 他のバンドル・`roadmap.json`・決まり・仕様書・`sources/*.json` は読むだけ。

## 先に読むもの（順に全部）
1. `data/<key>/common_rules.md` — 対象の決まり。**末尾の「読み直しで出た型（2026-09-24）」の項は今回の直しのために書かれた**
2. `data/<key>/prompts/roadmap_materials.md` と `roadmap_questions.md` — 仕様書。**末尾の「全対象に共通の書き方」「誤答の側から形をそろえる」の項が今回の中心**
3. `data/<key>/review/<bundle>.json` — 担当バンドルの指摘（`findings` と `patterns`）。**これが作業の一覧**
4. `data/<key>/roadmap.json` — 単位の順（`order`）・要約（`summary`）・前提。要約は触らない（報告に書く）

## やること（この順）
1. **指摘の高・中をすべて直す。** 低は、決まりに当たるものと同じ手で直せるものを直す（無理に全部は直さない。何を残したかを報告に書く）
2. **担当の全単位に、仕様書「全対象に共通の書き方」を当てる**（指摘に挙がっていない単位も）: 出典 `where` を日常語に／書き手の都合の文を消す／断定・条件抜きの法則を直す／記法（敬体・定義文・数字・関連用語の形）をそろえる／後の単位で定義する語に `[[ ]]` と言い換え／到達基準に効かない文（言い直し・図の繰り返し・脱線）を消し、欠けている要素（定義・しくみ・usageSection・計算の単位の数値の例。取り違えやすい相手があれば境界）を足す（仕様書「何を書き、何を削るか」。字数を理由に要る情報を削らない）
3. **担当の全問題に、仕様書「誤答の側から形をそろえる」を当てる**: **正解の文と記号は変えない**（設問と正解が食い違うと指摘された問題だけ、正解を直してよい。その場合は報告に明記）。誤答を正解と同じ密度・同じ形に足す。設問の「教材」を消す。判断問題が本文・練習・要約の写しなら別の場面に置き直す。`choice_notes`・`reason` の根拠を当該単位に限り、「〜の取り違え」の決め打ちをやめる
4. **数字の主張は検算する。** 例やケースの数字が「ほぼ並ぶ」「同じ 1 割」と書いてあれば計算して確かめ、合わなければ数字か文を直す
5. **要約（`roadmap.json` の `summary`）は触らず、本文と食い違う単位について「要約はこう変える」を報告に書く**（決まり: 本文を直したら要約も直す。親が写す）
6. `python3 scripts/check_roadmap.py --data data/<key>` と `python3 scripts/check_roadmap_bundle.py --data data/<key> --bundle <bundle>` を回し、**担当バンドル由来の警告・問題点が 0** であることを確認する（他バンドルは並行作業中）。門が新しく見る物: 設問の「教材」、台詞が正解にだけ、2 問とも最長、要約との 14 字一致、出典 where の記号・英字。門は字数・文数を見ない（止めも警告もしない）。要らない文は読み直し（`self_review.md`）と学習者役の測定で見つける

## やらないこと
- 他のバンドル・`roadmap.json`・`common_rules.md`・仕様書・`sources/*.json`・`review/*.json` に書かない
- 「原本と照合したい」と読む段が書いた所（`kind: その他`、severity 無し）は直さない。報告に「照合待ち」として残す
- 正解を短くして長さをそろえない（誤答に足す）
- 単位の名前（`term`）を変えない。単位を消したり足したりしない
- 作業用の一時ファイルを作るなら、名前に対象 key と担当バンドルを含める（作業用ディレクトリは並行する担当と共有）

## 報告（親へ）
- 直した単位と中身（指摘の番号か引用で分かるように）。高・中で**直さなかったもの**とその理由
- **「要約はこう変える」の一覧**（単位ごとに現行 → 新。食い違いが無ければ「無し」と書く）
- 正解を変えた問題があれば、その qid と理由
- 検算で数字を変えた所
- 「照合待ち」として残した所
- 門の結果（自分のバンドル由来の警告・問題点の数）
- **担当バンドル以外のファイルは読むだけ。書いたのは教材と問題の 2 ファイルだけ**、と明記
