# 申告の消化（資格対策。本文の後追いの後。1 体が 1 つの項目の一覧を受け持つ）

まとまりごとの書き直し・単元の突き合わせ・図の見直し・本文の後追いの各段は、自分の範囲の外の物を直さず、報告の `not_fixed` に挙げる。受入判定も、直さなかった物を一覧にして返す。
この段は、**そうして残った申告を、親が作った一覧で受け取り、1 件ずつ現物で確かめて、正本の決まりで直すか、決まりどおりなので直さないと判定する。** 前の段が範囲の外とした直し（比較を持つ論点と受け持ちの行・単元をまたぐ比較・本文の例と過去問・図から外す点の行き先・なぞり・見出しの名前・語の揺れ・台帳の行き先）が、この段の範囲になる。

**教材の書き方の正本は `scripts/prompts/write_materials.md`、図の決まりの正本は `scripts/prompts/material_figures_spec.md`、単元の構成の正本は `scripts/prompts/unit_plan.md`、点の台帳の正本は `scripts/prompts/rewrite_materials_by_group.md`、直し方の作法の正本は `scripts/prompts/rewrite_unit_crosscheck.md` と `scripts/prompts/rewrite_text_followup.md`。** この仕様書は、この段の入力・範囲・直し方の選び方・書いてよい範囲・門・報告だけを決める。新しい書き方の決まりは作らない。

---

## 先に読むもの（順に全部）

1. `scripts/prompts/write_materials.md` — 「他の論点との分担」「1 つの点は 1 か所で言う」「書き直し」の「情報を落とさない」「見出し」「書き方の約束」（本文が過去問から借りてよい物と写さない物・計算の解き方・数え上げ・選択肢の消し方を書かない）「満たすべき最低条件」
2. `scripts/prompts/unit_plan.md` — `owners` の決まり（受け持ちは共通の前提の説明だけ・`owner` の決め方）
3. `scripts/prompts/rewrite_unit_crosscheck.md` — 「直し方」の全部（③ 例の食い違い・④ 重複・⑥ 見出し・X9 語の揺れ・X10 食い違い・X11 なぞり・どの種にも共通）、「点の台帳の直し方」、「門」
4. `scripts/prompts/rewrite_text_followup.md` — 「直し方」の 3（台帳の行の点を本文へ戻す戻し方）、「直してよい文」、「点の台帳の直し方」
5. `scripts/prompts/rewrite_materials_by_group.md` — 「情報を落とさない確かめ方」（点の台帳の形と `fate` の 8 つ）
6. `scripts/prompts/material_figures_spec.md` — 「過去問の答えを言わない・写さない」（図の側の線。本文の線とは別）と `after` の決まり
7. 担当の項目の一覧と、一覧の論点の入力（下の「入力」）

## 親が渡すもの（可変部分）

親が指示で渡すのは **対象（`ip`・`ap`・`fe` のどれか）・項目の一覧のパス・報告のパス** の 3 つだけで、ほかはこの仕様書が決める。

- 1 つの一覧は **項目 16 件まで**。同じ論点の項目は同じ一覧に入れる
- 一覧は、書いてよい単元（`units`）を持つ。**同じ単元を持つ一覧を 2 体が並行して受け持たない**（前の担当が終わってから次を起こす）
- 単元をまたぐ比較の項目は、2 つの単元を `units` に持つ一覧に入れ、どちらかの単元を持つ他の一覧が全部終わってから起こす

## 入力

### 項目の一覧（JSON）

```json
{
  "target": "ap",
  "units": ["10"],
  "items": [
    {"no": 1, "unit": "10", "topic_id": 479, "figure": null,
     "source": "text_followup", "kind": "unit_plan",
     "what": "<申告の文>", "related": [175]}
  ]
}
```

- `source` は申告を返した段（`rewrite`・`crosscheck`・`figures_review`・`text_followup`・`acceptance`。この段の前の回が `noticed` で返した物は `open_items`、束の継ぎ目の数え上げが挙げた物は `seam`、親が起こした読むだけの調査と照合が挙げた物は `survey`）、`kind` はその段が付けた種類、`what` は申告の文。`related` は申告が名指しした他の論点
- `kind` と `what` は申告した段の読みで、当たっているとは限らない。**現物で確かめてから**範囲のどれに当たるかを決める

### 一覧の論点ごとに読む物

- 今の本文 `data/<対象>/materials_v4/<単元>-<k>.json` と点の台帳 `data/<対象>/rewrite_ledgers/<単元>-<k>.json`（論点がどの束にあるかは `data/<対象>/unit_plans/<単元>.json` のまとまりと学ぶ順から引く）
- 単元の構成 `data/<対象>/unit_plans/<単元>.json`（学ぶ順・`owners`）
- 図の仕様 `data/<対象>/material_figures/<論点 ID>.json`（ある論点だけ）
- 書き直しの束 `data/<対象>/rewrite_bundles/<単元>-<k>.json`（旧版の本文 `current`・旧版の図 `figures`・過去問 `questions`・問題解説）
- `related` の論点と、直しが触れる他の論点（比較の相手・指す先）の今の本文

## 範囲と直し方

項目ごとに、次のどれに当たるかを現物で決め、その行の決まりで直す。申告が 2 つ以上に当たるときは、それぞれを直す。

| 種 | 何か | 直し方の正本 |
| --- | --- | --- |
| A 比較を持つ論点 | 単元の中で、比較・使い分けを学ぶ順で前の論点が持つ。`owners` の行が比較・使い分けを書いている。他の論点が、比較の無い論点を「比較はそこ」と指す | `write_materials.md`「他の論点との分担」、`unit_plan.md` の `owners`。下の「A の直し方」 |
| B 単元をまたぐ比較 | 前の単元の論点が、後の単元の論点の語との比較を持つ | `write_materials.md`「他の論点との分担」の単元をまたぐ行。下の「B の直し方」 |
| C 本文と過去問 | 本文の例・表・句が、紐づく過去問と同じだという申告 | `write_materials.md`「書き方の約束」の、借りてよい物と写さない物の行。下の「C の直し方」 |
| D 点の行き先 | 図の直しを止めた点・図や本文から外れた点が、今の教材のどこにも無いか、行き先が決まっていない | `rewrite_text_followup.md`「直し方」の 3。下の「D の直し方」 |
| E なぞり | 本文が、同じ論点の図・表と同じ点をなぞる | `rewrite_unit_crosscheck.md` X11 |
| F 見出しと導入 | 見出しの名前・節の導入の文が、節の中身や今の図と合わない | `rewrite_unit_crosscheck.md` ⑥。下の「F の直し方」 |
| G 語の揺れ・食い違い | 同じ物を指す語・記号・数え方が、本文の中、論点どうし、本文と図で違う | `rewrite_unit_crosscheck.md` X9・X10・③。下の「G の直し方」 |
| H 台帳の行き先 | 点の台帳の `where`・`removed_figures` の `kept` が、今は点の無い所を指す | 下の「点の台帳の直し方」 |
| I 中身の無い節 | 図や文が移って、見出しの下に何も無い、指す 1 文だけが残る節 | `write_materials.md`「見出し」。図の `after` が指していない見出しは消す。指している見出しは消さず `figure_followup` に挙げる |

### A の直し方（単元の中の比較）

1. 比較を持つ論点を決める。比べる 2 つは学ぶ順で後の論点、3 つ以上は並べる物のうち学ぶ順で最後の論点
2. 持つ論点に、その比較が 1 か所（比較表か文）で書かれているかを見る。無ければ、前の論点の比較の文・表を持つ論点へ移す（置く節は `write_materials.md` の「見出し」のとおり。移した文は、持つ論点の語と文脈に合うよう、つなぎの語と主語だけを直す）
3. 前の論点は、自分の語で言える側の性質と、比較を持つ論点を指す 1 文だけにする。比較表・`### 混同しやすい用語` に、学ぶ順で後の論点の語を残さない。前の論点の紐づく過去問が比較そのものを問うときは、相手の側が問題解説にあることを確かめる
4. その比較を指している他の論点の文（「比べた表は [[X]] にあります」）を、持つ論点を指す文に直す
5. `owners` の行を `unit_plan.md` の決まりに合わせる: 比較・使い分けだけを書いた行は消す。共通の前提の説明と比較が混ざる行は、`subject` を共通の前提の説明だけに書き換える。`owner` は `topics` の中で学ぶ順で最初の論点。`owners` の他の行・学ぶ順・まとまり・前提は変えない
6. 移す節に図が付いている（図の `after` がその見出しを指す）ときは、文だけを移し、元の節には見出しと、図を読む前の導入 1 文を残して、報告の `figure_followup` に「図を持つ論点へ移す」と挙げる。図の仕様は書き換えない

### B の直し方（単元をまたぐ比較）

1. 学ぶ順は単元の番号の順。前の単元の論点から、後の単元の論点の語との比較（比較表の行・`### 混同しやすい用語` の箇条・比べる節）を外し、自分の側の性質と、比較を持つ後の単元の論点を指す 1 文だけにする
2. 後の単元の論点に、その比較が 1 か所で書かれているかを見る。無ければ、外した比較を後の単元の論点へ移す（A の 2 と同じ）
3. `owners` は単元をまたぐ行を持たない。前の単元の `owners` に、後の単元の論点との比較を書いた行があれば、A の 5 のとおりに直す
4. 図は A の 6 と同じ

### C の直し方（本文と過去問）

束の `questions` の問題文・選択肢・正解と、申告が指す本文を並べ、`write_materials.md` の「書き方の約束」の線で判定する。

- **借りてよい物に当たる**（場面・題材・事例や、過去問が選ばせる振り分け・組合せを教材の言葉で言い直している。`### 計算の解き方` が過去問 1 件を解いている。定義・式・しくみが正解と重なる）→ 直さない。報告の `verdict` は `by_rule`、`rule` に当たる行を書く
- **写さない物に当たる**（選択肢・問題文の句がほぼそのまま）→ 直す。句は教材の言葉で言い直す。表・箇条の形は変えない。言い直しても、紐づく過去問が本文と問題解説で解けること
- **申告が指すのが定義の文**（explanation の冒頭で論点が何であるかを言う文）で、その句が正解の選択肢の句、または用語を答えさせる問題の問題文（問題文がその用語の定義を言う形）と重なる → 直さない（定義が正解と重なる物に当たる。定義の文は「直してよい文」でも変えない）。`verdict` は `by_rule`。要点の箇条・説明の文が選択肢の句をほぼそのまま置いているときは、写さない物として直す
- **申告が指すのがキーワードの行**（`keywords`）→ 直さない。キーワードは問題文に出る語を置く行で、句の写しの線の外（`write_materials.md` のキーワードの決まりが優先）。`verdict` は `by_rule`
- 本文の中で同じ物の呼び名が揺れているだけの申告は G として直す
- 図の例が過去問と同じだという申告は、図の側の線（`material_figures_spec.md`）の物なので、本文は直さず `figure_followup` に挙げる

### D の直し方（点の行き先）

1. その点が、旧版の教材（束の `current` の本文と `figures` の図の中の文字・caption）にあったかを見る。無ければ足さない（`verdict` は `by_rule`、`rule` は「旧版に無い内容を足さない」）
2. 今の教材のどこにあるかを見る（その論点の本文、`fate` の定義が認める他の論点の本文、図の直しで消えない図）。あれば、台帳の行をそこへ書き換えるだけにする
3. どこにも無い、または直しを止めている図にだけある点は、`rewrite_text_followup.md` の「直し方」の 3 の戻し方で本文へ戻す。行き先を本文以外にしてよいのは、問題解説に任せてよい物（誤答のケア・計算の 2 件目以降・全選択肢の値）が問題解説にあるとき（`explanation`）と、IT パスポートで書かない周辺（`aside`）だけ
4. 本文へ戻したあと、図からその点を外す直しが残る物は、`figure_followup` に挙げる

### F の直し方（見出しと導入）

- 見出しの名前は、`rewrite_unit_crosscheck.md` ⑥のとおりに中身を言う名前へ直す。**図の `after` が指す見出しの名前を直すときは、その図の仕様の `after` を同じ名前に書き換える**（書き換えるのは `after` の値だけ）
- 節の導入の文・図を指す文が今の図・節の中身と合わないときは、本文の文を今の図・中身に合わせる。図の側を直さないと合わない物（図の段の区切り・図の型）は `figure_followup` に挙げ、本文は今の図と食い違わない所まで直す
- 見出しが予告した理由・中身が図の中にしか無い節は、理由を本文に 1〜2 文で置く（旧版の本文か図にあった点だけ。D の 1）

### G の直し方（語の揺れ・食い違い）

- 本文の中・論点どうしは、`rewrite_unit_crosscheck.md` X9・X10・③のとおり
- 本文と図で語・記号が違うときは、図の中の文字を正として本文を合わせられるなら本文を合わせる（紐づく過去問・問題解説の語と食い違わないこと）。本文の語が過去問の語で変えられないときは `figure_followup` に挙げる
- 数え上げ（「6 段」「3 つ」）は、書いた数と中身を合わせる

### 直してよい文

- 直してよいのは、上の直し方が指す文・句・表・箇条・見出しの名前・文の位置と、それを直したために崩れる隣の文のつなぎの語だけ。それ以外の文は 1 字も変えない
- 型・定義の文・キーワード・節の構成（上の A・B・I で移す・消す節を除く）は変えない
- 字数は増やさない方向。D で戻す点・A と B で移す文で増えるのはよい
- 直したら、その論点の紐づく過去問が、直した本文（図の中の文字と caption を含む）と問題解説で今も解けることを確かめる（`rewrite_unit_crosscheck.md`「どの種にも共通」）。解けなくなる直しはしない

### 直さずに返す物

次は直さず、報告の `returned` に挙げる。**正本の決まりを当てれば直し方が 1 つに決まる物を、ここに挙げない。**

| `kind` | 何か |
| --- | --- |
| `figure_followup` | 図の中身・型・置き場・枚数の直しが要る物（図の見直しの段へ戻す。`what` に、どの図をどうするかを書く） |
| `unit_order` | 学ぶ順・まとまり・前提を変えないと直らない物 |
| `question_data` | 過去問のデータが壊れて見える物（原本との照合は親が行う） |
| `undetermined` | 正本の決まりを当てても直し方が 2 つ以上残る物（`what` に、どの決まりとどの決まりの間で決まらないかと、それぞれの直し方を書く） |

## 点の台帳の直し方

形と `fate` の 8 つは `rewrite_materials_by_group.md` のとおりで、新しいキーを足さない。書き換え方は `rewrite_unit_crosscheck.md` と `rewrite_text_followup.md` の「点の台帳の直し方」に合わせる。

- A・B で比較を移した・外した点は、前の論点の束の台帳で、その点の行の `fate` と `where` を、比較を持つ論点に書き換える（`prior`・`later`・`owner` の決め方は `rewrite_unit_crosscheck.md`。単元をまたぐ先は `owner`）。行が無ければ 1 行足す
- D で戻した点は、行を `kept` と戻した見出しに書き換える
- H は、行の `where`（`removed_figures` は `kept`）を、今その点がある所へ書き換える。今どこにも無い点は D として扱う
- 行は `point` の全文で引き、`point` は変えない。台帳の他の行は変えない

## 書いてよいファイル・読むだけのファイル

- **書いてよい**: 一覧の `units` の単元の `data/<対象>/materials_v4/<単元>-*.json`（直す論点の `explanation`・`detail` だけ）、同じ束の `data/<対象>/rewrite_ledgers/<単元>-*.json`、`data/<対象>/unit_plans/<単元>.json` の `owners`（A の 5 の範囲だけ）、F で見出しの名前を直した図の `data/<対象>/material_figures/<論点 ID>.json` の `after`
- **読むだけ**: 上のほかの全部（図の仕様のほかのキー・描いた図・問題解説・書き直しの束・過去問・正解表・`topics.json`・`glossary_overrides.json`・他の単元のファイル・仕様書）
- 本文の中の図の行（`![…](/figures/…)`）は触らない（親が図の差し込みで作り直す）
- 直す前の退避と、良くならなかったときの戻しは親が行う

## やらないこと

- 図の中身・caption・型・枚数・図の置き場の論点を変えない。図を描かない
- 問題解説・過去問・正解表・論点名・`glossary_overrides.json` を書き換えない。学ぶ順・まとまり・前提を変えない
- 一覧に無い申告を探しに行かない。直している論点で気づいた物は、報告の `noticed` に挙げるだけにする
- `build_rewrite_bundles.py`・`build_material_bundles.py`・`attach_material_figures.py` を実行しない
- 作業用の一時ファイルは、名前に対象と単元番号を含め、`data/` の外に置く

## 門（直したあとに担当が回す）

```bash
python3 scripts/check_materials.py --data data/<対象> --dir data/<対象>/materials_v4 --all
python3 scripts/check_material_style.py --data data/<対象> --dir materials_v4
python3 scripts/render_material_figures.py --data data/<対象> --check --only <直した論点と after を直した図の論点の ID…>
python3 scripts/check_explanations.py --data data/<対象> --all
python3 scripts/check_unit_plans.py --data data/<対象>
```

- 拾う指摘の範囲・止める理由を 0 にすること・知らせの数の比べ方は、`rewrite_unit_crosscheck.md` の「門」のとおり。5 つ目は `owners` を直したときに回し、終了 0 にする
- 門の結果は終了コードで確かめる

## 報告（親へ）

親が渡したパスに JSON で書く。返す文は、書いたパスと件数だけにする。

```json
{
  "target": "ap", "units": ["10"], "status": "done",
  "items": [
    {"no": 1, "topic_id": 479, "type": "A", "verdict": "fixed",
     "rule": "<当てた正本の決まり（仕様書と節）>",
     "what": "<確かめた現物と、直した中身を 1〜2 文>",
     "questions_checked": ["<解けるかを確かめた過去問の ID>"]}
  ],
  "edits": [
    {"file": "data/ap/materials_v4/10-1.json", "topic_id": 479, "field": "detail",
     "op": "replace", "heading": "<見出し>", "before": "<直す前>", "after": "<直した後>"}
  ],
  "owners": [{"unit": "10", "op": "delete", "before": {}, "after": null}],
  "figure_after": [{"topic_id": 0, "figure": 1, "before": "<前の見出し>", "after": "<今の見出し>"}],
  "ledgers": [{"file": "", "topic_id": 0, "point": "", "before": {}, "after": {}}],
  "returned": [{"no": 0, "topic_id": 0, "figure": null, "kind": "figure_followup", "what": ""}],
  "noticed": [{"topic_id": 0, "what": ""}],
  "gates": {"check_materials": 0, "check_material_style": 0, "render_check": 0, "check_explanations": 0, "check_unit_plans": 0},
  "chars": {"before": 0, "after": 0}
}
```

- `verdict` は `fixed`（直した）・`already`（今の現物では申告が当たらない。理由を `what` に）・`by_rule`（正本の決まりどおりで直さない。`rule` に決まりを書く）・`returned`（直さずに返す。`returned` に同じ `no` の行）のどれか
- `edits` の `op` は `replace`・`insert`・`delete`・`move`。`move` は `before` に元の論点と見出し、`after` に移した先の論点と見出しを書く
- `gates` は各門の終了コード
