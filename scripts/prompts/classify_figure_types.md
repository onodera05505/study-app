# 教材に図を足すべきかの型判定（仕様）

教材（論点の解説）を読み、**図を足すことで理解が実際に助かる論点**を選ぶための判定。
点数を主観で付けるのではなく、**論点の型**で決める。型はほぼ論点の性質で決まり、担当が変わっても安定する。

## 型（type）

| 型 | 内容 | 例 | 図の効き（benefit） |
| --- | --- | --- | --- |
| A | 構造・構成・階層・状態 | RAID、3層クライアントサーバ、ネットワーク構成、OSI 階層、状態遷移、木構造 | 3 |
| B | 手順・やり取り・時間の流れ | TLS ハンドシェイク、ARP の解決、ロールフォワード、PDCA、アローダイアグラム | 3 |
| C | 対比・分類・マトリクス | 保守の4分類、正規形、成長マトリクス、リスク対応の4戦略 | 1（多くは**表**で足りる。2軸の分類だけ matrix の図） |
| D | 数量関係・グラフ・計算 | 損益分岐点、稼働率、待ち行列、EVM、故障率曲線、キャッシュのヒット率 | 3 |
| E | 定義・法律・略語・単発の知識 | 個人情報保護法、SRI、PSIRT、OP25B | 0（対象外） |

## 描ける図は 4 型だけ（template）

`blocks`（箱と矢印）／`sequence`（手順・やり取り）／`matrix`（2×2〜3×3）／`chart`（折れ線・棒・階段）。
これ以外の図（ベン図・回路図・自由なイラスト）は描けないので、それが要る論点は `template: "none"` にして理由を書く。
対比・分類で表で足りるものは `template: "table"`（図ではなく表に書き直す候補）。

## 現状の弱さ（weakness）

教材の文章が、**本来なら図で見せるものを言葉で頑張っているか**。

- 2: 構造・流れ・数量関係を文章で長々と説明している。読んでも頭に絵が浮かびにくい
- 1: 文章で一応追えるが、図があれば一目で分かる
- 0: 文章で十分。図は飾りになる

## 出力

入力ファイルの各論点について、次を JSON 配列で書く。**入力に無い論点を書かない。全論点を書く。**

```json
{"topic_id": 53, "type": "D", "template": "matrix", "benefit": 3, "weakness": 2,
 "idea": "4変数のカルノー図を格子で示し、1の塊の囲み方と落ちる変数を矢印で示す",
 "confidence": "high"}
```

- `idea` は 80 字以内。**その論点の過去問が解けるようになるための図**を書く（飾りの図は書かない）
- `template: "none"` / `"table"` のときも `idea` に理由か表の観点を書く
- 型 E は `benefit: 0`、`template: "none"`、`weakness: 0` で統一する
