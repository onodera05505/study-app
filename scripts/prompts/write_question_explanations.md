# 問題解説の執筆仕様

過去問 1 問ごとに「なぜその選択肢が正解か」と「誤答の選択肢はそれぞれ何の説明か」を書く。
教材との役割分担の中核なので、最初に背景を読むこと。

## なぜ問題側に解説を置くのか

誤答選択肢のケア（「○○と混同しやすい」「△△は別物」）を**論点の教材**が背負うと、
11 回で 1 度しか出ていない論点にも 1,000 字の教材が付き、学習者のやる気を削ぐ。
単語の説明に選択肢の話が書いてあるのも不自然になる。

そこで役割を分ける。

| 置き場所 | 書くもの |
| --- | --- |
| 論点の教材（`materials_v3`） | その用語が何か、何が出たらそれか（見分けワード）、図、計算の手順 |
| **問題の解説（このファイルの対象）** | 正解の根拠、**誤答ア〜エが何の用語の説明か**（各 1 行） |

12 回出た論点は 12 問ぶんの解説が付くので、**網羅性は問題の数が担保する**。教材を厚くしなくてよい。

誤答の 1 行は、そのまま**用語のポップ**（本文の色付き文字を押すと出る 1 行説明）の中身になる。
つまり、あなたが書く誤答の行は「用語集の見出し語＋定義 1 行」でもある。そのつもりで用語名と 1 行を書く。

## 入力

`data/<exam>/explanation_bundles/expl_NN.json`。論点単位で束ねてあり、論点ごとに:

- `topic_id`, `term`, `explanation`, `detail` — その論点の教材（`materials_v2` の本文）
- `questions[]` — 紐づく過去問。**同一内容の問題は 1 件に畳んである**（`content_key` が同じ）。
  `question_id`（代表＝最新の回）, `content_key`, `exam_label`, `stem`, `choices`（ア〜エ）, `answer`,
  `has_figure`, `figure_description`, `times_asked`, `other_question_ids`

解説は **`content_key` ごとに 1 本**。代表の `question_id` を書く。

## 書くもの

```json
{
  "bundle": "expl_01",
  "explanations": [
    {
      "question_id": "2024r06h-q05",
      "content_key": "…（入力の値をそのまま）",
      "correct": "エ",
      "correct_reason": "ビジネスモデルをコンピュータシステムとして実現した発明は、[[ビジネスモデル特許]]として**特許法**で保護されます。「新たな仕組みを技術で実現した」が出たら特許法です。",
      "choices": [
        {"label": "ア", "term": "意匠法", "note": "物品のデザイン（形・模様・色）を保護する法律です。仕組みは対象外です"},
        {"label": "イ", "term": "実用新案法", "note": "物品の形状・構造の考案を保護する法律です。無審査で登録され、保護期間は特許より短くなります"},
        {"label": "ウ", "term": "著作権法", "note": "表現（文章・プログラムのコードなど）を保護する法律です。アイデアや仕組みは守りません"},
        {"label": "エ", "term": null, "note": "正解。"}
      ]
    }
  ]
}
```

### `correct_reason` — 正解の根拠（1〜3 文）

- **なぜそれが正解になるのか**を、問題文の手がかりと結びつけて書く。「問題文の『〜』が決め手」の形が良い
- 計算問題は**式 → 数値を入れる → 答え**の順で、実際の数値で解いてみせる。単位の換算や切り上げなど、
  誤答がそこで生まれる箇所を明示する
- 正誤判定型（適切なものはどれか）は「正解の選択肢が正しい理由」を 1〜2 文
- IT パスポートは平易に。応用情報は式・判断基準・規格上の根拠まで置く（読者は学ぶ意欲のある人）

### `choices` — 4 件（ア〜エ）すべて

**誤答**の 3 件:

- `term` — その選択肢が**何の用語の説明か**。正式表記で書く（`data/<exam>/topics.json` に同じ論点名が
  あればその表記に合わせる。合わせると自動で「この論点を学ぶ →」が付く）。
  用語の説明になっていない誤答（計算の誤答値、正誤判定の誤りの文、手順の誤った並び）は `null`
- `note` — **1 行**（40〜80 字目安）。「〜のことです。」のように**敬体で**定義し、余裕があれば「正解と違う点」を短く
  （体言止め・「〜のこと。」「〜ではない」で止めない。バンドルごとに割れると用語集の見え方が割れる。
  `check_explanations.py` が常体の note を 1 件ずつ警告する）。
  `term` が `null` のときは「なぜ違うか」を 1 行（「単位を換算し忘れると出る値です」「〜は要件定義ではなく設計の作業です」など）。
  計算の誤答値は**どの誤りでその値になるかを逆算して 1 つ書く**（「この値にはなりません」で終わらせない。門が検出）。
  逆算で見つからないときは捏造せず「分母を総資本より小さく取ると出る値です」のように構造で説明する。
  **この 1 行は他の問題のポップにも使い回される**ので、この問題の文脈に依存しない書き方にする
  （×「この問題では対象外」 ○「物品のデザインを保護する法律です。仕組みは対象外です」）。
  **用語の核となる定義は 1 文目に収める。** 用語集（ポップ）に入るのは note の 1 文目だけで、2 文目は用語集に入らない（用語集の代表は最新の回の note）

**正解**の 1 件:

- `term` は `null`、`note` は `"正解。"` だけでよい（根拠は `correct_reason` にある）。
  補足したいことが 1 行あるなら「正解。〜」と続けてよい

### `[[用語]]` 記法

`correct_reason` と `note` の中で他の用語に触れるとき、`[[用語]]` で囲むと本文が色付きになり、
押すとポップで 1 行説明が出る。**片っ端に付けない**。読者が「これ何だっけ」と思う語だけ。
用語集に無い語を `[[ ]]` にすると `check_explanations.py` が「解決できない用語」として止める（用語集は全担当の `choices[].term` と論点名から自動で作られる。無い語は `glossary_overrides.json` に足すか、`[[ ]]` を外して素の太字にする）。

## 守ること

- **過去問の問題文・選択肢文を 30 字以上そのまま引用しない**（`check_explanations.py` が検出）。
  選択肢は記号（ア〜エ）で参照し、内容は言い換える
- **正解は入力の `answer` に従う。** 自分で解いて違うと思っても、正解表を変えない。
  疑わしければ報告に書く（これまで「原本と違う」と報告された 15 件のうち本物は 1 件だった）
- 太字は 1 か所まで。敬体（です・ます）。読点は「、」
- 不確かなことは書かない。用語の定義に自信が無ければ短く事実だけ書く

## 出力

- `data/<exam>/question_explanations/expl_NN.json`（バンドルと同じ番号）
- **8 件ずつ Write → Edit で追記**する。1 回の Write で全部書こうとして接続が切れる事故が繰り返し起きている
- バンドルの全 `question_id` を含めること。抜けるとその問題だけ解説無しになる

## 書き上げたら

```bash
python3 scripts/check_explanations.py --data data/<exam>
```

（全バンドルをまとめて検査する。自分のバンドル `expl_NN` に関する指摘だけ直せばよい）

選択肢 4 件の有無、正解表との一致、引用、バンドルとの突き合わせを機械的に見る。指摘が出たら直す。
