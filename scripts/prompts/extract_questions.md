# 問題抽出の共通仕様

問題冊子のページ画像から問題を文字起こしする際の指示書。**29回分すべてで同じ仕様を使う**ことが目的。

読み取りはページ範囲ごとに分担して行うため、担当者ごとに流儀が分かれると、
チャンク単位の系統的なブレになる。令和6年度の初回検証では、あるチャンクだけが
句点を「．」で書いており（52箇所）、他のチャンクは「。」だった。1回分なら
手で直せるが、29回分・2,900問では破綻する。以下はその再発を防ぐための取り決め。

`merge_questions.py` が正規化とブレ検出を行うが、**自動で直せるのは表記の一部だけ**。
構造の判断（箇条書きをどこに置くか、`has_figure` をいつ立てるか）は直せないので、
ここで決めておく。

---

## 大原則

**忠実な転記に徹する。** 問題を解かない。答えを書かない。誤字と思っても直さない。
要約しない。見えたままを写す。判読に自信がない箇所は推測で埋めず `confidence` を
下げて `notes` に理由を書く。

---

## 表記のルール

| 対象 | ルール |
| --- | --- |
| 読点 | **「，」**（全角カンマ）。「、」は使わない |
| 句点 | **「。」**（丸）。**「．」は使わない** |
| 英数字 | 原文の全角/半角のまま |
| 行の折り返し | **削除して1つの文字列にする**。単語の途中で折り返されていても繋げる |
| 空欄 | **`［ a ］`**（全角角括弧＋前後に半角スペース）で統一 |
| 分数 | 横線表記は **`分子/分母`** に変換（例: `1/216`） |
| ルビ | 本文には混ぜない。`notes` に「選択肢イの『嗜好』にルビ『し』」のように記録 |
| 引用符 | 原文がダブルミニュートなら `“ ”` を使う |

---

## 数式の書き方

応用情報の基礎理論では、指数・対数・平方根・総和が本文中に出る。
**表示側は Markdown の限られた記法しか解釈しない**（`###` / `-` / `1.` / `**`）ので、
LaTeX も上付き文字も使えない。プレーンテキストで書く。

| 対象 | 書き方 | 例 |
| --- | --- | --- |
| 指数 | `底^指数` | `2^10`、`n^2` |
| 添字 | `底_添字` | `a_1`、`x_i` |
| 対数 | `log底 真数` | `log2 n` |
| 平方根 | `√(…)` | `√(2)`、`√(a^2+b^2)` |
| 分数 | `分子/分母` | `1/216`、`(a+b)/2` |
| 総和 | `Σ(条件)` を言葉で補う | `Σ(i=1..n) a_i` |
| 掛ける | `×` | `2 × 10^6` |
| 単位 | 原文のまま | `10^6 バイト` |

## 論理否定のオーバーラインは `¬` に統一する

原本は否定を上線（`A` の上の横棒）で書くが、プレーンテキストで上線は表現できない。
結合マクロン（`Ā`）は環境によって位置がずれて読めなくなるし、
式全体に掛かる上線は1文字では表せない。**`¬` を使う。**

| 原本 | 書き方 |
| --- | --- |
| 上線付きの `a` | `¬a` |
| `a` の上線 ×  `b` | `¬a・b` |
| `Q→P` 全体に上線 | `¬(Q→P)` |

**掛かる範囲が2文字以上なら必ず括弧を付ける。** `¬Q→P` と `¬(Q→P)` は別物。

問題文に「“ ̄”は論理否定を表す」という凡例がある場合、その部分は
**「“¬”は論理否定を表す」と書き換えてよい。** 記号を変えたので凡例も揃える。

---

**16進数は原文の表記をそのまま残す。** `16^2` と `100(16)` と `0x64` を勝手に統一しない。

## タイミングチャートは表にする（実際に間違えた）

令和7年度秋期 問22（論理回路）で、波形を散文で書いた結果**読み取りを誤った**。

```
✗ 「Y は，B が0に下がるタイミングで0に下がり，その後1に戻り…」
```

実際に Y が 0 に落ちるのは **A が1に上がるタイミング**だった。この1点のずれで
NAND が XOR に見え、答えが変わる。散文は「どの立ち上がりと、どの立ち下がりが
対応するか」を表現できない。

```
✓ 区間ごとの値を表にする

| 区間 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A | 0 | 0 | 1 | 0 | 1 | 0 | 1 |
| B | 1 | 0 | 1 | 0 | 1 | 0 | 0 |
| Y | 1 | 1 | 0 | 1 | 0 | 1 | 1 |
```

**縦の点線で区間を数え、各区間の値を1つずつ読む。** 時間の前後関係を言葉で
説明しようとしない。同じことがパルス波形、状態遷移のタイムライン、
ガントチャートにも当てはまる。

---

## 規格名の副題を区切るのは「－」（長音記号ではない）

`JIS Q 27000:2019（情報セキュリティマネジメントシステム－用語）` のように、
規格名の副題は**全角ハイフンマイナス「－」**で区切られる。字形が似ているため
**長音記号「ー」に読み違えやすく、実際に回ごとに表記が割れた。**

```
✗ 情報セキュリティマネジメントシステムー用語
✓ 情報セキュリティマネジメントシステム－用語
```

前後がどちらもカタカナになる例（`シンボル－アイコン`）があるので、**位置からは
機械で直せない。** 規格名を写すときは、区切りは「－」だと意識して書くこと。
語中の本物の長音（`サーバ` `データ`）はそのまま。

---

**上付き文字でも、名前なら指数表記にしない。** `I²C`（バス規格）や `R²`（決定係数）の
ように、上付きが名前の一部になっているものは `I2C` `R2` と素直に書く。
`I^2C` と書くと「I の2乗×C」という別物に見える。**計算に使う値だけを `^` で書く。**

読み取れない記号があれば、推測で置き換えず `confidence` を下げて `notes` に書く。

---

## 箇条書きの置き場所

問題文中の `a` `b` `c` `d` や `(1)` `(2)` のリストは、**必ず `text` に入れ、項目間を改行 `\n` で区切る。**
`figure_description` には入れない。全角スペースで1行に連結しない。

```
"text": "次の作業のうち，適切なものはどれか。\na 要件定義\nb 外部設計\nc 内部設計\nd プログラミング"
```

理由: 箇条書きは図表ではなく本文の一部なので、`text` だけ読んで意味が通る状態にする。
令和6年度では問94 が `figure_description` 側に置かれ、`text` だけ読むと
「次の作業」の中身が無く意味が通らない状態になっていた。

---

## `has_figure` を立てる基準

**視覚的なブロックが存在する場合だけ true。** 具体的には以下。

- 表・グラフ・図（ネットワーク構成図、アローダイアグラム、信頼性ブロック図、E-R図 など）
- 擬似言語プログラム、プログラムコード
- 選択肢そのものが組合せ表になっている場合

**以下は false。**

- 本文中の `a` `b` `c` の箇条書きだけがある問題
- `(1)` `(2)` の番号付きリストだけがある問題
- 〔宛先〕のような見出し付きブロックだけがある問題

`has_figure` が true のときは `figure_description` を必ず埋める。false のときは `null` にする。
（両者の食い違いは `merge_questions.py` がエラーとして検出する）

---

## 図表の書き方

`figure_description` に入れる。

- **表** — Markdown の表として書き起こす。単位や見出しの注記も残す
- **タイミングチャート・波形** — **必ず区間ごとの値の表にする。** 散文で書かない
- **図** — 構造が分かる説明を書く。ノード・接続関係・数値を漏らさない
- **プログラム** — 全文を書き起こす。インデントを保つ
- **空欄セル** — 「（空欄の枠）」と明示する

例（令和6年度 問8）:

```
損益計算書の抜粋表（単位 百万円）。

| 項目 | 金額 |
| --- | --- |
| 売上高 | 8,000 |
| 販売費及び一般管理費 | （空欄の枠） |
```

---

## 選択肢そのものが図の場合（重要）

「DFD の記述例として適切なものはどれか」のように、**選択肢ア〜エがすべて図**という
問題がある。このとき **`choices` に図の種類名を書いてはいけない。**

原本の選択肢は図だけで、「データフロー図」「E-R 図」といった名前は書かれていない。
名前を補うと**答えがそのまま選択肢に書かれた状態**になり、問題として成立しなくなる。

```
✗ 悪い例（答えが漏れている）
  "イ": "データフロー図（処理1・処理2と，データ A〜C，データファイル1）"

✓ 良い例（見た目だけを中立に述べる）
  "イ": "円「処理1」「処理2」を，データ A〜C の矢印で結び，2本の横線で挟んだ
         「データファイル1」から矢印が入る図"
```

**図に描かれている形・ラベル・つながりだけを書く。** それが何と呼ばれる図かは書かない。
判断に迷ったら「この記述を読んだだけで答えが分かってしまわないか」を自問する。

この種の問題は原本の図も切り出して表示するので、文章が多少そっけなくても学習者は困らない。

## 選択肢が組合せ表の場合

原文の選択肢が「ア | 構成管理 | 問題管理 | …」のような表になっている問題がある。この場合:

1. `choices` には **`a：… ，b：… ，c：…`** の形に整形して入れる（ラベルは表の列見出しから補う）
2. `figure_description` に**元の表を Markdown でそのまま**残す
3. `has_figure` を true にする
4. `notes` に「choices のラベルは列見出しから補ったもの」と明記する

---

## ページをまたぐ問題

- 問題の見出し「問N」が**担当ページ範囲に現れる問題だけ**を出力する
- その問題の選択肢が次ページに続いている場合は、**次のページも読んで**補完してよい
- 見出しが担当範囲より前にある問題は出力しない（前の担当者が処理する）

## 出力しないもの

- 「問1から問35までは，ストラテジ系の問題です。」のような区分見出し
- 表紙、注意事項、擬似言語の記述形式や表計算ソフトの共通仕様といった付録ページ、奥付

---

## 出力形式

```json
{
  "exam": "2024r06",
  "pages": [1, 2, 3, 4, 5, 6],
  "questions": [
    {
      "number": 1,
      "page": 2,
      "text": "問題文",
      "choices": {"ア": "…", "イ": "…", "ウ": "…", "エ": "…"},
      "has_figure": false,
      "figure_description": null,
      "confidence": "high",
      "notes": null
    }
  ]
}
```

`confidence` は `high` / `medium` / `low`。`high` 以外にした場合は `notes` に理由を書く。
