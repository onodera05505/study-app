# 読む段の指摘を反映する（セルフフィードバックの「直す」段。資格版 ip / ap）

「読む」段（`scripts/prompts/self_review.md`）で出た指摘を、担当バンドルの教材（`materials_v3`）と問題解説に反映する。
**直すのは担当バンドルの 2 ファイルだけ**: `data/<key>/materials_v3/expl_NN.json` と `data/<key>/question_explanations/expl_NN.json`。
他のバンドル・`topics.json`・`topic_ids.json`・`questions/`・仕様書・`glossary_overrides.json`・`review/*.json` は読むだけ。

## 先に読むもの（順に全部）
1. `scripts/prompts/write_materials.md` — 教材の仕様。**教材と解説の役割分担の節と「書き方の約束」が今回の中心**
2. `scripts/prompts/write_question_explanations.md` — 問題解説の仕様
3. `docs/作業ログ_2026-09-01_問題解説と教材v3.md` — 教材と解説の役割分担（教材は「何か・何が出たらそれか・図・計算の手順」、誤答のケアは解説）
4. `data/<key>/review/expl_NN.json` — 担当バンドルの指摘（`findings` と `patterns`）。**これが作業の一覧**
5. `data/<key>/topics.json` — 論点名（`term`）と紐づく過去問。教材の `term` はここと一致させる

## やること（この順）
1. **指摘の高・中をすべて直す。** 低は、仕様に当たるものと同じ手で直せるものを直す（何を残したかを報告に書く）
2. **担当の全論点に「役割分担」を当てる**（指摘に挙がっていない論点も）: 教材から選択肢の消し方（「〜ではありません」「〜では絞れません」「〜を落とせます」「〜で見分けられます」「引っかけは」）を消す。同じ論点の解説 `choices[].note` とほぼ同文の行は教材から消す（note に無ければ note へ移す）。別名の見出し（判断軸・見分け方・対応づけ）で選択肢を振り分けている段は消すか「しくみ」の理由づけに書き直す
3. **担当の全論点に記法を当てる**: explanation の 1 文目は `**論点名**とは、…です`（論点名は括弧の前まで）／箇条書き・手順・表の説明も敬体／用語集にある語は `[[ ]]`（同じ教材で素の太字と混ぜない）／比較の項目（`- **[[用語]]** — 違い`）は見出し名に関わらず 2 つまで／`^` `~~` を書かない／略号は初出で 1 行の言い換えか `[[ ]]`
4. **食い違いを解く**: explanation と detail・表・図の説明が別のことを言っていたら、広く読まれる explanation の側を正しい方に。同じ語・同じ数値を 2 つの意味に使っていたら語を分ける。式は記号の意味を同じ場所に
5. **解説側**: 誤答 note が「この値にはなりません」で終わるなら「どの誤りでその値になるか」を 1 つ書く。同じ term の note は同じ論点の中で同文に（用語集で 1 つに畳まれる）。note の文末は**敬体（です・ます）**にそろえる（体言止めにしない。`write_question_explanations.md` の約束。バンドルごとに割れると用語集の見え方が割れる）。**正解（`correct`）は絶対に変えない**（原本で固定）
6. **数字・事実の主張は検算する**（計算の合計に出る数値は手順で導入されているか。法令・基準の策定主体）。原本に当たらないと決められない物は「照合待ち」として残す
7. `python3 scripts/check_materials.py --data data/<key> --dir data/<key>/materials_v3` と `python3 scripts/check_explanations.py --data data/<key>` を回し、**担当バンドル由来の警告・問題点が 0** であることを確認する（他バンドルは並行作業中）。門は字数・文数を見ない（止めも警告もしない）。要らない文は読み直し（`self_review.md`）と学習者役の測定で見つける。門が見る物: 選択肢の消し方の語、1 文目の太字、箇条書きの常体、比較項目の総数、`[[ ]]` と太字の混在、表のセル長、`^`、note の「にはなりません」、同じ term の別 note、note の文末の混在

## やらないこと
- 他のバンドル・`topics.json`・`questions/`・仕様書・`glossary_overrides.json`・`review/*.json` に書かない。論点名（`term`）を変えない
- **`correct` と選択肢の原文を変えない**。過去問の原文を 30 字以上写さない
- 「原本と照合したい」と読む段が書いた所（`kind: その他`、severity 無し）は直さない。報告に「照合待ち」として残す（親が原本画像で判定して渡す）
- 情報量を削って短くしない（AP は「判断材料は残す」。消すのは誤答のケアと重複だけ）
- 図の行 `![…](/figures/materials/…)` を消さない・動かさない
- 作業用の一時ファイルを作るなら、名前に対象 key と担当バンドルを含める（作業用ディレクトリは並行する担当と共有）

## 報告（親へ）
- 直した論点と中身（指摘の番号か引用で分かるように）。高・中で**直さなかったもの**とその理由
- 教材から解説へ**移した**文（どの論点のどの行を、どの問題のどの note へ）
- 検算で数字や事実を変えた所
- 「照合待ち」として残した所
- 門の結果（自分のバンドル由来の警告・問題点の数）
- **担当バンドル以外のファイルは読むだけ。書いたのは教材と解説の 2 ファイルだけ**、と明記
