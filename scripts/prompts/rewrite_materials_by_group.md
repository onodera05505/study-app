# まとまりの単位で教材を書き直す（資格対策）

単元の構成（`scripts/prompts/unit_plan.md`）の**まとまり 1 つ**を 1 つの束として受け取り、
そのまとまりの論点の教材を、学ぶ順に通して新しい教材の世代へ書き直すための指示書。
同じ担当がまとまりを通して書くので、論点をまたぐ繰り返しを 1 か所に寄せられる。

**書き方の決まりの正本は `scripts/prompts/write_materials.md`。** この指示書は、入力・出力・手順・情報を落とさない確かめ方だけを決める。
書き方で迷ったら `write_materials.md` に戻る（ここに決まりを書き写さない）。

---

## 先に読むもの（順に全部）

1. `scripts/prompts/write_materials.md` — 教材の書き方。「1 つの点は 1 か所で言う」「他の論点との分担」「中身の型ごとの組み方」「図の置き場」「書き直し」の節が中心
2. `scripts/prompts/material_figures_spec.md` — 図の JSON の形と caption の決まり（この作業で図の JSON に触れてよい所は、下の「出力」の 3 つだけ）
3. `scripts/prompts/write_question_explanations.md` — 問題解説が何を持つか（誤答のケアは解説の持ち場）
4. 担当の書き直しの束（下の「入力」）

## 入力

`data/<対象>/rewrite_bundles/<単元番号 2 桁>-<まとまりの順>.json`（例 `21-2.json`・`05-1.json`。形の正本は `docs/goals/GOAL-11-run-content-pipeline/UC-026-build-rewrite-bundles/contract.yaml` の `writeRewriteBundle`。書き直しの束を作る道具が作る。担当は作り直さない）

```json
{
  "bundle": "21-2",
  "unit_no": 21,
  "unit": "データベース",
  "overview": "…（単元の全体像）",
  "group": {"index": 2, "name": "表を操作する", "description": "…"},
  "groups_in_unit": [
    {"index": 1, "name": "表とキー", "topics": [{"topic_id": 214, "term": "関係データベース"}]}
  ],
  "owners": [
    {"subject": "関係演算の 3 つ（選択・射影・結合）", "owner": {"topic_id": 201, "term": "選択・結合"}, "topics": [201, 230, 231, 232]}
  ],
  "topics": [
    {
      "topic_id": 201,
      "term": "選択・結合",
      "field": "…", "major": "…", "middle": "…", "syllabus_item_name": "…",
      "question_count": 5,
      "related_terms": ["…"],
      "prerequisites": [{"topic_id": 214, "term": "関係データベース"}],
      "current": {"generation": "materials_v3", "explanation": "…", "detail": "…"},
      "questions": [{"question_id": "…", "content_key": "…", "exam_label": "…", "stem": "…", "choices": {"ア": "…"}, "answer": "エ", "has_figure": false, "figure_description": null}],
      "question_explanations": [{"question_id": "…", "correct_reason": "…", "choices": [{"label": "ア", "term": "…", "note": "…"}]}],
      "figure_file": "data/<対象>/material_figures/201.json",
      "figures": [{"id": 1, "type": "matrix", "caption": "…", "after": "explanation"}]
    }
  ]
}
```

- `topics` の並びが**学ぶ順**。この順に書く
- `owners` は、このまとまりの論点が触れる受け持ちだけ。受け持ちの論点が前のまとまりにあっても入る（`owner` の `term` で `[[用語]]` を指す）
- `current` は配る本文と同じ選び方で選んだ、今の最も新しい世代の教材。図の行（`![…](…)`）を含む
- `questions` は同一内容の問題を 1 件に畳んである。`question_explanations` はそれらの問題解説
- `figures` は `figure_file` の `figures` の写し（読むための写し。直すのは `figure_file` の方）
- `prerequisites` は先に読むと良い論点で、同じ束にあるとは限らない。他の束にある前提の論点は、その時点で配られている教材で読む: `python3 scripts/material_generations.py --data data/<対象>` が標準出力に出す JSON の `materials` から、`topic_id` がその論点の物を探し、`explanation`・`detail` を読む（`_generation` と `_file` が選ばれた世代とファイル）
- 束は並行して書かれる（1 束 1 担当）。束をまたぐ重複は単元の構成の受け持ち（`owners`）で防ぐので、他の束の論点が言う点を外せるのは、受け持ちに当たるときだけ

## 出力

1. **教材**: `data/<対象>/materials_v4/<束の名前>.json`（例 `materials_v4/21-2.json`）。形は `write_materials.md` の「出力形式」で、`"bundle"` には束の名前の文字列を入れる。束の全論点を含める
2. **図の JSON**: 束の論点の `figure_file` を、下の 3 つの範囲でだけ直す
3. **点の台帳**: `data/<対象>/rewrite_ledgers/<束の名前>.json`（下の「情報を落とさない確かめ方」）

- 教材の世代 `materials_v4/` には**束ごとに別のファイル**を書く。他の束のファイル・前の世代（`materials_v3/` など）・束のファイル・単元の構成は書き換えない（並行する担当が読んでいる）
- `figure_file` は**束の論点の物だけ**を直す。直してよいのは次の 3 つだけ。それ以外は、図を足さない・消さない・`id`・`type`・`caption`・図の中身を変えない（合わない図は報告に書く）
  1. **`after`** を、新しい教材の見出しに合わせて直す（置き方は `write_materials.md` の「図の置き場」）
  2. **同じ内容の図を外す。** 外せるのは、`write_materials.md` の「図の置き場」の「同じ内容の図は、まとまりの中で 1 枚だけ」で持たない側になった図だけで、次を全部満たすとき: 外す図と同じ内容の図（同じ内容かは `material_figures_spec.md` の「同じ内容の図の判定」）が、同じ束の別の論点に残る／外す図にだけある項目（残る図に無い項目・例の値）に、残る論点の本文か点の台帳で行き先がある／外す論点の紐づく過去問が、残る図を見なくても新しい教材と問題解説で解ける／点の台帳に外した図を書く（`removed_figures`）。外すのは `figures` の 1 件で、残りの図の `id` は詰め直さない。同じ内容の図が他の束の論点にあるときは外さず、報告の「束をまたぐ同じ内容の図」に挙げる（図の見直しの段が扱う）
  3. **caption の句を直す。** 学ぶ順が変わって、caption が学ぶ順でまだ出ていない例・図を指すようになった（図の仕様書の caption の決まり）ときは、その句だけを直してよい。図の中身は変えない。直したら点の台帳に書く（`fixed_captions`）
- 図の例が、紐づく過去問の答えそのもの（同じ数・同じ組）に見えるときは、直さずに報告の「図の見直し」に挙げる（親が原本と照合する）
- 新しい世代の本文には図の行（`![…](…)`）を**写さない**。図は差し込みの道具が `after` の位置に入れる

## やること（この順）

1. **束を通して読む。** 全体像・まとまりの説明・学ぶ順・受け持ち・前提を先に読み、まとまり全体で同じ点がどの論点に何回出ているかを見る
2. **束の中の重複を先に洗う。** 書く前に、束の全論点の今の教材（`current`）と図（`figures`）を通して読み、同じ例・同じ図・同じ比較表・同じ流れが何回出るかを数えて、どの論点が持つかを先に決める（決め方は `write_materials.md` の「他の論点との分担」と「図の置き場」）。決めた割り当てを点の台帳の先頭（`shared`）に書く
3. **論点ごとに点の台帳を作る**（下の「情報を落とさない確かめ方」の 1）
4. **中身の型を決める。** 紐づく過去問で何を問われたかで、主の型を 1 つ（要れば副の型を 1 ブロック）決める（`write_materials.md` の「中身の型の決め方」）
5. **学ぶ順に書く。** 各論点を `write_materials.md` のとおりに組み直す
   - 前提の論点（`prerequisites`）と、同じ束の学ぶ順で前の論点が説明した語は、説明し直さずに指す（指し方は `write_materials.md` の「他の論点との分担」）
   - 受け持ちの説明（`owners`）は、受け持つ論点でだけ書く。他の論点は受け持ちの論点を `[[用語]]` で指し、1 文以内で触れるだけにする
   - 受け持ちの論点の旧版に受け持つ説明が無ければ、束の中の他の論点の旧版から移す（足したことに当たらない。`write_materials.md` の「書き直し」）。束の中のどの旧版にも無ければ書かず、報告に挙げる
   - 比べる 2 つの比較は、学ぶ順で後の論点の教材に書く（`write_materials.md` の「他の論点との分担」）。前の論点の旧版にあった比較を後の論点へ移したら、前の論点の台帳の行き先は `later`
   - 2 で決めた割り当てのとおり、同じ例・比較表・流れは持つ論点でだけ書き、他の論点は持つ論点を指す
   - 全体像（`overview`）・まとまりの説明（`group.description`）に書かれた注意のうち、比べる 2 つのうち学ぶ順で後の論点が束にある物は、その論点の教材で説明する
   - 同じ論点の中で、図・表・箇条・文章が同じ点を言っていたら、1 つに寄せる（`write_materials.md` の「1 つの点は 1 か所で言う」）
6. **図の JSON を直す。** `after` は `write_materials.md` の「図の置き場」のとおりに直す（`after: "explanation"` か、新しい教材に実在する見出し）。2 で持たない側にした図を外し、学ぶ順でまだ出ていない例・図を指す caption の句を直す（どちらも上の「出力」の範囲で）
7. **情報を落とさない確かめ方**の 2・3 を行う
8. **検査を回す**（下の「書き上げたら」）

## 情報を落とさない確かめ方

何を削り何を残すか（重複でない情報は残す）と、決まりがぶつかったときの優先は `write_materials.md` の「書き直し」。次の 3 つで確かめる。

1. **点の台帳を書く。** 書き直す前に、今の教材（`current`）の点（定義・対応・条件・数値・式・例・理由・違い）を 1 つずつ挙げ、書き直した後に行き先を付ける。

   ```json
   {
     "bundle": "21-2",
     "shared": [
       {"item": "選択と射影の結果を並べた表", "count": 3, "holder": 230, "topics": [201, 230, 231]}
     ],
     "topics": [
       {
         "topic_id": 230,
         "points": [
           {"point": "選択は行を、射影は列を取り出す", "fate": "kept", "where": "### 選択との違い"},
           {"point": "射影の定義の言い直し（要点の箇条と detail の文章）", "fate": "duplicate", "where": "explanation の箇条"},
           {"point": "関係演算の 3 つの説明", "fate": "owner", "where": "201"},
           {"point": "射影は選択と違い行を絞らない（誤答の否定）", "fate": "explanation", "where": "question_explanations の note"},
           {"point": "射影で列を取り出した結果の表", "fate": "figure", "where": "230 の図 2"},
           {"point": "表の行と列の呼び方", "fate": "prior", "where": "201"},
           {"point": "射影と結合の違い", "fate": "later", "where": "231 の ### 射影との違い"},
           {"point": "関係代数の生まれた経緯（「なお、」の付け足し）", "fate": "aside", "where": "過去問にも定義・違いにも要らない周辺"}
         ],
         "removed_figures": [
           {"figure_id": 1, "caption": "…", "kept": {"topic_id": 201, "figure_id": 2}}
         ],
         "fixed_captions": [
           {"figure_id": 3, "old": "…", "new": "…"}
         ]
       }
     ]
   }
   ```

   `shared` は、手順の 2 で決めた割り当て（`item` は同じ例・図・比較表・流れの名前、`count` は束の中で出た回数、`holder` は持つ論点 ID、`topics` はそれが出た論点 ID）。`removed_figures` と `fixed_captions` は、上の「出力」で外した図（図の ID・説明文・残る図の論点 ID と図 ID）と、直した caption の句。無ければ書かない。

   試験の問われ方・覚え方・励ましの文（`write_materials.md` の「書き方の約束」が本文に書かないとする文）は点ではないので、台帳に挙げずに消す。その文の中に事実があれば、その事実だけを点として挙げる。

   `fate` は 8 つだけ:

   - `kept` — 新しい教材に残した。`where` は見出しか `explanation`
   - `duplicate` — 同じ論点の中の言い直しなので 1 か所に寄せた。`where` は残した所
   - `owner` — 受け持ちの論点が言う。`where` は受け持ちの論点 ID。他の束の論点が言う点に使えるのはこれだけ。受け持ちの論点の配られている世代（他の束の論点なら `python3 scripts/material_generations.py --data data/<対象>` が選ぶ世代、同じ束の論点なら新しい教材）にその点があることを確かめる。無ければ自分の論点に残し、報告に挙げる
   - `explanation` — 問題解説の持ち場の点で、問題解説が既に持つ。`where` は解説のどこか。送ってよいのは、`write_materials.md` の「書き直し」の「情報を落とさない」が問題解説に任せてよいとする物だけ（誤答の選択肢を打ち消す説明＝誤答のケアと、計算の型が同じ 2 件目以降の過去問を解いてみせる値・全選択肢の値）。正解の根拠（紐づく過去問の正解を選ぶのに要る事実・条件・例）は判断材料で、問題解説の `correct_reason` や誤答の `note` にあっても `explanation` に送らず、本文に残す（`kept`・`duplicate` か、他の論点が言うなら `owner`・`prior`・`later`、図が言うなら `figure`）
   - `figure` — 図が言う。`where` は図（その論点の図か、外した図の代わりに残る図の論点 ID と図 ID）。図の中の文字と caption にその点があることを確かめる（図の見直しの段で図を別の値に替え、点の事柄が図に残って例の値だけが消えた行は、その事柄があることを確かめる。`scripts/prompts/rewrite_figures_review.md` の「点の台帳の直し方」）
   - `prior` — 同じ束の、学ぶ順で前の論点が言う。`where` は論点 ID。その論点の**新しい教材**にその点があることを確かめる。他の束の論点には使わない（他の束は `owner` だけ）
   - `later` — 同じ束の、学ぶ順で後の論点が言う（後の論点へ移した比較など）。`where` は論点 ID と見出し。その論点の**新しい教材**にその点があることを確かめる。他の束の論点には使わない（他の束は `owner` だけ）
   - `aside` — IT パスポートだけで使う。紐づく過去問を解くのにも、その語の定義・決め手・違いにも要らない周辺（豆知識・「なお、」の付け足し・別の論点の丸ごとの説明・応用情報の水準の深掘り）。`where` に理由を 1 行。2 の解き直しで要らないことを確かめてから消す。応用情報では使わない（応用情報は周辺知識を残す）。受け持ち・同じ束の前の論点・後の論点が言う点には使わない（それぞれ `owner`・`prior`・`later`）

   **8 つのどれにも当たらない点は消さない。** `explanation` に送る点は、解説に既にあることを確かめる（無ければ消さずに教材に残し、報告に書く）
2. **紐づく過去問を解き直す。** 新しい教材（図の中の文字と caption を含む）と問題解説を読んで、束の各論点の `questions` を 1 問ずつ解けるか確かめる（正解は `answer` に従う）。同じ束の学ぶ順で前の論点の新しい教材と、`prerequisites` の論点も読んでよい（学習者はその順に読む）。前の論点の過去問が後の論点との比較を問うときは、相手の側を問題解説が補っているかを見る（`write_materials.md` の「他の論点との分担」）。解けない問題があれば、足りない事実を教材に戻す
3. **数値と式を突き合わせる。** 今の教材にある数値と式が、新しい教材（または台帳の行き先の図・前の論点・後の論点・受け持ちの論点・問題解説）にあることを見る。様式の門が「前の世代にあり新しい世代に無い数値」を知らせるので、知らせが出たら台帳の行き先を確かめる

## やらないこと

- 論点名（`term`）・論点 ID・単元の構成を変えない（学ぶ順や受け持ちが合わないと思ったら報告に書く）
- 問題解説（`question_explanations/`）・過去問・正解表を書き換えない
- 前のまとまりの論点の教材を書き直さない（受け持ちの説明が足りないと思ったら報告に書く）
- 書き直しの束を作る道具（`build_rewrite_bundles.py`）・`build_material_bundles.py` を実行しない。束が作り直され、並行する担当の範囲がずれる
- 作業用の一時ファイルを作るなら、名前に対象と束の名前を含める

## 書き上げたら

```bash
python3 scripts/check_materials.py --data data/<対象> --dir data/<対象>/materials_v4
python3 scripts/check_material_style.py --data data/<対象> --dir materials_v4
python3 scripts/render_material_figures.py --data data/<対象> --check --only <束の論点 ID…>
```

- 1 つ目は教材の門（記法・必須の要素・図と用語の実在・過去問の引用）、2 つ目は書き直した世代の様式の門（`explanation` の直後の図が 2 枚以上・単元の構成に無い論点で止め、問われ方の文・同じ点の繰り返し・受け持ちの繰り返し・消えた数値を知らせる）、3 つ目は図の門（`after` が新しい教材に実在する見出しか）
- 全論点の世代をまとめて見るので、**自分の束の論点に関する指摘だけ**直す（他の束は並行して書かれている）
- 止める理由は 0 にする。知らせ（警告）は 1 件ずつ見て、直すか、直さない理由を報告に書く
- 門は字数・文数・見出しの数・箇条書きや比較の項目の数を見ない（止めも警告もしない）

## 報告（親へ）

- 論点ごとの中身の型（主と副）と、見出しの名前。7 つの型のどれにも当たらず近い型に寄せた論点
- 点の台帳のパスと、`duplicate`・`owner`・`explanation`・`figure`・`prior`・`later`・`aside` の件数
- 受け持つ説明が束の中のどの旧版にも無かった受け持ち、配られている世代に点が無く `owner` にできなかった点、比較・使い分けが書かれていた受け持ちの行（どれも直していない）
- 解き直しで解けなかった問題と、戻した事実
- 図の `after` を直した論点と図、合わなくなった図
- 外した図（論点・図の ID・残る図）と、直した caption の句
- 図の見直し（図の例が紐づく過去問の答えそのものに見える図。直していない）
- 束をまたぐ同じ内容の図（自分の束の論点の図と、同じ内容の図を持つ他の束の論点と図。外していない）
- 学ぶ順や受け持ちが合わないと思った所（直していない）
- 門の結果（自分の束に関する止める理由・警告の数、直さなかった警告とその理由。字数・文数・見出しや項目の数の知らせは、`write_materials.md` の「書き上げたら」のとおり本文を変えずに挙げる）
- **書いたのは `materials_v4/<束の名前>.json`・束の論点の図の JSON（`after`・外した図・直した caption の句）・点の台帳だけ**、と明記
