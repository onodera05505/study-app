# 過去問の分類・論点付けの共通仕様

抽出済みの過去問を、シラバスの階層に紐づけ、**論点**を割り当てるための指示書。
29回分すべてで同じ仕様を使うことが目的。

## なぜこの作業が要るか

IT パスポートの公開問題には**分野タグが一切付いていない**。分類はアプリ側で行うしかない。

**応用情報は事情が違う。** 解答例 PDF に「問番号 / 正解 / 分野」の3列があり、分野は
公式に確定している（`data/ap/question_fields.json`）。応用情報を分類するときは:

- **分野は与えられたものを使う。自分で判断しない**
- 項目番号は**その分野の範囲から選ぶ**。テクノロジ系 1〜52 / マネジメント系 53〜70 /
  ストラテジ系 71〜96。範囲外を選んだら、それは間違い
- 候補が 96 から 20〜50 に絞れるので、迷いも取り違えも減る

分野は合否に直結する軸（分野ごとの基準がある）なので、ここが公式に取れる意味は大きい。

そして study-app の設計の根幹は「**論点に紐づく過去問の件数＝出題頻度＝重要度**」。
頻出論点から潰すのが最短合格経路になる。この重要度を算出するには、問題を論点に
紐づける必要がある。分類の質がそのままアプリの価値になる。

## 入力

- `data/questions/<exam>.json` — 抽出済みの問題（`text`, `choices`, `figure_description`）
- `data/syllabus_index.json` — シラバス Ver.6.5 の63項目。各項目に `terms`（IPA が
  「知識として習得すべき用語・キーワード例」として挙げている用語）が付いている

## 入力を読むときの注意

`choices` は `{"ア": "…", "イ": "…"}` という辞書。Python で中身を見るときは
`q["choices"].values()` を見ること。**キーだけを表示すると `["ア","イ","ウ","エ"]` に
見えて「選択肢が空だ」と誤解する**（実際に過去そう報告されたことがある）。

また、選択肢が1文字なのは壊れているのではなく正当なことがある。

- 「a〜c のうち適切なものを全て挙げよ」型 → 選択肢は `a` / `a，b` / `a，b，c` など
- 数値を答える計算問題 → 選択肢は `0` / `1` / `2` / `3` など

## 各問題に付けるもの

### 1. `syllabus_item` — シラバス項目番号（1〜63）

その問題が問うている知識が属する項目。**必ず1つに決める。** 迷う場合は
「その問題を解くために中心的に必要な知識」で選ぶ。

分野（ストラテジ系／マネジメント系／テクノロジ系）は項目番号から自動的に決まるので
指定しなくてよい。

### 2. `topic_term` — 論点（最重要）

**この問題が問うている中心的な論点を1つ**。学習の単位になる。

- **その項目の `terms`（用語例）にある語を優先して選ぶ。** IPA が公式に挙げている
  用語なので、網羅性の根拠になる
- 用語例に適切な語が無い場合だけ、自分で論点名を作り `topic_is_new: true` にする
- **粒度が重要**。項目名そのもの（例:「経営・組織論」）は広すぎる。逆に問題文特有の
  言い回しは狭すぎる。「損益分岐点」「RAID」「デッドロック」くらいの粒度にする
- **表記を揺らさない。** 用語例から選ぶ場合は**そのままコピー**する。用語例が
  「社会的責任（CSR：Corporate Social Responsibility）」なら、その文字列をそのまま使う。
  勝手に「CSR」と短縮しない。同じ論点が別表記になると頻度が分散して重要度が壊れる

#### 用語例の括弧の中に別概念が列挙されている場合

応用情報のシラバスには
`脆弱性管理（… SBOM（Software Bill of Materials）を利用した脆弱性管理ほか）` や
`情報セキュリティ関連組織（CSIRT，PSIRT，SOC …）` のように、
**1エントリの括弧内に複数の別概念が入っている**ものがある。担当ごとに
「総称を採る」「個別語を採る」が割れると頻度が分散する。判断を固定する。

- 括弧の中が**その語自身の言い換え・英語表記**なら、**丸ごとコピー**する。
  例: `社会的責任（CSR：Corporate Social Responsibility）`
- 括弧の中が**別概念の列挙**で、設問がそのうち1語を主題にしているなら、
  **その1語だけ**を `topic_term` にする。例: 主題が PSIRT なら `PSIRT`
- そのとき、**同じ語が他の項目に単独で載っていればその表記をコピーする。**
  無ければ `topic_is_new: true` にする

### 3. `related_terms` — 周辺の用語（0〜4語）

解答に関わる、あるいは選択肢に出てくる用語。教材で「周辺知識」を書くときの材料になる。
用語例にある語を優先するが、無ければ自分の言葉でよい。

### 4. `confidence`

`high` / `medium` / `low`。項目の選択や論点の割り当てに迷った場合は下げ、`notes` に理由を書く。
**迷ったまま high にしない。** 後で人がレビューする対象を絞るための情報なので、正直に付ける。

## 判断に迷いやすいケース

- **複数の項目にまたがる問題** — 「その問題を解くために中心的に必要な知識」で決める。
  たとえば「プロジェクトの工程表から所要日数を求める」問題は、計算そのものより
  プロジェクトマネジメントの知識を問うているので項目27
- **用語の意味を問うだけの問題** — その用語がそのまま `topic_term`
- **複数の用語を比較させる問題** — 問題文が主題としている用語を `topic_term` にし、
  比較対象を `related_terms` に入れる
- **計算問題** — 計算手法そのものが論点（「損益分岐点」「稼働率」など）

## 出力形式

```json
{
  "exam": "2024r06",
  "range": "1-50",
  "classifications": [
    {
      "number": 8,
      "syllabus_item": 3,
      "topic_term": "損益計算書",
      "topic_is_new": false,
      "related_terms": ["当期純利益", "販売費及び一般管理費"],
      "confidence": "high",
      "notes": null
    }
  ]
}
```

`classifications` には担当範囲の全問を入れる。抜けがあると重要度の集計が狂う。
