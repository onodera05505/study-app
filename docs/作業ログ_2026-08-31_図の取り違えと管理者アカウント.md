前日（8/30）の点検で挙げた懸念5件のうち4件を処理した。うち1件は**本番に出ていた実害のある

## 1. IT パスポートの画面に応用情報の図が出ていた（修正済み）

### 何が起きていたか

IT パスポート **令和2年度10月 問55**（アローダイアグラムの最短・最長所要日数を問う）の
図として、**応用情報の同回・同問番号の図**（逓減課金方式のグラフ）が表示されていた。

### 原因

図の画像は `public/figures/<試験ID>-q<問番号>.png` と平置きで、**試験をまたいで
同じディレクトリを共有していた**。そして IT パスポートと応用情報には
**同じ試験 ID が存在する**。令和2年度10月がそれで、どちらも `2020r02o`。

コロナ禍で春期が中止になり10月に1回だけ実施された回が、両方の試験にある。
両方が問55の図を切り出したため、`2020r02o-q55.png` を奪い合い、後から切り出した
応用情報（8/29 12:28）が IT パスポートの図（8/23）を上書きしていた。

`crop_figures.py` は上書きを警告しない。`build_seed.py` はファイルの実在しか見ない。
**どちらの検査も「正しい図か」を見ていなかった**ので通り抜けた。

### 直し方

画像を試験ごとのディレクトリに分けた。

| | 前 | 後 |
| --- | --- | --- |
| 置き場所 | `public/figures/<試験ID>-q<N>.png` | `public/figures/<試験>/<試験ID>-q<N>.png` |
| DB の `figure_image` | `/figures/2020r02o-q55.png` | `/figures/ip/2020r02o-q55.png` |

- `build_seed.py` … `--figures` の既定を `public/figures/<試験>` にし、URL にも試験を挟む
- `check_seed.py` … `/figures/<試験>/` 以外の URL があれば**問題として止める**
- 手順書（`回を追加する手順.md` / `応用情報を追加する.md` / README）の切り出しコマンドを
  `--out public/figures/ip`（`ap`）に更新

**旧い平置きのファイルは消していない。** 進行中のセッションは作成時のスナップショットを
持っていて、そこには旧 URL が入っているため。全セッションが終わったら消してよい。

### 確認したこと

- 切り出し直した画像40枚（応用情報）が、既存ファイルとバイト単位で一致
- IT パスポートの `2020r02o-q55` が**アローダイアグラムに戻った**ことを画像で目視
- 本番の URL が 200 を返し、中身がローカルと md5 一致
  （`https://itpass-study-c91.pages.dev/figures/ip/2020r02o-q55.png`）
- 本番 DB の `figure_image` が IT パスポート 39/39・応用情報 40/40 とも新形式

## 2. 図の切り出し定義が応用情報だけ古かった（修正済み）

`data/ap/figures/boxes.json`（統合ファイル）は13件しか入っていないのに、実際の画像は40枚
あった。回ごとの `boxes_<試験ID>.json` を作ったあと統合ファイルへ写す運用で、8/29 に
足した回ぶんの**写し忘れ**だった。

手順書の再生成コマンドは統合ファイルを指していたので、`public/figures` を消して再生成すると

`crop_figures.py` の `--boxes` にディレクトリを渡せるようにした。`boxes*.json` を全部読むので
写し忘れが起こらない。統合ファイルも作り直した（13件 → 40件）。

## 3. 既定パスワードの管理者アカウントが本番2サイトで生きていた（対処済み）

`admin@example.com` / `itpass-admin`（ADMIN）が両方の本番 DB にあり、**保存されている
ハッシュから再計算して既定パスワードのままだと確認**した。README にも書いてある値だった。

- 合言葉（`SIGNUP_CODE`）は新規登録にしか効かない。**ログインには効かない**ので素通り
- ログイン試行の回数制限は無い
- 救いは `ADMIN` ロールが `src/` のどこからも参照されていないこと。権限差が無いので、
  他人の進捗が見えるわけではない

### やったこと

- 両サイトの管理ユーザのパスワードを、ランダムな値に交換した（本人へ別途伝達）
- `build_seed.py` の `--admin-password` から**既定値を外した**。渡したときだけ
  `users` への INSERT を出す。渡さなければ `users` に一切触らない

後者が本題で、以前は**回を追加して再投入するたびにパスワードが既定値へ戻る**作りだった
（UPSERT が `password_hash` を更新していた）。DB 側で変えても意味がなかった。

IT パスポート側の管理ユーザには理解度が4件ぶら下がっていたので、行は消さずに残した。

## 4. 進捗データのバックアップが無かった（対処済み）

`progress` と `sessions` は本番 D1 にしか無い。問題・論点・教材は `data/` から作り直せるが、
進捗は作り直せない。しかも seed の投入は `DELETE FROM topics WHERE id NOT IN (…)` を含み、
`progress` は ON DELETE CASCADE。**中身のおかしい seed を流すと理解度が消える**
（`data/ip/seed.sql` の中身が応用情報になっていた事故が 8/28 にあった）。

`scripts/backup_d1.sh` を追加した。`wrangler d1 export` で両 DB を `backups/` に吸い出す
（`.gitignore` 済み）。初回のバックアップは取得済み。

```
study-app-db_2026-08-31_1317.sql     過去問1100 / 論点532 / 進捗5 / 受験0
study-app-ap-db_2026-08-31_1317.sql  過去問880 / 論点584 / 進捗3 / 受験4
```

README の「データを更新したとき」の手順を、**バックアップ → seed 生成 → check_seed →
投入**の順に書き換えた。

## 5. 判断が要るので手を付けていないもの

**応用情報に同一問題が51問ぶん重複している**（47組、全880問の 5.8%。3回出題が3組）。
本文・選択肢が完全一致するもので、IPA が午前で実際に使い回しているため**原本どおり**。
データの誤りではない。

- 出題頻度＝重要度の観点では「2回問われた」が正しいとも言える
- 一方で、通し受験や模試で**同じ問題が2回出る**

どちらの扱いにするかは学習体験の設計判断なので、判断待ちとして
[`未修正のバグ.md`](未修正のバグ.md) に残した。IT パスポートには重複が無い。

## ついでに確認して問題が無かったもの

点検のなかで、これまで検証していなかった箇所を機械的に照合した。

- **出題頻度**（`question_count`）を分類データから独立に数え直して**全件一致**
  （別名と照合キー NFKC＋小文字を反映）。`懸念_表示データに検証が無い.md` のテスト4のうち、
  出題頻度の検証はこれで済んだ
- 本番 DB とローカルが完全一致（IT パスポート 1,100問/532論点/1,100紐付け、
  応用情報 880/584/880）。紐付けの無い問題0件、教材の無い論点0件
- `topic_ids.json` の ID 重複・欠落なし。`topics.json` との ID 不一致0件
- 正解記号が選択肢に無い／選択肢が4つでない／本文が空、いずれも両試験0件

なお点検の途中、「ID が195件欠けている」「頻度が7件ずれている」と見えた箇所があったが、
どちらも**照合キーと別名を反映していなかったための誤報**だった。
CLAUDE.md の「必ず原本と照合してから判断する」がここでも効いた。
