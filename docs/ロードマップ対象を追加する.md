# ロードマップ対象（資格以外の学び）を 3 つ目以降の試験として本番に出す手順（線）

要件定義書 §13 の試作「IT コンサルになる（就活の目線）」を最初の実例として、2026-09-15 に作った。
資格版（ip / ap）と同じコード・別データ・別 D1・別 Pages。違いは **出題頻度が無い**ので並びを `topics.sort_order` で決めること、
問題が **自作の確認問題**であること、分野が自前の 4 つであること。

## 0. 前提
- `data/<対象>/` に試作の生成物がある: `roadmap.json`（`scripts/build_roadmap.py`）、`materials/*.json`、`roadmap_questions/bundle_*.json`、`topics_candidates.json`。
  作り方と 3 周の学習者ループは `docs/作業ログ_2026-09-15_ロードマップ試作.md`
- `src/shared/exam.ts` の `EXAMS` に対象を足す（`roadmap: true`、`fields` は自前の分野の並び、`words` は画面の文言、`mockSize` は単位数）
- `scripts/build_seed.py` の `EXAM_NAMES`、`scripts/check_seed.py` の `QUESTIONS_PER_EXAM`（1 日の単位数 × 2）、
  `deploy-pages.sh` / `seed_remote.sh` / `backup_d1.sh` / `verify_seed_remote.py` / `check_render.sh` / `check_api.sh` / `check_api.py` の対象一覧、`.env.<対象>`、`wrangler.jsonc` の `env.<対象>`

## 1. データを投入経路の形に変換する
```bash
python3 scripts/build_itc_dataset.py --data data/itc   # 対象を増やすときはこのスクリプトを一般化する（今は itc の名で決め打ち）
python3 scripts/build_seed.py --data data/itc
python3 scripts/check_seed.py --data data/itc
bash scripts/check_render.sh itc
```
変換で決めていること: 「回」＝日（`itc-d01`…、ラベル「1 日目」）、問題番号は日の中で 1〜6、論点 id は候補 id のまま、`sort_order` はロードマップの順、
教材末尾に `### 出典`、問題解説は `reason` を `correct_reason` に（誤答の note は空。検討事項）。

## 2. ローカルでリハーサル
```bash
CI=1 npx wrangler d1 migrations apply study-app-itc-db --env itc --local   # CI=1 が無いと確認プロンプトで止まる
bash scripts/seed_remote.sh itc --local
bash scripts/check_api.sh itc
```

## 3. 本番へ（対話端末で `npx wrangler login` を済ませてから）
```bash
bash scripts/setup_itc_remote.sh <合言葉>
```
D1 作成 → `wrangler.jsonc` に ID → マイグレーション → Pages プロジェクト → secret（JWT_SECRET 乱数・SIGNUP_CODE）→ deploy-pages.sh → seed_remote.sh を 1 本で回す。
終わったら `wrangler.jsonc` の ID をコミットし、ログイン後の画面（学習の並び・確認問題・確認テスト・出典）を人が見る。

## 落とし穴
- **OAuth トークンは失効する**（2026-09-15 未明に失効。非対話環境では更新できず、`d1 create` が黙って止まった）。本番操作の前に `npx wrangler whoami`
- `wrangler d1 migrations apply` は確認プロンプトで止まる。非対話で回すなら `CI=1`（ただし CI=1 だと OAuth を拒むので、**本番は人が対話端末で**）
- `data/<対象>/questions/` は投入経路が `*.json` を全部「回」として読む。生成前の問題ファイルは `roadmap_questions/` に置く（混ぜて `KeyError: 'exam'` になった）
- 資格版の D1 には `sort_order` 列が無くてよい（資格版の SQL は列を参照しない。seed も列を出さない）。ただし drizzle のスキーマは列を持つので、次に ip / ap を触るときに `migrations apply` を当てて揃える
