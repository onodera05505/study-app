# BR-031 論点の一覧の並びと論点の前後の導線は、学びの種類で決まる

資格対策の学びは、単元の中の論点を、その単元の構成が決める単元の学ぶ順（BR-057）に並べる。単元の構成を持たない単元では、論点を小項目の番号の順に束ね、小項目の中は出題頻度の降順、出題頻度が同じ論点どうしは論点の ID の順に並べる。単元を絞らない一覧は、単元の番号の順に、単元ごとにこの並びで置く。単元の構成は学びのデータとして投入で入り、利用者の操作では変わらない（投入された単元の構成の置き場は学び側の DB の表 `unit_plans`・`unit_groups`・`unit_group_topics`・`topic_prerequisites` で、定義の SSOT は `src/server/db/schema.ts`）。資格対策の学ぶ順は、ロードマップ型の学ぶ順の列 `topics.sort_order` には入れない（不変条件 D13）。

ロードマップ型の学びは、論点を学び全体を通した学ぶ順に並べる。学び全体を通した学ぶ順を持ち、それで回を決めるのはロードマップ型だけ。

論点の画面の前後の導線は、ロードマップ型の学びでは学ぶ順の前と次の論点、資格対策の学びでは「次に学ぶ」（BR-030）が受け持つ。

**意図**: 同じコードで 2 種類の学びを出しているため、種類の判定を 1 か所に寄せないと片方の学びが壊れること（不変条件 D13）。資格対策で単元の中を出題頻度の順に並べると、前提の論点が後ろに来て、まだ習っていない語で説明される（利用者と学習者役の指摘）。出題頻度は並びではなく、出題回数の印（BR-051）と次に学ぶ（BR-030）に使う。
