  - 阻止: 追跡も無視もされていないファイルを読む土台が挙がらない（仕様は「追跡しないファイル」、実装は git が無視するパスだけ）／パスを分けて書いた名前（`join(ROOT, 'data', …)`）が挙がらない／git の無い写しでは登録簿の検査が追跡を確かめずに成功する（UC-042 の事前条件に git が無い）／門の対応表のパスは決まった先頭の物しか読まない（`.githooks/`・`tests/`・`migrations/`・`portal/` を読まない）／単独で回す組の型が、手元に依らない名前のファイルも抱える
  - 問い: 起こした子のプロセスや設定が暗に読む追跡しないファイルを道具は見ない／受け渡し役が土台を通さずに手元の物を使う場合／入れ子の深さの上限 100 段は仕様に無い／文書の検査が git に断られたとき追跡の確かめを飛ばす
- 疑念（稼働でしか確かめられない）: 止めるときの待ちの間に番号が使い回されると、起こしていないプロセスを KILL しうる／固定した版は包みの版の記録で見るので、実行ファイルの先が別の包みでも見分けない
- 直しは、問いへの本人の決定を待って仕様から入れる

## 審査の阻止 5 件の直し（同日の夜）

- 本人の決定 4 点（`brain/PREMISES.md` の 2026-11-26 の 3 本目の行。親が推しから決めた読みも同じ行）で、仕様 → テスト → 実装の順に直した
  - 文書の検査と登録簿の検査は、追跡を確かめられない置き場（git の作業ツリーの根でない・git に断られる）では、理由を示して失敗で終える
  - 振り分けの道具は、置き場に実際にあって索引に無いパス（無視されていない未追跡も）を名指す土台、パスを分けて書いた名前、土台を通さずに手元の物を使う受け渡し役を挙げる。git の置き場そのもの・`node_modules`・原本 harness の置き場は数えない
  - 門の対応表が名指すパスは、先頭の置き場で絞らず全部見る。単独で回す組は `.local` の名前のファイルだけ
  - 図の形の門の入れ子の上限は 100 段（100 段は通り 101 段は止まる）
  - 子のプロセスや設定が暗に読む追跡しないファイルは道具の範囲の外で、共有の置き場で落ちることで見つける
- 受け渡し役の共通の部品は、追跡しない置き場の名前を持たずに、追跡する物だけを写して影の根を組む。シードの組み立て（UC-027）の契約の実例 25 件は手元だけに移った（手元に依らない UC 33・手元だけ 7）
- 通しは 5 回回した。落ちた原因は順に: 契約の実例を確かめるテストの影の根が git の置き場でなかった（土台を直した）／機械の負荷で契約の実例の段が時間の上限に当たった（負荷が下がるのを待って回し直した）／版の印のテストの仕込みが git を必ず失敗させていて、新しい決まりで文書の門が止まった（仕込みを「履歴の無い git の置き場」に替えた）／使わなくなった関数が 1 つ残っていた（消した）／5 回目は 11 検査すべて通過
- 負荷: 大量のファイルの作成と削除のあと、ファイルの見張り（fseventsd）と索引づくり（mds）が CPU を使い続け、1 分の負荷の平均が 15〜17 のまま下がらない時間があった。通しのテストの所要は 908〜1,350 秒（ふだんは 660 秒前後）。**負荷が下がる（6 未満）のを待ってから回す**と安定した
- 効き方の注意: 配備の道具は、git が使えない置き場（zip で取った写しなど）からは文書の門で止まる
