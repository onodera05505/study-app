# REQ-103

> 利用者が模試の入口を開いたとき、システムは回の一覧と、全範囲からランダム構成で受ける入口の両方を、そこから受験を始められる形で示す。

## 検証方針

- **分割クラス**:
  - `#both-entries` — 回の一覧とランダム構成の入口の両方が、そこから受験を始められる形で出る
  - `#not-loaded-vs-empty` — 取得前と、取得できて結果が空を別の状態として示す（BR-015）
- **尽きている根拠**: この文の入力は「一覧の取得の状態」だけで、未取得・空・1 件以上の 3 値。1 件以上が both-entries、未取得と空の区別が not-loaded-vs-empty に落ちる。
- **検証しない**: 取得が失敗したときの文言と読み直す手段（BR-014）。画面ごとに同じ形なので `tests/scenario/BR-014-api-failure.test.tsx` が見る。
- **参照先**: `tests/client/exams.test.tsx::模擬試験の画面`
