# REQ-250

> 模試へ送られた回答が指す問題の位置が、そのテストの現在の問題の位置と違う場合、システムは、BR-022 に従い、採点も記録もせず、その回答を受け付けずに断る。

## 検証方針

- **分割クラス**:
  - `#stale-idx-not-scored` — 送られた位置が現在の問題の位置と違う回答を、採点も記録もせず、その回答を受け付けずに断る
- **尽きている根拠**: 送られた位置と現在の位置の関係は（同じ）と（違う）の 2 つで、同じ側は REQ-113 が持つ。違う側は前にずれていても後ろにずれていても振る舞いが変わらない（どちらも採点しない）ので 1 クラス。
- **検証しない**: ずれの原因（二重送信・戻る操作）。原因は要求から観測できず、同じ 1 つの入力（位置の不一致）に畳まれる。画面側でのずれの伝え方と現在の問題の取り直し（REQ-277）。断りの本文の形（正本は契約の `ErrorBody`。位置は載らず、位置の正本は現在の問題の取得だけが持つ＝BR-022）。
- **参照先**: —（未被覆。`tests/client/session.test.tsx` の「位置が食い違っていると返されたら…」は画面側の受け取りで、1 テスト 1 クラスで REQ-068 が持つ。サーバが採点も記録もせずに断ることは system suite の `scripts/check_api.py`（二重回答）が本番相当で見る）
