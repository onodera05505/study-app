# REQ-277

> 模試で送った回答が受け付けられずに断られたとき、システムは、現在の問題を取り直し、取り直した結果（終わっている・現在の問題はどれか）に従って示し、取り直した位置が送った位置と違うときは表示がずれていたことを利用者に伝える。

## 検証方針

- **分割クラス**:
  - `#rejected-refetch-finished` — 断られて取り直した結果が「終わっている」（未回答なし・時間切れ）なら、断られた回答を採点したことにせず締めと結果の流れへ進む
  - `#stale-idx-refetch` — 断られて取り直した結果がまだ現在の問題を持つなら、表示がずれていたことを伝え、取り直した問題（位置と進み具合は取り直した結果の物）を示す
- **尽きている根拠**: 取り直した結果はUC-004 の契約 `getCurrentQuestion` の `finished` で「終わっている」と「現在の問題がある」の 2 つに分かれ、クラスもその 2 つ。断りの本文は ErrorBody だけで理由を区別しない（BR-022）ので、断られた理由（締めた・時間切れ・未回答なし・位置の食い違い）は分岐を生まない。終わっている側の未回答なしと時間切れは同じ流れへ進むので 1 クラスにし、両方を値の変種として持つ。現在の問題がある側は、その位置が送った位置と違う（同じ位置が現在の問題として返るなら、その回答は断られていない。同時の回答の断りでも先の回答で位置は進む）ので、「ずれを伝え、取り直した問題を示す」の 1 クラス（演習の REQ-068 と同じ切り方）。
- **検証しない**: 取り直しそのものが失敗したとき（演習の REQ-278 の射程で、模試の文は持たない）。断りの本文の文言（正本はコード）。
