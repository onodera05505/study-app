# REQ-085

> 進行中のテストが無い状態で破棄を求められた場合、システムは、それを失敗とせず、破棄が済んだものとして扱う。

## 検証方針

- **分割クラス**:
  - `#discard-without-current` — 進行中のテストが無い状態で破棄を求めた入力（失敗にせず、破棄が済んだものとして返る）
- **尽きている根拠**: 破棄の要求が届いた時点の状態は「進行中がある」と「進行中が無い」の 2 つで、ある側は REQ-090 が持つ。表の「進行中のテストが無い」行と「進行中の案内が古い」行は、要求が届いた時点で進行中が無いという同じ入力なので 1 クラス。
- **境界の扱い**: 破棄が成功した直後の 2 度目の破棄（冪等）も同じクラスに入る。
- **検証しない**: 応答の形（境界の契約の `discardCurrentSession` が持つ）。
- **参照先**: 未検証（単体テストは無い。system suite の `scripts/check_api.py::check_discard` が「進行中が無くても破棄は 200」を本番相当の経路で見ている＝`@covers` の対象外）
