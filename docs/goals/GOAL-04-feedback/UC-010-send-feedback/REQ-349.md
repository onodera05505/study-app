# REQ-349

> 送信中に利用者がフィードバックの画面を離れたとき、システムはその送信を取り消さず、受け付けられれば端末の下書きを残さず、拒まれるか届かなければ書いた本文を端末の下書きに残す。

## 検証方針

- **分割クラス**:
  - `#left-then-accepted` — 送信中に画面を離れ、その送信が受け付けられた入力（フィードバックは 1 件残り、戻ったときの本文は空で始まる）
  - `#left-then-rejected` — 送信中に画面を離れ、その送信が拒まれた、または届かなかった入力（フィードバックは残らず、戻ったときに書いた本文が下書きから戻る）
- **尽きている根拠**: UC.md の表 2「送信中」×「フィードバックの画面から離れて戻る」の 1 セルで、離れたあとの送信の帰結は受け付けられる／拒まれる・届かないの 2 つに尽きる（拒まれると届かないは、下書きが残るという同じ観測に落ちる）。
- **検証しない**: 戻った画面に受付文や断りの理由を出すこと（離れた画面の表示は残らず、この文は出すことを決めていない）。選んだ種類を下書きに残すこと（`saveFeedbackDraft` の request は本文だけを持つ）。端末の記憶に書けないとき（BR-011。下書きを残さないだけ）。
- **参照先**: `tests/client/repay_UC-010_feedback_screen.test.tsx::送信中に画面を離れたとき（UC-010）`（送信の応答を手で返す偽の fetch で、離れたあとに帰結を返す。取り消さないことは送信の中断の合図が立っていないことで見る）
