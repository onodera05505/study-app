# REQ-242

> 端末が添え先を覚えられないとき、または覚えた値が読めないとき、システムは添え先を覚えていないものとして扱い、画面の移りとフィードバックを送ることを止めない。

## 検証方針

- **分割クラス**:
  - `#unreadable-value` — 覚えた添え先が読めない値になっている（添え先を覚えていない扱いになり、画面が止まらない）
  - `#cannot-remember` — 端末が添え先を覚えられない（覚える操作が断りの種類の名前を持つ失敗を渡しても、画面の移りが止まらず、添え先を覚えていない扱いになる）
  - `#annotate-blocked` — 開いた画面が論点・問題を読み終えて添え先に足すときに端末の記憶が使えない（足す操作が名前を持つ失敗を渡しても、その画面が止まらない）
  - `#read-blocked-feedback` — フィードバックの画面が端末の記憶から添え先を読めない（読む操作が名前を持つ失敗を渡しても、添え先を示さず、フィードバックを送ることが止まらない）
- **尽きている根拠**: 端末の記憶で失敗しうる経路は読みと書きの 2 つで、BR-011 はその両方を「その機能を出さないだけにする」に畳む。添え先に触る場面は、学びの画面へ移る（覚える）・読み終えて足す・フィードバックの画面で読む、の 3 つで、覚えられない側をクラス 2・3、読めない側をクラス 1（値が読めない）と 4（記憶が読めない）が取る。読めた・書けた側は REQ-146・REQ-148・REQ-149 が持つ。
- **境界の扱い**: 読める値と読めない値の境目は記憶の中身の形だけで、値の大小の境界を持たない。
- **検証しない**: 添え先が無いままフィードバックを送れること（REQ-148 が添えるものが無い場合を持つ）。端末の記憶が使えない理由（設定・容量）の区別。記憶の鍵の名前（R-102）。
