# UC-019 学習者役のパックを作って読ませ、伝わったかを周の結果で測る

## 概要

作り手が、ロードマップ型の学びから周の番号を付けて学習者役のパックを作り、学習者役への指示と共に学習者役に渡し、返ってきた答えと自己申告をその周のパックの写しで採点して、どの単位が伝わりどこで詰まったかを周の結果として受け取る。

## 事前条件

- ロードマップ型の学びで、ロードマップ・確認問題と、利用者に配る本文がそろっている
- 適用される業務規則: BR-026, BR-031, BR-054, BR-055, BR-061

## 主シナリオ

1. 作り手が、学びと周の番号と出力先を指定して学習者役のパックを作る
2. システムが、その周のパックの写しを残す
3. システムが、ロードマップ・単位ごとの配る本文と図・確認問題、語の一覧がある学びでは説明テストを、正解を含めずにパックへ出す
4. 作り手が、学びの学習者役への指示を雛形から描き出す
5. 作り手が、パックと学習者役への指示だけを学習者役に渡す
6. 学習者役が、ロードマップの順に単位を読み、確認問題に答え、単位ごとの自己申告と説明テストの答えを返す
7. 作り手が、同じ周の番号を指定して学習者役の答えを採点する
8. システムが、その周のパックの写しで採点し、周の結果を残して作り手に示す

## 要件

### REQ-304

- pattern: Event-driven
- status: active

> 作り手が周の番号を指定して学習者役のパックを作ったとき、システムはロードマップの単位を学ぶ順に、各単位の ID と属する回を添えて並べた一覧、単位ごとのファイル、ロードマップの単位の確認問題と、単位の ID を必須とする答えと自己申告の書き方を出し、説明テストの語の一覧を持つ学びではその語の説明テストも出す。

#### 検証方針

- **分割クラス**:
  - `#order-id-and-round` — 一覧で単位が学ぶ順（単位の ID の順でない）に並び、各行に単位の ID、回の見出しの下に置かれる
  - `#unit-file-per-unit` — ロードマップの単位ごとに 1 ファイル、名前の番号の順が学ぶ順
  - `#quiz-questions` — ロードマップの単位の確認問題が問いと 4 つの選択肢とともに出る
  - `#answer-format` — 答えと自己申告の書き方が、answers 空・units の各行が単位の ID を持つ JSON で出る
  - `#explain-with-terms` — 語の一覧を持つ学びでは説明テストに一覧の語がすべて出る
  - `#no-explain-without-terms` — 語の一覧を持たない学びでは説明テストを出さない
  - `#response-lists-files` — 応答の files がパックの中に実在するファイルと一致する
- **尽きている根拠**: 出すもの（一覧・単位・確認問題・書き方・説明テスト）を 1 つずつと、説明テストの有無の 2 値で分けた。並びは学ぶ順と単位の ID の順を違えたロードマップで、順の取り違えを観測できる形にした
- **検証しない**: 日で束ねる学びの回の見出しの語（登録簿の値で契約に無い）。一覧・確認問題のファイルの書式（見出しや表の形）は契約が決めないので、語の有無と出現の順だけを見る

### REQ-305

- pattern: Ubiquitous
- br: BR-054
- status: active

> 学習者役のパックの各単位のファイルは、単位の名前と分野と単元を添え、その単位について利用者に配る本文（投入が教材の世代から論点ごとに選ぶ説明と詳しい解説で、出典と図の行（BR-054）を含む）を、図の参照先だけを変えて全文含む。

#### 検証方針

- **分割クラス**:
  - `#unit-header` — 単位のファイルが単位の名前・分野・単元を添える
  - `#full-body` — 説明と詳しい解説（出典と図の行を含む）を、図の参照先を戻せば全文含む
  - `#latest-generation-per-unit` — 配る本文は単位ごとに後の世代の教材を選び、後の世代に無い単位は前の世代の物を出す
  - `#delivered-not-edited` — 直したが組み立て直していない教材はパックに出ず、配る本文が出る
- **尽きている根拠**: 単位のファイルの中身を、添える属性・本文の全文・本文の出どころ（単位ごとにどの世代を選ぶか・配る本文か直した教材か）に分けた
- **検証しない**: 本文の中の改行や空白の正規化（配る本文を文字どおり含むかだけを見る）。materials_v2 の世代（ファイルの置き方が契約に無く、フィクスチャは materials と materials_v3 の 2 世代で前後を見る）

### REQ-306

- pattern: State-driven
- status: active

> 単位の配る本文が図を含むあいだ、学習者役のパックはその図を、元の置き場のサブパスを保ち拡張子を .png にした PNG の画像として、元の図の文字（長音符・中黒を含む）を欠かさずに描いて含み、パックの本文の図はその PNG を指して、学習者役がパックの外に出ずに図を画像として開ける。

#### 検証方針

- **分割クラス**:
  - `#svg-drawn-as-png` — 置き場の直下の svg の図が、figures の下に拡張子を .png にした PNG として入り、本文の図がそれを指す
  - `#subpath-kept` — 置き場のサブパスの下の図が、figures の下に同じサブパスの PNG として入る
  - `#png-source` — 元が png の図も同じ名前の PNG として入る
  - `#symbols-drawn` — 図の文字の中黒・長音符だけが違えば、パックの PNG の中身も違う
  - `#unit-without-figure` — 図を含まない単位のファイルは画像を指さない
  - `#no-outside-reference` — パックのどの本文も配信の置き場・パックの外・PNG でない画像を指さない
  - `#tall-and-wide-drawn-whole` — 縦長・横長の図を、元の図の幅と高さのまま切らずに描く（PNG の寸法が元の図の寸法と一致し、図の端に置いた文字だけが違う 2 つの図から作った PNG が違う）
  - `#same-on-ci` — 上の各クラスが、ubuntu の CI でも手元と同じく通る（描き方が OS に備わった道具に依らない）
- **尽きている根拠**: 元の図の形式（svg・png）× 置き場の深さ（直下・サブパス）と、図の有無、参照先がパックの外に漏れる場合、図の形（標準・縦長・横長）で尽きる。文字を欠かさず描くことは、その記号だけを違えた 2 つの図（縦長は下端、横長は右端に置く）から作った PNG が違うことで、切らずに描くことは PNG の寸法が元の図の幅と高さに一致することで見る。CI と同じことは、PATH から qlmanage・sips を持つディレクトリを外して作ったパックで見る
- **検証しない**: ubuntu の CI そのものでの実行（手元では PATH から macOS の道具を外して代える）。描いた文字が読めるか・欠けた字形（豆腐）で描かれていないか（画像の中の文字は機械で読めず、人が見る）。1 つの画像を複数の単位が指す場合（外から観測しても同じ）

### REQ-307

- pattern: Ubiquitous
- status: active

> 学習者役のパックは、確認問題の正解・正解の根拠・選択肢ごとの説明を、確認問題に添える欄として含まない。

#### 検証方針

- **分割クラス**:
  - `#answer-not-in-pack` — 正解だけが違う 2 つの学びから作ったパックがバイト単位で同じ
  - `#reason-not-in-pack` — 確認問題のファイルに、正解の根拠を添える欄が出ない（根拠の欄にしかない印の文で見る）
  - `#choice-notes-not-in-pack` — 確認問題のファイルに、選択肢ごとの説明を添える欄が出ない（説明の欄にしかない印の文で見る）
- **尽きている根拠**: 含まない物 3 つに 1 クラスずつ。正解は選択肢の記号で文字列の不在では見られないため、正解だけを変えた 2 つのパックが同じことで見る
- **検証しない**: 学習者役がパックの中の他の手掛かり（本文）から正解を推せるか（意味の判断で機械で見られない）。単位の本文が教材として、根拠や説明と同じ文を含むこと（REQ-305 が配る本文の全文を求める物で、この要件の外。本文は削らない）

### REQ-308

- pattern: Event-driven
- status: active

> 作り手が学習者役のパックを作るとき、システムはその時点のロードマップに無い単位の確認問題を、パックにも写しにも入れない。

#### 検証方針

- **分割クラス**:
  - `#off-roadmap-excluded` — ロードマップに無い単位の問題がパックにも写しにも入らない
  - `#roadmap-questions-kept` — ロードマップにある単位の問題はすべて写しに入る
- **尽きている根拠**: 問題の単位がロードマップにあるかの 2 値で尽きる。後者で「全部落とす」実装を弾く
- **検証しない**: ロードマップに無い単位の問題を出力に挙げるか（文が決めない）

### REQ-309

- pattern: Event-driven
- status: active

> 作り手が周の番号を指定して学習者役のパックを作ったとき、システムはその時点のロードマップの並びと、パックに出した順の確認問題ごとの正解・属する単位・測る到達基準・分野を、その周のパックの写しとしてパックの外に残す。

#### 検証方針

- **分割クラス**:
  - `#snapshot-file-and-response` — 写しが eval の下の pack_cycle_<周>.json にあり、応答の snapshot と同じ
  - `#roadmap-order-recorded` — 写しの units がその時点のロードマップの並び
  - `#questions-in-pack-order` — 写しの questions の並びが確認問題のファイルに出した順
  - `#question-attributes` — 写しの各問題が正解・単位・到達基準・単位の分野を持つ
  - `#snapshot-outside-pack` — 写しはパックの外にだけあり、パックに余分なファイルが無い
  - `#earlier-cycles-untouched` — より小さい番号の周の写しと結果があっても作り、それらを書き換えない
  - `#unreadable-earlier-result-not-read` — 差を取る前の周の結果が読めなくてもパックを作り、その結果を書き換えない
- **尽きている根拠**: 写しの置き場・中身の 2 部分（並び・問題）・パックとの分離と、前の周がある状態（UC の表の行）で分けた
- **検証しない**: 写しの JSON の書式（字下げ・鍵の順）。写しの各行の契約に無い欄（契約の欄だけを比べる）

### REQ-310

- pattern: Event-driven
- status: active

> 作り手が周の番号を指定して学習者役の答えを採点したとき、システムはいつもその周のパックの写しにある問題と正解で採点し、写しと今とで正解が変わった問題を挙げる。

#### 検証方針
