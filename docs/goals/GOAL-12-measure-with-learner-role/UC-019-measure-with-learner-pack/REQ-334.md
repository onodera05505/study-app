# REQ-334

> 作り手が採点しようとして、指定した周のパックの写しが契約の写しの形として読めないとき、システムはその写しを挙げて採点を止め、周の結果を残さない。

## 検証方針

- **分割クラス**:
  - `#snapshot-unreadable` — その周の写しが JSON として、または契約の写しの形として読めなければ止め、その写しを挙げ、結果を残さない
  - `#unreadable-before-result-exists` — 写しが読めず周の結果もあれば INVALID_INPUT で、結果を書き換えない（採点の errors の 5 と 6）
- **尽きている根拠**: 読めなさを、JSON でない・必須の欄が無い・欄の値が型や範囲の外の 3 種としてデータで回し、隣の errors との組を足して尽きる。errors の 4 と 5（無いと読めない）は同時に成り立たないので組にしない
- **検証しない**: 写しの cycle の値がファイル名の周と違う場合（読めないに当たるか文が決めない）
