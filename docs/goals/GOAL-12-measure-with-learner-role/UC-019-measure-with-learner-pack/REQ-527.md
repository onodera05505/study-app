# REQ-527

> 作り手がパックを作る入口・採点の入口・学習者役への指示を描き出す入口を呼んだとき、システムは BR-061 のとおりに、結果か断りを 1 つの JSON で示し、終了の状態で成功と断りを分ける。

## 検証方針

- **分割クラス**:
  - `#pack-success` — パックを作る入口が止まらずに終われば、標準出力は response の形の JSON 1 つだけで、終了の状態は契約が成功に定める物
  - `#pack-refused-invalid-input` — パックを作る入口が INVALID_INPUT の errors に当たれば、ToolError の形の JSON 1 つだけを出し、終了の状態は契約が断りに定める物
  - `#pack-refused-not-found` — 同じく NOT_FOUND の errors に当たったとき
  - `#pack-refused-conflict` — 同じく CONFLICT の errors に当たったとき
  - `#pack-refused-internal` — 同じく INTERNAL の errors に当たったとき
  - `#grade-success` — 採点の入口が止まらずに終われば、response（周の結果）の形の JSON 1 つだけで、成功の終了の状態
  - `#grade-refused-invalid-input` — 採点の入口が INVALID_INPUT の errors に当たれば、ToolError の形の JSON 1 つだけで、断りの終了の状態
  - `#grade-refused-not-found` — 同じく NOT_FOUND の errors に当たったとき
  - `#grade-refused-conflict` — 同じく CONFLICT の errors に当たったとき
  - `#instructions-success` — 指示を描き出す入口が止まらずに終われば、response の形の JSON 1 つだけで、成功の終了の状態
  - `#instructions-refused-invalid-input` — 指示を描き出す入口が INVALID_INPUT の errors に当たれば、ToolError の形の JSON 1 つだけで、断りの終了の状態
- **尽きている根拠**: 入口は 3 つで、結果は 止まらずに終わる か errors に当たる かの 2 つ。errors は入口ごとに契約が並べる code（パックを作る: INVALID_INPUT・NOT_FOUND・CONFLICT・INTERNAL、採点: INVALID_INPUT・NOT_FOUND・CONFLICT、指示: INVALID_INPUT）で分け、code ごとに代表の入力を 1 つ持つ
- **検証しない**: errors の各項目の当たり方・判定の順・挙げる欄（各失敗の要件 REQ-318 ほかが見る）。errors に当たらない想定外の失敗（契約が応答を定めていない）
- **参照先**: `tests/server/UC-019_entry_response.test.ts::UC-019 入口は結果か断りを JSON 1 つで示し、終了の状態で分ける（REQ-527）`
