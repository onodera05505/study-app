# REQ-310

> 作り手が周の番号を指定して学習者役の答えを採点したとき、システムはいつもその周のパックの写しにある問題と正解で採点し、写しと今とで正解が変わった問題を挙げる。

## 検証方針

- **分割クラス**:
  - `#graded-by-snapshot-answer` — 今の正解が変わっても写しの正解で正答を数える
  - `#changed-answers-listed` — 写しと今とで正解が変わった問題を挙げる
  - `#no-change-empty` — 変わった問題が無ければ空
  - `#removed-from-current-still-graded` — 今の確認問題から消えた写しの問題も採点に入る
  - `#added-to-current-not-graded` — 写しの後に足された問題は採点に入らない
  - `#roadmap-changed-irrelevant` — 今のロードマップが変わっても写しの単位で数える
  - `#body-and-figure-not-read` — 配る本文や図が今は欠けていても採点は止まらず同じ結果
  - `#explain-terms-not-read` — 説明テストの語の一覧が今は読めなくても採点は止まらず同じ結果
  - `#pack-build-failures-not-read` — 図を描けない・図の名前が重なる・今のロードマップに欠けた行がある状態でも、採点は止まらず同じ結果
- **尽きている根拠**: 写しと今の差を、正解の変化・問題の増減・ロードマップの変化・本文と図の欠け・語の一覧の読めなさ（UC の表の行）に分けた
- **検証しない**: 写しにあり今の確認問題から消えた問題を changed_answers に挙げるか（文が「正解が変わった」としか言わず一意に決まらない）
