# REQ-321

> 作り手がパックを作ろうとして、指定した周のパックの写しか周の結果が既にあるとき、システムはパックを作らず、写しも周の結果も書き換えずに止める。

## 検証方針

- **分割クラス**:
  - `#snapshot-exists` — その周の写しがあれば止め、写しを書き換えない
  - `#result-exists-without-snapshot` — 写しは無いが結果があれば止め、写しを作らない
  - `#unreadable-snapshot-exists` — その周の写しが壊れていて読めなくても、あれば止め、写しを書き換えない
  - `#both-exist` — 写しも結果もあれば止め、どちらも書き換えない
  - `#cycle-exists-before-questions-missing` — 写しがあり確認問題も無ければ CONFLICT（errors の 4 と 5）
- **尽きている根拠**: 写しと結果の有無の組 3 つ（両方無いのは成功）と、写しが読めない場合（UC の表の行）、隣の errors との組
- **検証しない**: 断る理由の文言（errors の 3 と 4 はどちらも CONFLICT で、文言でしか分けられず契約が文言を決めない）
