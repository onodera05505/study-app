# REQ-335

> 作り手がパックを作ろうとして、学びの説明テストの語の一覧が契約の語の一覧の形として読めないとき、システムはその一覧を挙げて、パックも写しも作らずに止める。

## 検証方針

- **分割クラス**:
  - `#explain-terms-unreadable` — 語の一覧が JSON として、または契約の語の一覧の形として読めなければ止め、その一覧を挙げ、パックも写しも作らない
  - `#unreadable-before-roadmap-row-broken` — 語の一覧が読めずロードマップに欠けた行もあれば、語の一覧だけを挙げる（作る errors の 8 と 9 は同じコードなので挙げた物で見る）
- **尽きている根拠**: 読めなさを、JSON でない・terms が無いか配列でない・項目の語が無いか空、としてデータで回し、後ろの errors との組を足して尽きる。前の errors（確認問題が読めない）との組は REQ-333 が持つ
- **検証しない**: 語の一覧のファイルが無い場合（説明テストを出さないだけで止めない。REQ-304 の #no-explain-without-terms が見る）
