# REQ-312

> 自己申告に、単位の ID が無いか整数でないかその周の写しのロードマップに無い行、ID が他の行と重なる行、同じ欄の決めた名前と別名か別名どうしが違う値で並ぶ行、または欄の値が契約の自己申告の形の範囲の外にある行があるとき、システムはそれらの行をすべて当たった条件とともに挙げて採点を止め、周の結果を残さない。

## 検証方針

- **分割クラス**:
  - `#missing-id` — 単位の ID が無い行を missingId で挙げて止める
  - `#non-integer-id` — 単位の ID が整数でない行を idNotInteger で挙げる
  - `#id-not-in-snapshot` — 単位の ID が写しのロードマップに無い行（今のロードマップにあっても）を idNotInSnapshot で挙げる
  - `#duplicate-id` — 同じ単位の ID の行を、重なる行すべて duplicateId で挙げる
  - `#canonical-alias-conflict` — 決めた名前と別名が違う値の行を aliasConflict で挙げる
  - `#alias-alias-conflict` — 別名どうしが違う値の行を aliasConflict で挙げる
  - `#value-out-of-range` — 欄の値が契約の自己申告の形の外の行を valueOutOfRange で挙げる
  - `#multiple-conditions-in-row` — 1 つの行が複数の条件に当たれば、その行に当たった条件をすべて添える（写しに無い ID の重なる 2 行は、各行に idNotInSnapshot と duplicateId）
  - `#all-rows-listed` — 条件の違う読めない行が複数あれば、すべての行を index とともに挙げる
- **尽きている根拠**: 文の条件 7 つ（別名の食い違いは決めた名前と別名・別名どうしの 2 つ）に 1 クラスずつと、行の中の「条件をすべて」と行の「すべて」で尽きる。範囲の外は契約の自己申告の欄ごとに型と範囲の外をデータで回す。どのクラスも周の結果が残らないことまで見る
- **検証しない**: 単位の ID が null・0 の行（無い・整数でない・写しに無いのどれに当たるか文が一意に決めない）。挙げる行の並びの順と、行の中の条件の並びの順（どちらも集合として比べる）。reason の文言
