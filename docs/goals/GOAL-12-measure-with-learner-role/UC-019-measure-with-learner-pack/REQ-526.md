# REQ-526

> 作り手が登録簿がロードマップを持つとする学びを指定して学習者役への指示を描き出そうとし、その学びの置き場にロードマップが無いか、ロードマップが JSON の object として読めないとき、システムは指示を書かずに断り、ロードマップの日数の差し込みを埋まらない差し込みとして挙げる。

## 検証方針

- **分割クラス**:
  - `#roadmap-missing` — 登録簿がロードマップを持つとする学びの置き場にロードマップのファイルが無ければ、差し込み days を挙げて INVALID_INPUT で断り、指示を書かない（前からある指示も書き換えない）
  - `#roadmap-not-json` — ロードマップのファイルが JSON として読めなければ（途中で切れた・空・JSON でない文）、差し込み days を挙げて断り、指示を書かない
  - `#roadmap-not-object` — ロードマップが JSON として読めても object でなければ（配列・文字列・数・null）、差し込み days を挙げて断り、指示を書かない
- **尽きている根拠**: 文の条件は「ロードマップが無い」と「JSON の object として読めない」で、後者は JSON として読めない・読めるが object でない の 2 つに分かれる。日で束ねるか章で束ねるかはロードマップから読む物で、読めないときは決まらないので、どちらの学び（itc・eng）でも同じ断りになることを各クラスで見る。指示を書かないことは、前から指示が無い・有る の 2 値で見る
- **検証しない**: object として読めるが欄の欠けや型の違いがあるロードマップ（この要件の条件の外で、days の欠けは REQ-412 が見る）。登録簿に無い学び・ロードマップを持たない学び（REQ-410 が先に断る）
- **参照先**: `tests/server/UC-019_render_roadmap_unreadable.test.ts::UC-019 指示を描き出すときにロードマップが無いか読めない（REQ-526）`
