# REQ-338

> ロードマップに、契約のロードマップの形が欠けてはならないとする欄が無いか型の違う行があるとき、システムはその行を挙げてパックも写しも作らずに止め、契約が任意とする欄の欠けでは止めない。

## 検証方針

- **分割クラス**:
  - `#required-field-missing` — 欠けてはならない欄（order・topic_id・term・field・middle・summary）が無い行を、その欄とともに挙げて止める
  - `#wrong-type` — 欠けてはならない欄の型が違う行を、その欄とともに挙げて止める
  - `#several-rows-listed` — 欠けた行が複数あれば、すべての行と欄を挙げる
  - `#optional-field-missing-ok` — 契約が任意とする欄（day・round・chapter）が無い行では止めない
  - `#row-broken-before-body-missing` — 欠けた行があり配る本文の無い単位もあれば INVALID_INPUT（作る errors の 9 と 10）
- **尽きている根拠**: 契約の readRoadmap の欄を、欠けてはならない欄の欠け・型の違いと、任意の欄の欠けに分け、欄ごとにデータで回す。行と欄が複数のときと、後ろの errors との組を足して尽きる。前の errors との組は REQ-335 が持つ
- **検証しない**: 値の範囲の外（order が 0 など。文は欠けと型の違いだけを挙げる）。ロードマップ全体が JSON として読めないか units が無い場合（readRoadmap の INVALID_INPUT が、作る入口のどの errors に当たるか一意でない）。挙げる欄の名前の並び（集合として比べる）
