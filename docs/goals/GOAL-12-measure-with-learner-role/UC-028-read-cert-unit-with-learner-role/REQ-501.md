# REQ-501

> 作り手が単元の読み物を作る入口に、BR-055 の読み方で契約の引数の形の外になる引数を渡したとき、システムは何も読まず書かずに断り、その引数を BR-055 のとおりに挙げる。

## 検証方針

- **分割クラス**:
  - `#bad-data` — 学びが学びの置き場の形でない（大文字・前置きの欠け・末尾の /・絶対パス・別の前置き・.. を含む・作り物の名前の形の外・数字を含む key）
  - `#bad-unit` — 単元が 2 桁の番号の形でない（1 桁・3 桁・英字・空・混ざり・全角）
  - `#empty-out` — 出力先が空
  - `#missing-argument` — data・unit・out のどれかの引数が無い（引数を付けない・契約の引数名の前の部分だけの名前でしか渡さない）
  - `#missing-value` — 名前だけで値を持たない引数（コマンドの末尾の名前・すぐ後が `--` で始まる名前）
  - `#duplicated-argument` — 同じ名前の引数が 2 回ある（前の値が形の外で後ろの値が形の内のときを含む）
  - `#extra-argument` — 契約に無い引数がある（契約に無い名前・契約の引数名の前の部分だけの名前・どの名前の値でもない語）
  - `#hyphen-value-in-shape` — `-` で始まる値（`--out -x`）を `=` の有無どちらで渡しても値として読み、断らない
  - `#all-bad-listed` — 形の外の引数が 2 つ以上あれば、BR-055 の並びで 1 回ずつ挙げる
  - `#bad-args-before-learning` — 引数が形の外で、かつ学びがロードマップ型か登録簿に無い（errors の 1 番目と 2 番目）
- **尽きている根拠**: request の 3 つの欄それぞれの値の形の外と、BR-055 が形の外とする引数の現れ方（欄の欠け・値の欠け・名前の重なり・余りの名前と語）で request の形の外が尽きる。値と名前の見分けの境は `-` で始まる値の 1 クラスで、形の内の側に置く。挙げ方は複数のときを 1 クラス、隣の失敗との順を 1 クラス
- **検証しない**: 「何も読まない」こと（読んだかを外から観測できない。出力先を作らないことと、読めば別の失敗になる学びでも引数の誤りで断ることで押さえる）
- **参照先**: `tests/server/UC-028_refusals.test.ts::UC-028 入口の引数・学び・出力先・単元で断る（buildUnitReading）`・`tests/server/UC-028_build_unit_reading.test.ts::UC-028 出力先の値が - で始まる（buildUnitReading）`
