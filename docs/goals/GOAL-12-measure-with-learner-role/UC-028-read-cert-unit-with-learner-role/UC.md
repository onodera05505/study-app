# UC-028 資格対策の単元を利用者と同じ見え方の読み物にして学習者役に通読させる

## 概要

作り手が、資格対策の学びの 1 単元を、利用者が画面で見るのと同じ並び・本文・用語・図の見え方で 1 本の単元の読み物にし、学習者役に通読させて、単元を通して読んだときのつまずきを学習者役の報告として受け取る。

## 事前条件

- 資格対策の学びが登録簿にあり、その単元の単元の構成・教材の世代・図の仕様・図の画像が学びの置き場と配信の置き場にある
- 適用される業務規則: BR-004, BR-026, BR-031, BR-048, BR-051, BR-054, BR-055, BR-061

## 主シナリオ

1. 作り手が、学びと単元と出力先を指定して単元の読み物を作る
2. システムが、単元の構成が単元の構成の門の止める理由に当たらないことを確かめる → BR-048
3. システムが、単元の構成の順に、全体像・まとまり・論点の名前と出題回数の印・前提の論点を並べる → BR-031, BR-051
4. システムが、論点ごとに配る本文を、用語と図を利用者が画面で見るのと同じ見え方にして並べ、図の画像を添える → BR-026
5. システムが、単元の読み物の項目の番号と論点の対応を作り手に示す
6. 作り手が、学習者役への単元の通読の指示に単元の値を埋め、単元の読み物と一緒に学習者役に渡す
7. 学習者役が、単元の読み物だけを頭から順に読み、学習者役の報告を返す

### REQ-494

- pattern: Event-driven
- br: BR-031
- status: active

> 作り手が資格対策の学びの単元を指定して単元の読み物を作ったとき、システムは、単元の読み物の冒頭に、単元の読み物で使う印と図の画像の置き方を言う読み方の注意と単元の全体像を 1 回ずつ置き、BR-031 の並びで、まとまりごとにその名前と説明を 1 回だけ見出しとして置いてからそのまとまりの論点を置き、論点には単元の中で 1 から続く項目の番号を振る。

#### 検証方針

- **分割クラス**:
  - `#notice-and-overview-at-top` — 最初のまとまりの見出しより前に読み方の注意（※ と図に触れる）と全体像があり、全体像は読み物に 1 回だけ
  - `#groups-once-in-plan-order` — まとまりの名前の見出しと説明が 1 回ずつ単元の構成の順に並び、各まとまりの論点がその見出しと次の見出しの間に学ぶ順で並ぶ
  - `#items-numbered-from-one` — 論点の見出しの項目の番号が学ぶ順に 1 から続き、応答の items の番号と一致する
  - `#previous-generation-unit` — 全論点を前の世代から選ぶ単元でも同じ並びと番号になる
- **尽きている根拠**: 文が決める置き物は冒頭の 2 つ・まとまり・論点の番号の 3 種で、それぞれ 1 クラスで見る。UC の表で並びに関わる行は「全論点が書き直した世代」と「全論点が前の世代」の 2 行なので、後者を 1 クラス足す
- **検証しない**: 読み方の注意の文言と、それが 1 回であること（文言を文が決めておらず、字で数えられない。※ と「図」を含むことだけを見る）。見出しの段の深さと番号の書き方（文が決めていない。番号は見出しの行の中の独立した数字として見る）

### REQ-495

- pattern: Ubiquitous
- br: BR-051
- status: active

> システムは、単元の読み物の各論点の頭に、論点の一覧の名前をそのまま 1 回と、出題頻度と BR-051 に従った出題回数の印を置き、前提の論点を持つ論点では、その前提の論点の論点の一覧の名前をそのまま、単元の構成に書かれた順に置く。

#### 検証方針

- **分割クラス**:
  - `#term-once-at-head` — 論点の頭（見出しから本文の最初の段の前まで）に論点の一覧の名前が 1 回だけ
  - `#names-as-is` — 末尾に括弧書きを持つ論点の名前を、論点の頭でも前提の論点としても括弧書きを落とさずに置く
  - `#frequency-zero-no-mark` — 出題頻度 0 の論点に印が無い
  - `#frequency-one` — 出題頻度 1 の論点に出題頻度と ★
  - `#frequency-two` — 出題頻度 2 の論点に出題頻度と ★★
  - `#frequency-three-or-more` — 出題頻度 3 と 3 を超える値の論点に出題頻度と ★★★
  - `#prerequisites-in-plan-order` — 前提を 2 つ持つ論点で、単元の構成に書かれた順（学ぶ順と逆）に前提の論点の名前が並ぶ
  - `#no-prerequisites` — 前提を持たない論点の頭にほかの論点の名前が無い
- **尽きている根拠**: 頭に置く物は名前・出題頻度と印・前提の 3 つ。名前は括弧書きの有無で、印は BR-051 の 3 段と印なしの 4 つで、前提は有無で分かれる。前提の並びは学ぶ順と書かれた順が違う入力でだけ見分けられるので、逆に書く
- **境界の扱い**: 最も高い段は境目の 3 とそれを超える値の 2 点で見る。段の境目の値は `src/server/lib/frequency-tier.ts` の値から引く
- **検証しない**: 出題頻度 0 の論点の出題頻度の表し方（「0 回」と書くかを文が決めていない。印が無いことだけを見る）

### REQ-496

- pattern: Ubiquitous
- br: BR-054
- status: active

> システムは、単元の読み物の各論点の本文に、投入がその論点に選ぶ配る本文の説明と詳しい解説をこの順に全文置き、図を、配る本文が図の行（BR-054）を持つ論点ではその行の位置に、持たない論点では図の差し込みが入れる位置（UC-027 の REQ-470）に置く。

#### 検証方針

- **分割クラス**:
  - `#explanation-then-detail-full` — 各論点の区切りに説明の段と詳しい解説の見出し・段が全部、説明・詳しい解説の順にある
  - `#selected-generation-body` — 投入が選ぶ世代（書き直した世代、前の世代では論点ごとに最も新しい世代）の本文が出て、前の世代にある同じ論点の別の本文は出ない
  - `#insert-after-explanation` — 書き直した世代から選んだ図の行を持たない論点の、差し込み位置が explanation の図が、短い説明の末尾（説明の最後の段の後・詳しい解説の最初の見出しの前）にある
  - `#insert-at-heading-section-end` — 書き直した世代から選んだ図の行を持たない論点の、差し込み位置が見出しの図が、その見出しの節の末尾（節の最後の段の後で、次の見出しの前か、後に見出しが無ければ詳しい解説の末尾）にある（後に見出しのある節と無い節の両方）
  - `#same-explanation-spec-order` — 書き直した世代から選んだ図の行を持たない論点の、短い説明を差し込み位置にする図が 2 枚以上あるとき、図の仕様に並ぶ順に上からある
  - `#same-heading-spec-order` — 書き直した世代から選んだ図の行を持たない論点の、同じ見出しを差し込み位置にする図が 2 枚以上あるとき、図の仕様に並ぶ順に上からある（後に見出しのある節と無い節の両方）
  - `#line-position` — 図の行を持つ論点（書き直した世代と前の世代の両方）で、図が行の前後の段の間にあり、前の世代では図の仕様の差し込み位置と違う位置でも行の位置にある
  - `#line-with-surrounding-space` — 行頭と行末に半角の空白・タブ・全角の空白を持つ図の行も図の行として、図がその行の位置にある
- **尽きている根拠**: 本文の置き方は「本文の全文と順」「どの世代の本文か」「図の位置」で、図の位置は図の行の有無で分かれ、行を持たない側は REQ-470 が位置を決めている書き直した世代の論点で、差し込み位置の 2 種（explanation と見出し）ごとに、置き場の中の位置（末尾）と、同じ差し込み位置に 2 枚以上あるときの並び（図の仕様の順）の 2 つで尽きる。見出しの節の末尾は、後に見出しのある節（次の見出しの直前）と無い節（詳しい解説の末尾）で文の言い方が分かれるので両方で見る。図の行の形（BR-054・MaterialFigureLine）が受け入れる側の端は、行頭と行末に置ける空白を持つ行で見る。図の行かどうかは BR-054 の形だけで決まり、配信の置き場を指すのに形に合わない行は REQ-512 で止まるので、図の位置の分かれ目に入らない
- **境界の扱い**: 位置は、見出しの行の直後に置く置き方と見分けるため、節に段を 2 つ持たせて最後の段の後かで見る（段が 1 つだと最初の段の末尾に置く置き方と見分けられない）。並びは、図の仕様の順が図の id の昇順・降順のどちらとも違う 3 枚で見て、図の仕様では差し込み位置の違う図を互い違いに並べる（id の順・逆順・差し込むたびに見出しの直後に入れる置き方と見分ける）
- **検証しない**: 前の世代から選んだ論点で図の行を持たない論点の、図の仕様にある図をどこに置くか（REQ-470 は前の世代の論点では置き方を変えないとだけ言い、行の無い図を足すかを決めていない。UC-027 の DEF-139）。図の仕様にあるのに図の行の無い図を、図の行を持つ論点で足すか（文が決めていない。UC-027 の DEF-139 と同じ）。本文の markdown の書き方の保ち方（太字・見出しの段の深さ。文は全文を置くことだけを決めるので段の文字で見る）

### REQ-497

- pattern: Ubiquitous
- status: active

> システムは、単元の読み物の本文で用語の記法で書かれた語のうち、投入が組み立てる用語集にある語を、UC-001 の REQ-008 と REQ-341 が決める用語の表示名に押すと説明が出る語である印を添えて置き、用語集に無い語を UC-001 の REQ-009 のとおり書かれた文字のまま置く。

#### 検証方針

- **分割クラス**:
  - `#glossary-term-marked` — 用語集にある括弧書きの無い語が、表示名の直後の ※ を添えて出て、記法の括弧が残らない
  - `#paren-dropped` — 括弧書きを落としても何とも重ならない語は、括弧書きを落とした表示名に ※
  - `#paren-kept-same-as-other-term` — 括弧書きを落とすと用語集の他の語と同じになる語は、正式な表記のまま ※
  - `#paren-kept-same-as-other-shortened` — 括弧書きを落とすと他の語から括弧書きを落とした表記と同じになる語は、正式な表記のまま ※
  - `#not-in-glossary-plain` — 用語集に無い語は印を添えず書かれた文字のまま
  - `#term-in-bold` — 太字の中の記法でも、用語集にある語に ※
- **尽きている根拠**: 記法の語は用語集にあるか無いかで分かれ、ある語の表示名は REQ-008・REQ-341 の 3 通り（括弧書き無し・落とす・残す 2 種）で尽きる。太字の中は記法の解釈が変わりうるので別に置く
- **検証しない**: 用語集の元のうち glossary_overrides.json 以外（問題解説の誤答の term・論点の名前）から入る語（用語集の組み立ては投入の決まりで、この文はその結果の語の置き方を決める）

### REQ-498

- pattern: Ubiquitous
- br: BR-054
- status: active

> システムは、単元の読み物の図を、その図が指す配信の置き場の図の画像を PNG に描いた画像として、BR-054 が決める出力先の中の置く先に置いて単元の読み物から指し、図の説明文を、UC-001 の REQ-427 と同じくその図に結び付けた文字として 1 回だけ置く。

#### 検証方針

- **分割クラス**:
  - `#svg-drawn-as-png` — 置き場の直下の svg の図が figures の下の同じ名前の PNG になり、読み物がそれを指す
  - `#subpath-kept` — 置き場のサブパスの下の図が figures の下に同じサブパスで PNG になる
  - `#png-source` — 元が png の図も同じ名前の PNG として入る
  - `#caption-once` — 図の説明文（差し込む図は図の仕様の説明文、図の行は行の説明文）が読み物に 1 回だけ、画像の代替文ではなく図のそばの文字として出る
  - `#no-outside-reference` — 読み物の図がどれも出力先の中の PNG を指し、配信の置き場を指さない
  - `#response-matches-files` — 応答の reading と figures が出力先のファイルと一致し、figures が読み物の指す図と一致する
  - `#topic-without-figure` — 図の仕様も図の行も持たない論点の区切りに図が無い
- **尽きている根拠**: 図の元は置き場の直下の svg・サブパスの svg・png の 3 つ、結び付きは説明文の 1 つ、指し先は出力先の内か外かで、応答との一致と図の無い論点を足して尽きる。図の行の指す先と置く先の形は BR-054 の形だけで決まり、形に合わない行（大文字・key の欠け・`..`・制御文字を含む指す先）は REQ-512 で止まるので、出力先の外を指す図の入力はここに無い
- **検証しない**: 説明文の結び付け方（「図の説明:」のような書き方を文が決めていない。画像の行と同じ行か前後で最も近い字の行にあることを見る）。実機の読み上げソフトでの届き方（GLOBAL の REQ-427 の行と同じ理由）

### REQ-499

- pattern: Ubiquitous
- status: active

> システムは、単元の読み物に過去問・正解・問題解説・教材の世代の名前を含めず、図の画像の参照先を除く単元の読み物の文に論点の ID を含めず、項目の番号ごとの論点の ID・論点の名前・選んだ教材の世代を、単元の読み物の外で作り手に示す。

#### 検証方針

- **分割クラス**:
  - `#no-question-content` — 単元の論点の過去問の問題文と、問題解説の正解の根拠・誤答の注が読み物に無い
  - `#no-topic-id` — 単元の論点の ID が読み物の文に数字として現れない
  - `#no-generation-name` — 教材の世代の名前が読み物に無い
  - `#items-to-maker` — 応答の items が項目の番号ごとに論点の ID・名前・選んだ世代を持つ（書き直した世代の単元と、論点ごとに違う前の世代を選ぶ単元）
- **尽きている根拠**: 文が含めないと決める物は過去問・正解・問題解説・論点の ID・世代の名前の 5 つで、作り手に示す物は items の 1 つ。過去問と問題解説は字の並びで見られる 1 クラスにまとめる
- **検証しない**: 正解（選択肢の記号 1 字で、本文の字と見分けられない。問題文と問題解説が無いことで押さえる）。図の画像の参照先に入る論点の ID（契約が図の PNG の名前を元の置き場のサブパスのまま決めるので、参照先を除いた文で見る）

### REQ-500

- pattern: Ubiquitous

  - `#previous-generation-body` — 全論点を前の世代から選ぶ単元の、選んだ前の世代の本文の形に合わない行でも止める
  - `#nothing-created` — 止めたとき、呼ぶ前からある空の出力先は空のまま、無かった出力先とその親は作らない
  - `#unselected-body-ignored` — 投入が選ばない世代の本文にだけ形に合わない行がある論点では止めない
  - `#outside-unit-ignored` — 単元の外の論点の配る本文にだけ形に合わない行があっても止めない
  - `#mixed-before-malformed-line` — 世代が混ざり、かつ形に合わない行がある（errors の「書き直した世代と前の世代が単元の中で混ざる」と「図の置き場を指すのに図の行の形に合わない行がある」）
  - `#malformed-line-before-figure-missing` — 形に合わない行があり、かつ図の画像が無い（errors の「図の置き場を指すのに図の行の形に合わない行がある」と「図の画像か差し込み位置の見出しが無い」）
- **尽きている根拠**: 止める行は、前置き（MaterialFigureRefPrefix）を含み MaterialFigureLine に合わない行で、合わない理由は形の部分ごとに分かれる。行全体が 1 つの画像の記法でない（行の中の位置・画像の記法の外）、図の説明文が空、指す先（MaterialFigureSrc）の段が合わない（key の段の字・key の段の欠け・`.` と `..` の段・名前とサブパスと拡張子の字・制御文字）。行頭と行末の空白を持つ行は形の内の側で、REQ-496 が持つ。文が見る範囲は単元の論点の配る本文で、その外（選ばれない世代の本文・単元の外の論点）を止めないことを 2 クラスで押さえる。どの世代から選んでも同じに止めることを前の世代の 1 クラス、挙げ方を 1 クラス、作らないことを 1 クラス、隣の失敗との順を 2 クラスで見る。作らないことは、どのクラスでも作業場の全部のファイルとディレクトリと配信の置き場の中身が呼ぶ前と同じことで見る
- **検証しない**: 挙げる行の並び（文と契約が決めていない。並びによらず比べる）。図の説明文が `](` を含む行（図の説明文の終わりの見分けが画面の読み方に依り、文が決めていない）

### REQ-528

- pattern: Event-driven
- br: BR-061
- status: active

> 作り手が単元の読み物を作る入口を呼んだとき、システムは BR-061 のとおりに、結果か断りを 1 つの JSON で示し、終了の状態で成功と断りを分ける。

#### 検証方針

- **分割クラス**:
  - `#success` — 単元の読み物を作る入口が止まらずに終われば、標準出力は response の形の JSON 1 つだけで、終了の状態は契約が成功に定める物
  - `#refused-invalid-input` — INVALID_INPUT の errors に当たれば、ToolError の形の JSON 1 つだけを出し、終了の状態は契約が断りに定める物
  - `#refused-not-found` — 同じく NOT_FOUND の errors に当たったとき
  - `#refused-conflict` — 同じく CONFLICT の errors に当たったとき
  - `#refused-internal` — 同じく INTERNAL の errors に当たったとき
- **尽きている根拠**: 結果は 止まらずに終わる か errors に当たる かの 2 つで、errors は契約が並べる code（INVALID_INPUT・NOT_FOUND・CONFLICT・INTERNAL）で分け、code ごとに代表の入力を 1 つ持つ
- **検証しない**: errors の各項目の当たり方・判定の順・挙げる欄（UC-028 の各失敗の要件が見る）。errors に当たらない想定外の失敗（契約が応答を定めていない）
