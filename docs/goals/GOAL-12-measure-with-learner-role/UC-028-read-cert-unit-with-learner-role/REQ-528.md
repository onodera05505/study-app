# REQ-528

> 作り手が単元の読み物を作る入口を呼んだとき、システムは BR-061 のとおりに、結果か断りを 1 つの JSON で示し、終了の状態で成功と断りを分ける。

## 検証方針

- **分割クラス**:
  - `#success` — 単元の読み物を作る入口が止まらずに終われば、標準出力は response の形の JSON 1 つだけで、終了の状態は契約が成功に定める物
  - `#refused-invalid-input` — INVALID_INPUT の errors に当たれば、ToolError の形の JSON 1 つだけを出し、終了の状態は契約が断りに定める物
  - `#refused-not-found` — 同じく NOT_FOUND の errors に当たったとき
  - `#refused-conflict` — 同じく CONFLICT の errors に当たったとき
  - `#refused-internal` — 同じく INTERNAL の errors に当たったとき
- **尽きている根拠**: 結果は 止まらずに終わる か errors に当たる かの 2 つで、errors は契約が並べる code（INVALID_INPUT・NOT_FOUND・CONFLICT・INTERNAL）で分け、code ごとに代表の入力を 1 つ持つ
- **検証しない**: errors の各項目の当たり方・判定の順・挙げる欄（UC-028 の各失敗の要件が見る）。errors に当たらない想定外の失敗（契約が応答を定めていない）
- **参照先**: `tests/server/UC-028_entry_response.test.ts::UC-028 入口は結果か断りを JSON 1 つで示し、終了の状態で分ける（REQ-528）`
