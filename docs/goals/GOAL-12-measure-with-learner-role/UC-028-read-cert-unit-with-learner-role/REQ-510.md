# REQ-510

> 作り手が指定した単元の読み物の出力先が学びの置き場（どの学びの物でも）の中にあるか、既に中身のある場所のとき、システムは単元の読み物を作らずに止める。

## 検証方針

- **分割クラス**:
  - `#inside-own-learning` — 出力先が指定した学びの置き場の中
  - `#inside-other-learning` — 出力先が同じ置き場の根のほかの学びの置き場（登録簿にある学びと無い学び）の中
  - `#inside-by-other-spelling` — .. を含む・絶対パス・./ 始まりの書き方で学びの置き場の中を指す
  - `#inside-before-not-empty` — 出力先が学びの置き場そのもの（中身がある。errors の 3 番目と 4 番目）
  - `#out-not-empty` — 出力先に中身がある
  - `#not-empty-before-unit-missing` — 出力先に中身があり、かつ単元が無い（errors の 4 番目と 5 番目）
  - `#existing-empty-dir-accepted` — 出力先が既にある空のディレクトリなら作る
- **尽きている根拠**: 出力先は、学びの置き場の中か外か（中は自分の学び・ほかの学び・書き方の違い）と、無いか空か中身があるかで分かれる。無い出力先は作る側（REQ-494 ほか）が持つ
- **検証しない**: 指定した学びと別の置き場の根（リポジトリの data/ と作り物の根）の学びの置き場の中（契約が学びの置き場をその根の data/ の下とするので、根をまたぐときを文が決めていない）。出力先がファイルのとき（中身がある場所かを文が決めていない）
- **参照先**: `tests/server/UC-028_refusals.test.ts::UC-028 入口の引数・学び・出力先・単元で断る（buildUnitReading）`・`tests/server/UC-028_build_unit_reading.test.ts::UC-028 出力先が既にある空のディレクトリ（buildUnitReading）`
