# REQ-276

> 利用者がある回の回ごとの確認を受けると答えて、その要求が進行中のテストがあること以外の理由で受け付けられなかったとき、システムは押した回の近くに理由を示し、回ごとの並びを消さない。

## 検証方針

- **分割クラス**:
  - `#start-failed-shows-reason-keeps-list` — 進行中の有無以外の理由で要求が受け付けられなかった入力（押した回の近くに理由が出て、回ごとの並びが残る）
- **尽きている根拠**: 受けると答えたあとの結果は（作れた）（進行中のテストがあって作れない）（それ以外の理由で作れない）の 3 通りで、1 つ目は REQ-142、2 つ目は REQ-143 が持つ。残る 3 つ目は、理由（その回の確認問題が 1 問も無い・通信が届かない・サーバが失敗を返す）が変わっても示し方が同じ（BR-014 の操作の失敗）なので 1 クラス。
- **境界の扱い**: その回の確認問題が 0 件のときも、通信そのものが届かないときも同じクラス（示し方が変わらない）。
- **検証しない**: 失敗の理由ごとの文言の違い（文言の正本はサーバの応答と画面のコード）。受け付けられない条件どうしの判定の順（正本は UC-008 の契約の `errors` の並び）。その回の確認問題の件数が合わないデータが投入されないこと（BR-032）。
- **参照先**: `tests/client/roadmap.test.tsx::各日の確認テスト（UC-009）`
