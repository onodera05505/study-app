# REQ-144

> 利用者がロードマップを開いたとき、システムは先頭に続きの導線を 1 つ示し、その行き先を、前回の続きがあればその論点、無ければ「ここから」の論点、どちらも無ければ論点の一覧の先頭とする。

## 検証方針

- **分割クラス**:
  - `#last-topic-destination` — 前回の続きがあるとき、続きの導線の行き先がその論点になる
  - `#fallback-here` — 前回の続きが無いとき（端末から読めないときも含む）、行き先が「ここから」の論点になる
  - `#fallback-list-head` — 前回の続きも未理解の論点も無いとき、行き先が論点の一覧の先頭になる
- **尽きている根拠**: 行き先は 3 段の優先で決まる。入力は（前回の続きの有無）×（未理解の論点の有無）だが、前回の続きがあれば未理解の有無は効かないので 3 クラスに尽きる。
- **検証しない**: 前回の続きの覚え方（BR-013 の書き込みの 1 か所で、UC-005 が持つ）。印で絞り込んでいるあいだの「ここから」の段の行き先（REQ-283）。
- **参照先**: `tests/client/roadmap.test.tsx::先頭の導線`（`#fallback-list-head` は観測するテストが未配置）
