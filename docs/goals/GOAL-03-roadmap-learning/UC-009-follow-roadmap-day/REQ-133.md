# REQ-133

> 利用者がロードマップを開いたとき、システムは各回に、その回の回ごとの確認の問数と、それを受けた回数と最高の正解数を示し、一度も受けていない回には受けた結果を示さない。

## 検証方針

- **分割クラス**:
  - `#attempted-day` — 一度以上受けた回に、問数と受けた回数と最高の正解数が出る
  - `#unattempted-day` — 一度も受けていない回には、問数は出すが受けた結果を出さない
- **尽きている根拠**: 入力は回ごとの受けた回数で、0 と 1 以上の 2 クラスに尽きる。問数はどちらのクラスでも出る。
- **境界の扱い**: 補足の別枠は回ごとの並びの回に入らない（REQ-134）ので、補足の回には問数も受けた結果も回ごとの確認の入口も示さない。この境界は `#unattempted-day` と `#attempted-day` のどちらにも入れず、クラスにしない。
- **検証しない**: 問数の値（日で束ねる学びは BR-005 の登録簿、章で束ねる学びは投入された回ごとの確認問題の数が正本で、投入の門は BR-032）。最高の正解数の算出（UC-008 が持つ）。
- **参照先**: `tests/client/roadmap.test.tsx`::各日の確認テスト（UC-009）（`#attempted-day`）、回ごとの確認の結果（UC-009）（`#unattempted-day`）
