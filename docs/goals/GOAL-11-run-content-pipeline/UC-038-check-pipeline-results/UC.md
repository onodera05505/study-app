# UC-038 取り込み・分類・書き直しの結果と手順書の書き換えを、機械で確かめる

## 概要

作り手が、取り込んだ問題文・分類・書き直した教材・書き換えた手順書を、正解表や前の版と機械で照らすことで、担当の自己申告に頼らずに次の手順へ回せる物を見分ける。

## 事前条件

- 手元の作業環境に、学びの置き場の取り込みと分類と教材の結果、正解表、手順書の前の版がある

## 主シナリオ

1. 作り手が、抽出した問題文だけで解いた結果を、回を指定して正解表と照らす
2. 作り手が、教材だけで解いた結果を正解表と照らす
3. 作り手が、分類の結果を確かめる
4. 作り手が、書き直した世代で前の世代から落ちた語を確かめる
5. 作り手が、書き換えた手順書に前の版の決まりが残っているかを確かめる
6. システムが、それぞれの結果を挙げて終える
7. 作り手が、挙がった物を直してから次の手順へ回す

## 事後条件

- 成功時: 作り手が、照らした結果（正解率・不正解・不足の申告・分類の誤り・落ちた語・手順書の欠け）を見て、次の手順へ回せる物を見分けている
- 失敗時: 理由か挙がった物が示されて終わっており、学びの置き場は書き換わっていない

## 要件

### REQ-603
- pattern: Event-driven
- status: active

> 作り手が回を指定して、抽出した問題文だけで解いた結果を正解表と照らしたとき、システムは正解率と不正解の問題と、問題文だけでは解けないと申告された問題を示して成功で終える。

#### 検証方針

- **分割クラス**:
  - `#all-correct` — どの問題も正解なら、正解率 100% を示して成功で終える
  - `#wrong-shown` — 不正解の問題があれば、正解率とその問題の番号を示して成功で終える
  - `#unanswerable-shown` — 問題文だけでは解けないと申告された問題があれば、その問題の番号を示して成功で終える
- **尽きている根拠**: 文が示す物（正解率・不正解・解けない申告）の有無で分け、どれも無い場合と、不正解がある場合と、申告がある場合に 1 つずつ置く
- **検証しない**: 解答の欠けた問題の扱い（文が決めていない）。正解率の丸め方

### REQ-604
- pattern: Unwanted behaviour
- status: active

> 作り手が問題文で解いた結果を照らすときに、正解表に指定した回が無いとき、システムはその旨を示して失敗で終える。

#### 検証方針

- **分割クラス**:
  - `#exam-not-in-key` — 正解表に指定した回が無いと、その回を示して失敗で終える
- **尽きている根拠**: 文の条件は 1 つで、正解表にほかの回があっても指定した回が無い場合で見る
- **検証しない**: 正解表のファイルそのものが無い・読めない場合（UC の表で未決）

### REQ-605
- pattern: Event-driven
- status: active

> 作り手が教材だけで解いた結果を正解表と照らしたとき、システムは不正解の問題と教材だけでは決まらないと申告された問題を示し、両方に当たる問題があれば失敗で終え、照らす結果が無ければ無いことを示して成功で終える。

#### 検証方針

- **分割クラス**:
  - `#all-correct-sufficient` — どの問題も正解で、不足の申告も無ければ、成功で終える
  - `#wrong-shown` — 不正解の問題（不足の申告なし）があれば、その問題を示して成功で終える
  - `#insufficient-shown` — 正解したが教材だけでは決まらないと申告された問題があれば、その問題を示して成功で終える
  - `#wrong-and-insufficient-fails` — 不正解で、しかも不足を申告された問題があれば、その問題を示して失敗で終える
  - `#no-results` — 照らす結果の置き場が無ければ、無いことを示して成功で終える
- **尽きている根拠**: 問題ごとの状態は、正解か・不足の申告があるかの 2 × 2 に尽き、組ごとに 1 つ置く。照らす結果が無い場合を 1 つ置く
- **検証しない**: 挙げる数の上限（top）の切り方（文が決めていない）

### REQ-606
- pattern: Event-driven
- status: active

> 作り手が分類を確かめたとき、システムは回ごとの抜け・重なり・余り、公式の分野と選んだ項目の分野の食い違い、無い項目の番号を誤りとして挙げ、用語例に無いのに新しい論点でないとした論点を参考として挙げ、誤りがあれば失敗で終える。

#### 検証方針

- **分割クラス**:
  - `#clean-passes` — 今の学び（ap）の分類には誤りが無く、成功で終える
  - `#missing-number` — 回の中に分類の無い問番号があると、誤りとして挙げて失敗で終える
  - `#duplicate-number` — 回の中に同じ問番号の分類が 2 つあると、誤りとして挙げて失敗で終える
  - `#extra-number` — 回の問題数を超える問番号の分類があると、誤りとして挙げて失敗で終える
  - `#field-mismatch` — 公式の分野と選んだ項目の分野が食い違うと、誤りとして挙げて失敗で終える
  - `#unknown-item` — シラバスに無い項目の番号を選ぶと、誤りとして挙げて失敗で終える
  - `#reference-only-passes` — 選んだ項目の用語例に無いのに新しい論点でないとした論点は、参考として挙げ、それだけでは成功で終える
- **尽きている根拠**: 文が挙げる誤り 5 つ（抜け・重なり・余り・分野・無い項目）に 1 つずつ、参考に 1 つ、誤りの無い場合に 1 つ置く
- **検証しない**: 1 回あたりの問題数（count）の既定の値（文が決めていない。契約の実例どおり省いて回す）

### REQ-607
- pattern: Event-driven
- status: active

> 作り手が書き直しの落ちを確かめたとき、システムは学びの置き場の最初の教材の世代にあって 2 番目の世代に無い英数字・数値・カタカナの語と、詳しい解説が最初の世代より短くなった論点を挙げて成功で終え、2 番目の世代が無ければ無いことを示して成功で終える。

#### 検証方針

- **分割クラス**:
  - `#dropped-words-listed` — 最初の世代にあって 2 番目の世代に無い英数字・数値・カタカナの語を、その論点とともに挙げて成功で終える
  - `#shorter-detail-listed` — 詳しい解説が最初の世代より短くなった論点を挙げて成功で終える
  - `#no-second-generation` — 2 番目の世代が無ければ、無いことを示して成功で終え、最初の世代と 3 番目より後の世代の間の落ちは挙げない
- **尽きている根拠**: 文が挙げる物は語の落ちと短くなった論点の 2 つで、1 つずつ置く。2 番目の世代が無い場合を 1 つ置く
- **境界の扱い**: 最初の世代は学びの置き場の `materials`、2 番目の世代は `materials_v2`（どちらも道具が決めた置き場）。3 番目より後の世代は比べない
- **検証しない**: 挙げる数の上限（top）の切り方。言い換えで同じ意味が残った語の見分け（文が求めていない）

### REQ-608
- pattern: Event-driven
- status: active

> 作り手が書き換えた手順書を前の版と照らしたとき、システムは前の版の決まりの 1 項目ずつについて、新しい版に同じ項目があるか、無ければその項目の鍵（数値・コードの書き方・かぎ括弧の引用。日付と 1 桁の数を除く）が全部残っているか、それも無ければ消した理由の一覧に載っているかを見て、説明できない欠けがあればそれを挙げて失敗で終える。

#### 検証方針

- **分割クラス**:
  - `#unchanged-passes` — 前の版と同じ手順書は、欠けが無く成功で終える
  - `#keys-kept-passes` — 同じ項目が無くても、その項目の鍵（数値・かぎ括弧の引用）が新しい版に全部残っていれば、欠けにしない
  - `#dropped-with-reason-passes` — 消した項目が消した理由の一覧に載っていれば、欠けにしない
  - `#unexplained-gap-fails` — 消した項目が理由の一覧に無ければ、その項目を挙げて失敗で終える
- **尽きている根拠**: 文の判定は、同じ項目がある・鍵が全部残る・理由の一覧にある・どれも無い、の 4 段に尽き、1 つずつ置く
- **境界の扱い**: 項目は箇条書きの 1 行と読む。消す項目は鍵（2 桁の数値）を持つ物で作る（鍵を持たない項目は「鍵が全部残る」がいつも成り立つので、欠けの段に届かない）。理由の一覧は 1 行に「項目の先頭 12 字以上 … — 理由」（道具の使い方の表示）
- **検証しない**: 前の版を git の版で渡す場合（前の版をファイルで渡しても判定は同じで、git の版の解決は git の役目）

### REQ-609
- pattern: Unwanted behaviour
- status: active

> 作り手が手順書の書き換えを照らすときに、前の版が取れないとき、システムはその旨を示して、欠けがあったときとは別の終了の状態で終える。

#### 検証方針

- **分割クラス**:
  - `#old-unavailable` — 前の版が取れないと、その旨を示して、欠けがあったとき（1）と別の終了の状態で終える
- **尽きている根拠**: 文の条件は 1 つで、前の版として渡したファイルが無い場合で見る
- **検証しない**: 前の版の git の版が無い場合（取れない理由の違いで振る舞いを分けない）
