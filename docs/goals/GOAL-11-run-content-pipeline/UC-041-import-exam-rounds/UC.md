# UC-041 過去問の回を取り込み、正解表・シラバス・分類から論点と出題頻度を組む

## 概要

作り手が、公開された過去問の PDF を取り、ページを画像にして読み取りの結果をまとめ、解答例から正解表を、シラバスから分類の受け皿を作り、分類の束を担当に渡して論点と出題頻度を組むことで、回を学びに足せる形にする。

## 事前条件

- 資格対策の学びが登録簿にあり、学びの置き場がある

## 主シナリオ

1. 作り手が、過去問の問題冊子と解答例の PDF を取る
2. 作り手が、問題冊子のページを画像に書き出し、読み取った結果を 1 回分の問題にまとめる
3. 作り手が、解答例から正解表（と公式の分野）を、シラバスから分類の受け皿を作る
4. 作り手が、回の分類の束を作り、担当の分類の結果から論点と出題頻度を組む
5. 作り手が、図を含む問題の図をページ画像から切り出す
6. システムが、それぞれの結果を学びの置き場か配信の置き場に書き出す

- 失敗時: 止まった道具と理由が示されている

## 要件

### REQ-630

- pattern: Event-driven
- status: active

> 作り手が IT パスポートの過去問の PDF を取ったとき、システムは取りに行く先（指定しなければ公開の配布の場所）から回ごとの問題冊子と解答例を取り、既にあるファイルは取り直さない。

#### 検証方針

- **分割クラス**:
  - `#asks-public-distributor` — 取りに行く先を指定しなければ、IT パスポートの公開の配布の場所に取りに行き、ほかの場所には行かない（外への接続を断る囲いの中で回し、断られた宛先が公開の配布の場所であることを見る。外の相手には届かない）
  - `#given-origin` — 取りに行く先に手元の偽の配布先を指定すると、そこから回ごとの問題冊子と解答例を取る
  - `#existing-not-refetched` — 取りに行く先を指定して、既にあるファイルは取り直さない
- **尽きている根拠**: 取りに行く先の指定の有無の 2 つと、既にあるファイルの有無で尽きる
- **検証しない**: 取りに行く先が応じないとき・ファイルが無いときの止まり方（文が決めていない）

### REQ-631

- pattern: Event-driven
- status: active

> 作り手が応用情報か基本情報の過去問の PDF を取ったとき、システムは取りに行く先（指定しなければ公開の場所）の年度ごとのページから、新しい方から指定した数の回（または指定した回）の問題冊子と解答例を取る。

#### 検証方針

- **分割クラス**:
  - `#asks-public-distributor` — 取りに行く先を指定しなければ、応用情報の年度ごとの公開のページに取りに行き、ほかの場所には行かない（外への接続を断る囲いの中で回し、断られた宛先が公開の場所であることを見る。外の相手には届かない）
  - `#given-origin-recent` — 取りに行く先に手元の偽の配布先を指定すると、新しい方から指定した数の回の問題冊子と解答例を取る
  - `#given-origin-exams` — 取りに行く先に手元の偽の配布先を指定し、回を指定すると、その回の問題冊子と解答例を取る
- **尽きている根拠**: 取りに行く先の指定の有無の 2 つと、回の選び方（数・指定）の 2 つで尽きる
- **検証しない**: 基本情報（同じ道具の別の試験の指定）。取りに行く先が応じないとき・ファイルが無いときの止まり方（文が決めていない）

### REQ-632

- pattern: Event-driven
- status: active

> 作り手が回を指定して問題冊子のページを画像にしたとき、システムは学びの置き場のその回の問題冊子の各ページを、指定した解像度の画像として回ごとの置き場に書き出す。

#### 検証方針

- **分割クラス**:
  - `#each-page` — 問題冊子の各ページを 1 枚ずつ、回の置き場に画像として書き出す
  - `#resolution` — 解像度の指定が画像の大きさに効く（72 dpi でページの幅、倍で倍）
- **尽きている根拠**: 書き出す枚数と解像度の 2 軸
- **検証しない**: 応用情報・基本情報の問題冊子の名前（IT パスポートの名前で代表する）

### REQ-633

- pattern: Event-driven
- status: active

> 作り手が回を指定して読み取りの結果をまとめたとき、システムはページの範囲ごとの読み取りの結果を問番号の順に 1 回分の問題にまとめ、表記の揺れを正規化し、機械で見つかる異常と範囲の間の食い違いを挙げる。

#### 検証方針

- **分割クラス**:
  - `#number-order` — 範囲ごとの結果を、問番号の順に 1 回分の問題にまとめる
  - `#normalized` — 表記の揺れ（読点の「、」）を「，」にそろえ、正規化しない指定では読み取りのまま残す
  - `#gap-reported` — 欠けた問番号を挙げる
  - `#range-conflict-reported` — 2 つの範囲が同じ問番号を持つ食い違いを挙げる
- **尽きている根拠**: まとめ方（順）・正規化の有無・異常（欠番）・範囲の間の食い違い（重複）で尽きる
- **検証しない**: 正規化する揺れの一覧（文が決めない。読点 1 つで代表する）。そのほかの機械で見つかる異常の種類

### REQ-634

- pattern: Event-driven
- status: active

> 作り手が IT パスポートの正解表を作ったとき、システムは解答例の PDF から回ごとの問番号と正解の記号の組を読み、正解表に書き出す。

#### 検証方針

- **分割クラス**:
  - `#answer-keys` — 解答例の 100 問の正解を、回の正解表に書き出す
- **尽きている根拠**: 読む物と書く物の組が 1 つ
- **検証しない**: 解答例の表の並びの変種（4 列の表で代表する）

### REQ-635

- pattern: Event-driven
- status: active

> 作り手が応用情報か基本情報の正解表を作ったとき、システムは解答例の PDF から回ごとの問番号と正解の記号と公式の分野を読み、正解表と分野の表に書き出す。

#### 検証方針

- **分割クラス**:
  - `#answer-keys-and-fields` — 解答例の 80 問の正解と分野（Ｔ・Ｍ・Ｓ）を、正解表と分野の表に書き出す
- **尽きている根拠**: 読む物と書く物の組が 1 つ
- **検証しない**: テキストの層が無い回の手で読んだ正解表（--manual。文が扱わない）

### REQ-636

- pattern: Event-driven
- status: active

> 作り手が IT パスポートのシラバスを読んだとき、システムはシラバスの PDF の分野・大分類・中分類・項目の階層と項目ごとの用語例を、分類の受け皿として書き出す。

#### 検証方針

- **分割クラス**:
  - `#hierarchy-and-terms` — 分野・大分類・中分類・項目の階層と項目ごとの用語例を書き出す
- **尽きている根拠**: 書き出す物が 1 つ。シラバスの形（3 分野・9 大分類・23 中分類・63 項目）の作り物で代表する
- **検証しない**: 項目の数がシラバスの版の数と違うとき（文が決めない。今の道具は書き出したうえで失敗で終える）

### REQ-637

- pattern: Event-driven
- status: active

> 作り手が応用情報か基本情報のシラバスを読んだとき、システムはシラバスの PDF の階層と用語例を分類の受け皿として書き出し、分類の束が読む索引も書き出す。

#### 検証方針

- **分割クラス**:
  - `#hierarchy-terms-and-index` — 階層と用語例を分類の受け皿に、小分類の一覧を索引に書き出す
  - `#no-heading-in-terms` — 分野が変わるページの切れ目でも、項目の用語例に次の分野の見出しの字を混ぜない
- **尽きている根拠**: 書き出す物（受け皿と索引）の組が 1 つ。分野が変わるページの切れ目を含む作り物で代表する
- **検証しない**: 版の名前（文が決めない）

### REQ-638

- pattern: Event-driven
- status: active

> 作り手が回を指定して分類の束を作ったとき、システムはその回の問題を指定した数ずつに分け、各問題に公式の分野に属するシラバスの項目だけを添えて、担当に渡す束として書き出す。

#### 検証方針

- **分割クラス**:
  - `#split-by-size` — 回の問題を指定した数ずつの束に分ける
  - `#official-field-items-only` — 各束には、その束の問題の公式の分野に属するシラバスの項目だけを添える
- **尽きている根拠**: 分け方と添える項目の 2 つ
- **検証しない**: 束の名前と束の中の欄の形（担当の仕様書が正本）

### REQ-639

- pattern: Event-driven
- status: active

> 作り手が論点を組んだとき、システムは担当の分類の結果から論点の一覧を作り、論点と過去問を紐づけ、紐づく過去問の件数を出題頻度として書き出す。

#### 検証方針

- **分割クラス**:
  - `#topics-and-frequency` — 2 回の分類の結果から、論点ごとに紐づく過去問と出題頻度を書き出す
- **尽きている根拠**: 論点の一覧・紐づけ・頻度は 1 つの書き出しの 3 つの面で、2 回にまたがる論点と 1 回だけの論点で代表する
- **検証しない**: 論点の ID の採番と別名の統合（論点 ID の固定は別の決まりと門が持つ）

### REQ-640

- pattern: Event-driven
- status: active

> 作り手が図を切り出したとき、システムは図の位置の一覧にある問題ごとに、問題冊子のそのページの指定した範囲を画像として配信の置き場に書き出す。

#### 検証方針

- **分割クラス**:
  - `#figure-per-question` — 図の位置の一覧の問題ごとに、問題冊子のそのページの範囲を画像にする
- **尽きている根拠**: 書き出す物が 1 つ。範囲の大きさを 5% までの余白で見る
- **検証しない**: 余白の量（文が決めない）

### REQ-641

- pattern: Unwanted behaviour
- status: active

> 作り手が取り込みの道具を回すときに、読む物（問題冊子や解答例の PDF・読み取りの結果・回の公式の分野・分類の結果・図の位置の一覧）が無いか、PDF を読む部品が入っていないとき、システムは理由を示して失敗で終える。

#### 検証方針

- **分割クラス**:
  - `#booklet-missing` — 問題冊子の PDF が無ければ（ページを画像にする）、理由を示して失敗で終える
  - `#answer-pdf-missing` — 解答例の PDF が 1 つも無ければ（応用情報か基本情報の正解表を作る）、0 回の正解表を書いて成功にせず、理由を示して失敗で終える
  - `#extracted-missing` — 読み取りの結果が無ければ（まとめる）、同じ
  - `#fields-missing` — 回の公式の分野のファイルが無ければ（分類の束を作る）、名前の無い例外の跡で止まらず、理由を示して失敗で終える
  - `#classified-missing` — 分類の結果が無ければ（論点を組む）、同じ
  - `#boxes-missing` — 図の位置の一覧が無ければ（図を切り出す）、同じ
  - `#pdf-reader-missing` — PDF を読む部品が入っていなければ（ページを画像にする）、同じ
- **尽きている根拠**: 文が挙げる読む物の 6 種類と部品の欠けに 1 つずつ。理由を示すとは、名前の無い例外で止まらず、無い物を名指すこととした
- **検証しない**: IT パスポートの解答例とシラバスの PDF が無いとき（同じ種類を応用情報の正解表と問題冊子で代表する）
