# REQ-435

> 作り手が単位の論点の ID と新しい要約を渡して要約を差し替えたとき、システムはロードマップの設定の要約の差し替えをその論点の ID を鍵として書き、ロードマップのデータでその論点の ID を持つ単位の要約を同じ値に書き換え、単位の名前では単位に当てない。

## 検証方針

- **分割クラス**:
  - `#config-keyed-by-id` — 設定の要約の差し替えに、渡した論点の ID の文字列を鍵として新しい要約が入り、名前の鍵は作らず、他の設定と他の鍵は変わらない
  - `#roadmap-unit-rewritten` — ロードマップのデータで、渡した ID を持つ単位の要約だけが新しい要約になる
  - `#several-pairs` — ID と要約の組を複数渡すと、組ごとに設定の鍵と単位の要約がその組の値になる（前からある鍵の上書きを含む）
  - `#names-not-matched` — 単位の名前を別の単位の ID と同じ文字にしてあっても、渡した ID を持つ単位に当たり、その名前の単位には当たらない
- **尽きている根拠**: 文が決める書き先は設定とロードマップのデータの 2 つで、それぞれを 1 クラスにし、渡し方（組 1 つか複数か）と当て方（名前では当てない）を 1 つずつ足す。名前の罠は、名前で当てれば必ず別の単位に当たる入力で見る。
- **検証しない**: 同じ値でもう一度渡したときに変更が無いこと（文が決めていない）。要約の文字の中身の決まり（要約の門の持ち分）。
