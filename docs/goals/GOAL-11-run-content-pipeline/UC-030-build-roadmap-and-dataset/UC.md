# UC-030 ロードマップ型の学びのロードマップと投入データを論点の候補から組み立てる

## 概要

作り手が、ロードマップ型の学びの論点の候補とロードマップの設定からロードマップのデータを組み立て直し、必要なら単位の要約を差し替え、教材と確認問題がそろったあとで投入データを組み立てて、配る本文を投入へ回せる形にする。

## 事前条件

- ロードマップ型の学びが登録簿にあり、論点の候補とロードマップの設定が学びの置き場にある
- 投入データを組み立てるときは、ロードマップの単位の教材と確認問題が学びの置き場にある

## 主シナリオ

1. 作り手が、論点の候補とロードマップの設定から、ロードマップのデータを組み立て直す
2. システムが、設定の回の束ね方、設定が指す論点の ID、候補の名前と、章で束ねる学びでは候補の章の名前と印を確かめる
3. システムが、到達基準を持つ候補から単位を選び、選んだ単位の前提の候補を含めて学ぶ順に並べ、各単位の名前と副題を分けたままロードマップのデータに書き出し、到達基準に繋がらない候補を落とした候補として残す
4. システムが、書き手の教材の束がまだ無い学びでは、書き手への束の割り当ても書き出す
5. 作り手が、単位の論点の ID と新しい要約を渡して、要約を差し替える
6. システムが、ロードマップの設定の要約の差し替えと、ロードマップのデータのその単位の要約を同じ値に書き換える
7. 作り手が、教材と確認問題がそろった学びの投入データを組み立てる
8. システムが、ロードマップの各単位の教材と確認問題の数と印と副題の欄を確かめる
9. システムが、各単位の名前と副題を分けたまま、ロードマップに無い論点の教材を補足の論点として学ぶ順の末尾に置き、投入データを書き出す
10. 作り手が、組み立てが止まらずに投入データが書き出されたことを見る

## 要件

### REQ-414

- pattern: Event-driven
- status: active

> 作り手がロードマップ型の学びの投入データを組み立てたとき、システムはロードマップの各単位の名前と副題を分けたまま投入データに移し、副題を持たない単位には副題を持たせない。

#### 検証方針

- **分割クラス**:
  - `#subtitle-carried-apart` — ロードマップのデータで副題を持つ単位は、投入データでも名前と副題がそれぞれ元の文字のまま分かれて入る
  - `#no-subtitle-none` — ロードマップのデータで副題を持たない単位は、投入データで副題を持たず、名前も元の文字のまま入る
- **尽きている根拠**: 単位ごとの入力は副題の有無の 2 通りで、名前と副題の文字の中身は値の変種。
- **境界の扱い**: 名前に括弧書きを含み副題を持たない単位を `#no-subtitle-none` の点に置き、組み立てが名前から副題を切り出さないことを見る。
- **検証しない**: 投入データから D1 への流し込みと応答（REQ-413 が応答まで通して見る）。副題の欄が空・空白だけ・文字列でも null でもないデータ（組み立てを止めることを REQ-422 が持つ）。

### REQ-422

- pattern: Unwanted behaviour
- status: active

> 作り手がロードマップ型の学びの投入データを組み立てたときに、ロードマップのデータに副題の欄が空の文字列・空白だけの文字列・文字列でも null でもない値である単位があれば、システムは投入データを書き出さずに組み立てを止め、その単位の名前を示す。

#### 検証方針

- **分割クラス**:
  - `#empty-string-stops` — 副題の欄が空の文字列の単位があると、投入データを書き出さずに止まり、その単位の名前を示す
  - `#blank-only-stops` — 副題の欄が空白だけの文字列（半角・全角の空白、タブ・改行の混ざり）の単位があると、投入データを書き出さずに止まり、その単位の名前を示す
  - `#non-string-stops` — 副題の欄が文字列でも null でもない値（数・真偽・配列・入れ物）の単位があると、投入データを書き出さずに止まり、その単位の名前を示す
  - `#null-or-text-not-stopped` — 副題の欄が null の単位、または空白以外の文字を含む文字列（前後に空白があっても）の単位だけなら止まらない
- **尽きている根拠**: 副題の欄の値は（欄が無い／null／文字列／それ以外の型）で、文字列は（空／空白だけ／空白以外を含む）に分かれる。止める側は文が挙げる 3 つで、それぞれ 1 クラス。止めない側のうち null と空白以外を含む文字列を 1 クラスに置いて上限を見る（欄が無い単位は REQ-414 の `#no-subtitle-none` が組み立てが通ることまで見る）。値の中身は値の変種。
- **境界の扱い**: 空白だけと空白以外を含むの境目は、前後に空白を持ち中に文字のある副題を `#null-or-text-not-stopped` の点に置く。「止まる」は終了コードが 0 でないこと、「書き出さない」は作業場の投入データ（`topics.json`）が組み立ての前から書き換わっていないこと、「名前を示す」は組み立ての出力にその単位の名前が出ることで見る。
- **検証しない**: 不正な単位が 2 つ以上あるときに名前をいくつ示すか（文が 1 単位の場合しか決めていない。問いとして返した）。止めない側で前後の空白を投入データに残すか削るか（この文も REQ-414 も決めていない）。

### REQ-429

- pattern: Event-driven
- status: active

> 作り手が論点の候補からロードマップのデータを組み立て直したとき、システムは候補の各単位の名前と副題を分けたままロードマップのデータに移し、候補で副題を持たない単位には副題を持たせない。

#### 検証方針

- **分割クラス**:
  - `#subtitle-carried-apart` — 候補で副題を持つ単位は、ロードマップのデータでも名前と副題がそれぞれ元の文字のまま分かれて入る
  - `#no-subtitle-absent` — 候補で副題を持たない単位は、ロードマップのデータで副題の欄を持たず、名前も元の文字のまま入る
- **尽きている根拠**: 単位ごとの入力は副題の有無の 2 通りで、名前と副題の文字の中身は値の変種。
- **境界の扱い**: 名前に括弧書きを含み副題を持たない単位を `#no-subtitle-absent` の点に置き、組み立てが名前から副題を切り出さないことを見る。
- **検証しない**: 候補の副題の欄が空・文字列でない値（移った先で REQ-422 が止める）。章で束ねる学び（副題の移し方は束ね方に依らないと文が決めている）。

### REQ-430

- pattern: Event-driven
- status: active

> 作り手が論点の候補からロードマップのデータを組み立て直したとき、システムはロードマップの設定と候補の前提が単位を指す所（単位ごとの設定の鍵、前提を足す・置き換える設定の値、含める・除く・続けて並べる単位の一覧、候補の前提）をすべて論点の ID として読んでその ID を持つ候補の単位に当て、単位の名前では当てない。

#### 検証方針

- **分割クラス**:
  - `#must-include-by-id` — 含める単位の一覧の ID の単位は、重みで上限から落ちる単位でも載る
  - `#exclude-by-id` — 除く単位の一覧の ID の単位は、重みが一番でも載らない
  - `#cluster-by-id` — 続けて並べる単位の一覧の ID の単位は、学ぶ順で間を空けずに並ぶ
  - `#prereq-add-by-id` — 前提を足す設定の鍵と値の ID で、値の単位が鍵の単位より前に並ぶ
  - `#prereq-replace-by-id` — 前提を置き換える設定の鍵と値の ID で、鍵の単位の前提が値の単位だけになる（元の前提は前に来ない）
  - `#summary-override-by-id` — 要約を差し替える設定の鍵の ID の単位だけ、要約がその値になる
  - `#candidate-prereq-by-id` — 候補の前提の ID の単位が、その候補の単位より前に並ぶ
  - `#names-not-matched` — 候補の名前を別の候補の ID と同じ文字に付け替えても、どの設定も前提も同じ ID の単位に当たり、結果が変わらない
- **尽きている根拠**: 文が列挙する単位を指す所（単位ごとの設定の鍵、前提を足す・置き換える値、含める・除く・続けて並べる一覧、候補の前提）を 1 つずつクラスにし、「名前では当てない」を名前と ID が食い違う入力 1 つで見る。単位ごとの設定の鍵は前提を足す・置き換える・要約を差し替えるの 3 つで、それぞれのクラスで鍵を見る。
- **境界の扱い**: 各クラスは、設定が無いときの結果がその設定の効いた結果と違うことを同じ仕込みで先に確かめる（効いたことが見分けられない仕込みにしない）。ID は一覧と値では整数、鍵では JSON の鍵の文字列（10 進）で書く。
- **検証しない**: 章で束ねる学び（ID の読み方は束ね方に依らない）。選び方・並べ方の重みの規則そのもの（文は当て方だけを決める）。分野ごとの下限（`min_per_field`）と分野の並び（`field_order`）は単位を指さないので対象外。

### REQ-434

- pattern: Unwanted behaviour
- status: active

> 作り手が論点の候補からロードマップのデータを組み立て直すときに、ロードマップの設定が指す論点の ID のどれかがどの候補の単位にも当たらなければ、システムはロードマップのデータを書き出さずに組み立てを止め、その ID を示す。

#### 検証方針

- **分割クラス**:
  - `#unknown-key` — 単位ごとの設定（前提を足す・置き換える・要約を差し替える）の鍵の ID が当たらないと、書き出さずに止め、その ID を示す
  - `#unknown-in-value` — 前提を足す・置き換える設定の値の ID が当たらないと、書き出さずに止め、その ID を示す
  - `#unknown-in-list` — 含める・除く・続けて並べる単位の一覧の ID が当たらないと、書き出さずに止め、その ID を示す
  - `#name-in-place-of-id` — ID の所に候補の名前を書くと、名前で当てずに書き出さずに止め、その値を示す
- **尽きている根拠**: 設定が ID を持つ所は鍵・値・一覧の 3 つの形に尽き、形ごとに該当する設定を値の変種として回す。当たらない値には、どの候補にも無い数と、候補の名前（ID として読めば当たらない）の 2 種があり、後者を別クラスにする。

  - `#extra-questions-in-extra-round` — 補足の論点の確認問題は補足の回に入る
  - `#roadmap-units-not-extra` — ロードマップの単位の論点とその確認問題は、補足の分野にも補足の回にも入らない
- **尽きている根拠**: 教材のある論点はロードマップの単位にある・無いの 2 つに分かれ、無い側は文の置き先（分野・回・学ぶ順・確認問題の回）ごとに、ある側はそこに入らないことを見る
- **境界の扱い**: 補足の論点は、写した itc の教材のうちロードマップの単位に無い論点を、その時の写しから求める
- **検証しない**: 補足の論点どうしの並び順（文が決めていない）

### REQ-545

- pattern: Unwanted behaviour
- status: active

> 作り手が単位の論点の ID と新しい要約を渡して要約を差し替えるときに、渡した論点の ID の数と要約の数が合わなければ、システムはロードマップの設定もロードマップのデータも書き換えずに止め、数が合わないことを示す。

#### 検証方針

- **分割クラス**:
  - `#more-ids-than-summaries` — 論点の ID が要約より多ければ（どれも当たる ID でも）、設定もロードマップのデータも書き換えずに止まり、標準出力に理由を出す
  - `#more-summaries-than-ids` — 要約が論点の ID より多ければ、同じく書き換えずに止まる
  - `#mismatch-before-unknown-id` — 数が合わず、渡した ID がどの単位にも当たらないときも、書き換えずに止まる（errors の順で数の不一致が先）
- **尽きている根拠**: 数の関係は ID が多い・要約が多いの 2 つ。errors の次の項目（当たらない ID）と両方に当たる入力を 1 つ置く
- **境界の扱い**: 止めたことは、終了 1 で書き換えないことと標準出力の理由で見る。2 つの条件のどちらで止めたか（断りの種類の名前 INVALID_INPUT と NOT_FOUND の見分け）はこの要件のクラスでは見ず、道具が断るときの出力は REQ-571 が持ち、名前は契約の実例 countMismatchBeforeUnknownId が見る
- **検証しない**: 「数が合わない」ことを示す理由の文の形（契約が決めていない。理由が標準出力にあることだけを見る）

### REQ-563

- pattern: Event-driven
- status: active

> 作り手が論点の候補からロードマップのデータを組み立て直したとき、システムは単位の数の上限・日で束ねる 1 回の論点数・到達基準ごとに確保する単位の数・回の束ね方を、ロードマップの設定にその値があればその値で、ロードマップの設定が無いかその値が無ければ渡した引数の値（引数も無ければ既定の値、回の束ね方は日）で決める。

#### 検証方針

- **分割クラス**:
  - `#config-value-over-argument` — ロードマップの設定に上限・1 回の論点数・到達基準ごとの数があれば、引数で別の値を渡しても設定の値で決まる
  - `#argument-when-config-lacks-value` — 設定はあるがその値が無ければ、引数の値で決まる
  - `#argument-when-no-config` — 設定のファイルが無ければ、引数の値で決まる
  - `#grouping-chapter-from-config` — 設定の回の束ね方が章なら、章で束ねて書き出す（単位が章の名前と章の番号を持ち、日を持たない）
  - `#grouping-day-when-unset` — 設定に回の束ね方が無いか、設定が無ければ、日で束ねて書き出す
- **尽きている根拠**: 値の出所は設定の値・引数・既定の 3 段で、設定は値がある・値が無い・ファイルが無いの 3 つ。回の束ね方は契約に引数が無いので、設定の値と欄が無いときの日の 2 つ
- **境界の扱い**: 上限は単位の数、1 回の論点数は各単位の日が学ぶ順と一致すること、到達基準ごとの数は重みの低い到達基準 2 の候補が確保される・されない（0 と 2）で見る
- **検証しない**: 既定の値（上限・1 回の論点数・到達基準ごとの数の既定の数を契約も REQ も決めていない）

### REQ-581

- pattern: Unwanted behaviour
- status: active

> 作り手がロードマップのデータを組み立て直すときに、学びの置き場に論点の候補が無ければ、システムはロードマップのデータも書き手への束の割り当ても書き出さずに断る。

#### 検証方針

- **分割クラス**:
  - `#candidates-file-missing` — 学びの置き場とロードマップの設定はあるが論点の候補のファイルが無いと、NOT_FOUND で断り、置き場を組み立ての前のまま残す（前に組み立てたロードマップのデータがある場合も書き換えない）
  - `#learning-dir-missing` — 学びの置き場そのものが無いと、NOT_FOUND で断り、置き場を作らず何も書き出さない
  - `#out-given-nothing-written` — 書き出す置き場を別に指定しても、論点の候補が無ければ NOT_FOUND で断り、その置き場に何も書き出さない
  - `#candidates-missing-before-unknown-config-id` — 論点の候補が無く、ロードマップの設定が論点の ID を指していても、候補が無いことで断り、その ID を示さない

- **境界の扱い**: 断ったときは、終了コード 1 で、標準出力に断りの名前を持つ ToolError を出し、例外の跡（Traceback）を残さない（契約の先頭の決まりと、2026-11-19 の本人の決定）
- **検証しない**: 候補のファイルはあるが候補が 0 件か読めない（文の「無い」がファイルの不在か候補 0 件かを決めていない）。登録簿に無い学びの組み立て直し（UC の表で未決）

### REQ-582

- pattern: Unwanted behaviour
- status: active

> 作り手が投入データを組み立てるときに、渡した学びが登録簿に無いか、学びの置き場にロードマップのデータが無ければ、システムは投入データを書き出さずに断る。

#### 検証方針

- **分割クラス**:
  - `#unknown-learning-with-roadmap` — 登録簿に無い学びの置き場に、ロードマップのデータ・教材・確認問題がそろっていても、INVALID_INPUT で断り、投入データを書き出さない
  - `#unknown-learning-before-roadmap-missing` — 登録簿に無い学びで、置き場にロードマップのデータも無いと、INVALID_INPUT で断る（ロードマップが無いことより先）
  - `#roadmap-missing` — 登録簿にある学びの置き場に、教材と確認問題はあるがロードマップのデータが無いと、NOT_FOUND で断り、置き場を組み立ての前のまま残す
  - `#learning-dir-missing` — 登録簿にある学びの置き場そのものが無いと、NOT_FOUND で断り、置き場を作らず何も書き出さない
- **尽きている根拠**: 文の条件は「登録簿に無い」と「ロードマップのデータが無い」の 2 つ。登録簿に無い側は、組み立てに要る物がそろっているか（登録簿だけで断るか）と、ロードマップのデータも無いか（契約の errors の順で先の項目が勝つか）の 2 つ。ロードマップのデータが無い側は、置き場があってそのファイルだけが無いか、置き場ごと無いかの 2 つ
- **境界の扱い**: 断ったときは、終了コード 1 で、標準出力に断りの名前を持つ ToolError を出し、例外の跡（Traceback）を残さない（契約の先頭の決まりと、2026-11-19 の本人の決定）
- **検証しない**: 登録簿にあるがロードマップ型でない学び（文が決めていない）。ロードマップのデータが無いことと、契約の errors の次の項目（教材の無い単位がある）が両方成り立つ入力（教材の無い単位はロードマップのデータの単位で決まるので、ロードマップのデータが無いと作れない）
