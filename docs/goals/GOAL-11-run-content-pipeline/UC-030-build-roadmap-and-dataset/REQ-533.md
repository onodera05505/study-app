# REQ-533

> 作り手が回を章で束ねる設定で論点の候補からロードマップのデータを組み立て直すときに、章の名前か印を欠く候補、または登録簿のその学びの印の段に無い印を持つ候補があれば、システムはロードマップのデータを書き出さずに組み立てを止め、その候補の名前を示す。

## 検証方針

- **分割クラス**:
  - `#chapter-missing-stops` — 章で束ねる設定で章の名前の欄を欠く候補があれば、書き出さずに止まり、その候補の名前を示す
  - `#tier-missing-stops` — 印の欄を欠く候補があれば、同じく止まり、その候補の名前を示す
  - `#tier-outside-registry-stops` — 印が登録簿のその学びの段に無い値（段の下の外・上の外）の候補があれば、同じく止まり、その候補の名前を示す
  - `#outside-selection-also-stops` — 欠けた候補が除く一覧にある・到達基準を持たずに単位にならない候補でも止まる（単位に選んだ候補に限らない）
  - `#all-present-built` — どの候補も章の名前と段にある印（段の両端を含む）を持てば止まらない
  - `#chapter-missing-before-tier-outside` — 章の名前を欠く候補と段に無い印の候補が両方あれば、errors の順で前の章の名前の欠けを示して止まり、印の候補は示さない
  - `#tier-outside-before-included-and-excluded` — 段に無い印の候補と含める・除く一覧の重なりが両方あれば、候補の名前を示して止まり、重なった ID は示さない
- **尽きている根拠**: 候補ごとの章の名前の欄は有る・無い、印は段にある・欄が無い・段の外（下・上）に分かれ、候補の位置は単位になる・除く・到達基準が無いに分かれる。errors の隣り合う組（章の欠け→段に無い印→一覧の重なり）は両方に当たる入力を 1 つずつ置く。日で束ねる設定で章と印を持たない候補が止まらないことは REQ-429・430 のテストが日で束ねる候補で見る
- **境界の扱い**: 段は登録簿の値をテストが読み、両端と両端の外を使う。条件の順は、後の条件に当たる候補を候補の並びで先に置いて、候補の順ではないことを見る
- **検証しない**: 章の名前や印の欄が空の文字列・文字列でない値・数でない印（「欠く」に当たるかを文が決めていない）
- **参照先**: `tests/server/UC-030_build_roadmap.test.ts::UC-030 章で束ねるのに章の名前か印を欠く候補があれば止める`
