# REQ-430

> 作り手が論点の候補からロードマップのデータを組み立て直したとき、システムはロードマップの設定と候補の前提が単位を指す所（単位ごとの設定の鍵、前提を足す・置き換える設定の値、含める・除く・続けて並べる単位の一覧、候補の前提）をすべて論点の ID として読んでその ID を持つ候補の単位に当て、単位の名前では当てない。

## 検証方針

- **分割クラス**:
  - `#must-include-by-id` — 含める単位の一覧の ID の単位は、重みで上限から落ちる単位でも載る
  - `#exclude-by-id` — 除く単位の一覧の ID の単位は、重みが一番でも載らない
  - `#cluster-by-id` — 続けて並べる単位の一覧の ID の単位は、学ぶ順で間を空けずに並ぶ
  - `#prereq-add-by-id` — 前提を足す設定の鍵と値の ID で、値の単位が鍵の単位より前に並ぶ
  - `#prereq-replace-by-id` — 前提を置き換える設定の鍵と値の ID で、鍵の単位の前提が値の単位だけになる（元の前提は前に来ない）
  - `#summary-override-by-id` — 要約を差し替える設定の鍵の ID の単位だけ、要約がその値になる
  - `#candidate-prereq-by-id` — 候補の前提の ID の単位が、その候補の単位より前に並ぶ
  - `#names-not-matched` — 候補の名前を別の候補の ID と同じ文字に付け替えても、どの設定も前提も同じ ID の単位に当たり、結果が変わらない
- **尽きている根拠**: 文が列挙する単位を指す所（単位ごとの設定の鍵、前提を足す・置き換える値、含める・除く・続けて並べる一覧、候補の前提）を 1 つずつクラスにし、「名前では当てない」を名前と ID が食い違う入力 1 つで見る。単位ごとの設定の鍵は前提を足す・置き換える・要約を差し替えるの 3 つで、それぞれのクラスで鍵を見る。
- **境界の扱い**: 各クラスは、設定が無いときの結果がその設定の効いた結果と違うことを同じ仕込みで先に確かめる（効いたことが見分けられない仕込みにしない）。ID は一覧と値では整数、鍵では JSON の鍵の文字列（10 進）で書く。
- **検証しない**: 章で束ねる学び（ID の読み方は束ね方に依らない）。選び方・並べ方の重みの規則そのもの（文は当て方だけを決める）。分野ごとの下限（`min_per_field`）と分野の並び（`field_order`）は単位を指さないので対象外。
