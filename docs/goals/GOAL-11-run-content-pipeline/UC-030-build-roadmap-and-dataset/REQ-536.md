# REQ-536

> 作り手が論点の候補からロードマップのデータを組み立て直したとき、システムは単位に選んだ候補が前提に挙げる候補を、除く一覧に無く到達基準を持つ限り、ロードマップの設定の単位の数の上限を超えても単位に含める。

## 検証方針

- **分割クラス**:
  - `#prereq-beyond-max` — 単位に選んだ候補が前提に挙げる候補は、重みで上限から落ちる候補でも単位に入る
  - `#prereq-of-prereq-beyond-max` — 前提として単位に入れた候補がさらに前提に挙げる候補も、上限を超えて単位に入る
  - `#excluded-prereq-not-added` — 前提の候補が除く一覧にあれば単位に入らない
  - `#no-goal-prereq-not-added` — 前提の候補が到達基準を持たなければ単位に入らない
- **尽きている根拠**: 前提の候補は、除く一覧にある・到達基準が無い・どちらでもない（直接の前提と、前提の前提）に分かれる
- **境界の扱い**: 前提が無ければその候補が上限で単位にならないことを、同じ候補で先に確かめる
- **検証しない**: ロードマップの設定の前提を足す・置き換える設定から来る前提（文は「候補が前提に挙げる候補」を言う。設定の前提の当て方は REQ-430）。上限を超えたときの単位の数そのもの
- **参照先**: `tests/server/UC-030_build_roadmap.test.ts::UC-030 単位の前提の候補は上限を超えても単位に含める`
