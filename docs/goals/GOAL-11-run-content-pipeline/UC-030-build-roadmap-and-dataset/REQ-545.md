# REQ-545

> 作り手が単位の論点の ID と新しい要約を渡して要約を差し替えるときに、渡した論点の ID の数と要約の数が合わなければ、システムはロードマップの設定もロードマップのデータも書き換えずに止め、数が合わないことを示す。

## 検証方針

- **分割クラス**:
  - `#more-ids-than-summaries` — 論点の ID が要約より多ければ（どれも当たる ID でも）、設定もロードマップのデータも書き換えずに止まり、標準出力に理由を出す
  - `#more-summaries-than-ids` — 要約が論点の ID より多ければ、同じく書き換えずに止まる
  - `#mismatch-before-unknown-id` — 数が合わず、渡した ID がどの単位にも当たらないときも、書き換えずに止まる（errors の順で数の不一致が先）
- **尽きている根拠**: 数の関係は ID が多い・要約が多いの 2 つ。errors の次の項目（当たらない ID）と両方に当たる入力を 1 つ置く
- **境界の扱い**: 止めたことは、終了 1 で書き換えないことと標準出力の理由で見る。2 つの条件のどちらで止めたか（断りの種類の名前 INVALID_INPUT と NOT_FOUND の見分け）はこの要件のクラスでは見ず、道具が断るときの出力は REQ-571 が持ち、名前は契約の実例 countMismatchBeforeUnknownId が見る
- **検証しない**: 「数が合わない」ことを示す理由の文の形（契約が決めていない。理由が標準出力にあることだけを見る）
- **参照先**: `tests/server/UC-030_apply_summary_count.test.ts::UC-030 論点の ID と要約の数が合わなければ書き換えずに止める`
