# UC-026 資格対策の教材の書き直しに配る束を単元とまとまりの単位で作る

## 概要

作り手が、資格対策の学びについて、単元の構成を書く書き手に配る単元の入力の束と、教材を書き直す書き手に配るまとまりごとの書き直しの束を作り、書き手に割り当てる。

## 事前条件

- 資格対策の学びが登録簿にあり、論点・シラバス・過去問・問題解説・教材の世代・図の仕様が学びの置き場にある
- 書き直しの束を作るときは、その単元の単元の構成が学びの置き場にある
- 束の中身の形は執筆の仕様書（`scripts/prompts/unit_plan.md`・`scripts/prompts/rewrite_materials_by_group.md`）が決める
- 適用される業務規則: BR-004, BR-028, BR-048, BR-052

## 主シナリオ

1. 作り手が、単元の入力の束を作る
2. システムが、単元ごとに 1 つ、その単元の全論点と今の教材を持つ単元の入力の束を書き出す
3. 作り手が、単元の構成を書き手に書かせ、教材の門を通してから、書き直しの束を作る
4. システムが、単元の構成が教材の門の止める理由に当たらないことを確かめる → BR-048
5. システムが、まとまりごとに 1 つ、学ぶ順の論点と、各論点の今の教材・同一内容の組に畳んだ過去問とそれに結んだ問題解説・図の仕様・前提と、まとまりに関わる受け持ちを持つ書き直しの束を書き出す → BR-052
6. 作り手が、書き出した束の数を見て、束ごとに書き手を割り当てる

## 事後条件

- 成功時: 作り手が、出力先に単元ごとの単元の入力の束、またはまとまりごとの書き直しの束が書き出され、その数が単元またはまとまりの数と同じであることを見ている
- 失敗時: いかなる状態変更も残っていない（部分適用なし。止めたときは束を 1 つも書き出さない）

## 要件

### REQ-461

- pattern: Event-driven
- status: active

> 作り手が資格対策の学びの単元の入力の束を作ったとき、システムは論点が 1 つ以上あるシラバスの単元ごとに 1 つ、その単元の全論点を小項目の番号と論点の番号の順に並べ、各論点の名前・小項目・出題回数・周辺の用語と、教材の世代を古い順に重ねて論点ごとに最も新しい世代の教材を持つ束を書き出し、論点の無い単元の束は書き出さない。

#### 検証方針

- **分割クラス**:
  - `#one-per-unit` — 単元を指定しなければ論点のあるシラバスの単元ごとに 1 つの束を書き出し、そのパスを返し、束は単元の番号・名前・分野・大項目を持つ
  - `#topicless-unit-skipped` — 論点が 1 つも無い単元の束は書き出さない
  - `#topic-order` — 束の論点は単元の全論点で、小項目の番号の順、同じ小項目の中は論点の番号の順
  - `#topic-attributes` — 各論点は名前・小項目の番号と名前・出題回数・周辺の用語を持つ
  - `#newest-generation` — 各論点の教材は、世代を古い順に重ねて論点ごとに最も新しい世代の物
  - `#ignores-unit-plans` — 単元の構成が無い・止める理由に当たる単元でも束を作る
- **尽きている根拠**: 文の要素（論点のある単元ごとに 1 つ・論点の無い単元は書かない・並び・論点の属性・教材の選び方）をそれぞれクラスにし、UC の表の「単元の入力の束は単元の構成を読まない」を加えた。教材の選び方は最も古い世代だけ・中間の世代まで・最も新しい世代まで有る論点を同じ仕込みに置く
- **検証しない**: 論点の無い単元を指定したとき（文は書き出さないとだけ言い、空の応答か断りかを観測で決める根拠が無い）。教材の本文の図の行の扱い（文が扱わない）

### REQ-462

- pattern: Event-driven
- br: BR-048, BR-052
- status: active

> 作り手が資格対策の学びの書き直しの束を作ったとき、システムは単元の構成のまとまりごとに 1 つ、単元の全体像とまとまりの名前と説明、学ぶ順に並べたまとまりの論点、各論点の最も新しい世代の教材・同一内容の組を 1 件に畳んだ紐づく過去問・同一内容の判定でその組に結んだ問題解説・図の仕様・前提の論点、そのまとまりの論点が触れる受け持ちを持つ束を書き出す。

#### 検証方針

- **分割クラス**:
  - `#one-per-group` — まとまりごとに 1 つの束を単元の番号 2 桁とまとまりの順の名前で書き出し、そのパスを返す
  - `#bundle-header` — 束は束の名前・単元の番号と名前・全体像・そのまとまりの順と名前と説明・単元の全部のまとまりを持つ
  - `#learn-order` — 束の論点はそのまとまりの論点だけで、単元の構成の学ぶ順
  - `#topic-attributes` — 各論点は名前・分野・大項目・単元・小項目の名前・出題回数・周辺の用語を持つ
  - `#newest-generation` — 各論点の今の教材は最も新しい世代の名前と教材
  - `#questions-folded` — 紐づく過去問は同一内容を 1 件に畳み、代表は新しい回の問題で、契約の作り方の content_key・本文・選択肢・正解を持つ
  - `#question-explanations` — 各論点は、組の古い回の問題の ID で書いた解説も含め、同一内容の判定で組に結んだ問題解説を持つ
  - `#figures` — 図の仕様を持つ論点はそのパスと figures の写しを、持たない論点は null と空を持つ
  - `#prerequisites` — 各論点は前提の論点を他の単元の物も含めて番号と名前で持ち、無ければ空
  - `#owners-touching-group` — 束はそのまとまりの論点が触れる受け持ちだけを、受け持ちの論点が前のまとまりにあっても持つ
- **尽きている根拠**: 文の束の中身の要素ごとに 1 クラス。過去問は同一内容の組・1 問・0 問、解説は代表と違う回の ID で書いた物・代表の ID で書いた物・無し、図は有る・無い、前提は同じ単元・他の単元・無し、受け持ちは触れる・触れないを同じ仕込みに置く
- **検証しない**: 過去問の exam_label・has_figure・figure_description（契約で任意の欄）。束の問題解説の question_id の値（契約の「問題解説を書いた代表の過去問」が、解説を書いたときの ID か畳んだ組の代表かを決めていない。報告済み）。問題解説の choices の中身（解説の写しで、REQ の文は解説を持つことだけを言う）。本文や選択肢に空白文字を含む過去問の鍵（作り方の正規化の変種で、値の正本は BR-052 が置く content_key_of）

### REQ-463

- pattern: Unwanted behaviour
- br: BR-048
- status: active

> 作り手が書き直しの束を作るときに、求めた単元（単元を指定しなければ論点のあるすべての単元）のどれかに単元の構成が無いか、学びの全部の単元の構成と合わせて判定した教材の門の止める理由のうち求めた単元に関する物があれば、システムは束を 1 つも書き出さずに止め、その単元と理由を示す。

#### 検証方針

- **分割クラス**:
  - `#plan-missing` — 求めた単元の構成が無ければ NOT_FOUND で止め、束を 1 つも書き出さず、ToolError の理由にその単元を示す
  - `#plan-stops` — 求めた単元の構成が門の止める理由に当たれば CONFLICT で止め、束を 1 つも書き出さず、その単元と理由を示す
  - `#plan-unreadable` — 求めた単元の構成が書きかけで読めなければ CONFLICT で止める
  - `#judged-with-all-plans` — 求めた単元の構成が他の単元の構成と合わせて前提の循環になれば CONFLICT で止める
  - `#other-unit-stop-ignored` — 止める理由が求めていない単元の構成にだけあれば、求めた単元の束を書き出す
  - `#units-omitted-plan-missing` — 単元を指定せず、論点のある単元に構成が無ければ NOT_FOUND で止める
  - `#units-omitted-topical-units` — 単元を指定せず、論点のある単元すべてに構成があれば、論点の無い単元に構成が無くても全部のまとまりの束を書き出す
  - `#plan-missing-before-plan-stops` — 構成の無い単元と止める理由に当たる単元を同時に求めると NOT_FOUND（契約の errors の順）
- **尽きている根拠**: 求めた単元は指定・省略（論点のある全単元）の 2 つ、その構成は無い・有って求めた単元に関する止める理由に当たる（読めない・その構成だけで当たる・他の構成と合わせて当たる）・求めた単元に関する止める理由は無い（他の単元にだけある場合を含む）に分かれる。errors の隣り合う NOT_FOUND と CONFLICT の順を 1 クラスで見る。止める理由の判定そのものは UC-024 の REQ が持つ
- **検証しない**: 理由の文の言い回し（単元の番号と、止める理由の種類か名前を含むことだけを見る）

### REQ-464

- pattern: Unwanted behaviour
- status: active

> 作り手が束を作るときに、出力先にその種類の束の名前の形をしたファイルが 1 つでもあれば（今回書き出す束と名前が違っても）、システムは束を 1 つも書き出さず、既にある束を書き換えずに止め、その出力先を示す。

#### 検証方針

- **分割クラス**:
  - `#same-bundle-exists` — 作る束と同じ名前の束が出力先にあれば、両方の入口で CONFLICT で止め、既にある束を書き換えず、他も書き出さず、ToolError の理由に出力先を示す
  - `#other-bundle-exists` — 作らない単元の束でも、その種類の束の名前の形のファイルが出力先にあれば、両方の入口で CONFLICT で止める
  - `#non-bundle-name-ignored` — 出力先にあるのがその種類の束の名前の形でないファイル（別の種類の束の名前・束でない名前）だけなら止めず、そのファイルを書き換えない
  - `#unknown-unit-before-exists` — シラバスに無い単元を求め出力先にも束があれば、両方の入口で INVALID_INPUT（契約の errors の順）
  - `#exists-before-plan-missing` — 出力先に束があり求めた単元の構成も無ければ CONFLICT（契約の errors の順）
- **尽きている根拠**: 出力先のファイルは、無い（REQ-461・462）・その種類の束の名前の形で今回作る名前・同じ形で別の名前・その種類の束の名前の形でない、の 4 つに分かれる。errors の隣り合う組の順を 2 クラスで見る
- **検証しない**: 作り直している途中に書き手が束を読む並行（同じ出力先へ作り直すこと自体を断るので、前の 2 クラスで見る）

### REQ-465

- pattern: Optional
- status: active

> 作り手が単元を指定して束を作る場合、システムは指定した単元の束だけを書き出し、指定した単元のどれかがその学びのシラバスに無ければ何も書き出さずに断る。

#### 検証方針

- **分割クラス**:
  - `#only-specified-unit-inputs` — 単元の入力の束は指定した単元の束だけを書き出す
  - `#only-specified-rewrite` — 書き直しの束は指定した単元のまとまりの束だけを書き出す
  - `#unknown-unit` — シラバスに無い単元を指定に含めれば、両方の入口で INVALID_INPUT で断り、何も書き出さない
- **尽きている根拠**: 指定は、無い（論点のある全単元。REQ-461・463）・シラバスの単元だけ・シラバスに無い単元を含むの 3 つで、2 つの入口それぞれで見る
- **検証しない**: 同じ単元を 2 回指定した並び（文が扱わない）

### REQ-466

- pattern: Unwanted behaviour
- br: BR-004
- status: active

> 作り手が登録簿に無い学びか資格対策でない学びの束を作ろうとしたとき、またはその学びのシラバスか論点の一覧が無いか読めないとき、システムは束を 1 つも書き出さずに断る。

#### 検証方針

- **分割クラス**:
  - `#unknown-learning` — 登録簿に無い学びは、置き場があっても両方の入口で INVALID_INPUT で断り、作業場に何も書き出さない
  - `#not-qualification` — 登録簿のロードマップ型の学びは、置き場があっても両方の入口で INVALID_INPUT で断り、作業場に何も書き出さない
  - `#learning-file-missing` — シラバスか論点の一覧が無ければ、両方の入口で NOT_FOUND で断り、何も書き出さない
  - `#learning-file-unreadable` — シラバスか論点の一覧が JSON として読めなければ、両方の入口で INVALID_INPUT で断り、何も書き出さない
  - `#registry-before-files` — 資格対策でなくシラバスも無ければ INVALID_INPUT（契約の errors の順）
  - `#missing-before-unreadable` — シラバスが無く論点の一覧も読めなければ NOT_FOUND（契約の errors の順）
- **尽きている根拠**: 断る条件は、登録簿（無い・ロードマップ型）と学びのファイル（シラバス・論点の一覧のそれぞれが無い・読めない）で尽きる。errors の隣り合う組のうち code の違う物を順のクラスにした
- **検証しない**: `data` の形に合わない値（引数の形の検査で、REQ の文が扱わない）。code の同じ隣り合う組（INVALID_INPUT 同士）の順（観測で区別できない）

### REQ-492

- pattern: Unwanted behaviour
- br: BR-028
- status: active

> 作り手が書き直しの束を作るときに、同一内容の組を 1 件に畳んだあとに束に入る代表の過去問のどれかの正解が正解表に無ければ、システムは束を 1 つも書き出さずに断り、畳まれて束に入らない過去問の正解が無いだけでは断らない。

#### 検証方針

- **分割クラス**:
  - `#answer-missing` — 書き直しの束に入る代表の過去問の正解が正解表に無ければ NOT_FOUND で断り、束を 1 つも書き出さない
  - `#answer-table-missing` — 正解表のファイルそのものが学びの置き場に無ければ、束に入る代表の過去問の正解も無いので NOT_FOUND で断り、束を 1 つも書き出さない（errors の前の行に当たらない置き場で）
  - `#plan-stops-before-answer-missing` — 求めた単元の構成が止める理由に当たり正解も無ければ CONFLICT（契約の errors の順）
  - `#folded-answer-missing-not-refused` — 同一内容の組のうち束に入らない古い回の過去問の正解だけが正解表に無ければ、断らずに束を書き出す
- **尽きている根拠**: 束を作るのに正解を引く過去問は、束に入る代表（正解が有る・無い）と、畳まれて束に入らない過去問（正解が無い）に分かれる。代表の正解が無いのは、正解表に問番号か回が無い場合と、正解表のファイルそのものが無い場合に分かれる。errors の隣り合う CONFLICT と NOT_FOUND の順を 1 クラスで見る
- **検証しない**: 単元の入力の束で正解が無い過去問（UC の表で不可: 単元の入力の束は過去問を持たない）。束に入る過去問の正解の値（REQ-462 が持つ）。正解表のファイルが JSON として読めない場合（REQ の文も契約の errors も扱いを決めていない）

### REQ-584

- pattern: Unwanted behaviour
- status: active

> 作り手が書き直しの束を作るときに、出力先に束を書き出せなければ、システムは書き出した束を残さずに断り、その出力先を示す。

#### 検証方針

- **分割クラス**:
  - `#out-path-is-file` — 出力先の位置に通常のファイルがあって出力先を作れないと、STORAGE_UNAVAILABLE で断り、そのファイルを書き換えず、出力先を示す
  - `#out-not-writable` — 出力先のディレクトリに書き込めないと、STORAGE_UNAVAILABLE で断り、束を 1 つも残さず、出力先を示す
  - `#partial-write-removed` — 1 つ目の束は書き出せて後の束を書き出せないと、STORAGE_UNAVAILABLE で断り、先に書き出した束を残さず、出力先を示す
  - `#answer-missing-before-write-failed` — 束に入る過去問の正解が正解表に無く、出力先にも書き出せないと、NOT_FOUND で断る（契約の errors の順）
- **尽きている根拠**: 書き出せない形は、出力先そのものを作れない・出力先はあるが 1 つも書けない・途中から書けないの 3 つに尽きる。文の「書き出した束を残さず」は途中から書けない場合でだけ書き出した束が生じるので、そこで見る。契約の errors の隣の項目（束に入る過去問の正解が無い）とは、両方が成り立つ入力で先の項目が勝つことを 1 つで見る
