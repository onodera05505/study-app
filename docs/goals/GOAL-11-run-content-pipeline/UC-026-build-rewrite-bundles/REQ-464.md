# REQ-464

> 作り手が束を作るときに、出力先にその種類の束の名前の形をしたファイルが 1 つでもあれば（今回書き出す束と名前が違っても）、システムは束を 1 つも書き出さず、既にある束を書き換えずに止め、その出力先を示す。

## 検証方針

- **分割クラス**:
  - `#same-bundle-exists` — 作る束と同じ名前の束が出力先にあれば、両方の入口で CONFLICT で止め、既にある束を書き換えず、他も書き出さず、ToolError の理由に出力先を示す
  - `#other-bundle-exists` — 作らない単元の束でも、その種類の束の名前の形のファイルが出力先にあれば、両方の入口で CONFLICT で止める
  - `#non-bundle-name-ignored` — 出力先にあるのがその種類の束の名前の形でないファイル（別の種類の束の名前・束でない名前）だけなら止めず、そのファイルを書き換えない
  - `#unknown-unit-before-exists` — シラバスに無い単元を求め出力先にも束があれば、両方の入口で INVALID_INPUT（契約の errors の順）
  - `#exists-before-plan-missing` — 出力先に束があり求めた単元の構成も無ければ CONFLICT（契約の errors の順）
- **尽きている根拠**: 出力先のファイルは、無い（REQ-461・462）・その種類の束の名前の形で今回作る名前・同じ形で別の名前・その種類の束の名前の形でない、の 4 つに分かれる。errors の隣り合う組の順を 2 クラスで見る
- **検証しない**: 作り直している途中に書き手が束を読む並行（同じ出力先へ作り直すこと自体を断るので、前の 2 クラスで見る）
- **参照先**: `tests/server/UC-026_build_rewrite_bundles.test.ts::出力先に既に束があれば何も書き出さず書き換えずに止める（REQ-464）`
