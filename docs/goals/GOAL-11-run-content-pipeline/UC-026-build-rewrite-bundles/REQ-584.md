# REQ-584

> 作り手が書き直しの束を作るときに、出力先に束を書き出せなければ、システムは書き出した束を残さずに断り、その出力先を示す。

## 検証方針

- **分割クラス**:
  - `#out-path-is-file` — 出力先の位置に通常のファイルがあって出力先を作れないと、STORAGE_UNAVAILABLE で断り、そのファイルを書き換えず、出力先を示す
  - `#out-not-writable` — 出力先のディレクトリに書き込めないと、STORAGE_UNAVAILABLE で断り、束を 1 つも残さず、出力先を示す
  - `#partial-write-removed` — 1 つ目の束は書き出せて後の束を書き出せないと、STORAGE_UNAVAILABLE で断り、先に書き出した束を残さず、出力先を示す
  - `#answer-missing-before-write-failed` — 束に入る過去問の正解が正解表に無く、出力先にも書き出せないと、NOT_FOUND で断る（契約の errors の順）
- **尽きている根拠**: 書き出せない形は、出力先そのものを作れない・出力先はあるが 1 つも書けない・途中から書けないの 3 つに尽きる。文の「書き出した束を残さず」は途中から書けない場合でだけ書き出した束が生じるので、そこで見る。契約の errors の隣の項目（束に入る過去問の正解が無い）とは、両方が成り立つ入力で先の項目が勝つことを 1 つで見る
- **検証しない**: 出力先に束の名前の形をしたディレクトリがある場合（REQ-464 の「束の名前の形をしたファイル」に当たるか、書き出せない側かを文が決めていない）。単元の入力の束（buildUnitInputs）の出力先に書き出せない場合（UC の表で未決）。書き出せない理由の種類（容量・権限・パスの形）ごとの違い（文は理由を分けない）
