# REQ-463

> 作り手が書き直しの束を作るときに、求めた単元（単元を指定しなければ論点のあるすべての単元）のどれかに単元の構成が無いか、学びの全部の単元の構成と合わせて判定した教材の門の止める理由のうち求めた単元に関する物があれば、システムは束を 1 つも書き出さずに止め、その単元と理由を示す。

## 検証方針

- **分割クラス**:
  - `#plan-missing` — 求めた単元の構成が無ければ NOT_FOUND で止め、束を 1 つも書き出さず、ToolError の理由にその単元を示す
  - `#plan-stops` — 求めた単元の構成が門の止める理由に当たれば CONFLICT で止め、束を 1 つも書き出さず、その単元と理由を示す
  - `#plan-unreadable` — 求めた単元の構成が書きかけで読めなければ CONFLICT で止める
  - `#judged-with-all-plans` — 求めた単元の構成が他の単元の構成と合わせて前提の循環になれば CONFLICT で止める
  - `#other-unit-stop-ignored` — 止める理由が求めていない単元の構成にだけあれば、求めた単元の束を書き出す
  - `#units-omitted-plan-missing` — 単元を指定せず、論点のある単元に構成が無ければ NOT_FOUND で止める
  - `#units-omitted-topical-units` — 単元を指定せず、論点のある単元すべてに構成があれば、論点の無い単元に構成が無くても全部のまとまりの束を書き出す
  - `#plan-missing-before-plan-stops` — 構成の無い単元と止める理由に当たる単元を同時に求めると NOT_FOUND（契約の errors の順）
- **尽きている根拠**: 求めた単元は指定・省略（論点のある全単元）の 2 つ、その構成は無い・有って求めた単元に関する止める理由に当たる（読めない・その構成だけで当たる・他の構成と合わせて当たる）・求めた単元に関する止める理由は無い（他の単元にだけある場合を含む）に分かれる。errors の隣り合う NOT_FOUND と CONFLICT の順を 1 クラスで見る。止める理由の判定そのものは UC-024 の REQ が持つ
- **検証しない**: 理由の文の言い回し（単元の番号と、止める理由の種類か名前を含むことだけを見る）
- **参照先**: `tests/server/UC-026_build_rewrite_bundles.test.ts::単元の構成が無いか止める理由に当たれば何も書き出さずに止める（REQ-463）`
