# REQ-492

> 作り手が書き直しの束を作るときに、同一内容の組を 1 件に畳んだあとに束に入る代表の過去問のどれかの正解が正解表に無ければ、システムは束を 1 つも書き出さずに断り、畳まれて束に入らない過去問の正解が無いだけでは断らない。

## 検証方針

- **分割クラス**:
  - `#answer-missing` — 書き直しの束に入る代表の過去問の正解が正解表に無ければ NOT_FOUND で断り、束を 1 つも書き出さない
  - `#answer-table-missing` — 正解表のファイルそのものが学びの置き場に無ければ、束に入る代表の過去問の正解も無いので NOT_FOUND で断り、束を 1 つも書き出さない（errors の前の行に当たらない置き場で）
  - `#plan-stops-before-answer-missing` — 求めた単元の構成が止める理由に当たり正解も無ければ CONFLICT（契約の errors の順）
  - `#folded-answer-missing-not-refused` — 同一内容の組のうち束に入らない古い回の過去問の正解だけが正解表に無ければ、断らずに束を書き出す
- **尽きている根拠**: 束を作るのに正解を引く過去問は、束に入る代表（正解が有る・無い）と、畳まれて束に入らない過去問（正解が無い）に分かれる。代表の正解が無いのは、正解表に問番号か回が無い場合と、正解表のファイルそのものが無い場合に分かれる。errors の隣り合う CONFLICT と NOT_FOUND の順を 1 クラスで見る
- **検証しない**: 単元の入力の束で正解が無い過去問（UC の表で不可: 単元の入力の束は過去問を持たない）。束に入る過去問の正解の値（REQ-462 が持つ）。正解表のファイルが JSON として読めない場合（REQ の文も契約の errors も扱いを決めていない）
- **参照先**: `tests/server/UC-026_build_rewrite_bundles.test.ts::束に入る代表の過去問の正解が正解表に無ければ何も書き出さずに断り、畳まれて束に入らない過去問の正解が無いだけでは断らない（REQ-492）`
