# REQ-488

> 作り手が教材に図を差し込むときに、図の画像が配信の置き場に無いか、書き直した世代から選んだ論点で図の仕様の差し込み位置の見出しが教材に無い図が 1 つでもあれば、システムは教材のファイルを 1 つも書き換えず、そうした図ごとにその論点と図と理由を問題として示して失敗で終える。

## 検証方針

- **分割クラス**:
  - `#image-missing` — 書き直した世代から選んだ論点の図で、図の画像が配信の置き場に無い
  - `#heading-missing-rewritten` — 書き直した世代から選んだ論点の図で、差し込み位置の見出しが教材に無い
  - `#heading-missing-previous-not-problem` — 前の世代から選んだ論点の図で、差し込み位置の見出しが教材に無い
  - `#no-material-rewritten-on-problem` — 差し込めない図が 1 つあり、同じ論点と他の論点に差し込める図があっても、どの教材のファイルも書き換わっていない
- **尽きている根拠**: 文の条件は「画像が無い」と「書き直した世代の論点で見出しが無い」の 2 つで、見出しの条件の外側（前の世代の論点）を 1 クラスにする。問題があるときの教材のファイルは、差し込める図が同じ論点にある・他の論点にあるを 1 つの仕込みに置いて書き換わらないことを見る
- **検証しない**: 前の世代から選んだ論点の図で画像が無いとき（文の画像の条件は世代を問わないので `#image-missing` と同じ扱い。写しの図を書き直した世代の論点で消して押さえる）。画像が無いときの理由の文言（図の仕様書の門の表に行が無く、`{where}` の形と理由が空でないことだけを見る）。`dryRun` を渡したとき（どの REQ の文にも無い）
- **参照先**: `tests/server/UC-027_assemble_generation.test.ts::置けない図は差し込まず、論点と図と理由を問題として示して失敗で終える（UC-027）`
