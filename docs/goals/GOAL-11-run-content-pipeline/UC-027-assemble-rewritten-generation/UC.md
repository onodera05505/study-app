# UC-027 書き直した世代の教材と単元の構成を配る本文に組み立てる

## 概要

作り手が、門を通った書き直した世代の教材に図を差し込み、単元の構成と一緒に投入へ組み立て、実データの描画の検査を通して、配る準備を整える。

## 事前条件

- 資格対策の学びが登録簿にあり、教材の世代・図の仕様・図の画像・単元の構成が学びの置き場にある
- 書き直した世代の教材が、教材の門と様式の門を通っている
- 適用される業務規則: BR-025, BR-026, BR-027, BR-028, BR-032, BR-037, BR-048, BR-062

## 主シナリオ

1. 作り手が、書き直した世代の教材に図を差し込む
2. システムが、論点ごとに配る本文と同じ選び方で教材の世代を選び、書き直した世代から選んだ論点の図を図の仕様の差し込み位置に入れる
3. 作り手が、投入を組み立てる
4. システムが、単元の構成が教材の門の止める理由に当たらないことを確かめる → BR-048
5. システムが、書き直した世代を最も新しい世代として配る本文を選び、単元の構成と一緒に投入に組み立てる
6. 作り手が、配る本文の教材を求める
7. システムが、論点ごとに配る本文と同じ選び方で選んだ教材を、選んだ世代と一緒に出す
8. 作り手が、実データの描画の検査をかける
9. システムが、配る本文と同じ選び方で選んだ教材を描き、決めた記法だけが解釈されていることを確かめる → BR-025, BR-026
10. 作り手が、流す前の投入を検査する
11. システムが、組み立てた投入の中身に流す前に止める問題が無いことを確かめる
12. 作り手が、どちらの検査も通ったことを見て、配備に回す

## 事後条件

- 成功時: 作り手が、書き直した世代の論点は書き直した教材と差し込み位置どおりの図で、他の論点は前の世代のまま、単元の構成と一緒に投入に組み立てられ、実データの描画の検査と流す前の投入の検査が通ったことを見ている
- 失敗時: いかなる状態変更も残っていない（部分適用なし。投入を止めたときは投入を書き出さず、図の差し込みが問題を示したときは教材のファイルを 1 つも書き換えない）

## 要件

### REQ-467

- pattern: Event-driven
- status: active

> 作り手が資格対策の学びの投入を組み立てたとき、システムは教材の世代を古い順に重ね、論点ごとに最も新しい世代（同じ世代の中では後のファイル）の教材を配る本文にし、書き直した世代にだけ教材がある論点もその教材を配る本文にする。

#### 検証方針

- **分割クラス**:
  - `#rewritten-topic` — 書き直した世代と前の世代の両方に教材がある論点（書き直した世代の束のファイルが複数でも同じ）
  - `#rewritten-only-topic` — 書き直した世代にだけ教材がある論点
  - `#unrewritten-topic-latest-previous` — 書き直した世代に教材が無い論点（最も新しい前の世代が v3 の論点と v2 の論点。書き直した世代がある学びと無い学びの両方）
  - `#later-file-in-generation` — 同じ世代の中の 2 つのファイルに教材がある論点
- **尽きている根拠**: 論点は教材がある世代の組み合わせで分かれる。最も新しいのが書き直した世代（前の世代にもある／書き直した世代にだけある）か、前の世代のどれか（v3 と v2 の 2 点で、どの世代でも最も新しい物を選ぶことを押さえる）か。どの世代でも、同じ世代の中に 2 つある場合は別に置く。
- **検証しない**: `topicsByGeneration` の数（REQ-471 の図の差し込みと描画の検査の側で見る）。書き直した世代が 2 つ以上ある場合（`materials_v5` 以降。今の学びの置き場に無く、選び方は世代を古い順に重ねる同じ規則）。どの世代にも教材が無い論点（文が決めていない）。

### REQ-468

- pattern: Event-driven
- br: BR-048
- status: active

> 作り手が資格対策の学びの投入を組み立てたとき、単元の構成が 1 つ以上あれば、システムは単元の構成を持つ表を今の単元の構成から作った行だけに入れ替え（単元の構成から無くなった単元の行を残さず）、単元の構成がある単元ごとに全体像、まとまりの名前と説明と順、まとまりの中の論点の学ぶ順、論点ごとの前提の論点を含める。

#### 検証方針

- **分割クラス**:
  - `#overview` — 単元の構成がある単元ごとの全体像
  - `#groups-in-order` — まとまりの名前と説明と、並びの順
  - `#topics-in-learning-order` — まとまりの中の論点の学ぶ順（論点 ID の順と違う並び）
  - `#prerequisites` — 論点ごとの前提の論点と、示す順（前提を 1 つ・2 つ・持たない論点）
  - `#unplanned-unit-absent` — 単元の構成が無い単元（一部の単元だけに構成がある学び）
  - `#replace-removed-unit` — 前の投入にあった単元の構成が今の構成から無くなった DB に、新しい投入を流したとき
- **尽きている根拠**: 文が挙げる 4 つの要素（全体像・まとまり・まとまりの中の順・前提）に 1 クラスずつ置き、文の「単元の構成がある単元ごとに」の外側（構成が無い単元）と、表を今の行だけに入れ替える約束（無くなった単元の行）を 1 クラスずつにする。
- **検証しない**: 一覧と論点の応答に出ること（UC-002 の `structure`・`groupNo`・`prerequisites`・`siblings` の API 側がまだ無いので、投入を流した表を SELECT で見る）。受け持ち（投入に含める要素に入っていない）。他の単元の論点を前提に持つ場合（単元の構成の門が通すかを UC-024 の契約が決めていない）。`units` の数。単元の構成が 1 つも無くなったとき（REQ-472 が持つ）。

### REQ-469

- pattern: Unwanted behaviour
- br: BR-048
- status: active

> 作り手が投入を組み立てるときに、教材の門の止める理由に当たる単元の構成があれば、システムは投入を書き出さずに止め、その単元と理由を示す。

#### 検証方針

- **分割クラス**:
  - `#stop-without-writing` — 止める理由に当たる単元の構成が 1 つあり、他の単元の構成は通るとき（形として読めない・欠けた欄・まとまりに入らない論点・実在しない論点・前提が自分自身）、投入を書き出さない
  - `#show-unit-and-reason` — 同じ入力で、止めた単元と理由を示す
  - `#warning-only-not-stopped` — 警告だけが当たる単元の構成（論点が 3 に届かないまとまり）
  - `#unregistered-learning-before-plan-stop` — 登録簿に無い学びに、止める理由に当たる単元の構成がある（errors の INVALID_INPUT が CONFLICT より先）
- **尽きている根拠**: 単元の構成は「止める理由に当たる／警告だけ／何も当たらない」に分かれ、何も当たらない側は REQ-468 が持つ。止める側は書き出さないことと示すことの 2 つの約束を別に置く。止める理由の種類ごとの判定は UC-024 が持つので、ここは門と同じ判定がかかることを代表の 5 種で見る。
- **検証しない**: 止める理由の全 18 種（判定の正本は UC-024 の門とそのテスト）。示す文言の形（ファイル名と種類の名前が出ることだけを見る）。

### REQ-470

- pattern: Event-driven
- status: active

> 作り手が資格対策の学びの教材に図を差し込んだとき、システムは学びを問わず、どの世代から選んだ論点でも図の仕様に無い図の行を配る本文に残さず、書き直した世代から選んだ論点では図の仕様にある図の行を 1 枚につき 1 行だけ、差し込み位置が短い説明の図は短い説明の末尾に、差し込み位置が見出しの図はその見出しの節の末尾（次の見出しの行の直前、後に見出しが無ければ詳しい解説の末尾）に、同じ差し込み位置の図は図の仕様に並ぶ順に上から置き、前の世代から選んだ論点では図の仕様にある図の置き方（どの図が短い説明にあり、どの図がどの見出しの節にあるかと、その並び）を変えない。

#### 検証方針

- **分割クラス**:
  - `#rewritten-after-explanation` — 書き直した世代から選んだ論点の、差し込み位置が explanation の図
  - `#rewritten-after-heading` — 書き直した世代から選んだ論点の、差し込み位置が detail の見出しの図（学びは IT パスポート）
  - `#rewritten-explanation-end` — 書き直した世代から選んだ論点の、本文のある短い説明を差し込み位置にする図（置き場の中の位置）
  - `#rewritten-heading-end-before-next-heading` — 書き直した世代から選んだ論点の、本文があり後に見出しがある節の見出しを差し込み位置にする図（置き場の中の位置）
  - `#rewritten-heading-end-of-detail` — 書き直した世代から選んだ論点の、本文があり後に見出しが無い節の見出しを差し込み位置にする図（置き場の中の位置）
  - `#rewritten-same-explanation-spec-order` — 書き直した世代から選んだ論点の、短い説明を差し込み位置にする図が 2 枚以上あるときの並び
  - `#rewritten-same-heading-spec-order` — 書き直した世代から選んだ論点の、同じ見出しを差し込み位置にする図が 2 枚以上あるときの並び
  - `#rewritten-existing-line-not-at-end` — 書き直した世代から選んだ論点の本文の、差し込み位置の中の末尾でない所（見出しの行の直後・短い説明の途中）に、図の仕様にある図の行が既にあるとき
  - `#rewritten-existing-line-in-other-place` — 書き直した世代から選んだ論点の本文の、差し込み位置と別の置き場（別の見出しの節・短い説明・詳しい解説）に、図の仕様にある図の行が既にあるとき
  - `#rewritten-existing-lines-in-other-order` — 書き直した世代から選んだ論点の本文の差し込み位置の末尾に、図の仕様にある図の行が図の仕様と違う並びで既にあるとき
  - `#rewritten-existing-line-stale-caption` — 書き直した世代から選んだ論点の本文に、図の仕様にある図の行が図の仕様と違う説明文で既にあるとき（差し込んだあとその図の行は差し込み位置に 1 行だけある）
  - `#rewritten-existing-line-duplicated` — 書き直した世代から選んだ論点の本文に、図の仕様にある同じ図の行が 2 行既にあるとき（差し込んだあとその図の行は差し込み位置に 1 行だけある）
  - `#rerun-same-placement` — 図の差し込みをもう一度かけたとき（置き場と、置き場の中の本文の行と図の行の順が 1 回目と同じ）
  - `#rewritten-unlisted-figure-dropped` — 書き直した世代から選んだ論点の本文にある、図の仕様に無い図の行
  - `#previous-unlisted-figure-dropped` — 前の世代から選んだ論点の本文にある、図の仕様に無い図の行
  - `#no-spec-file-unlisted-dropped` — 図の仕様のファイル（`material_figures/<論点>.json`）が無い論点の本文にある図の行（書き直した世代と前の世代の両方の論点の explanation と detail に置く）
  - `#previous-placement-kept` — 前の世代から選んだ論点の、図の仕様にある図（本文の置き方が図の仕様の差し込み位置と違う。差し込む前の配る本文の置き方と比べる）
  - `#bracket-caption-unlisted-dropped` — 図の説明文に角かっこ（`A[1]`）を含む、図の仕様に無い図の行（書き直した世代と前の世代の両方の論点に置く）
  - `#previous-bracket-caption-placement-kept` — 前の世代から選んだ論点の、図の説明文に角かっこを含む図の仕様にある図（差し込む前の配る本文と同じ節に同じ数だけある）

  - `#indented-unlisted-dropped` — 行頭に空白（半角の空白・タブ・全角の空白）のある、図の仕様に無い図の行（書き直した世代と前の世代の両方の論点の explanation と detail に置く）
