# REQ-468

> 作り手が資格対策の学びの投入を組み立てたとき、単元の構成が 1 つ以上あれば、システムは単元の構成を持つ表を今の単元の構成から作った行だけに入れ替え（単元の構成から無くなった単元の行を残さず）、単元の構成がある単元ごとに全体像、まとまりの名前と説明と順、まとまりの中の論点の学ぶ順、論点ごとの前提の論点を含める。

## 検証方針

- **分割クラス**:
  - `#overview` — 単元の構成がある単元ごとの全体像
  - `#groups-in-order` — まとまりの名前と説明と、並びの順
  - `#topics-in-learning-order` — まとまりの中の論点の学ぶ順（論点 ID の順と違う並び）
  - `#prerequisites` — 論点ごとの前提の論点と、示す順（前提を 1 つ・2 つ・持たない論点）
  - `#unplanned-unit-absent` — 単元の構成が無い単元（一部の単元だけに構成がある学び）
  - `#replace-removed-unit` — 前の投入にあった単元の構成が今の構成から無くなった DB に、新しい投入を流したとき
- **尽きている根拠**: 文が挙げる 4 つの要素（全体像・まとまり・まとまりの中の順・前提）に 1 クラスずつ置き、文の「単元の構成がある単元ごとに」の外側（構成が無い単元）と、表を今の行だけに入れ替える約束（無くなった単元の行）を 1 クラスずつにする。
- **検証しない**: 一覧と論点の応答に出ること（UC-002 の `structure`・`groupNo`・`prerequisites`・`siblings` の API 側がまだ無いので、投入を流した表を SELECT で見る）。受け持ち（投入に含める要素に入っていない）。他の単元の論点を前提に持つ場合（単元の構成の門が通すかを UC-024 の契約が決めていない）。`units` の数。単元の構成が 1 つも無くなったとき（REQ-472 が持つ）。
- **参照先**: `tests/server/UC-027_assemble_generation.test.ts::単元の構成を投入に含め、単元の構成を持つ表を今の構成の行だけに入れ替える（UC-027）`
