# REQ-530

> 作り手が学びの配る本文の教材を求めたとき、登録簿に無い学びを断ると指定して登録簿に無い学びを渡したのでなければ、システムは論点ごとに配る本文と同じ選び方で選んだ教材を、選んだ世代の名前とその教材があったファイルの名前を添え、世代ごとの論点の数とともに出す。

## 検証方針

- **分割クラス**:
  - `#rewritten-over-previous` — 書き直した世代と前の世代の両方に教材がある論点（選んだ教材・世代の名前・ファイルの名前）
  - `#rewritten-only` — 書き直した世代にだけ教材がある論点
  - `#later-file-in-generation` — 同じ世代の 2 つのファイルに教材がある論点
  - `#latest-previous-generation` — 書き直した世代に教材が無い論点（最も新しい前の世代が v3 の論点と v2 の論点）
  - `#topic-order-once` — 出す教材の並びと数（論点の番号の順に、どの世代かの教材がある論点ごとに 1 つ）
  - `#counts-by-generation` — 世代ごとの論点の数
  - `#stopping-plan-still-listed` — 単元の構成の門の止める理由に当たる単元の構成がある学び
  - `#unregistered-listed` — `registered` を渡さない、登録簿に無い学び
  - `#refusal-only-passes` — `registered` と `refusalOnly` を渡した、登録簿にある学び
- **尽きている根拠**: 論点は教材がある世代の組で分かれ（REQ-467 と同じ 4 つ）、論点ごとの選び方をそれぞれ 1 クラスで見る。出すものの全体は、並びと数・世代ごとの論点の数の 2 つ。UC の表で「配る本文の教材を求める」の列は単元の構成の状態に依らずこの要件なので、単元の構成を読まないことを止める理由のある単元の構成で 1 クラス見る（単元の構成が無い・一部だけの状態は選び方を変えない）。登録簿に無い学びは、`registered` を渡さないときだけこの要件の入力なので 1 クラス見る（渡したときの断りは REQ-487）。`refusalOnly` は契約の欄なので 1 クラス置く。
- **境界の扱い**: 同じ世代の中の後のファイルは、名前の順がどの読み方でも同じになる 2 つのファイル（`01-1.json` と `01-2.json`）で見る。世代ごとの論点の数は、学びの置き場の全世代の教材を古い順に重ねた結果と比べる。応答は標準出力の JSON（全体が 1 つ、または最後の行）で読む。
- **検証しない**: 書き直した世代が 2 つ以上ある場合（今の学びの置き場に無い。REQ-467 と同じ）。どの世代にも教材が無い論点（文が決めていない）。
- **参照先**: `tests/server/UC-027_delivered_materials_and_seed_check.test.ts::配る本文の教材を、選んだ世代とファイルの名前を添えて出す（UC-027）`
