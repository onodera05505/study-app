# REQ-529

> 作り手が投入を組み立てたとき、システムは用語集の表を、問題解説の注記と教材から BR-062 の作り方で作った語だけに入れ替える。

## 検証方針

- **分割クラス**:
  - `#choice-note-first-sentence` — 問題解説の選択肢の用語（注記が 2 文以上）の説明
  - `#correct-mark-removed` — 正解の選択肢の用語（注記が正解の印で始まる）の説明
  - `#newest-exam-note` — 古い回と新しい回の問題の両方に選択肢の用語としてある語の説明
  - `#markup-removed` — 注記の 1 文目に用語の記法と強調の記法がある語の説明
  - `#override-brief-and-topic` — 選択肢の用語にもあり、学びの置き場の用語の上書きにもある語（説明と結ぶ論点）
  - `#body-term-filled-from-topic` — 問題解説の本文で用語として示した、説明の無い語で、名前が一致する論点がある語（説明と結ぶ論点）
  - `#body-term-unfilled-absent` — 問題解説の本文で用語として示した、説明の無い語で、名前が一致する論点が無い語
  - `#exact-name-linked` — 論点の名前と完全に一致する選択肢の用語（結ぶ論点）
  - `#partial-name-not-linked` — 論点の名前を含むが一致しない選択肢の用語（結ぶ論点）
  - `#previous-rows-replaced` — 前の投入で用語集の表にあり、今回の作り方では作らない語の行
- **尽きている根拠**: BR-062 の作り方を、語の出どころ（選択肢の用語・上書き・本文で用語として示した語）、同じ語が複数あるときの選び方（回の新しさ）、説明の作り方（1 文目・正解の印・記法）、論点の結び方（完全一致か否か）、入れ替え（作らない語の行が残らない）の軸に分け、軸ごとに文が分ける値に 1 クラスを置く。軸どうしの掛け合わせは取らない（BR が軸ごとに独立に決めている）。本文で用語として示した語は、補えるか補えないかの 2 つで尽きる。
- **境界の扱い**: 説明の末尾の句点の有無は見ない（BR は「1 文目」とだけ決め、句点を残すかを決めていない）。本文で用語として示した語は、問題解説の本文（正解の理由）に置く（教材の本文に置くと、どの世代の本文から拾うかが REQ-530 の選び方と掛け合わさる）。補う論点の短い説明は、前の世代のどれでも同じ 1 文目にする。
- **検証しない**: 別名で一致する論点への結び付けと補い（別名の置き場の値の SSOT が実装にあり、契約と BR から仕込みの形を導けない）。同じ回の中の 2 問に同じ語があるとき（BR が回より細かい順を決めていない）。単元の読み物・問題解説の門が同じ用語集を使うこと（この要件は投入の組み立てだけを持つ）。用語の表示名の括弧書き（REQ-341 が持つ）。
