# REQ-489

> 作り手が流したあとの DB を投入と突き合わせたとき、システムは投入が単元の構成を持つ表を書くときだけその表ごとに DB の行の数を投入の行の数と比べ、一致しない表があればその表と両方の数を示して失敗で終える。

## 検証方針

- **分割クラス**:
  - `#unit-tables-match` — 投入が単元の構成を持つ表を書き、DB の行の数が一致する
  - `#unit-table-count-mismatch` — 投入が単元の構成を持つ表を書き、DB の行の数が 1 つの表で違う
  - `#seed-without-unit-tables-skipped` — 投入が単元の構成を持つ表を書かず、DB にその表の行がある
- **尽きている根拠**: 文は「投入が表を書くとき／書かないとき」で分かれ、書くときは一致か不一致かで尽きる。
- **検証しない**: 本番の DB（`local` を渡さない突き合わせ。外の環境を起こさない。手元の DB も wrangler だけを、SQLite ファイルに流す偽物に差し替えて作る）。単元の構成を持つ表のほかの表の突き合わせ（この文が決めるのは単元の構成を持つ表だけ）。
- **参照先**: `tests/server/UC-027_assemble_generation.test.ts::流したあとの DB を投入と突き合わせ、単元の構成を持つ表は投入が書くときだけ行の数を比べる（UC-027）`
