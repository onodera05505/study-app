# REQ-174

> 存在しないアカウントを指してパスワードの再設定を求められた場合、システムは、いかなるパスワードも入れ替えず、どのセッションも終わらせず、その相手が見つからないことを示す。

## 検証方針

- **分割クラス**:
  - `#reset-unknown-id` — 既にあるどのアカウントの id でもない値を指してパスワードの再設定を求める入力（どのパスワードも入れ替わらず、どのセッションも終わらず、相手が見つからないことが示される。契約の例 `notFound`）
- **尽きている根拠**: 存在しない id を指す求めは、形を満たすパスワードの値によらず同じ応答になるので 1 クラス。入れ替わらないこととセッションが終わらないことは同じ入力の 2 つの観測なので分けない（R-1105）。
- **検証しない**: 形を満たさないパスワードと在らない id を同時に含む求め（契約の errors の順で先に出るのは INVALID_INPUT。REQ-179 の `#invalid-before-not-found`）。
- **参照先**: 単体テストは無い（`tests/portal/` にこの UC のテストが無く、宣言した全クラスが未検証）。本番相当の経路は system suite の `scripts/check_portal_api.py::check_admin_accounts`（まなびばに実際に HTTP で当てる検査。`@covers` の対象外）。
