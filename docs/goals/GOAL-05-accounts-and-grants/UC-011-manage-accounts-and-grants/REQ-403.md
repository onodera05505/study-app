# REQ-403

> 管理者が自分自身のパスワードの再設定を求めた場合、システムは、パスワードを入れ替えず、どのセッションも終わらせず、自分のパスワードはこの操作では変えられないことを示す。

## 検証方針

- **分割クラス**:
  - `#self-reset-rejected` — 呼び出した本人の id を指す再設定の入力（パスワードは入れ替わらず、呼び出した端末と別の端末のセッションも残り、変えられないことが示される。契約の例 `selfReset`）
- **尽きている根拠**: 契約の `resetAccountPassword` の request は id とパスワードだけで、「自分自身」は id が呼び出した本人と一致するか否かの 2 値。一致しない側は REQ-168 が持つので、この要件の入力空間は 1 クラス。入れ替わらないこと・セッションが残ること・示すことは同じ入力の観測なので分けない（R-1105）。
- **境界の扱い**: 契約の errors では形の INVALID_INPUT と自分自身の INVALID_INPUT が隣り合うが同じ code で、先後は応答から観測できない。自分自身の INVALID_INPUT と NOT_FOUND は、自分自身の id が必ず在るので両方の条件を満たす入力が作れず、先後を確かめるクラスは置けない。
- **検証しない**: 断りの文面（R-102）。自分のパスワードを本人が変える経路（UC-014）。
