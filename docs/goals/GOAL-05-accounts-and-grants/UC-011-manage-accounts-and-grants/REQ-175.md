# REQ-175

> 存在しないアカウントを指して削除を求められた場合、システムは、いかなるアカウントも権限も消さず、その相手が見つからないことを示す。

## 検証方針

- **分割クラス**:
  - `#delete-unknown-id` — 既にあるどのアカウントの id でもない値を指して削除を求める入力（どのアカウントも権限も消えず、相手が見つからないことが示される。契約の例 `notFound`）
- **尽きている根拠**: 契約の `deleteAccount` の request は id だけなので、「存在しないアカウントを指す」は 1 クラスで尽きる。消えないことの観測（アカウント・権限）は同じ入力の 2 面。
- **検証しない**: 呼び出した本人の id（REQ-172。契約の errors は INVALID_INPUT が NOT_FOUND より先で、自分の id は必ず在るので両方の条件を満たす入力は作れない）。
- **参照先**: 単体テストは無い（`tests/portal/` にこの UC のテストが無く、宣言した全クラスが未検証）。本番相当の経路は system suite の `scripts/check_portal_api.py::check_admin_accounts`（まなびばに実際に HTTP で当てる検査。`@covers` の対象外）。
