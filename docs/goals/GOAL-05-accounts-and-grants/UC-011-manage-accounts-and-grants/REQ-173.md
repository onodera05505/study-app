# REQ-173

> 存在しないアカウントを指して名前・役割・権限の更新を求められた場合、システムは、いかなるアカウントの項目も権限も変えず、その相手が見つからないことを示す。

## 検証方針

- **分割クラス**:
  - `#update-unknown-id` — 既にあるどのアカウントの id でもない値を指して名前・役割・開ける学びを送る入力（どのアカウントの項目も権限も変わらず、相手が見つからないことが示される。契約の例 `notFound`）
- **尽きている根拠**: 契約の `id` は `minLength: 1` だけを決めるので、「存在しないアカウントを指す」は形の違いで分かれず 1 クラス。送る項目の組み合わせによらず同じ応答になり、組み合わせの分割は REQ-165 が持つ。
- **境界の扱い**: 形は妥当だが在らない id と、どのアカウントの id でもない任意の文字列は同値（R-102。値の正本は契約とまなびばの検証スキーマ）。
- **検証しない**: 項目の形も満たさない求め（契約の errors の順で先に出るのは INVALID_INPUT。REQ-178 の `#invalid-before-not-found`）。経路に id が無い呼び出し（契約の `wire` の経路に当たらず、この operation に届かない）。
- **参照先**: `tests/portal/repay_UC-011_manage_accounts.test.ts` の describe「REQ-173〜175 存在しない相手」（全クラス）。本番相当の経路は system suite の `scripts/check_portal_api.py::check_admin_accounts`（まなびばに実際に HTTP で当てる検査。`@covers` の対象外）。
