# REQ-474

> 資格対策の学びで利用者が単元を選んだとき、システムはその単元に属する論点を BR-031 に従った並びで、論点ごとの出題頻度と理解度を添えて示す。

## 検証方針

- **分割クラス**:
  - `#structured-order` — 単元の構成を持つ単元を選んだ入力（まとまりの順、まとまりの中は学ぶ順。並べ替えを省いても同じ）
  - `#unstructured-order` — 単元の構成を持たない単元を選んだ入力（小項目の番号の順、小項目の中は出題頻度の降順、同じ頻度は論点の ID の順）
  - `#shown-as-received` — 単元を選んだ画面の入力（単元の構成の並びを求め、返った並びを出題頻度の順などに並べ替えずに示す）
  - `#frequency-and-status-shown` — 理解度の段階が違う論点（未を含む）を持つ単元を選んだ画面の入力（行ごとに出題頻度の数と段階の名前を添える）
  - `#selected-unit-only-after-late-response` — 単元を選んだあと別の単元に移り、移った先の論点を示したあとで前の単元の一覧の応答が返った画面の入力（示す論点は移った先の単元に属する物だけのまま）
- **尽きている根拠**: BR-031 の並びは単元の構成の有無で 2 つの規則に分かれ、それぞれをサーバの境界で 1 クラスずつ見る。並びを決めるのはサーバで、画面は返った並びを崩さないことだけが観測になるので 1 クラス。示す論点が「選んだ単元に属する」ことは、単元を 1 つだけ選んだ画面では返った論点がそのまま当たり、単元を移ったあとに前の単元の応答が遅れて返るときだけ別の単元の論点が紛れ込みうるので、その移り変わりを 1 クラスで見る。添える物は出題頻度と理解度の 2 つで、どの論点でも同じ形で添うので 1 クラス。段階そのものの求め方は REQ-480・REQ-482（BR-049・BR-050）、まとまりと小項目の見出しは REQ-475・REQ-476、印は REQ-478 が持つ。
- **境界の扱い**: 構成を持たない単元では、出題頻度が同じ論点を ID の順が逆になるように置き、ID の順の境目を見る。
- **検証しない**: 単元を絞らない一覧の並び（単元の番号の順。UC-002 の論点の一覧は単元を選んで入るので、この要件の入力に現れない）。ロードマップ型の学びの並び（要件が資格対策に限る）。論点が 0 件の単元（REQ-028 の側で、0 件の示し方は要件が決めていない）。
