# REQ-021

> 利用者が理解度の絞り込みを選び直したとき、システムは論点の一覧を、その絞り込みで、BR-031 に従った並びを保ったまま示し直す。

## 検証方針

- **分割クラス**:
  - `#refilter-status` — 理解度の絞り込みを、1 つ以上選んだ別の組み合わせへ選び直した入力（その組み合わせで取り直し、外した段階の論点が消える）
  - `#unanswered-selectable` — 資格対策で、理解度の絞り込みを未だけに選び直した入力（BR-029 の未を絞り込みで選べる）
  - `#order-kept` — 絞り込みで一部の論点が外れる選び直しの入力（残った論点が BR-031 の並びのままで、画面が別の並べ替えを求めない）
- **尽きている根拠**: 選び直しの観測は「何で取り直すか」「何が残るか」「どの順で残るか」の 3 つで、前の 2 つは組み合わせの違いで同じ形をとるが、未だけは資格対策で未理解と別に選べることが BR-029 の決める点なので分ける。並びは画面（返った並びを崩さない）とサーバ（絞っても BR-031 の並びで返す）の両方に 1 本ずつ置く。理解度を 1 つも選ばない選び直しは REQ-022、取れなかった場合は REQ-027 が持つ。
- **検証しない**: 単元を絞らない一覧の並び（UC-002 の論点の一覧は単元を選んで入るので、この要件の入力に現れない）。おすすめ順を選んだときの並び（BR-030 の並びで、次に学ぶを持つ UC が持つ）。
- **参照先**: `tests/client/repay_UC-002_topics.test.tsx::論点の一覧（UC-002）`（`#refilter-status`）、`tests/client/UC-002_unit_structure.test.tsx::理解度の絞り込みを選び直したとき（UC-002）`（`#unanswered-selectable`・`#order-kept`）、`tests/server/UC-002_unit_structure_api.test.ts::理解度の絞り込みを選び直したときの並び（GET /api/topics。UC-002）`（`#order-kept`）
