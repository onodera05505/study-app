# REQ-479

> 資格対策の学びで利用者が論点を選んだとき、システムはその論点の教材とともに、前提の論点を単元の構成に書かれた順に名前つきで、その論点の教材へ移る導線として示し、前提の論点を持たない論点では前提の論点の欄を示さない。

## 検証方針

- **分割クラス**:
  - `#prerequisites-in-plan-order` — 前提の論点を 2 つ持つ論点と、別の単元の論点を前提に持つ論点の教材を求めた入力（単元の構成に書かれた順に、名前と ID つきで返す）
  - `#prerequisite-links` — 前提の論点を持つ論点の教材を示した画面の入力（教材とともに、渡された順に名前つきで、その論点の教材へ移る導線を示す）
  - `#no-prerequisites-no-section` — 前提の論点を持たない論点の教材を示した画面の入力（教材を示し、前提の論点の欄を示さない）
- **尽きている根拠**: 選んだ論点は前提の論点を持つか持たないかの 2 つ。持つ論点では、前提の順を決めるのはサーバ（単元の構成の順）で、画面は渡された前提を渡された順で導線にするだけなので、境界と画面に 1 クラスずつ。持たない論点は欄を示さないことを画面で 1 クラス見る（契約は空の配列を渡す）。前提の数の上限は契約の `prerequisites` の型が持つ。
- **境界の扱い**: 単元の構成に書かれた順を、論点の ID の順とも名前の順とも逆になるように置く。
- **検証しない**: ロードマップ型の学び（要件が資格対策に限り、契約はロードマップ型で空の配列を返す）。
