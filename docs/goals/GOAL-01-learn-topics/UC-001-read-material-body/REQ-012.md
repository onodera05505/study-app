# REQ-012

> 用語集を取得できなかった場合、システムはそれを空の用語集として扱い、本文は出す。

## 検証方針

- **分割クラス**:
  - `#fetch-failed-empty-glossary` — 用語集の取得が失敗した状態（空の用語集として扱い、用語を押せる語にせず本文を出す）
- **尽きている根拠**: 取得の結果は成功と失敗の 2 つで、成功は REQ-002・REQ-007 が持つ。失敗は理由（通信が届かない・5xx・本文が読めない）が変わっても空の用語集として扱う振る舞いが同じなので 1 クラス。未取得との区別は REQ-005 が持つ。
- **検証しない**: 失敗の理由ごとの違い（どの理由でも空の用語集として扱う）。失敗を利用者に知らせる文言（要件は本文を出すことまでを言う）。取り直さないこと（REQ-001 が持つ）。
- **参照先**: `tests/client/glossary.test.ts::用語集の取得（UC-001）`
