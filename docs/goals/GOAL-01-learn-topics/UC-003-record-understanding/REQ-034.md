# REQ-034

> 利用者が論点に理解度の段階を選んだとき、システムは、その利用者のその論点の理解度の記録を選ばれた段階だけとし、同じ論点に続けて記録が届いたときは最後に届いた段階だけを残す。

## 検証方針

- **分割クラス**:
  - `#record-chosen-stage` — 3 段階のいずれかを選んだとき、その論点の理解度の記録が選ばれた段階になる（回答の無い論点なので示す段階もそれになる）
  - `#overwrite-keeps-last` — 同じ論点に続けて記録が届いたとき、以前の段階が残らず最後の段階だけになる
  - `#rerecord-after-answer-takes-effect` — 記録より後の回答で判定に戻った論点に記録し直すと、記録は 1 件のまま新しい記録になり、再び本人の上書きとして効く
- **尽きている根拠**: 記録の入力は「選ばれた段階が 3 段階の中か外か」（外は REQ-036）と「その論点に以前の記録があるか」の 2 軸で、以前の記録がある側は、その記録がまだ効いているか（`#overwrite-keeps-last`）、後の回答で効かなくなっているか（`#rerecord-after-answer-takes-effect`）で分かれる。後者は、記録を置き換えずに段階だけを書き換えると以前の記録の時刻が残り、記録し直しても効かないことを分ける。
- **境界の扱い**: 3 段階の端（未理解・理解）は `#record-chosen-stage` の値の変種として扱う。外側の最近傍は REQ-036 が持つ。
- **検証しない**: 未認証の要求を拒むことは BR-001 の範囲（UC.md 例外系の走査）。記録を 1 件に保つ仕組み（表の制約）の在処はスキーマの正本が持つ。記録と回答の前後で示す段階が決まることは REQ-482 が持つ。
- **参照先**: `tests/server/repay_UC-003_record_understanding.test.ts::理解度の記録が残ること（UC-003）`（`#record-chosen-stage`・`#overwrite-keeps-last`）、`tests/server/UC-003_judged_understanding.test.ts::理解度の記録し直し（UC-003）`（`#rerecord-after-answer-takes-effect`）
