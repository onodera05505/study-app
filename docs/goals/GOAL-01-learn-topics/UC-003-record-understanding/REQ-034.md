# REQ-034

> 利用者が論点に理解度の段階を選んだとき、システムは、その利用者のその論点の理解度を選ばれた段階だけとし、同じ論点に続けて記録が届いたときは最後に届いた段階だけを残す。

## 検証方針

- **分割クラス**:
  - `#record-chosen-stage` — 3 段階のいずれかを選んだとき、その論点の理解度が選ばれた段階になる
  - `#overwrite-keeps-last` — 同じ論点に続けて記録が届いたとき、以前の段階が残らず最後の段階だけになる
- **尽きている根拠**: 記録の入力は「選ばれた段階が 3 段階の中か外か」（外は REQ-036）と「その論点に以前の記録があるか」の 2 軸だけで、初回も上書きも事後条件は「選ばれた段階だけが残る」1 つに落ちる。続けて届いた複数の記録も、最後の 1 件についての上書きとして `#overwrite-keeps-last` に入る。
- **境界の扱い**: 3 段階の端（未理解・理解）は `#record-chosen-stage` の値の変種として扱い、クラスを増やさない。外側の最近傍は REQ-036 が持つ。
- **検証しない**: 未認証の要求を拒むことは BR-001 の範囲（UC.md 例外系の走査）。記録を 1 件に保つ仕組み（表の制約）の在処はスキーマの正本が持つ。
- **参照先**: 被覆するテストが無い（偽の D1 では記録の結果を観測できず、`scripts/check_api.py` も既存の記録を守るため理解度を書かない）。
