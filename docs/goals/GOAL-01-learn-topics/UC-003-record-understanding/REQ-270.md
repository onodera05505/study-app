# REQ-270

> 利用者が本人として学びを使ったとき、システムはその日を本人が学びを開いた日として、同じ日につき高々 1 件だけ記録する。

## 検証方針

- **分割クラス**:
  - `#first-use-of-day` — 学びを開いた日の記録がまだ 1 件も無い状態で本人として学びを使う（その日が 1 件記録される）
  - `#same-day-again` — 同じ日に重ねて使う（その日の記録が 2 件にならない）
  - `#next-day` — 前の日の記録があり今日の記録が無い状態で使う（前の日の記録を残したまま、今日が 1 件増える）
- **尽きている根拠**: UC.md の表の 2 状態（今日の分をまだ記録していない／記録している）のうち、まだ記録していない側を前の日の記録の有無で 2 つに分けた 3 つ。どの画面を開いたかは記録の件数を分けない。
- **境界の扱い**: 暦日の切れ目（契約の `getHomeSummary` の `visits.today` が日本時間の暦日と決めている）が「同じ日」と「別の日」の境目。今日は応答の `visits.today` から採り、前の日の記録はその前の暦日として置く。
- **検証しない**: 未認証の求め（BR-001）。記録の置き場所と列の形（R-102）。記録から算出する値（REQ-271）。時計を進めて暦日の切れ目そのものを跨ぐこと（今日の値の正本は応答の `visits.today` で、前の日の記録を置くことで同じ入力になる）。
