# REQ-042

> 利用者が論点の一覧をおすすめ順で求めたとき、システムは、BR-030 に従い、まだ理解していない論点を先に、理解にした論点を一覧から除かずに最後に並べて返す。

## 検証方針

- **分割クラス**:
  - `#understood-not-removed` — おすすめ順の一覧に、理解にした論点も残る
  - `#not-understood-first` — まだ理解していない論点（未理解・やや理解・記録なし）がすべて先に、理解にした論点がすべて最後に並ぶ（頻度の順なら先頭に来る論点を理解にした入力で）
  - `#not-understood-one-order` — まだ理解していない論点は、未理解・やや理解・記録なしを分けず、その学びの種類の並びの 1 つの並びになる
  - `#understood-follow-learning-type` — 理解にした論点どうしも、最後の塊の中でその学びの種類の並びに従う（全件を理解にした場合も含む）
- **尽きている根拠**: 入力は一覧に入る論点それぞれの理解度（理解・やや理解・未理解・記録なし。記録なしは未理解として扱う。BR-029）と、学びの種類の並びでの位置だけ。理解度は「理解」と「まだ理解していない」の 2 群に分かれ（BR-030）、群の間の順（先と最後）・まだ理解していない群の中の順・理解の群の中の順・除かないこと、の 4 つで並びが一意に決まる。記録が 1 つも無い／全件を理解にした の両端は、群の中の順のクラスの値の変種に入れる。
- **境界の扱い**: 論点は ID の順・名前の順・記録した順・出題頻度の順が互いに一致しないように置き、群の中の順がどれか 1 つの順でたまたま緑にならないようにする。未理解とやや理解を分けると並びが変わる組（出題頻度の最も高い論点を未理解、2 番目と最も低い論点をやや理解）を置く。
- **検証しない**: 出題頻度が同じ論点どうしの順（BR-030・BR-031 が決めていない）。受け付ける並べ替えの値の検証と一覧そのものの形は UC-002 の listTopics の範囲（この UC の contract.yaml の但し書き）。過去問の紐づかない論点の位置（一覧に入るかどうかは UC-002 の範囲）。ロードマップ型の学ぶ順は GOAL-03 の範囲。実データでの実際の並びは `scripts/check_api.py` が本番相当で見る。
