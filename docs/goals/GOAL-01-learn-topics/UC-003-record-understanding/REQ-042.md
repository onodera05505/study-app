# REQ-042

> 利用者が論点の一覧をおすすめ順で求めたとき、システムは、理解にした論点を一覧から除かず、理解度の低い論点を先に、同じ理解度の中ではその学びの種類の並びに従って並べて返す。

## 検証方針

- **分割クラス**:
  - `#understood-not-removed` — おすすめ順の一覧に、理解にした論点も残る
  - `#low-understanding-first` — 理解度の低い論点が先に並ぶ（記録の無い論点は未理解として並ぶ）
  - `#same-stage-follows-learning-type` — 同じ理解度の中は、その学びの種類の並びに従って並ぶ
- **尽きている根拠**: おすすめ順の入力は、一覧に入る論点の理解度（3 段階と記録なし＝未理解。BR-029）と、同じ理解度の中の並びの 2 軸だけで、除かないことと 2 軸の並びで尽きる。
- **検証しない**: 受け付ける並べ替えの値の検証と一覧そのものの形は UC-002 の listTopics の範囲（この UC の contract.yaml の但し書き）。ロードマップ型の学ぶ順は GOAL-03 の範囲。実データでの実際の並びは `scripts/check_api.py` が本番相当で見る。
- **参照先**: 被覆する単体のテストが無い（並びの観測には実データが要る）。
