# REQ-042

> 利用者が論点の一覧をおすすめ順で求めたとき、システムは、BR-030 に従い、まだ理解していない論点を先に、理解にした論点を一覧から除かずに最後に並べて返す。

## 検証方針

- **分割クラス**:
  - `#understood-not-removed` — おすすめ順の一覧に、理解にした論点も残る
  - `#not-understood-first` — まだ理解していない論点（未理解・やや理解・記録なし）がすべて先に、理解にした論点がすべて最後に並ぶ（頻度の順なら先頭に来る論点を理解にした入力で）
  - `#not-understood-one-order` — まだ理解していない論点は、未理解・やや理解・記録なしを分けず、その学びの種類の並びの 1 つの並びになる
  - `#understood-follow-learning-type` — 理解にした論点どうしも、最後の塊の中でその学びの種類の並びに従う（全件を理解にした場合も含む）
  - `#tie-by-field` — 資格対策の学びで出題頻度が同じで分野が違う論点どうしは、シラバスの分野の順に並ぶ（まだ理解していない塊・理解にした塊のどちらでも）
  - `#tie-by-item` — 出題頻度と分野が同じで項目が違う論点どうしは、シラバスの項目の順に並ぶ
  - `#tie-by-id` — 出題頻度と項目が同じ論点どうしは、論点の ID の順に並ぶ
- **尽きている根拠**: 入力は一覧に入る論点それぞれの理解度（理解・やや理解・未理解・記録なし。記録なしは未理解として扱う。BR-029）と、学びの種類の並びでの位置だけ。理解度は「理解」と「まだ理解していない」の 2 群に分かれ（BR-030）、群の間の順（先と最後）・まだ理解していない群の中の順・理解の群の中の順・除かないこと、の 4 つで並びが一意に決まる。記録が 1 つも無い／全件を理解にした の両端は、群の中の順のクラスの値の変種に入れる。資格対策の並びの中の順は、2 つの論点の出題頻度が違うか、同じなら分野・項目・ID のどこで初めて違うかで尽き（BR-031）、出題頻度が違う組は上の 4 クラスが見る。同じ項目の論点は同じ分野にあるので、組はこの 3 つの段のどれか 1 つに必ず入る。
- **境界の扱い**: 分野と項目の順の期待値は、正本の `data/<学びの key>/syllabus.json` の項目をそのまま仕込んで、分野が初めて現れる順・項目の number の順で組む。分野の順が違う 2 つの学び（ip はストラテジ系が先、ap はテクノロジ系が先。ap の登録簿の分野の並びはストラテジ系が先）で同じ検査を回し、分野の名前の文字の順・登録簿の分野の並び・一方の学びの順の決め打ちでは緑にならないようにする。同頻度の論点は ID の順・名前の順が期待の順と一致しないように置き、頻度の最も高い論点を期待の最後の項目に、最も低い論点を先頭の項目に置いて頻度が先に効くことも同じ入力で見る。論点は ID の順・名前の順・記録した順・出題頻度の順が互いに一致しないように置き、群の中の順がどれか 1 つの順でたまたま緑にならないようにする。未理解とやや理解を分けると並びが変わる組（出題頻度の最も高い論点を未理解、2 番目と最も低い論点をやや理解）を置く。
- **検証しない**: 項目の順と分野の順が食い違うシラバス（今のシラバスはどの学びも分野ごとに項目が続いて並び、分野の順で並べた結果と項目の順で並べた結果が同じになる）。受け付ける並べ替えの値の検証と一覧そのものの形は UC-002 の listTopics の範囲（この UC の contract.yaml の但し書き）。過去問の紐づかない論点の位置（一覧に入るかどうかは UC-002 の範囲）。ロードマップ型の学ぶ順は GOAL-03 の範囲。実データでの実際の並びは `scripts/check_api.py` が本番相当で見る。
