# REQ-268

> 論点の ID が整数として読めない求めで理解度の記録を求められた場合、システムは理解度を記録せず、求めが受け付けられなかったことを示す。

## 検証方針

- **分割クラス**:
  - `#non-integer-id-rejected` — 論点の ID が整数として読めない求め（英字・小数・数字の後ろに文字が続く表記。先頭の数字だけを読めば在る論点になる表記を含む。理解度が残らず、受け付けられなかったことが示される）
  - `#before-not-found` — ID が整数として読めず、その ID の論点も無いことになる求め（契約の `errors` の並びどおり、受け付けの拒みが先に立つ）
- **尽きている根拠**: 契約の `recordUnderstanding` の経路の id は「整数として読める」「読めない」の 2 つに尽き、読める側は REQ-034・REQ-037 が持つ。読めない側の自由度は、同時に成り立つ他の失敗条件（その ID の論点が無い）があるかどうかだけ。
- **境界の扱い**: 整数として読める表記が内側（REQ-034・REQ-037 の範囲）で、その外側がこの要件の側。数字で始まり文字が続く表記は外側。
- **検証しない**: 未認証が先に立つこと（契約の `errors` の並びが正本。R-1207。拒み自体は BR-001）。3 段階の外の値（REQ-036）。存在しない論点（REQ-037）。示す文言（要件が決めていない）。
- **参照先**: `tests/server/repay_UC-003_record_understanding.test.ts::整数として読めない論点の ID（UC-003）`
