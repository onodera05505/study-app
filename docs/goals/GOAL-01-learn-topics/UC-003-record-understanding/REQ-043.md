# REQ-043

> 利用者が次に学ぶの候補を求めたとき、システムは、過去問が紐づく論点だけを候補とし、その学びの種類の並びに従った順で返す。

## 検証方針

- **分割クラス**:
  - `#only-topics-with-questions` — 過去問が紐づかない論点は候補に入らない
  - `#order-follows-learning-type` — 候補の順が、その学びの種類の並びに従う
- **尽きている根拠**: 候補に入るかは「過去問が紐づくか」の二分（まだ理解していないことは BR-030 の定義で、候補が尽きた状態は REQ-046 が持つ）で、入った候補の観測点は順だけ。
- **検証しない**: 実データでの実際の並びと件数は `scripts/check_api.py` が本番相当で見る。ロードマップ型の学ぶ順は GOAL-03 の範囲。候補の上限の値は契約の `nextTopics` が持つ。
- **参照先**: 被覆する単体のテストが無い（並びの観測には実データが要る）。
