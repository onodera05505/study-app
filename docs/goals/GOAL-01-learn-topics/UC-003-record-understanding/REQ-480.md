# REQ-480

> 資格対策の学びでは、システムは論点の画面・論点の一覧の行・分野と単元の集計・理解度の絞り込み・次に学ぶの候補のすべてで、BR-049 と BR-050 に従いその時点の回答の履歴と理解度の記録から求めた同じ段階を、その論点の理解度として使う。

## 検証方針

- **分割クラス**:
  - `#list-row-same-as-detail` — 論点の一覧の行が、どの論点でも論点の画面と同じ段階を示す
  - `#filter-same-stage` — 理解度の絞り込み（未・未理解・やや理解・理解とその組）が、論点の画面と同じ段階で論点を選ぶ
  - `#aggregate-same-stage` — 分野と単元の集計とホームの集計が、論点の画面と同じ段階で論点を数える
  - `#next-candidates-same-stage` — 次に学ぶの候補・論点の画面の次に学ぶ・おすすめ順が、論点の画面と同じ段階で理解の論点を分ける
- **尽きている根拠**: 文が並べる使い場所（論点の画面・一覧の行・集計・絞り込み・次に学ぶ）ごとに 1 クラスで、論点の画面を基準にほかの使い場所が一致するかを見る。入力は、段階の決まり方の全種（未・判定の未理解・やや理解・理解・効いている上書き（判定より上と下）・後の回答で失効した上書き・締める前の模試の回答・他の利用者の回答と記録）を 1 つの仕込みに混ぜて全クラスで回す。段階の求め方そのものは REQ-482・REQ-484 が持つ。
- **検証しない**: ロードマップ型の学び（文の範囲外。GOAL-03）。実データでの件数（`scripts/check_api.py`）。
- **参照先**: `tests/server/UC-003_judged_understanding.test.ts::理解度はどこでも同じ段階（UC-003）`
