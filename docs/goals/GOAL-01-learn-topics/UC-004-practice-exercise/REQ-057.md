# REQ-057

> 進行中のテストがあるのに利用者が新しい演習を始めようとした場合、システムは、新しいテストを作らず、進行中のテストの範囲と回答の進み具合を示す。

## 検証方針

- **分割クラス**:
  - `#conflict-when-in-progress` — 進行中のテストがあるのに始めようとしたとき、作らず、進行中のテストの範囲と回答の進み具合を示す
  - `#in-progress-fetch-failed` — 作れなかったあとに進行中のテストそのものを取れなかったとき、範囲と進み具合の代わりに再開か破棄へ進める案内と、取得の失敗（理由・読み直す手段）を示す（BR-017・BR-014）
- **尽きている根拠**: 始めようとしたときの状態は進行中のテストがあるか無いかに尽き、無い側は REQ-050 が持つ。ある側で示す物は、断られたあとに進行中のテストを取り直せたか（範囲と進み具合）取れなかったか（案内と取得の失敗）の 2 つに尽きる（BR-017）。
- **検証しない**: 画面側で入口を押せなくすること（REQ-056 が持つ）。
- **参照先**: `tests/server/repay_UC-004_sessions.test.ts`::演習の開始（作らないこと）、`tests/client/repay_UC-004_practice.test.tsx::練習テストの画面（UC-004。単元の一覧の失敗と、進行中があるのに始めようとしたとき）`（進行中の範囲と進み具合を示すこと・in-progress-fetch-failed）
