# REQ-066

> 同じ問題への回答が続けて、または同時に 2 回以上送られた場合、システムは、最初に記録した 1 件だけを残し、ほかの回答は受け付けずに断る。

## 検証方針

- **分割クラス**:
  - `#duplicate-answer-kept-once` — 同じ問題への回答が続けて 2 回以上送られても、残る回答は最初の 1 件だけで、2 回目は受け付けずに断る
  - `#concurrent-answer-first-only` — 同じ問題への回答が同時に 2 つ届いても、受け付けるのは最初に記録した 1 件だけで、ほかは断り、残る回答もその 1 件（演習と模試の両方を値の変種に持つ）
- **尽きている根拠**: 同じ問題への 2 回目以上の回答は、前の回答が記録されたあとに届く（続けて）か、記録される前に重なって届く（同時に）かに尽きる。1 回だけの側は REQ-061（演習）と REQ-113（模試）が持つ。
- **境界の扱い**: 同時の側は、2 つの要求の D1 への読み書きを 1 回ずつ交互に通し、両方が「まだ答えていない」を読んでから書き込む最も重なった順で見る（同期の SQLite に並べるだけでは重ならない）。どちらが先に記録されても「受け付けた側の選択肢が残る」で見る。
- **検証しない**: 画面が送信中と判定後に 2 回目の送信を抑えること（同じ要求を起こさせない側で、REQ-061 の `#send-current-idx-and-choice` のテストが併せて観測している）。断る理由の内訳（契約 `answerQuestion` の `CONFLICT` は本文が区別しない）。
- **参照先**: `tests/server/repay_UC-004_sessions.test.ts::回答（POST /api/sessions/:id/answer。UC-004）`（duplicate-answer-kept-once）、`tests/server/UC-004_sessions_sqlite.test.ts::同じ問題への同時の回答（POST /api/sessions/:id/answer。UC-004）`（concurrent-answer-first-only）
