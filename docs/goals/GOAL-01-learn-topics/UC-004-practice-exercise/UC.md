# UC-004 範囲を選んで演習を解き、問題解説を読む

## 概要

利用者が演習の種別（論点ドリル・分野別演習・単元演習・弱点復習）と範囲を選び、出題された過去問を
1 問ずつ解き、回答ごとに問題解説を読んで、正答数が確定するまでを 1 回で終える。

## 事前条件

- 利用者が学びの権限を持ってログインしている
- 過去問が投入され、論点・単元・分野に紐づいている
- 進行中のテストが無い
- 論点ドリルは、論点を開いた状態から始まる
- 適用される業務規則: BR-005, BR-014, BR-015, BR-017, BR-018, BR-019, BR-020, BR-021, BR-022, BR-023, BR-024, BR-028, BR-034

## 主シナリオ

1. 利用者が練習テストを開く
2. システムが選べる範囲（分野と、分野を選んだあとの単元）と、進行中のテストの有無を出す
3. 利用者が範囲を選んで演習を始める
4. システムが範囲に合う過去問から出題を組み、範囲の名前と問題数を示す
5. システムが未回答のうち最も小さい位置の問題を、問題文・選択肢・回答済みの問題数と問題数とともに出す（正解と問題解説はまだ出さない）
6. 利用者が選択肢を 1 つ選ぶ
7. システムが正誤と正解の選択肢を示し、その問題の問題解説を出す
8. 利用者が次の問題へ進み、未回答が無くなるまで 5〜7 を繰り返す
9. システムが正答数を確定して演習を完了にし、結果を出す

## 要件

### REQ-048

- pattern: Event-driven
- br: BR-015
- status: active

> 利用者が練習テストを開いたとき、システムは、選べる分野と、選んだ分野の単元を演習の範囲として示す。

#### 検証方針

- **分割クラス**:
  - `#fields-listed` — 範囲の一覧に選べる分野が並び、そこから分野を選べる
  - `#categories-after-field` — 分野を選んだときだけ、その分野の単元が選べる形で出る（選んだだけでは始まらない）
- **尽きている根拠**: 示すものは「選べる分野」「選んだ分野の単元」の 2 段で、分野を選ぶ前と選んだ後の両方を見ている。
- **検証しない**: 進行中のテストがあるかどうかの表示（同じ振る舞いを UC-006 の REQ-087 が持ち、練習テストの画面の案内のテストはそちらに属する。要件の重複として報告済み）。単元の一覧の取得が失敗したとき（REQ-244 が持つ）。

### REQ-049

- pattern: Unwanted behaviour
- br: BR-014, BR-015
- status: active

> 範囲の一覧と進行中のテストの有無のいずれかが取得できない場合、システムは、BR-014 に従い、取得できた側はそのまま示し、取得できなかった側の取得の失敗を示す。

#### 検証方針

- **分割クラス**:
  - `#fields-failed` — 範囲の一覧だけが取れないとき、その側に取得の失敗（失敗した旨・理由・読み直す手段。BR-014）だけを出し、進行中の側は取れたまま示す
  - `#current-failed` — 進行中の有無だけが取れないとき、その側に取得の失敗（失敗した旨・理由・読み直す手段。BR-014）を出し、範囲の一覧は出す
- **尽きている根拠**: 取得は範囲の一覧と進行中の有無の 2 つで、片側ずつ落ちる場合を両方見ている。両方落ちる場合は、独立した 2 つの表示が重なるだけで新しい振る舞いを作らない。
- **検証しない**: 両方が同時に取れない組み合わせ（上の理由）。取り直しの結果（成功したときの表示は `#fields-listed` と同じ経路）。

### REQ-050

- pattern: Event-driven
- status: active

> 進行中のテストが無い状態で利用者が演習の種別と範囲を選んで始めたとき、システムは、進行中のテストを 1 つ作り、その範囲の名前と問題数を示す。

#### 検証方針

- **分割クラス**:
  - `#start-middle` — 単元を選んだとき、その単元を範囲として 1 つ作ることを頼む
  - `#start-field-and-review` — 分野と弱点復習を選んだとき、それぞれの種別と範囲で 1 つ作ることを頼む
  - `#scope-label-and-count` — 作ったテストの範囲の名前と問題数が、種別ごとの形で返る
- **尽きている根拠**: 練習テストの画面から始められる種別は分野別演習・単元演習・弱点復習の 3 つで、範囲を伴う種別（単元）と伴わない／分野だけの種別を分けて見ている。
- **検証しない**: 論点ドリルの開始（論点を開いた状態から始まる経路で、その画面のテストは UC-002 側のファイルに属する）。作ったテストが 1 つに限られること（REQ-056・REQ-057 が持つ）。

### REQ-051

- pattern: Ubiquitous
- br: BR-005
- status: active

> システムは、演習の出題を選んだ範囲に紐づく過去問だけから組み、その件数を、要求が問題数を指定するときはその数以下に、指定しないときは BR-005 の正本が定める既定の問題数以下に収める。

#### 検証方針

- **分割クラス**:
  - `#scope-drill` — 論点ドリルは、選んだ論点に紐づく過去問だけを範囲にする
  - `#scope-field-middle` — 分野別演習・単元演習は、その分野／単元に紐づく過去問だけを範囲にする
  - `#size-requested-cap` — 要求が問題数を指定し、範囲の過去問がそれより多いとき、出題の件数は指定の数で止まる
  - `#size-default-cap` — 論点ドリルで要求が問題数を指定せず、範囲の過去問が既定の問題数より多いとき、出題の件数は `app_settings` の既定の問題数で止まる
  - `#size-default-cap-registry` — 分野別演習・単元演習・弱点復習で要求が問題数を指定せず、範囲の過去問が既定の問題数より多いとき、出題の件数は登録簿の学びの既定の問題数で止まる（契約 `startSession` の `size` の省略時）
- **尽きている根拠**: 範囲の決め方は種別ごとの 3 通りに尽き、件数の上限は要求が問題数を指定するか（指定の数）しないか（既定の数）の 2 通りに尽き、既定の数の正本は論点ドリル（`app_settings`）とそれ以外の演習（登録簿）の 2 つに尽きる。
- **境界の扱い**: 件数は「範囲が上限より多い」側で見る。少ない側は範囲の全件がそのまま出るだけで、上限が効かない（REQ-050 の `#scope-label-and-count` が組めた数を見る）。既定の問題数は 2 つの値で見て、値の決め打ちと区別する。
- **検証しない**: 範囲に紐づかない過去問が混ざらないことを本物のデータで確かめること（出題を組む条件の発行で見ており、投入済みのデータとの突き合わせは本番相当の API の検査が持つ）。既定の問題数の値そのもの（正本は `app_settings` と登録簿。R-102）。

### REQ-052

- pattern: Ubiquitous
- br: BR-019
- status: active

> システムは、演習の出題を、定着した問題を除いた範囲の過去問から組む。

#### 検証方針

- **分割クラス**:
  - `#mastered-excluded` — 範囲の一部が定着した問題のとき、その問題を出題から外す
  - `#mastered-all-fallback` — 範囲の全部が定着した問題のとき、外さずそのまま出す
- **尽きている根拠**: 定着した問題が範囲に無い・一部ある・全部であるの 3 通りに尽き、無い場合は除外が働かない対照（`#mastered-excluded` の残る側）として同じテストが見ている。
- **検証しない**: 連続正解の回数の値（正本は `app_settings`。テストは app_settings に置いた値で定着を作る。R-102）。公開回をそのまま通しで受ける形で外さないこと（BR-019 の但し書きで、模試の UC が持つ）。

### REQ-053

- pattern: Ubiquitous
- br: BR-028
- status: active

> システムは、演習では同一内容の過去問を 1 件にまとめて出題し、まとめた問題には同一内容の件数と他の出典を添える。

#### 検証方針

- **分割クラス**:
  - `#exam-recency-order` — 回の新旧の順序（代表の選び方と他の出典の並びが依る）
  - `#fold-same-content` — 同一内容を 1 件にまとめ、代表を回の新しいものにし、件数と他の出典を添える
  - `#duplicate-row-not-counted` — 同じ過去問が複数行で来ても、同一内容の件数を増やさない
  - `#no-content-key` — 同一内容の関係を持たない過去問は、まとめずに別の問題として残す
  - `#fold-in-drill` — 範囲から組んだ出題に同一内容が 2 件以上あるとき、出題は 1 件になる
  - `#fold-across-review-sources` — 弱点復習の 2 つの集め方の両方に同一内容が来たとき、出題は 1 件になる
  - `#times-asked-recount` — 同一内容の件数と他の出典は、範囲に入った過去問ではなく過去問の全体から数える
  - `#mark-shown-when-multiple` — 同一内容が 2 件以上の問題にだけ、件数と他の出典を出す
- **尽きている根拠**: まとめる対象は「同一内容が複数」「1 件だけ」「関係を持たない」の 3 通りに尽き、まとめた結果に添える値（件数・他の出典）と、それを画面に出す条件を別に見ている。
- **検証しない**: 公開回をそのまま通しで受ける形で畳まないこと（BR-028 の但し書きで、模試の UC が持つ）。DB に全問を残すこと（投入の検査が持つ）。出題頻度が同一内容を数えたままであること（論点の一覧の UC が持つ）。

### REQ-054

- pattern: Ubiquitous
- br: BR-049, BR-050
- status: active

> システムは、弱点復習の出題を、BR-049 が数える本人の回答で間違えた過去問を、BR-049 が決める回答の時刻で最後に間違えた順に先へ詰め、残りを、資格対策の学びでは BR-049 と BR-050 で求めた理解度が未理解またはやや理解の論点（未の論点は含めない）の、ロードマップ型の学びでは理解度を記録して未理解またはやや理解にした論点の過去問で、出題頻度の高い論点から埋めて組む。

#### 検証方針

- **分割クラス**:
  - `#wrong-recent-first` — 間違えた過去問を、最後に間違えた時刻の新しい順に先へ詰める（2 回間違えた問題は後の誤答の時刻で）
  - `#wrong-time-mock-finish` — 模試で間違えた過去問の時刻は、回答した時刻ではなく模試を締めた時刻になる
  - `#wrong-same-time-by-question-order` — 同じ時刻に間違えた過去問どうし（同じ模試の誤答）は、出題の順で後に間違えた過去問を先にする
  - `#wrong-only-incorrect` — 間違えた側には、本人の誤答がある過去問だけが入る（正解しかしていない過去問・他の利用者の誤答は入らない）
  - `#wrong-then-weak-fill` — 問題数に余りがあるとき、間違えた過去問のあとを理解度の低い論点の過去問で埋める
  - `#wrong-fills-size` — 間違えた過去問だけで問題数に達するとき、埋める側を足さない
  - `#weak-by-frequency` — 埋める側は出題頻度の高い論点の過去問から取る
  - `#weak-exam-judged-stage` — 資格対策では、埋める側の論点を BR-049・BR-050 で求めた段階（未理解・やや理解）で選ぶ（判定・上書き・失効した上書きのどれでも）
  - `#weak-exam-excludes-unanswered` — 資格対策では、未の論点（他の利用者だけが回答した論点を含む）の過去問は埋める側に入らない
  - `#weak-roadmap-recorded` — ロードマップ型では、理解度を記録して未理解・やや理解にした論点だけで埋め、回答の履歴では選ばない
- **尽きている根拠**: 出題は「間違えた過去問」と「理解度の低い論点の過去問」の連結で、間違えた側は集める範囲（誤答があるか・本人か）と並び（BR-049 の時刻で、演習と模試で時刻の取り方が違い、同じ時刻どうしは出題の順）、埋める側は集める範囲（学びの種類ごとの段階の決まり方と、資格対策の未）と並び（出題頻度）、連結の分かれ目（余りがある／無い）で尽きる。
- **境界の扱い**: 段階は、判定より上・下の上書き、後の回答で失効した上書き、未を置く。模試は回答した時刻と締めた時刻の間に演習の誤答を挟む。理解度の低い論点の側は、定着した問題の除外（REQ-052）に掛からないよう未回答の過去問で見る。
- **検証しない**: 間違えた過去問も理解度の低い論点も無いときの出題（REQ-055 が持つ）。締める前の模試の誤答が間違えた側に入らないこと（締める前の模試は進行中のテストで、進行中のテストがあると弱点復習を始められない（REQ-057）ため、境界から観測できる状態が無い。演習の締める前の誤答も同じ）。埋める側が正誤で絞らないこと（正解したことのある過去問が入るかは、定着した問題の除外 REQ-052 の値と重なり、この文だけでは観測が一意に決まらない）。

### REQ-055

### REQ-056

- pattern: State-driven
- br: BR-017
- status: active

#### 検証方針

- **検証しない**: 要求が届いたときにサーバが作らないこと（REQ-057 が持つ）。論点ドリルの入口（論点の画面にあり、この UC のテストのファイルに無い）。

### REQ-057

- pattern: Unwanted behaviour
- br: BR-017
- status: active

> 進行中のテストがあるのに利用者が新しい演習を始めようとした場合、システムは、新しいテストを作らず、進行中のテストの範囲と回答の進み具合を示す。

#### 検証方針

- **分割クラス**:

#### 検証方針

- **分割クラス**:
  - `#size-out-of-range` — 1 回の問題数が下限未満か上限超の要求（テストを作らず理由を示す）
  - `#size-at-bounds` — 問題数が範囲の両端の要求は、問題数の形では弾かない
  - `#kind-or-type-malformed` — 種別が無い・決めの値以外・問題数が整数でない要求
  - `#scope-missing-for-kind` — 種別（論点・分野・単元）に対応する範囲が付いていない要求（範囲を取らない種別に読み替えない）
  - `#scope-value-malformed` — 範囲の値そのものが形を外れる要求（論点番号・単元番号が下限未満、分野が空）
- **尽きている根拠**: 契約 `startSession` の要求は種別・種別ごとの範囲（論点番号／分野／単元番号）・1 回の問題数の 3 軸だけで、種別は（無い）（決めの値以外）、範囲は（無い）（値が形を外れる）、問題数は（下限未満）（上限超）（整数でない）（範囲内）に尽きる。範囲を取らない種別（復習）は範囲の軸を持たないので `#scope-missing-for-kind` の対象外。
- **境界の扱い**: 問題数は範囲の外側の 2 点と内側の両端を取る（値はテストが持つ）。
- **検証しない**: 認証されていない要求（契約の errors の先頭だが、ログインそのものは UC の事前条件で外れる。他人のテストを指した操作は REQ-076）。進行中のテストが既にあるとき（REQ-057）と、範囲に出題できる問題が 1 問も無いとき（REQ-055）＝入力の形ではなく状態の検査で、本物のデータが要るため system suite の `scripts/check_api.py` が見る。理由の文言そのもの（文言の正本はコード）。

- status: active
