# REQ-347

> テストを作る途中で出題の保存に失敗した場合、システムは、そのテストも出題も残さず、始められなかった理由を示す。

## 検証方針

- **分割クラス**:
  - `#save-failed-leaves-nothing` — 出題の保存が途中で落ちると、テストの行も出題の行も残らず、始められなかった理由が返り、続けて始め直せる（最初の 1 問・途中の問題で落ちる場合と、演習・模試を値の変種に持つ）
  - `#reason-shown-on-screen` — 始められなかった理由が、始めようとした画面に出て、画面を離れない
- **尽きている根拠**: 文は「残さない」（サーバ）と「理由を示す」（画面）の 2 つを述べる。保存が落ちる位置は最初か途中かで、どちらも「何も残さない」で同じ。テストを作る経路は演習と模試で共用（UC-008 の表）なので種別は値の変種。
- **境界の扱い**: 落ちる位置は位置 0 と位置 2 の 2 点。実装が 1 行ずつ足しても一括で足しても同じ所で落ちるよう、D1 の側で行の追加を断らせる。
- **検証しない**: テストの行そのものの保存が落ちるとき（出題の保存の前で、何も作られていない）。理由の文言（正本はサーバの応答）。模試の入口の画面での理由の出方（入口の画面は REQ-109 の `#empty-scope-message` と同じ失敗の示し方で、作れなかった理由を出す経路は 1 つ）。
- **参照先**: `tests/server/UC-004_sessions_sqlite.test.ts::テストを作る途中で出題の保存に失敗したとき（POST /api/sessions。UC-004）`（save-failed-leaves-nothing）、`tests/client/repay_UC-004_practice.test.tsx::練習テストの画面（UC-004。単元の一覧の失敗と、進行中があるのに始めようとしたとき）`（reason-shown-on-screen）
