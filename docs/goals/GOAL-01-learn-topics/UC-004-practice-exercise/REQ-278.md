# REQ-278

> 現在の問題を取れなかったとき、システムは、現在の問題が出るはずだった場所に理由を示し、取り直す手段を添える。

## 検証方針

- **分割クラス**:
  - `#refetch-failed-shows-reason-with-retry` — 現在の問題を取れなかった入力（出るはずだった場所に理由が出て、取り直す手段が添う）
  - `#retry-refetches-current-only` — 添えられた取り直す手段を押した入力（回答を送り直さずに現在の問題の取得だけが走り、取り直せたらその問題が出る）
- **尽きている根拠**: 現在の問題の取得は（取れた）と（取れなかった）の 2 通りで、取れた側は REQ-058・REQ-071・REQ-237（と、断られた回答のあとの取り直しは REQ-068）が持つ。残る取れなかった側がこの文の射程で、取得の契機（画面を開いた直後の最初の取得／断られた回答のあとの取り直し）が変わっても、取れない理由（契約 `getCurrentQuestion` が断る側＝`NOT_FOUND`（破棄されて残っていない）・`UNAUTHENTICATED`、サーバの失敗、通信そのものが届かない側）が変わっても、示し方は同じ（BR-014 の取得の失敗）なので 1 クラス。添えた手段は押せて初めて手段なので、押したあとを 2 つ目のクラスに置く（押して取れた先は取れた側の REQ へ戻る）。
- **境界の扱い**: 最初の取得が落ちるときも、断られた回答のあとの取り直しが落ちるときも、404 で断られるときも通信そのものが届かないときも同じクラス（示し方が変わらない）。取得の失敗はこの文が持ち、取れたあとの示し方は REQ-058・REQ-071・REQ-237・REQ-068 が持つ境目。
- **検証しない**: 取れない理由ごとの文言の違い（文言の正本はサーバの応答と画面のコード）。取得が断られる条件どうしの判定の順（正本は契約 `getCurrentQuestion` の `errors` の並び＝R-1207）。破棄されて残っていないテストをサーバが見つからないものとして断ること（REQ-237。サーバ側）。断られた回答をサーバが採点も記録もしないこと（BR-022。サーバ側で REQ-067 が持つ）。取得が 401 で断られたあとの行き先（ログインはこの UC の事前条件の外＝別ゴールの範囲）。
