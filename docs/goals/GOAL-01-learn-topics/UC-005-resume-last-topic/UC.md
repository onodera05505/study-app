# UC-005 前回の続きから論点へ戻る

## 概要

利用者が、最後に開いた論点を端末に覚えさせ、学びを開き直したときにホームの「前回の続き」からその論点へ戻る。

## 事前条件

- 利用者（ACT-01）がログインしており、学びを 1 つ選んでいる（ログインとトークンの扱いは GOAL-08 の範囲）
- 学びの種類が資格対策である（ロードマップ型では続きの導線を置く場所と、覚えた続きが無いときの行き先が違う。GOAL-03 の範囲）
- 適用される業務規則: BR-010, BR-011, BR-012, BR-013, BR-041

## 主シナリオ

1. 利用者が論点の画面を開く
2. システムが、その論点を前回の続きとして端末に覚え、以前に覚えていた論点を残さない
3. 利用者が学びを開き直し、ホームを開く
4. システムが、覚えた前回の続きの論点名と単元を添えた導線を出す
5. 利用者がその導線を選ぶ
6. システムが、覚えた論点の画面を開く

| --- | --- | --- | --- | --- |
| 覚えていない（まだ論点を開いていない、または捨てられた） | REQ-077 | REQ-079 | 不可: 前回の続きの導線が出ていない | BR-010 |
| 覚えている | REQ-077 | REQ-080 | REQ-081 | BR-010 |

| 覚えた値が読めない | REQ-077 | REQ-082 | 不可: 前回の続きの導線が出ていない | BR-010 |
| 端末が覚えられない | REQ-078 | REQ-082 | 不可: 前回の続きの導線が出ていない | BR-010 |

## 例外系の走査（4 分類）

| 軸 | 該当ステップ | 導出 |
| --- | --- | --- |
| 権限 | 2・4 | 前回の続きは端末に残るため、同じ端末を別のアカウントが使うと前の人の続きが出る → 表「トークンを捨てる」列の BR-010（捨てる側の振る舞いは GOAL-08 の範囲）。端末をまたいで続きを出さないことは BR-012 |
| 不変条件違反 | 2 | 覚える前回の続きは常に 1 件（最後に開いた論点）で、以前の記憶を残さない → REQ-077。覚えた論点がもう無いときに導線を選ぶと、単元の一覧へ戻して見つからないことを伝え、覚えた前回の続きを捨てる → REQ-342 |
| 並行性 | 2・4 | 続けて別の論点を開いたときに残るのは最後に開いた論点 → REQ-077。覚えた直後に開いたホームがその論点を出す → REQ-080 |
| 外部依存 | 2・4 | 端末が覚えられない → REQ-078、覚えた値が読めない → REQ-082（表の下 2 行） |

## 事後条件

- 成功時: 最後に開いた論点が端末に 1 件だけ残り、開き直したホームにその論点名と単元を添えた前回の続きの導線が出て、選ぶとその論点の画面が開く
- 失敗時: 端末が覚えられない・覚えた値が読めないときは、端末の記憶は変わらず、前回の続きの導線が出ないだけで画面の操作は止まらない。覚えた論点がもう無いと分かったときは、単元の一覧が開き、端末の記憶から前回の続きが捨てられている以外の状態変更は残っていない（部分適用なし）

## 要件

### REQ-077

- pattern: Event-driven
- br: BR-013
- status: active

> 利用者が論点の画面を開いたとき、システムは、その論点を前回の続きとして端末に 1 件だけ覚え、以前に覚えていた前回の続きを残さない。

#### 検証方針

- **分割クラス**:
  - `#opened-topic-remembered` — 覚えが無い端末で論点の画面を開いた入力。開いた論点が前回の続きになる
  - `#saved-value-readable` — 覚えさせた前回の続きを端末の記憶から読む入力（契約 saveLastTopic → readLastTopic の往復）。覚えが無い端末では無しが戻る
  - `#replaces-previous` — すでに覚えがある端末で別の論点を開いた入力。残るのは後の 1 件だけで以前の論点は残らず（BR-013）、覚える項目は契約の LastTopic の 4 つで、学びを開き直しても端末の値から復元できる
- **尽きている根拠**: 論点の画面を開く出来事の入力は、端末が前回の続きを覚えていない状態と覚えている状態の 2 つで尽きる（前者が `#opened-topic-remembered`、後者が `#replaces-previous`）。覚えた値が端末に残って同じ論点として読めることは、どちらの状態でも同じ 1 つの往復に畳めるので `#saved-value-readable` が持つ。端末が覚えられないときは REQ-078、覚えた値が読めないときは REQ-082 が持つ。
- **境界の扱い**: 端末に残る件数の境界は 0 件と 1 件だけで、2 件以上になる入力が無いこと（BR-013）を `#replaces-previous` が見る。
- **検証しない**: 端末に書く鍵の名前と値の表し方（利用者から観測できない。契約 saveLastTopic は鍵の名前を operation 名が表すとだけ決めるので、テストは鍵の名前に頼らず値で探す）。トークンを捨てたときに覚えも捨てること（BR-010。UC-013 の REQ-198 が持つ）。他の端末や別の人の画面に覚えが出ないこと（BR-012。端末をまたいで観測する手段が無い）。

### REQ-078

- pattern: Unwanted behaviour
- br: BR-011
- status: active

> 端末が前回の続きを覚えられない場合、システムは、論点の画面の操作を止めない。

#### 検証方針

- **分割クラス**:
  - `#storage-blocked-keeps-going` — 端末の記憶に書けない入力（契約 saveLastTopic の STORAGE_UNAVAILABLE）。覚える操作が断りの種類の名前を持つ失敗を渡しても、論点の画面の操作が止まらない
- **尽きている根拠**: 端末が覚えられる／覚えられないの 2 つのうち、この要件は覚えられない側だけを言い、覚えられる側は REQ-077 が持つ。覚えられない理由（端末の設定・容量・私的閲覧）はいずれも書き込みが失敗することに畳めるので 1 クラスで尽きる。
- **検証しない**: 覚えられなかったことを利用者に知らせること（BR-011 は出さないだけにすると決めており、知らせは要件に無い）。ホームの側の振る舞い（REQ-082 が持つ）。

### REQ-079

- pattern: State-driven
- status: active

> 前回の続きを覚えていない間、システムは、ホームに前回の続きの導線を出さず、論点の一覧へ進む導線を出す。

#### 検証方針

- **分割クラス**:
  - `#not-remembered-topics-link` — 端末が前回の続きを覚えていない状態でホームを開いた入力。前回の続きの導線を出さず、論点の一覧へ進む導線を出す
- **尽きている根拠**: ホームを開いたときの入力は、前回の続きが読めて値がある／無いの 2 つで尽き（契約 readLastTopic は errors を持たず、読めない・使えないもすべて無しに畳む）、この要件は無い側だけを言う。値がある側は REQ-080、無しに畳んだ原因が端末の失敗である側は REQ-082 が持つ。UC.md の表の「まだ論点を開いていない」と「捨てられた」は、ホームから見た入力が同じ（前回の続きが無し）なので 1 クラス。
- **検証しない**: 捨てる側の振る舞い（BR-010。UC-013 の REQ-198 が持つ）。ロードマップ型の先頭の導線（事前条件で資格対策の学びに限っており、UC-009 の REQ-144 が持つ）。

### REQ-080

- pattern: State-driven
- br: BR-013
- status: active

> 前回の続きを覚えている間、システムは、ホームに、覚えた論点の名前とその単元を添えた前回の続きの導線を出す。

#### 検証方針

- **分割クラス**:
  - `#remembered-shows-term-and-middle` — 覚えた前回の続きがある状態でホームを開いた入力。覚えた論点の名前とその単元を添えた導線が出る
  - `#remembered-topic-gone` — 覚えた論点がもう無い状態でホームを開いた入力（UC.md の表 3 行目）。ホームは端末に覚えた値から同じ導線を出す
- **尽きている根拠**: 覚えがある状態の入力は、覚えた論点が今もある／もう無いの 2 つで尽きる。ホームは端末に覚えた値だけで導線を組むので、添える名前と単元の出所は両方の入力で同じ。
- **検証しない**: 導線を選んだ先（REQ-081 が持つ）。覚えが無いとき・読めないとき（REQ-079・REQ-082 が持つ）。導線を置く位置と見た目（要件は名前と単元を添えることだけを言う）。

### REQ-081

- pattern: Event-driven
- status: active

> 端末が覚えた前回の続きの論点が今もあるときに利用者が前回の続きの導線を選んだとき、システムは、覚えた論点の画面を開く。

#### 検証方針

- **分割クラス**:
  - `#follow-link-opens-topic` — 覚えた論点が今もあるときに前回の続きの導線を選んだ入力。覚えた論点の画面が開く
- **尽きている根拠**: 導線を選べるのは導線が出ているとき（＝覚えた前回の続きがあるとき）だけで、導線が出ていない状態では選べない（UC.md の表の「不可」）。導線を選んだ入力は、覚えた論点が今もある・もう無いの 2 つで尽き、もう無い方は REQ-342 が持つ（UC.md の表 3 行目）ので、この REQ の入力は 1 つ。
- **検証しない**: 覚えた論点がもう無いときに導線を選んだ先（REQ-342 が持つ）。導線の見え方と添える名前・単元（REQ-080 が持つ）。

### REQ-082

- pattern: Unwanted behaviour
- br: BR-011, BR-041
- status: active

> 覚えた前回の続きが読めない場合、または端末が前回の続きを覚えられない場合、システムは、ホームに前回の続きの導線を出さないだけにし、ホームの他の部分を出す。

#### 検証方針

- **分割クラス**:
  - `#unreadable-value` — 端末に覚えた値が読めない入力（壊れた値）。前回の続きは無しに畳まれ（契約 readLastTopic は errors を持たない）、ホームは導線を出さないだけにして他の部分を出す
  - `#storage-unavailable` — 端末の記憶そのものが使えない入力。同じく導線を出さないだけにして、ホームの他の部分を出す
- **尽きている根拠**: ホームに前回の続きが出ない原因は、覚えが無い（REQ-079 が持つ）・覚えた値が読めない・端末の記憶が使えないの 3 つで尽き、この要件は後の 2 つを言う。壊れ方（途中で切れた値・別の形の値・知らない項目）はいずれも読めないことに畳める。
- **検証しない**: 読めなかったことを利用者に知らせること（BR-011 は出さないだけにすると決めている）。論点の画面の側（REQ-078 が持つ）。壊れた値を端末から取り除くかどうか（要件は出さないだけにすると言い、片付けを言わない）。

### REQ-342

- pattern: Unwanted behaviour
- status: active

> 端末が覚えた前回の続きの論点がもう無いときに利用者が前回の続きの導線を選んだ場合、システムは、論点の画面に取れなかったことを示す代わりに単元の一覧を開いて前回の続きの論点が見つからないことを示し、端末が覚えた前回の続きを捨てる。

#### 検証方針

- **分割クラス**:
  - `#gone-via-resume-link` — 端末が覚えた前回の続きの論点がもう無い（論点の取得が契約の `NOT_FOUND`）ときに、ホームの前回の続きの導線を選んだ入力。論点の画面に取れなかったことを示さずに単元の一覧が開き、前回の続きの論点が見つからないことが示され、端末が覚えた前回の続きが捨てられる
- **尽きている根拠**: この要件の入力は「覚えた論点がもう無い」状態で「導線を選ぶ」1 つだけで、覚えた値の中身（名前・単元）は行き先を分けない。覚えた論点が今もあるときは REQ-081、前回の続きの導線を経ずに開いた論点の取得の失敗と、導線から開いて `NOT_FOUND` 以外で取れなかったときは REQ-033 が持つ。1 つの入力の 3 つの観測点（開く画面・示すこと・端末の記憶）を同じクラスの別のテストで見る。
- **検証しない**: 見つからないことを示す文言そのもの（要件は示すことだけを言う）。単元の一覧の中身（UC-002 の REQ が持つ）。
