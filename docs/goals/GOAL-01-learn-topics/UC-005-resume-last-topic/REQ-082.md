# REQ-082

> 覚えた前回の続きが読めない場合、または端末が前回の続きを覚えられない場合、システムは、ホームに前回の続きの導線を出さないだけにし、ホームの他の部分を出す。

## 検証方針

- **分割クラス**:
  - `#unreadable-value` — 端末に覚えた値が読めない入力（壊れた値）。前回の続きは無しに畳まれ（契約 readLastTopic は errors を持たない）、ホームは導線を出さないだけにして他の部分を出す
  - `#storage-unavailable` — 端末の記憶そのものが使えない入力。同じく導線を出さないだけにして、ホームの他の部分を出す
- **尽きている根拠**: ホームに前回の続きが出ない原因は、覚えが無い（REQ-079 が持つ）・覚えた値が読めない・端末の記憶が使えないの 3 つで尽き、この要件は後の 2 つを言う。壊れ方（途中で切れた値・別の形の値・知らない項目）はいずれも読めないことに畳める。
- **検証しない**: 読めなかったことを利用者に知らせること（BR-011 は出さないだけにすると決めている）。論点の画面の側（REQ-078 が持つ）。壊れた値を端末から取り除くかどうか（要件は出さないだけにすると言い、片付けを言わない）。
