# REQ-077

> 利用者が論点の画面を開いたとき、システムは、その論点を前回の続きとして端末に 1 件だけ覚え、以前に覚えていた前回の続きを残さない。

## 検証方針

- **分割クラス**:
  - `#opened-topic-remembered` — 覚えが無い端末で論点の画面を開いた入力。開いた論点が前回の続きになる
  - `#saved-value-readable` — 覚えさせた前回の続きを端末の記憶から読む入力（契約 saveLastTopic → readLastTopic の往復）。覚えが無い端末では無しが戻る
  - `#replaces-previous` — すでに覚えがある端末で別の論点を開いた入力。残るのは後の 1 件だけで以前の論点は残らず（BR-013）、覚える項目は契約の LastTopic の 4 つで、学びを開き直しても端末の値から復元できる
- **尽きている根拠**: 論点の画面を開く出来事の入力は、端末が前回の続きを覚えていない状態と覚えている状態の 2 つで尽きる（前者が `#opened-topic-remembered`、後者が `#replaces-previous`）。覚えた値が端末に残って同じ論点として読めることは、どちらの状態でも同じ 1 つの往復に畳めるので `#saved-value-readable` が持つ。端末が覚えられないときは REQ-078、覚えた値が読めないときは REQ-082 が持つ。
- **境界の扱い**: 端末に残る件数の境界は 0 件と 1 件だけで、2 件以上になる入力が無いこと（BR-013）を `#replaces-previous` が見る。
- **検証しない**: 端末に書く鍵の名前と値の表し方（利用者から観測できない。契約 saveLastTopic は鍵の名前を operation 名が表すとだけ決めるので、テストは鍵の名前に頼らず値で探す）。トークンを捨てたときに覚えも捨てること（BR-010。UC-013 の REQ-198 が持つ）。他の端末や別の人の画面に覚えが出ないこと（BR-012。端末をまたいで観測する手段が無い）。
