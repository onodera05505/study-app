# UC-025 書き直した世代の資格対策の教材を様式の門で確かめる

## 概要

作り手が、単元の構成に沿って書き直した世代の資格対策の教材を様式の門にかけ、止める理由が無ければ通し、あればその論点と理由を、知らせ（警告）と一緒に受け取って書き手へ戻す。

## 事前条件

- 資格対策の学びが登録簿にあり、論点・教材の世代・図の仕様・単元の構成が学びの置き場にある
- 教材の書き方は執筆の仕様書（`scripts/prompts/write_materials.md`）が決める
- 適用される業務規則: BR-004, BR-042, BR-048

## 主シナリオ

1. 作り手が、書き直した世代の教材を様式の門にかける
2. システムが、書き直した世代の論点が、止める理由の無い単元の構成のまとまりに入っていることを確かめる → BR-048
3. システムが、書き直した世代の論点の図のうち、短い説明の直後に置く図が 1 枚までであることを確かめる
4. システムが、情報の量を見ずに、問われ方の文・同じ点の繰り返し・受け持ちの説明の繰り返し・前の世代から消えた数値を警告として挙げる → BR-042
5. システムが、見た論点の数、警告、止める理由を返し、止める理由が無いので通す
6. 作り手が、通ったことを見て、図の差し込みと投入に回す

## 要件

### REQ-451

- pattern: Event-driven
- status: active

> 作り手が資格対策の学びの書き直した世代の教材を様式の門にかけたとき、止める理由に当たる教材が無ければ、様式の門は警告の有無によらず通し、見た論点の数と、警告ごとの種類と論点と箇所を返す。

#### 検証方針

- **分割クラス**:
  - `#clean-pass` — 止める理由も警告も無い世代は、見た論点の数（束をまたいで数える）と契約の limits を返して終了コード 0 で通す
  - `#warnings-only-pass` — 警告の 4 種類だけが当たる世代は通し、警告ごとに種類と論点を返す（警告は exitCode を変えない）
  - `#default-dir` — `--dir` を省くと、書き直した世代の始まり（`REWRITTEN_FROM` の世代）を確かめる
- **尽きている根拠**: 通す側の入力は「何も当たらない」「警告だけが当たる」の 2 つで尽き、止める理由が 1 件でも当たる側は REQ-454・455 が受け持つ。置き場の指し方は「指す」「省く」の 2 つで、指す側は REQ-452 の `#dir-selects-generation`。
- **検証しない**: 警告の箇所（where）の書式そのもの（契約は例しか持たない。論点 ID が前後を数字でない形で現れることだけを見る）。止める理由と警告が同時に当たる組み合わせ（止める側の各クラスが警告の有無によらず止まることで足りる）。

### REQ-452

- pattern: Ubiquitous
- status: active

> 様式の門は、書き直した世代の置き場にある教材だけを確かめ、前の世代にだけ教材がある論点と、書き直した世代の置き場が無い学びを、止める理由にも警告にもしない。

#### 検証方針

- **分割クラス**:
  - `#no-rewritten-dir` — 書き直した世代の置き場が無い学びは、名前を省いても、始まりやそれより後の書き直した世代の名前を渡しても、前の世代の言い回し・数値や図の置き場に当たる物があっても 0 論点で通し、警告も出さない
  - `#previous-only-topic` — 前の世代にだけ教材がある論点は、単元の構成に無くても、図の置き場・読めない図の仕様・言い回し・数値に当たる物があっても、止めも警告もしない
  - `#dir-selects-generation` — `--dir` に始まりより後の書き直した世代の名前を渡すとその世代だけを確かめ、始まりの書き直した世代の置き場にある言い回しは警告しない
- **尽きている根拠**: 門が見る教材の範囲の外は「置き場ごと無い」「論点が前の世代にだけある」「別の書き直した世代の置き場にある」の 3 通りで、どれも指した書き直した世代の置き場の外にある。
- **境界の扱い**: 世代の名前は `scripts/material_generations.py` の `REWRITTEN_FROM`（書き直した世代の始まり）を道具から引いて作る。
- **検証しない**: 書き直した世代でない名前の `--dir`（REQ-453 の `#earlier-generation`・`#not-generation-name`）。

### REQ-453

- pattern: Unwanted behaviour
- br: BR-004
- status: active

> 作り手が登録簿に無い学びか資格対策でない学びの教材を様式の門にかけたとき、指定した世代が書き直した世代でないとき、またはその学びのシラバスか論点の一覧が無いか読めないとき、様式の門は何も確かめずに断る。

#### 検証方針

- **分割クラス**:
  - `#unknown-learning` — 登録簿に無い学び（zzz）は、置き場に止める理由と警告に当たる物があっても、ToolError の INVALID_INPUT と終了コード 2 で断り、止める理由も警告も返さない
  - `#not-qualification` — 登録簿の資格対策でない学び（登録簿の kind が exam でないすべての学び）を INVALID_INPUT と終了コード 2 で断る
  - `#earlier-generation` — `--dir` が書き直した世代の始まりより前の世代の名前（materials から始まりの 1 つ前まで全部）なら、その置き場があっても INVALID_INPUT と終了コード 2 で断る
  - `#not-generation-name` — `--dir` が世代の名前の形でない値（パス・末尾の区切り・別の語・番号の無い形・大文字・後ろに語の付いた形・前後に改行や空白やタブの付いた形・番号が全角の形）なら、その置き場があっても INVALID_INPUT と終了コード 2 で断る。契約の形は値の全体に当たり、末尾の改行も形の外
  - `#catalog-missing` — シラバスか論点の一覧のファイルが無ければ NOT_FOUND と終了コード 2 で断る
  - `#catalog-unreadable` — シラバスか論点の一覧が JSON として読めないか形が違えば INVALID_INPUT と終了コード 2 で断る
  - `#not-qualification-before-not-rewritten` — 資格対策でない学びに書き直した世代でない世代の名前を渡すと INVALID_INPUT で断る（errors の 2 項と 3 項の隣り合い）
  - `#not-rewritten-before-catalog-missing` — 書き直した世代でない世代の名前を渡し、シラバスも無い学びは、NOT_FOUND でなく INVALID_INPUT で断る（3 項と 4 項）
  - `#catalog-missing-before-unreadable` — シラバスが無く論点の一覧が読めない学びは、INVALID_INPUT でなく NOT_FOUND で断る（4 項と 5 項）
- **尽きている根拠**: 契約の errors の 5 項が 1 クラスずつで、3 項は契約が括弧で分ける 2 つ（始まりより前の世代・名前の形でない）を別のクラスにする。シラバスと論点の一覧は同じ項の 2 つの値として各テストで両方を試す。隣り合う組は、1 項と 2 項が同時に満たせない（登録簿に無い学びに種類は無い）ので除き、2・3、3・4、4・5 の 3 組を持つ。
- **境界の扱い**: 書き直した世代の始まりは `scripts/material_generations.py` の `REWRITTEN_FROM` を道具から引く。始まりちょうどとそれより後は断らない側（REQ-452 の `#no-rewritten-dir`・`#dir-selects-generation`）、始まりの 1 つ前から materials までは断る側。
- **検証しない**: 断ったときの reason の文面（空でないことだけを見る）。`--data` が契約の形（`^data/[a-z]+$`）から外れる入力（errors に無い）。2・3 の組は code が同じで、先の項が当たったことは観測できず、断ることだけを見る。

### REQ-454

- pattern: Unwanted behaviour
- status: active

> 書き直した世代の置き場に、契約の教材の形として読めないか束の名前の形を満たさない JSON のファイルがあるとき、様式の門はそのファイルをすべて挙げて止める。

#### 検証方針

- **分割クラス**:
  - `#not-json` — 書きかけで JSON として読めない束のファイルは、そのファイルを挙げて止める
  - `#missing-field` — 必須の欄（bundle・materials・topic_id・term・explanation・detail）のどれかが欠ける束のファイルは、そのファイルを挙げて止める
  - `#wrong-type` — 欄の型・範囲が契約と違う束のファイル（materials が配列でない・topic_id が文字列か 0・bundle が数・本文が空・中身が配列）は、そのファイルを挙げて止める
  - `#bundle-name-shape` — ファイルの名前が束の名前の形（2 桁の単元番号-1 始まりの番号）でない JSON のファイル（bundle_01・1-1・01-0・001-1・01_1・01-1a）は、中身が読めてもそのファイルを挙げて止める
  - `#non-json-file-ignored` — 書き直した世代の置き場にある JSON でないファイル（.md・.json.tmp）は止める理由にしない
  - `#all-listed` — 止める理由は件数で打ち切らず、読めない束のファイルをすべて挙げる
- **尽きている根拠**: ファイルは、JSON でない・欄が欠ける・型が違う・名前が束の形でない（と、JSON でないファイルという外側）で尽きる。挙げる数は 1 件で打ち切らないことを `#all-listed` が見る。
- **検証しない**: 束のファイルの bundle の値とファイルの名前が食い違うとき（文は名前の形だけを言う）。

### REQ-455

- pattern: Unwanted behaviour
- status: active

> 書き直した世代に教材がある論点の図の仕様のファイルが読めないとき、またはその図の仕様で短い説明の直後に置く図が 2 枚以上あるとき、様式の門はそのファイルか論点と図を挙げて止める。

#### 検証方針

- **分割クラス**:
  - `#figure-spec-unreadable` — 書き直した世代に教材がある論点の図の仕様のファイルが、JSON でない・figures が配列でない・図の after か caption が無い・図の id が 0・topic_id が文字列・中身が配列のどれかなら、そのファイルを unreadableFigureSpec で挙げて止める
  - `#over-max` — 短い説明の直後に置く図（after が explanation）が上限 + 1・+ 2 枚の論点は、その論点だけを挙げて止める
  - `#within-max` — 短い説明の直後に置く図が 0 枚か上限ちょうどなら、見出しの後ろの図がいくつあっても止めない
- **尽きている根拠**: 図の仕様は、読めない（`#figure-spec-unreadable`）と読める（枚数で 2 つに分かれる）で尽き、読める側の after が explanation の図の数は上限以下か上限超えかの 2 つで尽きる。
- **境界の扱い**: 上限は契約の `explanationFiguresMax`（1）。下は 0 と上限ちょうど、上は上限 + 1 と + 2。
- **検証しない**: 前の世代にだけ教材がある論点の図（REQ-452 の `#previous-only-topic` が見る）。図の仕様のファイルが無い論点（文は「読めない」とだけ言い、図の無い論点との区別を決めていない）。止める理由の where が挙げる図の番号（契約の例は図の仕様のファイルだけを挙げるので、論点を名指すことだけを見る）。

### REQ-457

- pattern: State-driven
- status: active

> 書き直した世代の教材の短い説明か詳しい解説で、契約が定める試験の問われ方・覚え方の言い回しが、見出しの行の文そのものも含めて、混同しやすい用語の見出しの下（次の見出しの手前まで）の外にあるあいだ、様式の門はその論点と箇所を警告として挙げ、止める理由にはしない。

#### 検証方針

- **分割クラス**:
  - `#in-explanation` — 短い説明にある契約の言い回し（examPhrases の全部）は、どれも論点と短い説明の箇所を挙げて警告し、通す
  - `#in-detail-outside` — 詳しい解説の、混同しやすい用語より前の見出しの下にある言い回しは、どれも論点と詳しい解説の箇所を挙げて警告する
  - `#inside-confusion-heading` — `### 混同しやすい用語` の見出しの下にある言い回しは、どれも警告しない
  - `#after-confusion-section` — 混同しやすい用語の後ろに続く別の見出しの下にある言い回しは警告する
  - `#phrase-in-heading` — 混同しやすい用語でない見出しの行の文そのものにある言い回しは、どれも論点と詳しい解説の箇所を挙げて警告する
  - `#near-miss` — 言い回しの一部だけの語（試験・出題・覚える・問い）は警告しない
- **尽きている根拠**: 言い回しの置き場は、短い説明・詳しい解説の見出しの外（見出しの下の本文と、見出しの行そのもの）・混同しやすい用語の見出しの中の 3 つで、見出しの中の範囲の終わりは次の見出しで切れる。言い回しかどうかの境は、契約の並びの全部（当たる側）と一部だけの語（当たらない側）。
- **境界の扱い**: 言い回しは契約の `examPhrases` から読むので、契約の並びが変わればテストが追う。
- **検証しない**: 図の説明文（caption）にある言い回し（文は教材とだけ言う）。

### REQ-458

- pattern: State-driven
- status: active

> 書き直した世代の 1 つの論点の中で、図の説明文と本文、または短い説明と詳しい解説が契約が定める長さ以上に一致するあいだ、様式の門はその論点と一致した 2 か所を警告として挙げ、止める理由にはしない。

#### 検証方針

- **分割クラス**:
  - `#caption-body-at-threshold` — 図の説明文と短い説明・詳しい解説が上限の字数ちょうど一致すると、論点を挙げて警告し、通す
  - `#explanation-detail-at-threshold` — 短い説明と詳しい解説が上限の字数ちょうど一致すると、論点と 2 か所を挙げて警告する
  - `#below-threshold` — 一致が上限より 1 字短ければ、どの 2 か所でも警告しない
  - `#markup-excluded-reaches` — 記法（`**`・`[[ ]]`）と空白（半角・全角）で途切れていても、除いて上限の字数に届けば警告する
  - `#markup-not-counted` — 記法と空白を含めると上限を超えても、除いて上限に届かなければ警告しない
  - `#across-topics` — 別の論点の図の説明文や本文との一致は、同じ論点の繰り返しとして警告しない
- **尽きている根拠**: 一致する 2 か所の組は、図の説明文と本文（短い説明・詳しい解説）、短い説明と詳しい解説の 2 種類で、長さは上限ちょうどとその 1 字下、数え方は記法と空白を除く側と含める側で分かれる。論点の内か外かは `#across-topics` が切る。
- **境界の扱い**: 上限は契約の `sameTopicMatchLength`（20）。一致させる並びの前後には別の字を置き、一致が並びの外へ伸びないようにする。
- **検証しない**: 2 枚の図の説明文どうしの一致（文は図の説明文と本文の組だけを言う）。見出しの `###` と箇条の `- ` を記法として除くか（文中で途切れる位置に置かないので、結果に効かない）。

### REQ-459

- pattern: State-driven
- status: active

> 同じ単元の構成に入っている 2 つの論点の書き直した世代の本文が、`[[ ]]` で囲んだ用語の中の字を一致の長さに数えずに、契約が定める長さ以上に一致するあいだ、様式の門はその 2 つの論点と、単元の構成がその説明の受け持ちを決めていればその受け持ちの論点を警告として挙げ、止める理由にはしない。

#### 検証方針

- **分割クラス**:
  - `#at-threshold` — 同じ単元の構成の同じまとまりの 2 論点の本文が上限の字数ちょうど一致すると、その 2 論点だけを挙げて警告し、通す
  - `#below-threshold` — 一致が上限より 1 字短ければ警告しない
  - `#markup-excluded` — 記法（`**` など）と空白で途切れていても、除いて上限の字数に届けば警告する
  - `#term-not-counted` — `[[ ]]` で囲んだ用語が両方の論点で同じでも、その中の字は数えず、外の一致が上限に届かなければ警告しない
  - `#term-joins-across` — `[[ ]]` で囲んだ用語が論点ごとに違っても、その前後の外の一致をつなげて上限に届けば警告する
  - `#across-groups` — 同じ単元の構成の別のまとまり（別の束）の 2 論点の一致も警告する
  - `#different-units` — 別の単元の構成に入っている 2 論点の一致は、長くても警告しない
  - `#owner-named` — 一致した 2 論点がどちらも単元の構成の受け持ちの topics にあれば、受け持ちの論点も挙げる
- **尽きている根拠**: 2 論点の組は、同じ構成の同じまとまり・同じ構成の別のまとまり・別の構成の 3 つで尽き、長さは上限ちょうどとその 1 字下。一致の長さの数え方は、記法と空白を除く（`#markup-excluded`）、`[[ ]]` の中の字を数えない（`#term-not-counted`）、`[[ ]]` を除いた前後をつなげる（`#term-joins-across`）の 3 つ。受け持ちは、決めている（`#owner-named`）と決めていない（`#at-threshold` で他の論点を挙げないことを見る）の 2 つ。
- **境界の扱い**: 上限は契約の `sameUnitMatchLength`（30）。
- **検証しない**: 一致が受け持ちの説明に当たるかの見分け方（契約は決めていない。2 論点がどちらも受け持ちの topics にあるときに挙げることだけを見る）。記法を含めて上限を超え除くと届かない側（記法と空白は REQ-458 の `#markup-not-counted` と同じ数え方）。構成が使えない単元の論点どうしの一致（その単元は REQ-490 で止まる）。

### REQ-460

- pattern: State-driven
- status: active

> ある論点の前の世代の教材（配る本文の選び方で、書き直した世代を除いて最も新しい世代の教材）にある数値が、その論点の書き直した世代の教材に無いあいだ、様式の門はその論点と数値を警告として挙げ、止める理由にはしない。

#### 検証方針

- **分割クラス**:
  - `#lost-number` — 前の世代にある 2 桁の数値が書き直した世代に無ければ、論点と数値を挙げて警告し、通す
  - `#kept-number` — 前の世代の数値（整数・小数）が書き直した世代の短い説明か詳しい解説にあれば警告しない
  - `#single-digit-not-compared` — 小数点を含まない 1 桁の数値（半角・全角）は、書き直した世代に無くても警告しない
  - `#decimal-compared` — 小数点を含む数値は、桁が少なくても書き直した世代に無ければ警告する
  - `#fullwidth-normalized` — 全角の数値と小数点は半角に寄せて比べ、どちらの書き方で書き直しても警告しない
  - `#fullwidth-lost` — 全角の数値が書き直した世代にどの書き方でも無ければ警告する
  - `#figure-line-not-counted` — 前の世代の図の行（`![…](…)`）の中の数値は、書き直した世代に無くても警告しない
  - `#figure-line-caption-brackets-not-counted` — 図の説明文に角かっこ（`A[1]`）を含む前の世代の図の行の中の数値も、書き直した世代に無くても警告しない
  - `#number-as-token` — 数値は取り出した数として比べ、桁の多い別の数の一部としてあるだけなら無いとみなして警告する
  - `#newest-previous-generation` — 前の世代は書き直した世代を除いて最も新しい世代（materials_v3）で、それより古い世代（materials_v2・materials）にだけある数値は警告しない
  - `#previous-per-topic` — 最も新しい前の世代に無い論点は、その論点がある中で最も新しい世代（materials_v2）の数値と比べ、さらに古い世代（materials）の数値は比べない
  - `#rewritten-not-previous` — 始まりより後の書き直した世代を確かめるとき、始まりの書き直した世代にだけある数値は前の世代に数えず警告しない
- **尽きている根拠**: 数値の取り出しは、桁（1 桁と 2 桁の境）・小数点の有無・全角と半角・図の行の内外・数としての切り出しの 5 つの軸で、それぞれの両側を持つ。図の行の内側は、図の説明文が記法の区切りと同じ角かっこを含むかで図の行と読めるかが変わりうるので、含まない行と含む行の 2 つを置く。有無は、ある（`#kept-number`）と無い（`#lost-number`）。比べる相手の世代は、論点が最も新しい前の世代にある（`#newest-previous-generation`）と無い（`#previous-per-topic`）で尽き、書き直した世代どうしは前の世代にならない（`#rewritten-not-previous`）。
- **境界の扱い**: 桁の下限は契約の `numberMinDigits`（2）。1 桁は比べず、2 桁は比べる。世代の名前は `REWRITTEN_FROM` を道具から引いて作る（例の materials_v3・v2・materials は始まりが 4 のときの名前）。
- **検証しない**: 受け持ちの論点や問題解説にある数値で足りたとみなすか（文は論点の教材だけを言う）。書き直した世代の図の説明文にある数値。

### REQ-485

- pattern: Ubiquitous
- status: active

> 様式の門は、通すときも止めるときも断るときも、教材・単元の構成・図の仕様のどのファイルも書き換えない。

#### 検証方針

- **分割クラス**:
  - `#unchanged-on-pass` — 警告を出して通すとき、作業場のどのファイルも書き換えず、足しも消しもしない
  - `#unchanged-on-stop` — 読めない束・使えない単元の構成・読めない図の仕様・図の上限超えで止めるとき、作業場のどのファイルも書き換えない
  - `#unchanged-on-refuse` — 資格対策でない学び・書き直した世代でない名前・読めない論点の一覧で断るとき、作業場のどのファイルも書き換えない
- **尽きている根拠**: 文の 3 つの終わり方（通す・止める・断る）が 1 クラスずつ。止める側は止める理由の 4 つの読み物（束・単元の構成・図の仕様と図の数）を 1 回に重ねて当て、断る側は errors の 3 種類（学び・世代・一覧）を代表に試す。
- **検証しない**: 作業場の外（リポジトリの scripts や登録簿の正本）への書き込み（作業場を cwd にして呼ぶので、門が読む学びの置き場はすべて作業場の中にある）。ファイルの更新時刻だけが変わる書き換え（中身とファイルの有無で見る）。

### REQ-490

- pattern: Unwanted behaviour
- br: BR-048
- status: active

> 書き直した世代に論点がある単元の単元の構成が無いか読めないとき、または学びの全部の単元の構成と合わせて判定した単元の構成の門の止める理由のうちその単元に関する物（前提の循環のように複数の単元の構成にまたがる止める理由は、それに入るすべての単元に関する物とする）があるとき、様式の門はその単元を挙げて止め、書き直した世代に論点の無い単元の単元の構成はどの状態でも止める理由にしない。

#### 検証方針

- **分割クラス**:
  - `#unit-without-plan` — 書き直した世代に論点がある単元に単元の構成が無ければ、その単元を unitPlanStops で挙げて止め、その単元の論点を topicNotInPlan で重ねて挙げない
  - `#plan-has-stops` — 書き直した世代に論点がある単元の単元の構成が単元の構成の門の止める理由（実在しない論点・まとまりの上限超え・必須の要素の欠け）に当たれば、その単元を挙げて止め、論点を重ねて挙げない
  - `#plan-file-unreadable` — 書き直した世代に論点がある単元の単元の構成のファイルが書きかけで読めなければ、その単元を挙げて止め、論点を重ねて挙げない
  - `#cross-unit-cycle` — 前提の循環が 2 つの単元の構成にまたがるとき、書き直した世代に論点がある側の単元は、循環の止める理由がどちらの単元を指していても、その単元を挙げて止め、論点を重ねて挙げない
  - `#cycle-outside-units` — 前提の循環に入らない単元にだけ書き直した世代の論点があるときは、学びの別の単元の構成どうしの循環があっても止めない
  - `#plan-outside-scope` — 書き直した世代に論点が無い単元の単元の構成は、無くても読めなくても止める理由に当たっても見ずに通す
- **尽きている根拠**: 単元の構成は、見る範囲（書き直した世代に論点がある単元）の内で、無い・読めない・止める理由に当たるの 3 つと、範囲の外で尽きる。止める理由は、その単元の構成だけで決まる物（`#plan-has-stops`）と、複数の単元の構成にまたがる前提の循環（入る単元の側 `#cross-unit-cycle`・入らない単元の側 `#cycle-outside-units`）で尽きる。使えない単元の論点を重ねないことは、構成のクラスがそれぞれ見る。
- **境界の扱い**: 単元の構成の止める理由の種類ごとの判定は UC-024 のクラスが受け持ち、ここでは 3 種類と読めないファイルを代表に、様式の門が単元を挙げて止めることだけを見る。単元は where か reason に単元の番号（0 詰めかどうかによらない）が出ることで見る。
- **検証しない**: 止める理由の種類ごとの判定そのもの（UC-024 の REQ が持つ）。

### REQ-491

- pattern: Unwanted behaviour
- status: active

> 書き直した世代に、単元の構成が無いか読めないか止める理由に当たる単元の論点を除いて、どの単元の構成のどのまとまりにも入っていない論点があるとき、様式の門はその論点をすべて挙げて止める。

#### 検証方針

- **分割クラス**:
  - `#unknown-topic` — 論点の一覧に無い論点が書き直した世代にあれば、その論点を topicNotInPlan で挙げて止める
  - `#all-listed` — 止める理由は件数で打ち切らず、構成に無い論点をすべて挙げる
- **尽きている根拠**: 論点は、構成の使える単元のどのまとまりにも無い（論点の一覧に無いために単元が決まらない）で尽きる。単元の構成が使えない単元の論点を除くことは、REQ-490 の構成の 3 つのクラスが見る。
- **検証しない**: 構成の使える単元にあり、どのまとまりにも無い論点（構成の門が論点の過不足を止めるので、構成が使えるのにまとまりに無い論点は論点の一覧に無い論点に限られる）。

### REQ-663

- pattern: Unwanted behaviour
- status: active

> 作り手が様式の門に、知らない名前の引数・値の無い引数を渡すか、学びの置き場を渡さないか形の外の値で渡したとき、システムは何も確かめずに断る。

#### 検証方針

- **分割クラス**:
  - `#unknown-argument` — 知らない名前の引数を渡すと、何も確かめずに INVALID_INPUT で断る
  - `#value-missing` — 値の要る引数（学びの置き場・書き直した世代）を名前だけ渡して値を付けないと、何も確かめずに INVALID_INPUT で断る
  - `#arguments-before-syllabus-missing` — 引数を誤り、しかもシラバスの無い学びの置き場を渡すと、シラバスの欠け（NOT_FOUND）でなく引数の誤り（INVALID_INPUT）で断る（契約の errors の順）
  - `#missing-data` — 学びの置き場を渡さないと、同じく断る
  - `#data-not-in-shape` — 学びの置き場を形の外の値で渡すと、同じく断る
- **尽きている根拠**: 文が挙げる引数の誤り（知らない名前・値の無い引数・置き場の欠け・形の外）に 1 つずつ。値の無い引数は、契約の request の値の要る欄 2 つ（data・dir）のどちらでも成り立つので、場合ごとに見る。「何も確かめずに」の順は、契約の errors の先頭（引数の誤り）と、名前の違う最初の後ろの断り（シラバスか論点の一覧が無い。NOT_FOUND）の組で見る
- **検証しない**: 書き直した世代（dir）を形の外の値で渡す場合（REQ-453 のクラスが持つ）。引数の誤りと、すぐ後ろの名前の同じ断り（登録簿に無い学び・資格対策でない学び・書き直した世代の名前でない。どれも INVALID_INPUT）との順（名前で区別できない）
