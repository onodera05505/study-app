# UC-024 資格対策の単元の構成を教材の門で確かめる

## 概要

作り手が、書き手から上がった資格対策の学びの単元の構成を教材の門にかけ、止める理由が無ければ通し、あればその単元と理由を受け取って書き手へ戻す。

## 事前条件

- 資格対策の学びが登録簿にあり、論点とシラバスと単元の構成が学びの置き場にある
- 単元の構成の書き方は執筆の仕様書（`scripts/prompts/unit_plan.md`）が決める
- 適用される業務規則: BR-004, BR-057, BR-058（保証点は ADR-0009）

## 主シナリオ

1. 作り手が、資格対策の学びの単元の構成を教材の門にかける
2. システムが、各単元の構成が必須の要素を持ち、シラバスに実在する単元を指すことを確かめる
3. システムが、構成のある単元の論点が、どれもちょうど 1 つのまとまりに入り、まとまりの論点の数が上限の内にあることを確かめる
4. システムが、受け持ちと前提が実在する論点を指し、学ぶ順と食い違わないことを確かめる
5. システムが、見た単元と論点の数、警告、止める理由を返し、止める理由が無いので通す
6. 作り手が、通ったことを見て、書き直しの束を作るのに回す

## 事後条件

- 成功時: 作り手が、資格対策の学びの単元の構成について「止める理由が無い」という門の結果と、見た単元と論点の数と警告を見ている
- 失敗時: いかなる状態変更も残っていない（部分適用なし。門は単元の構成を書き換えず、止める理由の単元と理由だけが結果に残る）

## 要件

### REQ-442

- pattern: Event-driven
- status: active

> 作り手が資格対策の学びの単元の構成を教材の門にかけたとき、止める理由に当たる単元の構成が無ければ、教材の門は警告の有無によらず通し、見た単元の数と論点の数と、警告ごとの種類と単元と箇所を返す。

#### 検証方針

- **分割クラス**:
  - `#pass-clean` — 止める理由も警告も無い単元の構成だけのとき、通し、見た単元の構成と論点の数と門が使った値を返す
  - `#pass-with-warnings` — 警告だけが当たるとき、通し、警告ごとに種類と単元のファイルと箇所（まとまりは学ぶ順の 1 始まり）を返す
- **尽きている根拠**: 通すか止めるかは止める理由の有無の 2 値で、止める理由が無い側を警告の無い・有るの 2 つに分ける。止める理由が有る側は REQ-444〜448 が持つ
- **検証しない**: 単元の構成が 1 つも無いときの通し方（REQ-450）。箇所の文の言い回しのうち、ファイル名と「まとまり n」以外の部分

### REQ-443

- pattern: Unwanted behaviour
- br: BR-004
- status: active

> 作り手が登録簿に無い学びか資格対策でない学びの単元の構成を教材の門にかけたとき、またはその学びのシラバスか論点の一覧が無いか読めないとき、教材の門は何も確かめずに断る。

#### 検証方針

- **分割クラス**:
  - `#unknown-learning` — 登録簿に無い学びは、置き場と壊れた単元の構成があっても何も確かめずに、終了コード 2 の ToolError（INVALID_INPUT）だけを返す
  - `#not-qualification` — 登録簿のロードマップ型の学びは、同じく INVALID_INPUT で断る
  - `#learning-file-missing` — シラバスか論点の一覧が無い学びは NOT_FOUND で断る
  - `#learning-file-unreadable` — シラバスか論点の一覧が JSON として読めない学びは INVALID_INPUT で断る
  - `#registry-before-files` — 資格対策でなくシラバスも無い学びは INVALID_INPUT（契約の errors の順）
  - `#missing-before-unreadable` — シラバスが無く論点の一覧も読めない学びは NOT_FOUND（契約の errors の順）
- **尽きている根拠**: 断る条件は、登録簿（無い・ロードマップ型）と学びのファイル（シラバス・論点の一覧のそれぞれが無い・読めない）で尽きる。errors の隣り合う組のうち code の違う 2 組を順のクラスにした。資格対策と同じ形の写しを置き、置き場の中身でなく登録簿で断ることを見る
- **検証しない**: `data` の形（`^data/[a-z]+$`）に合わない値（引数の形の検査で、REQ の文が扱わない）。シラバスか論点の一覧が JSON として読めても形が違う場合（読めないの同値で、壊し方の変種は JSON の途切れで代表する）。code の同じ隣り合う組（INVALID_INPUT 同士）の順（観測で区別できない）

### REQ-444

- pattern: Unwanted behaviour
- br: BR-058
- status: active

> 単元の構成のファイルが JSON でないか欄の型か欄の名前が契約の形と合わないとき、教材の門はそのファイルと読めない理由だけを挙げてその中身を他に確かめずに止め、全体像・まとまりの名前と説明と論点の並び・受け持ちの欄・単元の番号と名前のどれかが欠けるとき、単元の番号がファイル名の番号と食い違うとき、指す単元がその学びのシラバスに無いか名前が食い違うとき、または同じ単元にまとまりの名前が重なるときは、そのファイルと理由を挙げて止める。

#### 検証方針

- **分割クラス**:
  - `#unreadable-partial` — 書いている途中で途切れた JSON のファイルを挙げて unreadablePlan で止め、他のファイルの止める理由も打ち切らずに挙げる
  - `#not-plan-shape` — JSON として読めても欄の型が契約と合わない（最上位が配列・まとまりが配列でない・論点に整数でない値・まとまりが文字列）ファイルを unreadablePlan で止める
  - `#unknown-field-unreadable` — 契約に無い欄を持つ（最上位・まとまり・受け持ちのどこか）ファイルを unreadablePlan で止める
  - `#owner-item-incomplete-unreadable` — 受け持ちの項目に subject・owner・topics のどれかが無いか subject が空のファイルを unreadablePlan で止める（missingElement にしない）
  - `#unreadable-skips-content` — 読めないファイルは、他に欠け・上限超え・下限未満・名前の重なり・前提の食い違いを持っていても、そのファイルについて読めない理由 1 件だけを挙げ、他の止める理由も警告も挙げない
  - `#missing-overview` — 全体像が無いか空のファイルを missingElement で止める
  - `#missing-group-element` — まとまりの名前・説明・論点の並びのどれかが無いか空、またはまとまりが無いファイルを missingElement で止める
  - `#missing-owners` — 受け持ちの欄が無いファイルを missingElement で止める
  - `#missing-unit-identity` — 単元の番号か名前が欠けるファイルを missingElement で止める
  - `#unit-no-mismatch` — 単元の番号がファイル名の番号と食い違うファイルを unitNoMismatch で止める
  - `#unknown-unit` — シラバスに無い単元を指すファイルを unknownUnit で止める
  - `#unit-name-mismatch` — 単元の名前がシラバスのその番号の名前と食い違うファイルを unitNameMismatch で止める
  - `#duplicate-group-name` — 同じ単元にまとまりの名前が重なるファイルを duplicateGroupName で止める
  - `#mismatch-kept-with-missing-groups` — まとまりの欄が欠けた（読める）ファイルでも、単元の番号がファイル名と食い違えば missingElement と unitNoMismatch を打ち切らずに両方挙げる
- **尽きている根拠**: 文は読めないファイルと読めるファイルを分け、読めないは JSON でない・欄の型が合わない・欄の名前が合わない・受け持ちの項目の欄が欠けるの 4 つにクラスを 1 つずつ置き、読めないときに中身を確かめないことを 1 つ置く。読めるファイルは、欠ける（全体像・まとまり・受け持ち・単元の番号と名前の欄の群）・番号がファイル名と食い違う・単元が無い・名前が食い違う・名前が重なるの条件ごとに 1 つ。欠けると読めないの境目は、最上位の欄（全体像・まとまり・受け持ち・単元の番号と名前）とまとまりの欄（名前・説明・論点の並び）は無いか空なら欠ける、欄があって型が違うか名前が契約に無いなら読めない。受け持ちの項目の中の欄（subject・owner・topics）は、無いか subject が空なら読めない（契約 UnitPlanFields の受け持ちの項目の required と subject の minLength）。欄ごとの値の変種（無い・空、型の違い方、契約に無い欄の置き場）は各クラスの場合の並びで回す。欠けたファイルは読める側なので、文の「中身を他に確かめずに」は掛からず、欠けと他の止める理由が同時のときも両方挙げる（契約の stops は件数で打ち切らない）。単元を指す側の条件と欠けの同時は、まとまりの欄が無いうえに番号がファイル名と食い違う場合で見る
- **境界の扱い**: 最上位の欄とまとまりの欄の空の文字列・空の配列は型が合っているので欠ける側（missingElement）。受け持ちの項目の空の subject は読めない側（unreadablePlan）。読めないファイルは中身を確かめないので、他の止める理由と同時のときも読めない理由 1 件だけ
- **検証しない**: 受け持ちの項目の空白だけの subject（契約は minLength: 1 だけを決め、空白だけを空と読むかを決めていない）。値が null の欄（欠けと型違いのどちらに当たるかを文と契約が分けていない）。型は合うが契約の範囲の外の値（単元の番号 0・論点の番号 0 など。minimum を欄の型として読むかを文が決めていない）。前提のキーが論点の番号の形でない（propertyNames を欄の名前として読むかを文が決めていない）

### REQ-445

- pattern: Unwanted behaviour
- status: active

> 単元の構成のある単元で、その単元の論点がまとまりの並びにちょうど 1 回だけ現れないとき（どのまとまりにも無い、2 つ以上のまとまりにある、同じまとまりに 2 回以上並ぶ）、またはまとまりに他の単元の論点か学びに無い論点があるとき、教材の門はその単元と論点を挙げて止める。

#### 検証方針

- **分割クラス**:
  - `#topic-not-grouped` — どのまとまりにも入っていない単元の論点を topicNotGrouped で挙げる
  - `#topic-in-many-groups` — 2 つのまとまりに入る論点を topicInManyGroups で挙げる
  - `#topic-repeated-in-group` — 同じまとまりに 2 回並ぶ論点を topicRepeatedInGroup で挙げる
  - `#foreign-topic` — まとまりにある他の単元の論点を foreignTopic で挙げる
  - `#unknown-topic` — まとまりにある学びに無い論点を unknownTopic で挙げる
- **尽きている根拠**: 単元の論点がまとまりの並びに現れる回数は 0・ちょうど 1（正しい側で REQ-442）・2 以上で、2 以上は別のまとまり・同じまとまりに分かれる。まとまりの論点の側は他の単元の論点・学びに無い論点（単元の論点が正しい側）で尽きる
- **検証しない**: 3 回以上現れる場合（2 回と同じ側の値）

### REQ-446

- pattern: Unwanted behaviour
- status: active

> 単元の構成のまとまりに、契約が定める上限を超える数の論点があるとき、教材の門はその単元とまとまりを挙げて止める。

#### 検証方針

- **分割クラス**:
  - `#over-max` — 論点が上限を 1 つ超える（9）まとまりを groupTooLarge で、単元のファイルと「まとまり n」を挙げて 1 件止める
  - `#at-max` — 論点がちょうど上限（8）のまとまりは止めない
  - `#over-max-with-identity-stop` — 同じファイルが単元の番号・名前・指す単元の食い違いで止まるときも、上限を超えるまとまりを groupTooLarge で打ち切らずに挙げる
  - `#over-max-with-missing-element` — 同じファイルが要素の欠け（論点の並びが空のまとまり・単元の番号が無い）で止まるときも、上限を超えるまとまりを groupTooLarge で打ち切らずに挙げる
- **尽きている根拠**: まとまりの論点の数は上限以下と超えるの 2 つで、境目の両側を見る。上限を超えるかはまとまりの論点の数だけで決まり、どの単元を指すかによらないので、同じファイルに単元を指す側の止める理由（番号がファイル名と食い違う・名前がシラバスと食い違う・シラバスに無い単元）が付く場合と付かない場合の両方で見る。欠けたファイルは読める側（REQ-444）なので、要素の欠けで止まる場合にも上限を超えるまとまりを挙げることを、まとまりの側の欠け（論点の並びが空）と単元の側の欠け（単元の番号が無い）で見る
- **検証しない**: 上限の値そのもの（契約の limits の const で、REQ-442 の #pass-clean が応答の値を見る）。同じファイルが読めない（欄の型か欄の名前が契約と合わない）ときにまとまりを確かめないこと（REQ-444 の #unreadable-skips-content が見る）。単元を指す側の止める理由と同時の、単元の論点の側の止める理由（REQ-445。どの単元の論点として数えるかが、番号とファイル名の食い違いでは決まらない）

### REQ-447

- pattern: Unwanted behaviour
- br: BR-057, BR-058
- status: active

> 単元の構成の前提で、前提を持つ側の論点が学びに無い論点かその単元の外の論点のとき、先に読む側の論点が学びに無い論点か自分自身のとき、1 つの論点の前提に同じ論点が 2 回以上並ぶとき、1 つの論点に契約が定める上限を超える本数あるとき、同じ単元の学ぶ順でその論点より後ろの論点を指すとき、または学びの全部の単元の構成の前提をたどって元の論点に戻るとき、教材の門はその論点と前提を挙げて止める。

#### 検証方針

- **分割クラス**:
  - `#prerequisite-key-unknown` — 前提を持つ側が学びに無い論点なら prerequisiteKeyUnknown でその論点を挙げる
  - `#prerequisite-key-foreign` — 前提を持つ側がその単元の外の論点なら prerequisiteKeyForeign でその論点を挙げる
  - `#prerequisite-unknown` — 学びに無い論点を前提にすると prerequisiteUnknown で論点と前提を挙げる
  - `#prerequisite-self` — 自分自身を前提にすると prerequisiteSelf で挙げる
  - `#prerequisite-duplicate` — 1 つの論点の前提に同じ論点が 2 回並ぶ（本数は上限の内、どれも学ぶ順で前）と prerequisiteDuplicate でその論点と前提を挙げ、読めないファイルとはしない
  - `#prerequisite-too-many` — 前提が上限を 1 つ超える（3 本、どれも学ぶ順で前）と prerequisiteTooMany で挙げ、後ろの前提とはしない
  - `#prerequisite-at-max` — 前提がちょうど上限（2 本）なら止めない
  - `#prerequisite-after` — 同じ単元の学ぶ順で後ろの論点を前提にすると prerequisiteAfter で論点と前提を挙げる
  - `#other-unit-allowed` — 他の単元の論点を前提にするだけなら止めない
  - `#cycle-across-units` — 2 つの単元の構成の前提をたどって元に戻ると prerequisiteCycle で論点と前提を挙げる
  - `#cycle-with-missing-element` — 循環に加わる単元の構成の 1 つが論点の並びが空のまとまりで missingElement で止まるときも、prerequisiteCycle を打ち切らずに挙げる
  - `#self-with-missing-element` — 論点の並びが空のまとまりを持つファイルでも、自分自身を前提にする論点を prerequisiteSelf で打ち切らずに挙げる
  - `#key-unknown-with-missing-unit-no` — 単元の番号が欠けたファイルでも、学びに無い論点が前提を持てば prerequisiteKeyUnknown で打ち切らずに挙げる
  - `#unknown-with-missing-unit-no` — 単元の番号が欠けたファイルでも、学びに無い論点を前提にすれば prerequisiteUnknown で打ち切らずに挙げる
  - `#self-with-missing-unit-no` — 単元の番号が欠けたファイルでも、自分自身を前提にする論点を prerequisiteSelf で打ち切らずに挙げる
  - `#duplicate-with-missing-unit-no` — 単元の番号が欠けたファイルでも、前提に同じ論点が 2 回並べば prerequisiteDuplicate で打ち切らずに挙げる
  - `#too-many-with-missing-unit-no` — 単元の番号が欠けたファイルでも、前提が上限を超えれば prerequisiteTooMany で打ち切らずに挙げる
  - `#cycle-with-missing-unit-no` — 循環に加わる単元の構成の 1 つが単元の番号の欠けで止まるときも、prerequisiteCycle を打ち切らずに挙げる
- **尽きている根拠**: 前提を持つ側は学びに無い・単元の外・単元の論点の 3 つ、先に読む側は学びに無い・自分・同じ単元で前・同じ単元で後ろ・他の単元の 5 つ、前提の並びは同じ論点の重なりがある・ない、本数は上限以下と超える、全体はたどって戻るか否かで分かれる。同じ単元の中の循環は必ず後ろを指す 1 本を含むので、循環のクラスは単元をまたぐ物で見る。欠けたファイルは読める側（REQ-444）なので、要素の欠けで止まるファイルの前提も確かめる。単元をまたぐ判定（循環）と単元の中の判定（自分自身）を 1 つずつ、要素の欠けと同時の場合で見る。単元の番号の欠けは、単元が決まらないまま前提を確かめる入力で、まとまりの欠けとは別の同値類になる。そこでは単元に依らない判定（持つ側が学びに無い・前提が学びに無い・自分自身・重なり・本数・循環）を 1 つずつ見る
- **検証しない**: 前提の本数が 0 の論点（キーを書かない決まりで、空の配列のキーは文が扱わない）。重なりのある前提で、重なりを数えると上限を超える並び（[a, a, b] など。上限の本数を重なりごと数えるかを文が決めていない）。単元の番号がファイル名と食い違うファイルで前提を確かめ続けるか（DEFERRED の DEF-121 で保留）。単元の番号が欠けたファイルで、単元に依る判定（前提を持つ側が単元の外・学ぶ順で後ろ）を続けるか（単元をファイル名で決めるかを文が決めていない）

### REQ-448

- pattern: Unwanted behaviour
- br: BR-057
- status: active

> 単元の構成の受け持ちで、触れる論点が 1 つだけのとき、触れる論点に受け持ちの論点が無いとき、受け持ちの論点がその説明に触れる論点のうち学ぶ順で最初の論点でないとき、または触れる論点がその単元の外か学びに無い論点のとき、教材の門はその単元と受け持ちを挙げて止める。

#### 検証方針

- **分割クラス**:
  - `#owner-too-few-topics` — 触れる論点が 1 つだけなら ownerTooFewTopics で単元と受け持ちを挙げる
  - `#owner-not-first` — 受け持ちの論点が触れる論点のうち学ぶ順で最初でなければ ownerNotFirst で挙げる
  - `#owner-not-in-topics` — 受け持ちの論点が触れる論点に無ければ ownerNotInTopics で挙げる
  - `#owner-topic-outside` — 触れる論点に他の単元の論点があれば ownerTopicOutside で挙げる
  - `#owner-topic-unknown` — 触れる論点に学びに無い論点があれば ownerTopicOutside で挙げる
- **尽きている根拠**: 触れる論点の数（1 つ・2 つ以上）、受け持ちの論点の位置（触れる論点に無い・有って最初でない・最初）、触れる論点の行き先（単元の論点・他の単元・学びに無い）で尽きる。正しい側は REQ-442 が持つ
- **検証しない**: 触れる論点が 0 の受け持ち（1 つと同じ側で、形の欠けとも重なる）。受け持ちを挙げる書き方は契約が決めておらず、説明の名前か owners の箇所のどちらかを含むことだけを見る

### REQ-449

- pattern: State-driven
- status: active

> 単元の構成のまとまりの論点の数が契約が定める下限に届かないあいだ、教材の門はそのまとまりを警告として挙げ、止める理由にはしない。

#### 検証方針

- **分割クラス**:
  - `#below-min-warns` — 論点が下限に 1 つ届かない（2）まとまりを groupTooSmall の警告に、単元のファイルと「まとまり n」を挙げて出し、通す
  - `#at-min-no-warning` — 論点がちょうど下限（3）のまとまりは警告に挙げない
  - `#warning-kept-with-stops` — 他の止める理由で止めたときも、下限に届かないまとまりは警告の側にだけ挙げる
  - `#warning-kept-with-identity-stop` — 同じファイルが単元の番号・名前・指す単元の食い違いで止まるときも、下限に届かないまとまりを警告の側に打ち切らずに挙げる
  - `#warning-kept-with-missing-topics` — 同じファイルの別のまとまりの論点の並びが空で missingElement で止まるときも、下限に届かないまとまりを警告の側に打ち切らずに挙げる
- **尽きている根拠**: まとまりの論点の数は下限に届かない・届くの 2 つで、境目の両側を見る。警告が止める理由にならないことは、止めない場合と止める場合の両方で見る。止める場合は、止める理由がまとまりの要素の欠けのときと、単元を指す側（番号がファイル名と食い違う・名前がシラバスと食い違う・シラバスに無い単元）のときに分ける。下限に届くかはまとまりの論点の数だけで決まり、どの単元を指すかによらない。まとまりの要素の欠けは、説明が空（#warning-kept-with-stops）と論点の並びが空（#warning-kept-with-missing-topics）に分ける。論点の並びが空のまとまりは論点を数える欄そのものが欠けるので、他のまとまりの数え方に掛かるかを別に見る
- **検証しない**: 論点が 1 つのまとまり（2 と同じ側の値。REQ-446 の #at-max の仕込みで警告に当たるが、そのテストは止めないことだけを見る）。同じファイルが読めない（欄の型か欄の名前が契約と合わない）ときに警告を挙げないこと（REQ-444 の #unreadable-skips-content が見る）。論点の並びが空のまとまりそのものを警告に挙げるか（欠けで止めるまとまりが下限にも当たるかを文と契約が決めていない。#warning-kept-with-missing-topics は別のまとまりの警告だけを見る）

### REQ-486

- pattern: Ubiquitous
- status: active

> 単元の構成の門は、通すときも止めるときも断るときも、単元の構成・シラバス・論点の一覧のどのファイルも書き換えない。

#### 検証方針

- **分割クラス**:
  - `#unchanged-on-pass` — 通すとき（警告が当たる構成を含む）、学びの置き場のどのファイルも書き換えない
  - `#unchanged-on-stop` — 止めるとき（読めない構成と欠けた構成を含む）、学びの置き場のどのファイルも書き換えない
  - `#unchanged-on-refuse` — 断るとき（登録簿に無い学び・論点の一覧が読めない学び）、学びの置き場のどのファイルも書き換えない
- **尽きている根拠**: 門の結果は文が挙げる通す・止める・断るの 3 つで尽きる。各クラスは学びの置き場の全ファイルの中身を、門にかける前と後で比べる（単元の構成・シラバス・論点の一覧を含み、それより広い）。止めるときは、直したくなる形の崩れ（読めない・欠け）を持つ構成を置く
- **検証しない**: 門が学びの置き場の外（作業ディレクトリの他の場所）に書くこと（文はシラバス・論点の一覧・単元の構成のファイルだけを挙げる）。ファイルの更新時刻だけが変わる書き戻し（中身で比べる）
