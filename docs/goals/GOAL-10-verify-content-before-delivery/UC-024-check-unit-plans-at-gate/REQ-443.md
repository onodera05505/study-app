# REQ-443

> 作り手が登録簿に無い学びか資格対策でない学びの単元の構成を教材の門にかけたとき、またはその学びのシラバスか論点の一覧が無いか読めないとき、教材の門は何も確かめずに断る。

## 検証方針

- **分割クラス**:
  - `#unknown-learning` — 登録簿に無い学びは、置き場と壊れた単元の構成があっても何も確かめずに、終了コード 2 の ToolError（INVALID_INPUT）だけを返す
  - `#not-qualification` — 登録簿のロードマップ型の学びは、同じく INVALID_INPUT で断る
  - `#learning-file-missing` — シラバスか論点の一覧が無い学びは NOT_FOUND で断る
  - `#learning-file-unreadable` — シラバスか論点の一覧が JSON として読めない学びは INVALID_INPUT で断る
  - `#registry-before-files` — 資格対策でなくシラバスも無い学びは INVALID_INPUT（契約の errors の順）
  - `#missing-before-unreadable` — シラバスが無く論点の一覧も読めない学びは NOT_FOUND（契約の errors の順）
- **尽きている根拠**: 断る条件は、登録簿（無い・ロードマップ型）と学びのファイル（シラバス・論点の一覧のそれぞれが無い・読めない）で尽きる。errors の隣り合う組のうち code の違う 2 組を順のクラスにした。資格対策と同じ形の写しを置き、置き場の中身でなく登録簿で断ることを見る
- **検証しない**: `data` の形（`^data/[a-z]+$`）に合わない値（引数の形の検査で、REQ の文が扱わない）。シラバスか論点の一覧が JSON として読めても形が違う場合（読めないの同値で、壊し方の変種は JSON の途切れで代表する）。code の同じ隣り合う組（INVALID_INPUT 同士）の順（観測で区別できない）
- **参照先**: `tests/server/UC-024_check_unit_plans.test.ts::登録簿に無い学び・資格対策でない学び・シラバスか論点の一覧が無いか読めない学びは断る（REQ-443）`
