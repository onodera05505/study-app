# UC-029 書き直した世代の資格対策の教材を束の継ぎ目の門で確かめる

## 概要

作り手が、別々の書き手が束ごとに書き直した世代の資格対策の教材を継ぎ目の門にかけ、論点どうしの比較の持ち場と点の台帳の行き先が教材のデータだけで食い違わないかを確かめ、止める理由が無ければ通し、あればその論点と理由を警告と一緒に受け取って書き手へ戻す。

## 事前条件

- 資格対策の学びが登録簿にあり、論点の一覧・シラバス・書き直した世代の教材・単元の構成・図の仕様・点の台帳が学びの置き場にある
- 比較の持ち場の決まりは執筆の仕様書（`scripts/prompts/write_materials.md` の「他の論点との分担」）、学ぶ順は単元の構成（`scripts/prompts/unit_plan.md`）が決める
- 適用される業務規則: BR-004

## 主シナリオ

1. 作り手が、書き直した世代の教材を継ぎ目の門にかける
2. システムが、書き直した世代の論点ごとに、混同しやすい用語の見出しの下の項目と表の行の先頭に示した用語が、同じ単元で学ぶ順の後の論点を指していないことを確かめる
3. システムが、前の単元の論点の同じ箇所が後の単元の論点を指すものを警告として挙げる
4. システムが、点の台帳の行き先が名指す見出しと図が、今の教材と図の仕様にあることを確かめ、無いものを警告として挙げる
5. システムが、見た論点の数、警告、止める理由を返し、止める理由が無いので通す
6. 作り手が、通ったことを見て、図の差し込みと投入に回す

| 書き手が書いている途中の束のファイル・点の台帳を門にかける | REQ-517 |
| 前の論点の混同しやすい用語の項目か表の行の先頭の用語が、同じ単元で学ぶ順の後の論点を指す | REQ-518 |
| 前の単元の論点の混同しやすい用語の項目か表の行の先頭の用語が、後の単元の論点を指す | REQ-519 |
| 点の台帳の行き先が見出しだけか図だけを名指し、その見出しが今の教材に無いか、その図が図の仕様に無い | REQ-520 |
| 本文の見出し・文が後の論点の語との比較を言う（混同しやすい用語の項目と表の行の先頭の外） | 不可: 語の一致だけでは比較か別の語の一部かを決められない（「RAM」と「SRAM」、「クラス」と「クラスタ」）。単元の突き合わせの段が読む |
| 受け持ちの行が比較を書いている、受け持ちの論点の本文にその説明が無い | 不可: 受け持ちの説明の名前は自由な文で、本文のどこが受けるかを機械で決められない。受け持ちの形の食い違いは単元の構成の門（UC-024）が止める |
| 本文が書いた数（「3 つ」「6 段」）と続く箇条か表の行の数が合わない | 不可: 表の列や別の節が数える物を持つ書き方があり、数が合わない物の多くが食い違いでない |
| 他の論点を指す文の先にその中身が無い、図を指す文の先にその図の中身が無い | 不可: 指す先に中身があるかは文の意味で決まる。読む担当が見る |
| 図の中の文字が後の論点の語との比較を持つ | 不可: 図の仕様の文字は用語の印を持たず、語の一致では比較と決められない |
| 同じ単元の 2 論点の本文が長く一致する | 不可: 様式の門（UC-025）が警告し、継ぎ目の門は重ねて確かめない |
| どの状態でも（門が読む教材・単元の構成・点の台帳・図の仕様は、門にかける前と同じ） | REQ-521 |

## 事後条件

- 成功時: 作り手が、書き直した世代の教材について「止める理由が無い」という門の結果と、見た論点の数と警告を見ている
- 失敗時: いかなる状態変更も残っていない（部分適用なし。門は教材も単元の構成も点の台帳も図の仕様も書き換えず、止める理由の論点と理由だけが結果に残る）
