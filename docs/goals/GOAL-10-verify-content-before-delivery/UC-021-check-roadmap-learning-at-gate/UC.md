# UC-021 ロードマップ型の学び全体を配る前に教材の門で確かめる

## 概要

作り手が、すべての束がそろったロードマップ型の学び全体を、独立解答を添えるか添えずに教材の門にかけ、止める理由が無ければ通し、あればその単位か問題と理由を受け取って直しに回す。

## 事前条件

- ロードマップ型の学びが登録簿にあり、ロードマップ・教材・確認問題・集めた資料が学びの置き場にある
- 適用される業務規則: BR-004, BR-025, BR-037, BR-042, BR-043

## 主シナリオ

1. 作り手が、学び全体を、書き手の独立解答を添えて教材の門にかける
2. システムが、ロードマップの学ぶ順・章・印・要約がそろっていることを確かめる → BR-037
3. システムが、ロードマップのどの単位にも教材があり、各教材が必須の要素を持ち、決めた記法で書かれ、出典と用語が学びで解決でき、登録簿が禁じた書き方を含まないことを確かめる → BR-025
4. システムが、確認問題の形と単位ごとの数を確かめ、独立解答と正解の食い違いが閾値の内にあることを確かめる
5. システムが、情報の量を見ずに、表示の制約と書き方と確認問題の手がかりとロードマップの並びの気になる所を警告として挙げる → BR-042, BR-043
6. システムが、見た論点と問題の数、警告、止める理由を、人が読む行と末尾の機械向けの 1 行で返し、止める理由が無いので通す
7. 作り手が、通ったことを見て、教材と確認問題を配る本文の組み立てと投入に回す

## 事後条件

## 要件

### REQ-374
- pattern: Event-driven
- status: active

> 作り手がロードマップ型の学び全体を教材の門にかけたとき、止める理由に当たる単位・教材・要約・確認問題・独立解答が無ければ、教材の門は警告の有無によらず通し、見た論点と問題の数と、警告ごとの種類と単位か論点か問題と箇所を返す。

#### 検証方針

- **分割クラス**:
  - `#pass-without-solutions` — 止める理由も警告も無い学び全体を独立解答なしでかけると、終了の状態 0・止める理由 0 件・警告 0 件
  - `#pass-with-solutions` — 食い違いが閾値の内の独立解答を添えてかけると通す
  - `#pass-with-warnings` — 警告だけが当たる学び全体は通し、警告ごとに種類と箇所を返す
  - `#counts` — 見た論点の数はロードマップの単位の数、問題の数はその単位の確認問題の数（補足の論点は数えない）
- **尽きている根拠**: 通すか止めるかは止める理由の有無の 2 値で、通す側を「独立解答の有無」×「警告の有無」で分け、返す数を 1 クラスにした。止める理由が有る側は REQ-379〜388 が持つ
- **検証しない**: 箇所の文の言い回し（論点の ID・論点名・ファイル名・問題の識別子のどれかを含むことだけを見る）

### REQ-375
- pattern: Unwanted behaviour
- br: BR-004
- status: active

> 作り手が必須の引数を渡さないか知らない名前の引数か値の無い引数を渡したとき、登録簿に無い学びかロードマップ型でない学びを学び全体の門にかけたとき、またはその学びのロードマップが無いか契約のロードマップの形として読めないとき、教材の門は何も確かめずに断る。

#### 検証方針

- **分割クラス**:
  - `#bad-arguments` — 学びの置き場の引数が無い・知らない名前の引数・値の無い学びの置き場の引数は INVALID_INPUT で断る（場合ごと）
  - `#unknown-learning` — 登録簿に無い学び（zzz）は、ロードマップ型の置き場の形があっても INVALID_INPUT で断る
  - `#exam-learning` — 資格対策の学び（ip）は、ロードマップ型の置き場の形があっても INVALID_INPUT で断る
  - `#learning-dir-missing` — 置き場の無いロードマップ型の学びは NOT_FOUND で断る
  - `#roadmap-missing` — ロードマップの無い学びは NOT_FOUND で断る
  - `#roadmap-not-json` — JSON として読めないロードマップは INVALID_INPUT で断る
  - `#roadmap-without-units` — units の無いロードマップは INVALID_INPUT で断る
  - `#not-roadmap-before-roadmap-missing` — ロードマップ型でなくロードマップも無い学びは INVALID_INPUT（errors の 3 番目が 4 番目に先立つ）
  - `#roadmap-unreadable-before-solution-missing` — ロードマップが読めず独立解答のファイルも無いときは INVALID_INPUT（errors の 5 番目が 6 番目に先立つ）
- **尽きている根拠**: 断る条件は引数（無い・知らない名前・値が無い）と登録簿（無い・ロードマップ型でない）とロードマップ（置き場ごと無い・ファイルが無い・JSON でない・units が無い）で尽きる。errors の隣り合う組のうち、両方を満たす入力があり code が違う組を順のクラスにした。どの断りも、止める理由と警告を返さないこと（何も確かめないこと）を同じテストで見る
- **検証しない**: 登録簿に無い学びとロードマップ型でない学びの順（両方を満たす学びが無い）、ロードマップが無いと読めないの順（両方を満たす入力が無い）、code の同じ隣り合う組（1・2 番目、2・3 番目。観測で区別できない）。値を並べない独立解答の引数（独立解答を添えない呼び方と同じに読む）

### REQ-376
- pattern: Unwanted behaviour
- status: active

> 作り手が添えた独立解答のファイルのどれかが無いか、契約の独立解答の形として読めないとき、教材の門は何も確かめずに断る。

#### 検証方針

- **分割クラス**:
  - `#solution-missing` — 添えた独立解答のファイルのどれかが無ければ NOT_FOUND で断る
  - `#solution-not-json` — JSON として読めない独立解答は INVALID_INPUT で断る
  - `#solution-without-answers` — answers を持たない独立解答は INVALID_INPUT で断る
  - `#answer-outside-choices` — ア〜エでない答えを持つ独立解答は INVALID_INPUT で断る
  - `#missing-before-unreadable` — 読めない独立解答と無い独立解答を添えたときは NOT_FOUND（errors の 6 番目が 7 番目に先立つ。添える順は読めない方が先）
  - `#refused-before-checking` — 止める理由のある学びでも、独立解答が無ければ止める理由を返さずに断る
- **尽きている根拠**: 断る条件は、ファイルが無い（NOT_FOUND）と、契約の独立解答の形として読めない（JSON でない・answers が無い・答えが記号の外）で尽きる。errors の 6・7 番目の組は code が違うので順のクラスにした
- **検証しない**: 独立解答の answers が問題の識別子でない鍵を持つ場合（形の上では読めるので REQ-388 の食い違いの側。REQ の文がどちらとも決めない）

### REQ-377
- pattern: Ubiquitous
- br: BR-042
- status: active

> 学び全体の門は、教材の説明と詳しい解説と要約の字数・文数・見出しの数・箇条書きや比較の項目の数がどれだけ多くても少なくても、それを止める理由にせず、表の列と行の数とセルの字数が契約の表示の制約から外れるときのほかは警告にもしない。

#### 検証方針

- **分割クラス**:
  - `#long-material` — 説明 60 文・詳しい解説が 10 の見出しと 60 文超・要約 200 字の単位を、止める理由にも警告にも挙げない
  - `#short-material` — 説明と詳しい解説の各節が 1 文・要約が 2 字の単位を挙げない
  - `#many-items` — 箇条書き 30 項目・比較の項目 20 項目の単位を挙げない
- **尽きている根拠**: 情報の量の軸（字数・文数・見出しの数・項目の数）を多い側と少ない側の両端で代表した。表の列・行・セルの字数は REQ-378 が持つ
- **境界の扱い**: 上限・下限を持たないので境目のクラスは無い（両端の値で代表する）
- **検証しない**: 長さの値の中間（両端で挙げなければ中間でも挙げない、と読む）

### REQ-378
- pattern: Unwanted behaviour
- br: BR-043
- status: active

> 学び全体の教材の表の列か行の数が契約の表示の制約の下限に満たないか上限を超えるとき、または表のセルの字数が上限を超えるとき、教材の門は止めずに、その論点と箇所を警告として挙げる。

#### 検証方針

- **分割クラス**:
  - `#too-many-columns` — 列が上限 + 1 の表を tableTooWide で警告する（止めない）
  - `#too-few-columns` — 列が下限 − 1 の表を tableTooNarrow で警告する
  - `#too-few-rows` — 行（ヘッダを含む）が下限 − 1 の表を tableTooShort で警告する
  - `#too-many-rows` — 行（区切りの行を数えない）が上限 + 1 の表を tableTooLong で警告する
  - `#cell-too-long` — セルの字数が上限 + 1 の表を tableCellLong で警告する
  - `#within-limits` — 列・行・セルの字数が上限ちょうどの表と、列・行が下限ちょうどの表は警告しない
- **尽きている根拠**: 表示の制約の 5 つの境目（列の上下・行の上下・セルの上限）のそれぞれの外側 1 つと、内側のちょうどの値で尽きる
- **境界の扱い**: 値は契約の limits（tableColumns・tableRows・tableCellLength）から読み、境目の外側は 1 だけ外す
- **検証しない**: 要約・説明の中の表（表は詳しい解説に置くと読み、詳しい解説で代表する）

### REQ-379
- pattern: Unwanted behaviour
- status: active

#### 検証方針

- **分割クラス**:

  - `#mechanism-heading-missing` — 詳しい解説に「しくみ」の見出しが無い教材を止める

  - `#required-field-missing` — 必須の欄（詳しい解説）が無い教材を止める

- **検証しない**: 必須の欄のうち論点の ID と論点名の欠け（論点名の欠けは REQ-380 の食い違いと区別できない。欄ごとの変種は説明と詳しい解説で代表する）

### REQ-380
- pattern: Unwanted behaviour
