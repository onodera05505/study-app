# UC-043 手元のクローンにコミットの件名の検査を入れる

## 概要

運用者が手元のクローンにコミットの件名の検査を入れることで、配信する版の履歴を決めた件名の形で残す。

## 事前条件

- 手元の作業環境がこのリポジトリのクローンで、git が使える

## 主シナリオ

1. 運用者が、コミットの件名の検査を入れる
2. システムが、このクローンの git のフックの置き場をリポジトリの中のフックの置き場に向け、向けた先と試し方を示す

## 状態 × イベント表

| クローンの状態 \ イベント | コミットの件名の検査を入れる |
| --- | --- |
| フックの置き場がまだ向いていないか、既に向いている | REQ-652 |

## 例外系の走査（4 分類）

| 軸 | 該当ステップ | 導出 |
| --- | --- | --- |
| 権限 | 1 | なし（手元のクローンの設定だけを変える） |
| 不変条件違反 | 2 | なし（何度回しても同じ置き場に向く） |
| 並行性 | 2 | なし |
| 外部依存 | 2 | git の設定 → REQ-652 |

## 事後条件

- 成功時: 運用者が、このクローンのフックの置き場がリポジトリの中の置き場に向いたことを見ている
- 失敗時: 理由が示されている

## 要件

### REQ-652

- pattern: Event-driven
- status: active

> 運用者がコミットの件名の検査を入れたとき、システムはリポジトリの中のフックを実行できるようにし、このクローンの git のフックの置き場をその置き場に向け、向けた先と試し方を示す。

#### 検証方針

- **分割クラス**:
  - `#hooks-made-executable` — 実行できない印のフックが、実行できるようになる
  - `#hooks-path-set` — このクローンのフックの置き場が、リポジトリの中の置き場（`.githooks`）に向き、成功で終える
  - `#target-and-try-shown` — 向けた先と、件名の検査のフック（commit-msg）の試し方を示す
  - `#already-pointed` — 既に向いているクローンで回しても、成功で終え、向きは 1 つのまま変わらない
  - `#only-this-clone` — 利用者の git の設定（このクローンの外）は書き換えない
- **尽きている根拠**: 文の振る舞い（実行できるようにする・向ける・示す）に 1 つずつ置き、UC の表の 2 つの状態（まだ向いていない・既に向いている）のうち後の物を 1 つ足す。「このクローンの」を、クローンの外を変えない場合で 1 つ見る
- **境界の扱い**: 道具はクローンの git の設定を書き換えるので、一時の置き場に git init した別のクローンで回し、利用者の git の設定も一時の置き場に向ける
- **検証しない**: 試し方の文言と、示した試し方を実行した結果（文は示すことだけを言う）。git が使えない環境（UC の事前条件の外）
