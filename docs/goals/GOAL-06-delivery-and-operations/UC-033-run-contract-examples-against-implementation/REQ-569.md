# REQ-569

> 契約の実例が本番の保存先・配備先・外の相手に触れる操作の物であっても、システムは契約の実例の確かめの中でそれらに何も送らない。

## 検証方針

- **分割クラス**:
  - `#production-store` — 本番の保存先を読み書きする操作の実例（投入を流す手続きの seedRemote、投入後の突き合わせの verifySeedRemote）を回しても、本番の保存先に要求も書き込みも届かない
  - `#deploy-target` — 配備先に触れる操作の実例（配備先から秘密の名前の一覧を取る listDeploymentSecretNames。他者の形を写した操作なので、写しの操作も回すと指定したときだけ回る）を回しても、配備先に何も届かない
  - `#external-party` — 外の相手を呼ぶ操作の実例（本番の検査が配備を外から叩く checkDeploymentHealth・readDeploymentHealthHeaders・openDeploymentEntry・probeRetiredPasswordRoute、学び側からまなびばへ交換を求める signInWithCode、版の印を取りに行く fetchVersionStamp）を回しても、外の相手に何も届かない
- **尽きている根拠**: 手元の外にあるものは、本番の保存先・配備先・外の相手の 3 つに尽きる。
- **検証しない**: 手元に用意した代わりの相手の作り（実装の手段）。
- **参照先**: `tests/server/UC-033_no_outside.test.ts`（子のプロセスすべての外向きの通信を、記録する代理と node の接続を記録して断る前置きに集め、記録が空であることで見る。`#deploy-target` は写しの操作を回す指定（`--include-external`）の有無で 2 回回す）
