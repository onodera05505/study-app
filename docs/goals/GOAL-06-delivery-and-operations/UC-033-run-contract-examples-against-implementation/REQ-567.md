# REQ-567

> 運用者が契約の実例の確かめを回すとき、システムは確定した契約の自分の持ち物の操作の実例をすべて実装に渡し、成功例では実装の応答が例の応答を含み、失敗例では実装が例と同じ断りの種類の名前で断ったときだけ、通ったことを示して終える。

## 検証方針

- **分割クラス**:
  - `#success-shape` — 成功例を渡し、実装の応答が例の応答を含む（応答の余分な欄は含むことを妨げない）
  - `#failure-name` — 失敗例を渡し、実装が例と同じ名前で断る
  - `#all-examples` — 確定した契約の自分の持ち物の操作の実例の全件が渡され、全件が合ったときだけ通ったことを示す（下書きの契約と、他者の形を写した操作の実例は渡さない）
- **尽きている根拠**: 実例は成功例と失敗例の 2 つに尽き、通る条件はそれぞれの照らし方（含む・同じ名前）だけ。合わない側は REQ-568 が持つ。
- **検証しない**: 応答の中身の意味（各操作の要件のテストが持つ）。どの経路にも同じ形で立つ断り（ADR-0011。契約の実例に無いので、受け口の要件のテストが持つ）。
- **参照先**: テスト設計の担当が決める
