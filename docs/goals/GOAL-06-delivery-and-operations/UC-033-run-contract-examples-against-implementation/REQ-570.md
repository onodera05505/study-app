# REQ-570

> システムは、契約の実例の確かめで、各実例をその実例が前提とする状態を用意してから回し、ほかの実例を回したかどうかと回した順によって、その実例の結果を変えない。

## 検証方針

- **分割クラス**:
  - `#same-request-different-premise` — 同じ入力で成功例と失敗例が並ぶ操作（前提の状態だけが違う。例の名前と契約の `when` で見分ける）で、どちらも例どおりに応える
  - `#order-independent` — 実例を 1 件だけ回したときと、ほかの実例のあとに回したとき、順を入れ替えたときで結果が同じ
  - `#premise-identity` — 本人や権限を前提とする実例で、その実例が前提とする本人と権限が用意されている
- **尽きている根拠**: 実例の結果を変えうるのは、その実例が前提とする状態と、ほかの実例が残した状態の 2 つ。前者は前提の用意（クラス 1・3）、後者は回し方の違い（クラス 2）で尽きる。
- **検証しない**: 前提の状態の用意の作り（実装の手段）。
- **参照先**: テスト設計の担当が決める
