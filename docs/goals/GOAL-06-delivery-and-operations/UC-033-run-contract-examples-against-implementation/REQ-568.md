# REQ-568

> 契約の実例の確かめで、実装の応えが例と合わない実例、応答も断りの名前も持たない実例、または実装に渡せない実例が 1 件でもあれば、システムはその実例を挙げて失敗で終える。

## 検証方針

- **分割クラス**:
  - `#success-mismatch` — 成功例に、実装が例の応答を含まない応答を返すか、断る（名前を出さずに止まる・断るのも断り。例の応答が終了の状態や状態の番号だけでも合わない）
  - `#failure-mismatch` — 失敗例に、実装が応答を返すか、例と違う名前で断る
  - `#failure-unnamed` — 失敗例に、実装が名前を出さずに断る（道具が終了の状態だけで止まる・HTTP の状態の番号だけで断る）
  - `#malformed-example` — 応答も断りの名前も持たない実例がある
  - `#unreachable` — 当たる入口が無い実例か、実装が応えない実例がある（回さずに通す実例は無い）
- **尽きている根拠**: 合わない形は、成功例の取り違え・失敗例の取り違え・名前の欠け・例そのものの不備・渡せないの 5 つに尽きる。1 件でもあれば失敗で終えることは、各クラスで合う実例と混ぜて見る。
- **検証しない**: 失敗を示す文の文言。
- **参照先**: `tests/server/UC-033_contract_run.test.ts`（照らす側だけを差し替えた影の置き場（`--docs`）と、道具 1 本か契約の wire の成功の状態を差し替えた影の根（`--root`）で作る。実装とアダプターは本物のまま）。`#unreachable` のうち、外の相手を呼ぶ操作の要求を道具が送らない場合は `tests/server/UC-033_prod_check_examples.test.ts`（本番の確かめの道具を包み、決めた経路だけを開かない影の根（`--root`）で作る）
