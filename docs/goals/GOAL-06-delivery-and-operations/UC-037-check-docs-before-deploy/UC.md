# UC-037 配備の前に、文書の索引と門の対応表と決定の記録が現物と食い違っていないことを確かめる

## 概要

運用者が配備の前に文書の検査を回し、システムが文書の索引・門の対応表・決定の記録・審議台帳を現物と照らすことで、名指した物が消えた文書のまま配らないようにする。

## 事前条件

- 手元の作業環境に、配信しようとする版のソースと文書がそろっている
- 手元の作業環境がこのリポジトリのクローンで、git が使える

## 主シナリオ

1. 運用者が、文書の検査を回す
2. システムが、文書と報告書の索引、門の対応表が名指すパス、仕様書の現在形、決定行の反映先、作業ログの還元行、道具の複製、対象の登録簿の整合、審議台帳を確かめる
3. システムが、食い違いをすべて挙げるか、一致したことを示して終える
4. 運用者が、一致したことを見て配備に進む

## 状態 × イベント表

| 文書の状態 \ イベント | 文書の検査を回す | 審議台帳の検査を回す |
| --- | --- | --- |
| 文書と記録が現物と一致する | REQ-601 | REQ-602 |
| 索引・門の対応表・決定行・還元行・登録簿のどれかが現物と食い違う | REQ-601 | 不可: 審議台帳の検査は台帳と判断基準だけを読む |
| 審議台帳の行が判断基準に無い規則を名指すか、規則を名指さないか、列が足りない | REQ-601 | REQ-602 |
| 門の対応表が名指すパスが、手元にあってもリポジトリが追跡していないか、置き場で追跡を確かめられない | REQ-680 | 不可: 審議台帳の検査は台帳と判断基準だけを読む |

## 例外系の走査（4 分類）

| 軸 | 該当ステップ | 導出 |
| --- | --- | --- |
| 権限 | 1 | なし（手元の作業環境の道具で、読むだけ） |
| 不変条件違反 | 2・3 | 文書や記録が名指す物が現物と食い違う → REQ-601・REQ-602／門の対応表が名指す物をリポジトリが追跡していない → REQ-680 |
| 並行性 | 2 | なし（読むだけで書き換えない） |
| 外部依存 | 2 | 審議台帳の検査を中で回す → REQ-601・REQ-602／中央の還元行の検査の道具の有無 → REQ-601／置き場が git の作業ツリーの根でないか、git が追跡の確かめを断る → REQ-680 |

## 事後条件

- 成功時: 運用者が、文書の索引と門の対応表と決定の記録が現物と一致したことを見ている
- 失敗時: 食い違いがすべて挙げられて失敗で終わっており、文書は書き換わっていない

## 要件

### REQ-601
- pattern: Event-driven
- status: active

> 運用者が文書の検査を回したとき、システムは文書と報告書の索引の網羅、門の対応表が名指すパスの実在、仕様書の本文の現在形、決定行の反映先の実在、作業ログの還元行（中央の還元行の検査があれば文法も）、リポジトリに写した追跡の道具が共通の置き場の正本と同じこと（正本が無ければ見ない）、対象の登録簿の整合、審議台帳を確かめ、食い違いがあればすべて挙げて失敗で終え、無ければ一致したことを示して成功で終える。

#### 検証方針

- **分割クラス**:
  - `#all-consistent` — 今のリポジトリでは、食い違いが無く、一致したことを示して成功で終える
  - `#doc-not-in-index` — 文書の索引に無い文書が `docs/` にあると、その文書を挙げて失敗で終える
  - `#report-not-in-index` — 報告書の索引に無い報告書があると、その報告書を挙げて失敗で終える
  - `#gate-path-missing` — 門の対応表が名指すパスが無いと、そのパスを挙げて失敗で終える
  - `#spec-not-present-tense` — 仕様書の本文に経緯の言い回しがあると、その仕様書を挙げて失敗で終える
  - `#decision-target-missing` — 決定行の反映先が無いと、その反映先を挙げて失敗で終える
  - `#return-line-missing` — 還元行の要る作業ログに還元行が無いと、その作業ログを挙げて失敗で終える
  - `#return-line-grammar-no-central` — 中央の還元行の検査の道具が手元に無いときは、還元行の文法を見ず、文法に合わない還元行（素の「ブレイン: 無し」）だけでは失敗にしない
  - `#tracking-tool-copy-differs` — リポジトリに写した追跡の道具が手元の共通の置き場の正本と違うと、その道具を挙げて失敗で終える
  - `#tracking-tool-no-central` — 共通の置き場の正本が無いときは、写した追跡の道具を見ず、それでは失敗にしない
  - `#registry-mismatch` — 対象の登録簿にある対象が配備先の一覧に無いと、その対象を挙げて失敗で終える
  - `#ledger-problem` — 審議台帳に判断基準に無い規則を名指す行があると、失敗で終える
  - `#all-mismatches-listed` — 食い違いが 2 つの種類にあると、両方を挙げて失敗で終え、文書を書き換えない
- **尽きている根拠**: 文が挙げる確かめる物（索引 2 つ・門の対応表・現在形・決定行・還元行・追跡の道具の写し・登録簿・審議台帳）ごとに食い違う場合を 1 つ、全部一致する場合を 1 つ置き、「すべて挙げる」を 2 つの種類が同時の場合で見る。追跡の道具の写しは、正本の置き場が無いときに見ない場合を 1 つ足す。還元行の文法は、中央の検査の道具が無いときに見ない場合を 1 つ足す
- **境界の扱い**: リポジトリに写した追跡の道具は `scripts/trace/` の物、共通の置き場の正本は `~/.claude/brain/tools/trace/` の同じ名前の物と読む（`docs/INVENTORY.md`）。門の対応表が名指すパスは REQ-680 の境界の扱いと同じく読む（先頭の置き場で絞らない）
- **検証しない**: 経緯の言い回しの語の一覧（語の正本は道具。「以前は」1 語で見る）。中央の還元行の検査の道具が手元にあるときの文法の中身（文法の正本はその中央の道具で、リポジトリの外にある）

### REQ-602
- pattern: Event-driven
- status: active

> 運用者が審議台帳の検査を回したとき、システムは台帳の各行が名指す規則が判断基準にあるかを確かめ、判断基準に無い規則・規則を名指さない行・列の足りない行があればそれを挙げて失敗で終え、決定が空でも「（」で始まるのでもなく、案の「（」より前の部分が決定の中に含まれない行の数を、案と決定がずれた行の数として示す。

#### 検証方針

- **分割クラス**:
  - `#consistent` — どの行も判断基準にある規則を名指し、列がそろっていると、成功で終える
  - `#unknown-rule` — 判断基準に無い規則を名指す行があると、その規則を挙げて失敗で終える
  - `#no-rule` — 規則を名指さない行があると、失敗で終える
  - `#columns-short` — 列の足りない行があると、失敗で終える
  - `#drift-count-shown` — 決定が空でも「（」で始まるのでもなく、案の「（」より前の部分が決定に含まれない行の数を、ずれた行の数として示す（ずれた行は失敗にしない）
- **尽きている根拠**: 文が挙げる失敗の形は 3 つ（無い規則・規則が無い・列が足りない）に尽き、1 つずつ置く。問題が無い場合と、ずれの数を示すことを 1 つずつ置く
- **境界の扱い**: ずれは文字の含みで数える。案「採用」・決定「不採用」は、案の語が決定の中に含まれるのでずれに数えない。決定が「（」で始まる行（「（同上）」など）と、案か決定が空の行は数えない

### REQ-680

- pattern: Unwanted behaviour
- status: active

> 運用者が文書の検査を回すときに、門の対応表が名指すパスが、手元にあってもリポジトリが追跡していないか、置き場が追跡を確かめられないとき、システムはそのパスか確かめられない理由を挙げて失敗で終える。

#### 検証方針

- **分割クラス**:
  - `#gate-path-untracked` — 門の対応表が、手元にあってリポジトリが追跡していないファイルを名指すと、そのパスを挙げて失敗で終える
  - `#gate-path-ignored` — 名指すファイルが git の無視する物（`.gitignore` に当たる物）でも、同じく挙げて失敗で終える
  - `#gate-path-any-top-untracked` — 名指すパスの先頭の置き場が何でも（`.githooks`・`tests`・`migrations`・`portal` など、`scripts`・`src`・`.claude`・`docs`・`brain`・`data`・`public` の外の置き場）、手元にあってリポジトリが追跡していなければ、そのパスを挙げて失敗で終える（先頭の置き場を値の変種に）
  - `#gate-path-tracked-passes` — 門の対応表が名指すパスをすべてリポジトリが追跡していれば、この確かめでは失敗にしない
  - `#tracking-unverifiable-fails` — 置き場が git の作業ツリーの根でないか、git が追跡の確かめを断ると、確かめられない理由を示して失敗で終える（`.git` の無い写し・git に断られる置き場を値の変種に）
- **尽きている根拠**: 名指したファイルの 3 つの状態（追跡されている・追跡されていない・無視されている）に 1 つずつ置く。名指すパスを先頭の置き場で絞らないことを、絞りうる置き場の外のパスで 1 つ置く。追跡を確かめられる置き場かどうかで 1 つ足す。無い場合は REQ-601 の `#gate-path-missing` が持つ
- **境界の扱い**: 門の対応表が名指すパスは、対応表の中の `` ` `` で囲んだ、空白を含まず `/` を含む、根からの相対の書き方の物で、先頭の置き場で絞らない（`/` で始まる物は根からの相対のパスでなく、画面や API の経路なので読まない）。「リポジトリが追跡している」は、git の索引にそのパスがあること（ディレクトリは、その下に索引のパスが 1 つ以上あること）。「追跡を確かめられない」は、置き場が git の作業ツリーの根でないこと（`.git` の無い写し・別の作業ツリーの中の置き場）か、git の索引の読み出しを git が断ること（持ち主の違いで断る・`.git` が読めない など）。影の根を git の作業ツリーにして、追跡する物・追跡しない物・無視する物を作る。確かめられない置き場は、`.git` の無い影の根と、`.git` が読めない物を指す影の根で作る
- **検証しない**: 名指しの形が `<` や `*` を含むパス（REQ-601 と同じく、パスとして読まない）。git の道具そのものが無い作業環境（UC の事前条件の外）
