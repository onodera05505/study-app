# UC-036 配る前に手元の配備に API と画面を当てて、契約と食い違う応答と崩れた画面を見つける

## 概要

運用者が、手元に起こした学びとまなびばの配備に API の検査を当て、検査用のアカウントで画面を採取することで、契約や要件と食い違う応答と崩れた画面を、配る前に見つける。

## 事前条件

- 手元の作業環境に、配信しようとする版のソースと、手元の保存先がそろっている
- 検査用のアカウントの用意と画面の採取では、学び側の配備を、まなびばの場所として検査用のアカウントの道具が起こす手元の SSO の偽物の場所と、共有秘密としてその偽物と同じ値を与えて起こしておく（値の正本は `scripts/audit_fixtures.mjs`。画面の採取の入口が起こす）
- 手元の SSO の一巡では、次の状態が成り立っている（口の番号・学び・メールとパスワードの値の正本は `scripts/check_sso_flow.py`）: 手元のまなびばと手元の学び mkt の配備が決まった口で応じ、両方に同じ手元用の共有秘密が与えられ、学び側にはまなびばの場所として手元のまなびばとトークンの署名の秘密が与えられている。手元のまなびばに、一巡の道具が使うメールとパスワードでログインでき、学び mkt の権限を持つ管理者がいる

## 主シナリオ

1. 運用者が、学びを指定して API の検査を回す
2. システムが、手元に学びの配備を起こし、要求を当てて応答を契約と登録簿に照らし、食い違いを挙げて終える
3. 運用者が、まなびばの API の検査を回す
4. システムが、手元にまなびばの配備を起こし、要求を当てて応答を要件に照らし、食い違いを挙げて終える
5. 運用者が、学びを指定して画面の採取を回す
6. システムが、API を通して状態の違う検査用のアカウントを用意し、画面の組ごとに写しを撮って書き出す
7. 運用者が、食い違いが無いことと、撮れた写しを見る

## 事後条件

- 成功時: 運用者が、学びとまなびばの応答が契約・登録簿・要件と食い違わないことと、画面の写しの一覧を見ている
- 失敗時: 食い違いが挙げられて失敗で終わっており、手元の保存先のデータは消えていない

## 要件

### REQ-596

- pattern: Event-driven
- status: active

> 運用者が学びを指定して API の検査を回したとき、システムは手元のその学びの配備に要求を当て、認証の境界・断りの形・各応答の形と件数・テストの一連の流れ・空の一覧・並びと絞り込み・模試の設定・セキュリティヘッダのどれかが契約と登録簿と食い違えばそれを挙げて失敗で終え、食い違いが無ければ成功で終える。

#### 検証方針

- **分割クラス**:
  - `#consistent-passes` — 手元の保存先がそろった学び ip の配備が契約と登録簿に合えば成功で終える
  - `#security-header-differs` — 配備の応答からセキュリティヘッダを 1 つ外すと、そのヘッダを挙げて失敗で終える
- **尽きている根拠**: 結果は食い違いの有無の 2 つで尽きる。食い違う側は、要件が挙げる観点のうち、配備のコードを変えずに応答の外から 1 つだけ外せるセキュリティヘッダで代表する
- **検証しない**: ほかの観点（認証の境界・断りの形・応答の形と件数・テストの流れ・空の一覧・並びと絞り込み・模試の設定）を 1 つずつ外す入力（当たる入力を作るには配備のコードを変える必要があり、どの応答をどう変えるとどの観点に当たるかを要件が決めていない）。学びを省略した呼び方（契約の注記で ip と同じ）

### REQ-597

- pattern: Unwanted behaviour
- status: active

> 運用者が API の検査に登録簿に無い学びを指定したとき、システムは配備を起こさずに、指定できる学びを示して失敗で終える。

#### 検証方針

- **分割クラス**:
  - `#unknown-learning` — 登録簿に無い学びを指定すると、配備を起こさず（手元の保存先も組み立ても作らず）、登録簿の学びをすべて示して失敗で終える
- **尽きている根拠**: 登録簿に無い学びの指定は 1 つの同値で、形の違う key（大文字・記号）は契約の pattern の外
- **検証しない**: 契約の pattern に合わない値（REQ の文が扱わない）

### REQ-598

- pattern: Event-driven
- status: active

> 運用者がまなびばの API の検査を回したとき、システムは手元のまなびばの配備に要求を当て、ログイン・学びへの入口とコードの交換・学びの一覧・本人の情報・管理・入力の検証・自分への保護・自分の設定・Cookie の境界・セキュリティヘッダ・死活確認・知らない経路の断りのどれかが要件と食い違えばそれを挙げて失敗で終え、食い違いが無ければ成功で終える。

#### 検証方針

- **分割クラス**:
  - `#consistent-passes` — 手元の保存先がそろったまなびばの配備が要件に合えば成功で終える
  - `#security-header-differs` — 配備の応答からセキュリティヘッダを 1 つ外すと、そのヘッダを挙げて失敗で終える
- **尽きている根拠**: 結果は食い違いの有無の 2 つで尽きる。食い違う側は、配備のコードを変えずに応答の外から外せるセキュリティヘッダで代表する
- **検証しない**: ほかの観点（ログイン・入口とコードの交換・学びの一覧・本人の情報・管理・入力の検証・自分への保護・自分の設定・Cookie の境界・死活確認・知らない経路）を 1 つずつ外す入力（配備のコードを変える必要があり、どう変えるとどの観点に当たるかを要件が決めていない）

### REQ-599

- pattern: Event-driven
- status: active

> 運用者が検査用のアカウントを用意したとき、システムは手元の学びの配備に API を通して進み具合の違う検査用のアカウントを作り、既に居るアカウントは作り直さず、手元の保存先のどのデータも消さない。

#### 検証方針

- **分割クラス**:
  - `#creates-accounts` — 検査用のアカウントが居ない保存先に、進み具合の違う検査用のアカウントを 2 つ以上作る
  - `#existing-not-recreated` — 既に居るときにもう一度用意しても、同じアカウント（id）を作り直さない
  - `#keeps-data` — 用意する前から手元の保存先にあった行は、用意した後もすべて残る
- **尽きている根拠**: アカウントが居ない・既に居るの 2 状態と、保存先のほかのデータが残ることで尽きる
- **境界の扱い**: 用意は画面の採取（auditScreens）が手元に起こした配備に API を通して行う物で観測する
- **検証しない**: 検査用のアカウントの用意（auditFixtures）を単独で、起きている配備に当てる呼び方（その配備をどの SSO の設定で起こしておくかを要件と契約が決めていない）

### REQ-600

- pattern: Event-driven
- status: active

> 運用者が学びを指定して画面の採取を回したとき、システムは手元のその学びの配備で、画面・アカウント・画面の幅・配色・読み込み中や失敗の状態の組ごとに画面の写しを撮って一覧とともに書き出し、読み込み中のまま撮れた写しと撮れなかった組を挙げて終える。

#### 検証方針

- **分割クラス**:
  - `#shots-with-list` — 学び ip の画面の組ごとに写しを撮り、撮った写しを挙げた一覧とともに書き出して成功で終える
  - `#existing-accounts` — 検査用のアカウントが既に居る学びでも、組ごとに写しを撮って書き出して成功で終える
  - `#tool-made-states` — 道具が自分で作る読み込み中（応答の遅れ）と失敗（500・通信断）の状態の組も撮り、読み込み中のまま撮れた写しと撮れなかった組を挙げる
- **尽きている根拠**: 検査用のアカウントが居ない・既に居るの 2 状態と、道具が自分で作る状態の組で尽きる。居ない状態は組を絞らずに撮り（道具が作る状態の組を含める）、既に居る状態は --limit で絞る
- **検証しない**: 登録簿に無い学びの指定（状態 × イベント表で決まっていない「?」）。画面・幅・配色の組の網羅（組の作り方は道具の値で、要件は組ごとに撮ることだけを言う）

### REQ-629

- pattern: Event-driven
- status: active

> 運用者が手元に起こしたまなびばと学びの配備で SSO の一巡を回したとき、システムはまなびばへのログインから学びに入るまでと、権限の無い学び・自分のパスワードの変更・管理の断り・ログアウトを確かめ、作った一時のアカウントを消し、確かめに 1 つでも食い違いがあれば失敗で終える。

#### 検証方針

- **分割クラス**:
  - `#consistent-passes` — 事前条件の状態にある手元のまなびばと学び mkt で一巡を回すと、成功で終える
  - `#temp-accounts-removed` — 一巡の後、まなびばのアカウントは一巡の前と同じ（一巡が作った一時のアカウントは残らない）
  - `#mismatch-fails` — 起きているまなびばと学びの配備が要件と食い違う応答を返すと、失敗で終える
- **尽きている根拠**: 結果は食い違いの有無の 2 つで尽き、通る側は一巡の後に一時のアカウントが残らないことを別に見る。食い違う側は、どの確かめが食い違っても失敗で終わることを、どの要求にも同じ 200 で応える配備で代表する
- **検証しない**: 確かめの 1 つずつを外す入力（どの応答をどう変えるとどの確かめに当たるかを要件が決めていない。食い違う側は 1 つの同値で代表する）

### REQ-664

- pattern: Event-driven
- status: active

> 運用者が画面の採取を回したとき、システムは出力先にある前の回の写しを消してから撮り、前の回の物を残すと指定したときは消さない。

#### 検証方針

- **分割クラス**:
  - `#previous-shots-removed` — 出力先に前の回の写しがあると、それを消してから撮る
  - `#keep-previous` — 残すと指定すると、前の回の写しを消さずに撮る
- **尽きている根拠**: 残す指定の有無の 2 つで尽きる
- **検証しない**: 出力先に前の回の写しが無いとき（消す物が無い）
