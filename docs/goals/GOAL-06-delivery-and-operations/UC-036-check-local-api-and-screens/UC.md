# UC-036 配る前に手元の配備に API と画面を当てて、契約と食い違う応答と崩れた画面を見つける

## 概要

運用者が、手元に起こした学びとまなびばの配備に API の検査を当て、検査用のアカウントで画面を採取することで、契約や要件と食い違う応答と崩れた画面を、配る前に見つける。

## 事前条件

- 手元の作業環境に、配信しようとする版のソースと、手元の保存先がそろっている
- 検査用のアカウントの用意と画面の採取では、学び側の配備を、まなびばの場所として検査用のアカウントの道具が起こす手元の SSO の偽物の場所と、共有秘密としてその偽物と同じ値を与えて起こしておく（値の正本は `scripts/audit_fixtures.mjs`。画面の採取の入口が起こす）
- 手元の SSO の一巡では、次の状態が成り立っている（口の番号・学び・メールとパスワードの値の正本は `scripts/check_sso_flow.py`）: 手元のまなびばと手元の学び mkt の配備が決まった口で応じ、両方に同じ手元用の共有秘密が与えられ、学び側にはまなびばの場所として手元のまなびばとトークンの署名の秘密が与えられている。手元のまなびばに、一巡の道具が使うメールとパスワードでログインでき、学び mkt の権限を持つ管理者がいる

## 主シナリオ

1. 運用者が、学びを指定して API の検査を回す
2. システムが、手元に学びの配備を起こし、要求を当てて応答を契約と登録簿に照らし、食い違いを挙げて終える
3. 運用者が、まなびばの API の検査を回す
4. システムが、手元にまなびばの配備を起こし、要求を当てて応答を要件に照らし、食い違いを挙げて終える
5. 運用者が、学びを指定して画面の採取を回す
6. システムが、API を通して状態の違う検査用のアカウントを用意し、画面の組ごとに写しを撮って書き出す
7. 運用者が、食い違いが無いことと、撮れた写しを見る

## 事後条件

- 成功時: 運用者が、学びとまなびばの応答が契約・登録簿・要件と食い違わないことと、画面の写しの一覧を見ている。道具がその回に一時の置き場に作った記録は残っていない。道具がその回に起こした手元の配備のプロセスは残っていない
- 失敗時: 食い違いか読めなかった問い合わせが挙げられて失敗で終わっており、手元の保存先のデータは消えていない。道具がその回に一時の置き場に作った記録は残り、その場所が示されている。道具がその回に起こした手元の配備のプロセスは残っていない

## 要件

### REQ-596

- pattern: Event-driven
- status: active

> 運用者が学びを指定して API の検査を回したとき、システムは手元のその学びの配備に要求を当て、認証の境界・断りの形・各応答の形と件数・テストの一連の流れ・空の一覧・並びと絞り込み・模試の設定・セキュリティヘッダのどれかが契約と登録簿と食い違えばそれを挙げて失敗で終え、食い違いが無ければ成功で終える。

#### 検証方針

- **分割クラス**:
  - `#consistent-passes` — 手元の保存先がそろった学び ip の配備が契約と登録簿に合えば成功で終える
  - `#security-header-differs` — 配備の応答からセキュリティヘッダを 1 つ外すと、そのヘッダを挙げて失敗で終える
- **尽きている根拠**: 結果は食い違いの有無の 2 つで尽きる。食い違う側は、要件が挙げる観点のうち、配備のコードを変えずに応答の外から 1 つだけ外せるセキュリティヘッダで代表する
- **検証しない**: ほかの観点（認証の境界・断りの形・応答の形と件数・テストの流れ・空の一覧・並びと絞り込み・模試の設定）を 1 つずつ外す入力（当たる入力を作るには配備のコードを変える必要があり、どの応答をどう変えるとどの観点に当たるかを要件が決めていない）。学びを省略した呼び方（契約の注記で ip と同じ）

### REQ-597

- pattern: Unwanted behaviour
- status: active

> 運用者が API の検査に登録簿に無い学びを指定したとき、システムは配備を起こさずに、指定できる学びを示して失敗で終える。

#### 検証方針

- **分割クラス**:
  - `#unknown-learning` — 登録簿に無い学びを指定すると、配備を起こさず（手元の保存先も組み立ても作らず）、登録簿の学びをすべて示して失敗で終える
- **尽きている根拠**: 登録簿に無い学びの指定は 1 つの同値で、形の違う key（大文字・記号）は契約の pattern の外
- **検証しない**: 契約の pattern に合わない値（REQ の文が扱わない）

### REQ-598

- pattern: Event-driven
- status: active

> 運用者がまなびばの API の検査を回したとき、システムは手元のまなびばの配備に要求を当て、ログイン・学びへの入口とコードの交換・学びの一覧・本人の情報・管理・入力の検証・自分への保護・自分の設定・Cookie の境界・セキュリティヘッダ・死活確認・知らない経路の断りのどれかが要件と食い違えばそれを挙げて失敗で終え、食い違いが無ければ成功で終える。

#### 検証方針

- **分割クラス**:
  - `#consistent-passes` — 手元の保存先がそろったまなびばの配備が要件に合えば成功で終える
  - `#security-header-differs` — 配備の応答からセキュリティヘッダを 1 つ外すと、そのヘッダを挙げて失敗で終える
- **尽きている根拠**: 結果は食い違いの有無の 2 つで尽きる。食い違う側は、配備のコードを変えずに応答の外から外せるセキュリティヘッダで代表する
- **検証しない**: ほかの観点（ログイン・入口とコードの交換・学びの一覧・本人の情報・管理・入力の検証・自分への保護・自分の設定・Cookie の境界・死活確認・知らない経路）を 1 つずつ外す入力（配備のコードを変える必要があり、どう変えるとどの観点に当たるかを要件が決めていない）

### REQ-599

- pattern: Event-driven
- status: active

> 運用者が検査用のアカウントを用意したとき、システムは手元の学びの配備に API を通して進み具合の違う検査用のアカウントを作り、既に居るアカウントは作り直さず、手元の保存先のどのデータも消さない。

#### 検証方針

- **分割クラス**:
  - `#creates-accounts` — 検査用のアカウントが居ない保存先に、進み具合の違う検査用のアカウントを 2 つ以上作る
  - `#existing-not-recreated` — 既に居るときにもう一度用意しても、同じアカウント（id）を作り直さない
  - `#keeps-data` — 用意する前から手元の保存先にあった行は、用意した後もすべて残る
- **尽きている根拠**: アカウントが居ない・既に居るの 2 状態と、保存先のほかのデータが残ることで尽きる
- **境界の扱い**: 3 つのクラスは、画面の採取（auditScreens）が手元に起こした配備に API を通して行う用意で観測する
- **検証しない**: 3 つのクラスを、検査用のアカウントの用意（auditFixtures）を単独で回す呼び方でも見ること（単独の呼び方は、事前条件の設定で起こした配備に当てる物として REQ-667#fixtures-alone-wrong-shape と契約の実例 auditFixtures.ok が通す。用意の振る舞いは画面の採取の経路で見る）

### REQ-600

- pattern: Event-driven
- status: active

> 運用者が学びを指定して画面の採取を回したとき、システムは手元のその学びの配備で、画面・アカウント・画面の幅・配色・読み込み中や失敗の状態の組ごとに画面の写しを撮って一覧とともに書き出し、読み込み中のまま撮れた写しと撮れなかった組を挙げて終える。

#### 検証方針

- **分割クラス**:
  - `#shots-with-list` — 学び ip の画面の組ごとに写しを撮り、撮った写しを挙げた一覧とともに書き出して成功で終える
  - `#existing-accounts` — 検査用のアカウントが既に居る学びでも、組ごとに写しを撮って書き出して成功で終える
  - `#tool-made-states` — 道具が自分で作る読み込み中（応答の遅れ）と失敗（500・通信断）の状態の組も撮り、読み込み中のまま撮れた写しと撮れなかった組を挙げる
- **尽きている根拠**: 検査用のアカウントが居ない・既に居るの 2 状態と、道具が自分で作る状態の組で尽きる。居ない状態は組を絞らずに撮り（道具が作る状態の組を含める）、既に居る状態は --limit で絞る
- **検証しない**: 画面・幅・配色の組の網羅（組の作り方は道具の値で、要件は組ごとに撮ることだけを言う）

### REQ-629

- pattern: Event-driven
- status: active

> 運用者が手元に起こしたまなびばと学びの配備で SSO の一巡を回したとき、システムはまなびばへのログインから学びに入るまでと、権限の無い学び・自分のパスワードの変更・管理の断り・ログアウトを確かめ、作った一時のアカウントを消し、確かめに 1 つでも食い違いがあれば失敗で終える。

#### 検証方針

- **分割クラス**:
  - `#consistent-passes` — 事前条件の状態にある手元のまなびばと学び mkt で一巡を回すと、成功で終える
  - `#temp-accounts-removed` — 一巡の後、まなびばのアカウントは一巡の前と同じ（一巡が作った一時のアカウントは残らない）
  - `#mismatch-fails` — 起きているまなびばと学びの配備が要件と食い違う応答を返すと、失敗で終える
- **尽きている根拠**: 結果は食い違いの有無の 2 つで尽き、通る側は一巡の後に一時のアカウントが残らないことを別に見る。食い違う側は、どの確かめが食い違っても失敗で終わることを、どの要求にも同じ 200 で応える配備で代表する
- **検証しない**: 確かめの 1 つずつを外す入力（どの応答をどう変えるとどの確かめに当たるかを要件が決めていない。食い違う側は 1 つの同値で代表する）

### REQ-664

- pattern: Event-driven
- status: active

> 運用者が画面の採取を回したとき、システムは出力先にある、前の回の採取が書いた写しと一覧だけを消してから撮り、出力先のほかのファイルは残し、前の回の物を残すと指定したときは写しと一覧も消さない。

#### 検証方針

- **分割クラス**:
  - `#previous-shots-removed` — 出力先に前の回の写しと一覧があると、それを消してから撮る
  - `#other-files-kept` — 出力先に前の回の写しと一緒に採取が書いていないファイルがあると、写しと一覧を消して撮り、そのファイルは中身ごと残る
  - `#keep-previous` — 残すと指定すると、前の回の写しを消さずに撮る
- **尽きている根拠**: 出力先の物は、前の回の採取が書いた物（写しと一覧）とそれ以外の 2 つで、残す指定の有無の 2 つと組む。残すと指定したときはどちらも消さないので、それ以外のファイルは指定の無い側で 1 つ置いて尽きる
- **境界の扱い**: 前の回の採取が書いた写しは、出力先の前の回の一覧（`manifest.json`）が挙げる写しで、一覧が無いか読めないときは出力先の直下の写しの形式（PNG）のファイルを前の回の写しとして消し、ほかのファイルは残す。採取が書いていないファイルは、写しでも一覧でもない文字のファイルで作る
- **検証しない**: 出力先に前の回の写しが無いとき（消す物が無い）。一覧が読める出力先にある、写しの形式を持つが一覧に挙がらないファイル（消す物と残す物の分かれは `#previous-shots-removed` と `#other-files-kept` で代表し、写しの形式の別ファイルは変種として置かない）

### REQ-667

- pattern: Unwanted behaviour
- status: active

> 運用者が検査用のアカウントを用意するか画面の採取を回すときに、手元の学びの配備がアカウントの用意か撮る画面の組み立てに要る問い合わせ（論点の詳細の 1 件ずつを除く）に成功の状態で中身の無い答えか期待と違う形の答えを返したとき、システムは画面を撮らずに、答えを読めなかった問い合わせを 1 行で示し、断りの名前を出して失敗で終える。

#### 検証方針

- **分割クラス**:
  - `#fixtures-empty-answer` — 画面の採取で、アカウントの用意に要る問い合わせ（論点の一覧）が成功の状態で中身の無い答えを返すと、写しを撮らずに、その問い合わせを示して UPSTREAM_UNAVAILABLE で失敗で終える
  - `#fixtures-wrong-shape` — 画面の採取で、アカウントの用意に要る問い合わせが成功の状態で期待した一覧の欄を持たない答えを返すと、写しを撮らずに、その問い合わせを示して UPSTREAM_UNAVAILABLE で失敗で終える
  - `#screens-wrong-shape` — 画面の採取で、アカウントの用意は通り、撮る画面の組み立てに要る問い合わせ（単元の一覧か単元ごとの論点の一覧）が成功の状態で期待した一覧の欄を持たない答えを返すと、写しを撮らずに、その問い合わせを示して UPSTREAM_UNAVAILABLE で失敗で終える
  - `#fixtures-alone-wrong-shape` — 検査用のアカウントの用意を単独で回し、用意に要る問い合わせが成功の状態で期待と違う形の答えを返すと、その問い合わせを示して UPSTREAM_UNAVAILABLE で失敗で終える
  - `#fixtures-item-wrong-shape` — 画面の採取で、アカウントの用意に要る問い合わせ（論点の一覧）が成功の状態で一覧の欄は持つが要素が期待した形でない答えを返すと、写しを撮らずに、その問い合わせを示して UPSTREAM_UNAVAILABLE で失敗で終える
  - `#screens-item-wrong-shape` — 画面の採取で、アカウントの用意は通り、撮る画面の組み立てに要る問い合わせ（単元の一覧）が成功の状態で一覧の欄は持つが要素が期待した形でない答えを返すと、写しを撮らずに、その問い合わせを示して UPSTREAM_UNAVAILABLE で失敗で終える
  - `#topic-detail-skipped` — 論点の詳細の 1 件が成功の状態で期待と違う形の答えを返しても、断らずにその 1 件を飛ばして撮り、成功で終える
- **尽きている根拠**: 文の条件は、答えの中身が無い・形が違うの 2 つと、その答えを要る段（アカウントの用意・撮る画面の組み立て）の 2 つ、入口（画面の採取・アカウントの用意の単独）の 2 つ。形が違う側は、一覧の欄が無い・一覧の要素の形が違うの 2 つに分かれる。中身が無い側はアカウントの用意の段で代表し、欄が無い側を段と入口ごとに、要素の形が違う側を段ごとに置く。除く問い合わせ（論点の詳細の 1 件ずつ）を境として 1 つ置く
- **境界の扱い**: 「成功の状態」は配備が 2xx で答えた場合。中身の無い答えは本文が空の応答、欄の無い答えは JSON として読めるが期待した一覧の欄を持たない応答、要素の形が違う答えは期待した一覧の欄を配列で持つが、その要素に null を含む応答で作る
- **検証しない**: 配備が 2xx 以外で答えた場合（文は成功の状態の答えだけを扱う）。期待と違う形の答えの変種の網羅（欄の欠けと要素の null で代表する）。要素の形の違いを、アカウントの用意を単独で回す入口でも見ること（単独の入口の形の違いは欄の欠けで代表する）。示す 1 行の言い回し（問い合わせの経路を含むことだけを見る）

### REQ-668

- pattern: Event-driven
- status: active

> 運用者が学びの API の検査かまなびばの API の検査か画面の採取を回して道具が終えたとき、システムは、成功で終えるならその回に一時の置き場に作った記録を残さず、失敗で終えるならその記録を残してその場所を示す。

#### 検証方針

- **分割クラス**:
  - `#check-api-success-removed` — 学びの API の検査が成功で終えると、その回が一時の置き場に作った記録は残らない
  - `#check-api-failure-kept` — 学びの API の検査が失敗で終えると、その回が一時の置き場に作った記録が残り、その場所が出力に示される
  - `#portal-api-success-removed` — まなびばの API の検査が成功で終えると、その回が一時の置き場に作った記録は残らない
  - `#portal-api-failure-kept` — まなびばの API の検査が失敗で終えると、その回が一時の置き場に作った記録が残り、その場所が出力に示される
  - `#screens-success-removed` — 画面の採取が成功で終えると、その回が一時の置き場に作った記録は残らない
  - `#screens-failure-kept` — 画面の採取が失敗で終えると、その回が一時の置き場に作った記録が残り、その場所が出力に示される
- **尽きている根拠**: 一時の置き場に記録を作る道具は 3 つで、終わり方は成功・失敗の 2 つ。道具ごとに 2 つ置いて尽きる
- **境界の扱い**: 一時の置き場は、道具を回す環境が指す一時の置き場をテストごとに空の置き場にして、回した後に残る物で見る。道具が起こす実行環境（Node と wrangler）が回をまたいで使い回す控えの置き場は、その回の記録に数えない。テストは道具を運用者のシェルと同じ環境で回す（テストの走り手が足した PATH の項目と変数を外し、道具の `npx` が運用者の PATH の先頭の物に当たるようにする）。失敗は、配備が要件と食い違う応答を返す場合で作る
- **検証しない**: 道具が打ち切られた場合（成功でも失敗でも終えていない）。一時の置き場にある、その回が作っていない物（文はその回に作った記録だけを扱う）

### REQ-674

- pattern: Unwanted behaviour
- status: active

> 運用者が画面の採取に登録簿に無い学びを指定したとき、システムは配備を起こさずに、指定できる学びを示して失敗で終える。

#### 検証方針

- **分割クラス**:
  - `#unknown-learning` — 登録簿に無い学びを指定すると、配備を起こさず（手元の保存先も組み立ても作らず）、出力先に写しも一覧も書かず、登録簿の学びをすべて示して失敗で終える
- **尽きている根拠**: 登録簿に無い学びの指定は 1 つの同値で、形の違う key（大文字・記号）は契約の pattern の外
- **検証しない**: 契約の pattern に合わない値（REQ の文が扱わない）。学びを省略した呼び方（契約の注記で ip と同じで、REQ-600 が見る）

### REQ-675

- pattern: Event-driven
- status: active

> 運用者が学びの API の検査かまなびばの API の検査か画面の採取を回して道具が終えるとき、システムは、成功で終えるか失敗で終えるかを問わず、道具がその回に起こした手元の配備とその子のプロセスを止めて 1 つも残さず、道具が起こしていない既に応じている手元の配備は止めない。

#### 検証方針

- **分割クラス**:
  - `#check-api-success-stopped` — 学びの API の検査が自分で配備を起こして成功で終えると、終えた時点でその回が起こした配備のプロセスが 1 つも残っていない
  - `#check-api-failure-stopped` — 学びの API の検査が自分で配備を起こして失敗で終えると、終えた時点でその回が起こした配備のプロセスが 1 つも残っていない
  - `#portal-api-success-stopped` — まなびばの API の検査が自分で配備を起こして成功で終えると、終えた時点でその回が起こした配備のプロセスが 1 つも残っていない
  - `#portal-api-failure-stopped` — まなびばの API の検査が自分で配備を起こして失敗で終えると、終えた時点でその回が起こした配備のプロセスが 1 つも残っていない
  - `#screens-success-stopped` — 画面の採取が自分で配備を起こして成功で終えると、終えた時点でその回が起こした配備のプロセスが 1 つも残っていない
  - `#screens-failure-stopped` — 画面の採取が自分で配備を起こして失敗で終えると、終えた時点でその回が起こした配備のプロセスが 1 つも残っていない
  - `#check-api-existing-kept` — 学びの API の検査の口で道具が起こしていない配備が既に応じていると、道具が終えたあともその配備のプロセスが生きていて口に応じる
  - `#portal-api-existing-kept` — まなびばの API の検査の口で道具が起こしていない配備が既に応じていると、道具が終えたあともその配備のプロセスが生きていて口に応じる
  - `#screens-existing-kept` — 画面の採取の口で道具が起こしていない配備が既に応じていると、道具が終えたあともその配備のプロセスが生きていて口に応じる
- **尽きている根拠**: 手元の配備を起こす道具は 3 つで、道具がその回に配備を起こしたときの終わり方は成功・失敗の 2 つ、配備を起こさないのは口で配備が既に応じているときの 1 つ。道具ごとに 3 つ置いて尽きる。既に応じている配備を使う回は終わり方で止め方が分かれないので、終わり方を問わず 1 つに置く
- **境界の扱い**: 道具がその回に起こした配備のプロセスは、道具のプロセスから起きたプロセス（配備の道具を呼ぶ `npm exec` とその子・孫）。テストは道具を影の根（UC-036 の土台の囲い）を作業の場所にして、新しいプロセスグループの頭として回し、道具が終えた時点で、そのプロセスグループに属するプロセスが 1 つも無く、道具が配備に使う口（土台が決めた口）を掴むプロセスも無く、作業の場所が影の根の下にあるプロセスも無いことで見る（道具が配備を別のプロセスグループに入れても居残りを捉える）。テストは道具を運用者のシェルと同じ環境で回す（テストの走り手が足した PATH の項目と変数を外し、道具の `npx` が運用者の PATH の先頭の物に当たるようにする）。失敗は、道具が起こした配備が要件と食い違う応答を返す場合で作る（REQ-668 と同じ作り方）。既に応じている配備は、道具を回す前に道具と別のプロセスグループで、作業の場所を影の根の外に置いて起こした、道具が配備に使う口で死活確認に応じるプロセスで作り、道具の終わり方は問わない
- **検証しない**: 道具が打ち切られた場合（成功でも失敗でも終えていない。REQ-668 と同じ）。道具が配備を起こす前に断る場合（登録簿に無い学びは REQ-597・REQ-674 が配備を起こさないことを見る）。口を離すまでの時間の長さ（文は終えた時点で残らないことだけを言う）
