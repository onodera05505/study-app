# UC-044 手元に依らない検査を共有の置き場で回し、手元に依る検査を手元の入口に受け持たせる

## 概要

運用者が変更を共有の置き場に出すと、システムが手元の物を要らない検査だけを回し、手元の物を要る検査の名前を手元の入口が受け持つ物として示すことで、どのクローンでも同じ結果になる検査で配る版を確かめ、手元の物を要る検査を黙って落とさない。

## 事前条件

- 変更がこのリポジトリのブランチにコミットされ、共有の置き場（GitHub）に出せる
- 共有の置き場の検査の環境には、リポジトリが追跡する物と、リポジトリが宣言した依存だけがある（手元の物は無い）
- 手元の物は、macOS の囲い（sandbox-exec）、手元の配備（wrangler や vite の開発用の配備）と手元の保存先（`.wrangler`）、リポジトリが追跡しないファイル（置き場に実際にあって git の索引に無いファイル。どこにも無い名前は数えない。git が無視する物も、無視されていない未追跡の物も、家の置き場の物も含む。リポジトリが宣言した依存の置き場と、git の置き場そのもの（`.git` とその下）は含まない）を指す
- 手元に依る検査は、手元の全部の検査（`npm test`。UC-033・UC-035 の範囲）と push 前の検査（`.githooks/pre-push`）が回す

## 主シナリオ

1. 運用者が、変更を共有の置き場に出す（プルリクエストを開くか、main に push する）
2. システムが、テストのファイルと契約の受け渡し役の受け持ちを、手元の物の土台を読み込むかどうかで、手元に依らない物と手元だけの物に分ける
3. システムが、仕様と紐づきの検査、入口の一覧の突き合わせ、型、静的な門と、手元に依らない契約の実例とテストを回す
4. システムが、回さなかった手元だけのテストのファイルと契約の実例の UC と実行の記録の門の名前を、手元の入口が受け持つ物として示し、結果を返す
5. 運用者が、通ったことと、手元の入口が受け持つ物の名前を見る

| --- | --- | --- |
| テストのファイルと土台の名前が、読み込む物・使う物と合っている | REQ-677 | REQ-678 |
| 手元の物の土台を読み込むのに手元だけの名前を持たないテストのファイルか、その逆がある | REQ-679 | REQ-679 |
| 手元の物を使うのに手元の物の土台の名前を持たない土台がある | REQ-679 | REQ-679 |

## 例外系の走査（4 分類）

| 軸 | 該当ステップ | 導出 |
| --- | --- | --- |
| 権限 | 1 | なし（共有の置き場の検査は読むだけで、配備も投入もしない） |
| 不変条件違反 | 2 | テストのファイルや土台の名前と、読み込む物・使う物が食い違う → REQ-679／契約の受け渡し役が手元の物の土台を通さずに手元の物を使う → REQ-679 |

## 事後条件

- 成功時: 運用者が、手元に依らない検査がすべて通ったことと、手元の入口が受け持つテストのファイル・契約の実例の UC・実行の記録の門の名前を見ている
- 失敗時: 落ちた検査か、名前の食い違うテストのファイルと土台が挙げられて失敗で終わっており、リポジトリは書き換わっていない

## 要件

### REQ-677

- pattern: Event-driven
- status: active

> 運用者が手元に依らない検査を回したとき、システムは仕様と紐づきの検査・入口の一覧の突き合わせ・型・静的な門と、手元に依らないテストのファイルと手元に依らない UC の契約の実例だけを回し、手元だけのテストのファイルと手元だけの UC の契約の実例と実行の記録の門は回さずに、その名前を手元の入口が受け持つ物として示す。

#### 検証方針

- **分割クラス**:
  - `#portable-ran` — 手元に依らないテストのファイルと UC の契約の実例が回り、その結果で成否が決まる
  - `#local-not-ran` — 手元だけのテストのファイルと UC の契約の実例は回らない（手元の物を使った跡が残らない）
  - `#local-named` — 回さなかった手元だけのテストのファイル・UC・実行の記録の門の名前を、手元の入口が受け持つ物として示す
  - `#spec-and-static-ran` — 仕様と紐づきの検査・入口の一覧の突き合わせ・型・静的な門が回る
  - `#portable-failure-fails` — 手元に依らないテストが 1 つ落ちると、失敗で終える
  - `#portable-alone-shape-ran` — 単独で回す組（組 `alone`）が抱える名前の形に当たるが手元だけの名前を持たないテストのファイルも、手元に依らない検査で回り、その結果で成否が決まる（どの組にも入らず回らないファイルが無い）
- **尽きている根拠**: 文の 3 つの振る舞い（回す・回さない・名前を示す）に 1 つずつと、回す物のうちテスト以外の検査に 1 つ置く。回した物の失敗が成否に効くことを 1 つ足す。単体テストの組は名前の形で分けるので、手元に依らない名前のファイルが組 `portable` から外れうる形（単独で回す組の名前の形）を 1 つ足す
- **境界の扱い**: 手元に依らない検査の入口は `npm run test:ci`（共有の置き場の検査が回す物）。テストのファイルの振り分けは REQ-678 の分け方と読む。手元だけの UC は、その UC の受け持ちが手元の物の土台を読み込む物。単独で回す組の名前の形の正本は `vitest.config.ts`。影の根に、手元に依らないテストと手元だけのテストを 1 つずつ持つ小さな作業ツリーを作り、そこで回す。`#portable-alone-shape-ran` は、単独で回す組の名前の形に当たり手元だけの名前を持たず手元の物の土台を読み込まないテストのファイルを影の根に置き、落ちる中身にすると失敗で終えることと、その名前が手元の入口が受け持つ物に出ないことで見る
- **検証しない**: 共有の置き場（GitHub の ubuntu）そのものでの実行（手元では、手元の物を外した影の根で代える）。回す検査の時間

### REQ-678

- pattern: Event-driven
- status: active

> 運用者が検査の振り分けを確かめたとき、システムはすべてのテストのファイルと契約の受け渡し役の受け持ちを、手元の物の土台を直にか間接に読み込む物は手元だけ、ほかは手元に依らない物として、どちらか一方にだけ分けて示す。

#### 検証方針

- **分割クラス**:
  - `#direct-import-local` — 手元の物の土台を直に読み込むテストのファイルは、手元だけに分ける
  - `#indirect-import-local` — 手元の物の土台を読み込む別の土台を通して読み込むテストのファイルは、手元だけに分ける
  - `#no-local-portable` — 手元の物の土台を読み込まないテストのファイルは、手元に依らない物に分ける
  - `#handler-local` — 手元の物の土台を読み込む受け持ちの UC は、手元だけに分ける
  - `#each-once` — どのテストのファイルと受け持ちも、2 つのどちらか一方にだけ現れ、漏れが無い
- **尽きている根拠**: 読み込み方（直に・間接に・読み込まない）に 1 つずつ置き、受け持ちに 1 つ置く。分け方が全部を一度ずつ覆うことを 1 つ置く
- **境界の扱い**: 手元の物の土台は、テストの土台のうち名前が `.local.ts` で終わる物。手元だけのテストのファイルは、名前が `.local.test.ts` か `.local.test.tsx` で終わる物（単体テストの組 `local` か、単独で回す組 `alone` が回す。組 `alone` は手元だけの名前のファイルだけを抱える）。手元に依らないテストのファイルは、名前の形によらずすべて単体テストの組 `portable` が回す。影の根に土台とテストを置いて作る
- **検証しない**: 読み込みが文字列から組み立てた名前で行われる場合（静的に読めない読み込みは土台に書かない決まりで、道具は見ない）

### REQ-679

- pattern: Unwanted behaviour
- status: active

> 運用者が手元に依らない検査を回すか検査の振り分けを確かめるときに、手元の物の土台を読み込むのに手元だけの名前を持たないテストのファイル、手元だけの名前を持つのに手元の物の土台を読み込まないテストのファイル、手元の物を使うのに手元の物の土台の名前を持たない土台、または土台を通さずに手元の物を使う契約の受け渡し役のファイルがあるとき、システムはそれをすべて挙げて、どのテストも回さずに失敗で終える。

#### 検証方針

- **分割クラス**:
  - `#local-import-unnamed` — 手元の物の土台を読み込むのに手元だけの名前を持たないテストのファイルを挙げて失敗で終える
  - `#local-name-no-import` — 手元だけの名前を持つのに手元の物の土台を読み込まないテストのファイルを挙げて失敗で終える
  - `#sandbox-fixture-unnamed` — macOS の囲いを起こすのに手元の物の土台の名前を持たない土台を挙げて失敗で終える
  - `#local-deploy-fixture-unnamed` — 手元の配備を起こすか手元の保存先を読むのに手元の物の土台の名前を持たない土台を挙げて失敗で終える
  - `#untracked-fixture-unnamed` — リポジトリが追跡しないファイルを名指すのに手元の物の土台の名前を持たない土台を挙げて失敗で終える（git が無視するファイルと、無視されていない未追跡のファイルを値の変種に）
  - `#split-path-fixture-unnamed` — パスを組む関数に置き場の名前を別々の文字列で渡す書き方で、リポジトリが追跡しないファイルを名指すのに手元の物の土台の名前を持たない土台を挙げて失敗で終える
  - `#tracked-or-provided-not-counted` — 土台が名指すのが、リポジトリが追跡するファイルと、宣言した依存の置き場（`node_modules`）・原本 harness の置き場（`.harness`）の下の物だけなら、手元の物を使うとは数えず、その土台を挙げない
  - `#all-cases-fixture-unnamed` — 契約の実例の確かめを UC を絞らずに起こすのに手元の物の土台の名前を持たない土台を挙げて失敗で終える
  - `#adapter-direct-local-use` — 契約の受け渡し役のファイル（受け持ちか共通の部品）が、手元の物の土台を通さずに手元の物を使うと、そのファイルを挙げて失敗で終える（受け持ちと共通の部品、手元の物を使う 4 つの形を値の変種に）
  - `#all-listed-none-ran` — 食い違いが 2 つの種類にあると両方を挙げ、手元に依らない検査を回すときもどのテストも回さない
- **尽きている根拠**: 文の 4 つの食い違いに 1 つずつ置き、3 つ目は手元の物を使う 4 つの形（囲い・手元の配備と保存先・追跡しないファイル・UC を絞らない契約の実例の確かめ）に分ける。追跡しないファイルは名指し方（1 つの文字列・置き場ごとに分けた文字列）で分け、数えない物（追跡するファイル・宣言した依存と原本 harness の置き場の下）を 1 つ対にする。4 つ目は 3 つ目と同じ 4 つの形で読み、置き場（受け持ち・共通の部品）と形を値の変種に畳む。「すべて挙げて、どのテストも回さない」を 2 つの種類が同時の場合で見る
- **境界の扱い**: 手元の物を使うことは、そのファイルの中で囲いの道具（`sandbox-exec`）か配備の道具（`wrangler`）を起こすか、手元の保存先（`.wrangler`）か家の置き場かリポジトリが追跡しないパスを名指すか、契約の実例の確かめを UC を絞らずに起こす（手元だけの UC の実例も回る）ことと読む。「リポジトリが追跡しないパス」は、置き場に実際にあって git の索引に無い、根からの相対のパス（git が無視する物も、無視されていない未追跡の物も）で、どこにも無い名前（影の根の中だけで作る名前）は数えない。宣言した依存の置き場（`node_modules`）と原本 harness の置き場（`.harness`）の下は、共有の置き場の検査でも宣言した依存として揃うので数えない。git の置き場そのもの（`.git` とその下）も、共有の置き場の写しにもあり、git 自身も未追跡にも無視にも数えないので数えない。「名指す」は、パスを 1 つの文字列で書く場合と、パスを組む関数（`join`・`resolve` など）に根と置き場の名前を別々の文字列で渡す場合の両方を含む。契約の受け渡し役のファイルは、`scripts/contract_adapter/` の受け持ちの置き場（`handlers`）と共通の部品の置き場（`kit`）のファイル。「土台を通さずに」は、そのファイルの中で手元の物を使うこと（手元の物の土台を読み込んで使う物は数えない）。影の根を git の作業ツリーにして、土台・テスト・受け渡し役のファイルと、追跡する・無視される・無視されない未追跡のファイルを置いて作る
- **検証しない**: 手元の物を、土台を通さずにテストのファイルが直に使う場合（テストのファイルは土台を通して手元の物を使う決まりで、道具はテストのファイルの中を見ない）。パスの一部を変数や計算で組む場合（静的に読めない名前で、REQ-678 の文字列から組み立てた読み込みと同じく道具は見ない）。テストが起こした子のプロセス（土台が起こす道具など）や設定（`vitest.config.ts`・Vite の設定）が暗に読む追跡しないファイル（振り分けの道具の範囲の外で、追跡する物しか無い共有の置き場の検査で落ちることで見つける）
