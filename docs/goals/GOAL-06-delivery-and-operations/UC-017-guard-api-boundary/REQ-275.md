# REQ-275

> トークンの署名の秘密が与えられていない配備では、学び側は認証を要する要求に添えられたトークンを読まず、求められた応答も要求された変更も行わないまま、配備に設定が無いことに当たる形で断る。

## 検証方針

- **分割クラス**:
  - `#token-present-refused` — 署名の秘密が無い配備に、トークンを添えた認証を要する要求が来た状態
  - `#token-absent-refused` — 同じ配備に、トークンを添えない認証を要する要求が来た状態（断りは添えたときと同じ形）
  - `#public-route-not-refused` — 同じ配備でも、認証を要さない経路（死活確認と、ログインの形の問い合わせ）は秘密の不足では断られない（条件の外側の境界）
- **尽きている根拠**: この配備に来る要求は（認証を要する）（要さない）の 2 つで、要する側は添えられたものが（在る）（無い）の 2 値 ＝ クラス 1・2、要さない側の端をクラス 3 が取る。添えられたものが在る側は、署名の秘密が無い配備では通る／通らないを判じないので 1 クラスにまとまる。受け持たない経路はこの文の射程に入らない（REQ-256 が先で、見つからないことで断る）。
- **境界の扱い**: 断る側と断らない側の切れ目は「その経路が認証を要するか」で、要さない経路の一覧の正本はサーバの経路の定義（BR-001・R-102）。
- **検証しない**: 断りの本文が足りない秘密を明かさないこと（REQ-206 のクラス `#same-text-as-other-not-configured` が見る）。まなびば側の振る舞い（まなびばのセッションはトークンの署名の秘密に依らない）。トークンを発行する側の断りは REQ-274 が持つ。
- **参照先**: `tests/server/signing_secret.test.ts` の describe「署名の秘密が無い配備では添えられたトークンを読まない（UC-017）」（`#public-route-not-refused` は死活確認とログインの形の問い合わせを 1 本ずつ観測する）
