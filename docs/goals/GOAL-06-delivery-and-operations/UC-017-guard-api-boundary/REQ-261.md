# REQ-261

> 学び側への要求が失敗の応答で返されたとき、画面はその応答に添えられた理由を利用者に伝え、理由が添えられていなければ日本語の 1 文に倒す。

## 検証方針

- **分割クラス**:
  - `#reason-from-body` — 失敗の応答の本文に理由が添えられている
  - `#reason-absent-fallback` — 失敗の応答だが本文に理由が無い（日本語の 1 文に倒す）
- **尽きている根拠**: UC の表の 3 つ目の表の 2 つのセル（理由が在る／理由が無い）がそのまま 2 クラス。応答そのものが返らない場合は REQ-262 の領域。
- **境界の扱い**: 「理由が無い」は本文に理由の項目が無い場合と本文が読めない場合の両方で、画面から見ればどちらも同じ 1 文に倒れるので 1 クラスに畳む。
- **検証しない**: 倒したときの 1 文の語そのもの（実装が正本。R-102）。理由をどの位置に出すか・読み直す手段を添えるか（BR-014 の画面側で、機械の門が無い）。失敗を投げる形（1 つの型かどうか）は実装の設計で、外から観測できない（R-401）。
- **参照先**: `tests/client/api_helpers.test.ts::API 呼び出しの失敗の形`、`tests/client/repay_UC-017_error_reason_fallback.test.ts::UC-017 失敗の応答に理由が無いときの画面の文`。
