# REQ-258

> 要求の処理の途中で想定していない失敗が起きたとき、学び側とまなびばは、要求の内容と失敗の中身によって変わらない固定の日本語の 1 文だけを返す。

## 検証方針

- **分割クラス**:
  - `#learning-internal-fixed` — 学び側で処理の途中に想定していない失敗が起きた要求
  - `#portal-internal-fixed` — まなびばで処理の途中に想定していない失敗が起きた要求
  - `#same-text-regardless-of-input` — 同じ失敗に違う入力を与えても、返る 1 文が変わらない
- **尽きている根拠**: 「想定していない失敗」は外から種類を指定できないので、分けられる軸は（配備が学び側かまなびばか）の 2 つ（クラス 1・2）と（同じ失敗に別の入力を与えたか）の 1 つ（クラス 3）だけ。失敗の中身が文に映らないことは、クラス 1・2 が本文に内部の語（例外の文・種類・呼び出しの履歴）が出ないことで取る。
- **境界の扱い**: 想定している失敗（認証の断り・本文の断り・知らない経路）は REQ-255〜257 が持ち、この文は残りの全部を 1 つの固定の 1 文に倒す側だけを述べる。
- **検証しない**: 固定の 1 文の語そのもの（実装が正本。R-102）。失敗の中身を運用の記録に残すこと（利用者に返る応答の外で、この文が述べていない）。途中で書きかけた変更が残らないこと（経路ごとの事後条件で、各 UC の領域）。
- **参照先**: `tests/server/protection.test.ts::知らない経路と想定していない例外`、`tests/portal/onerror.test.ts::想定していない例外（まなびば）`。
