# REQ-259

> 学び側とまなびばは、認証を要さない経路の応答・本人として通った要求の応答・断りの応答のいずれにも、定められたセキュリティヘッダをすべて載せて返す。

## 検証方針

- **分割クラス**:
  - `#headers-on-public` — 認証を要さない経路の応答
  - `#headers-on-refusal` — 断りの応答（認証の断り）
  - `#headers-on-authenticated` — 本人として通った要求の応答
  - `#headers-on-portal` — まなびばの応答（認証を要さない側と本人の側の両方）
- **尽きている根拠**: 文が挙げる応答の種類は（認証を要さない）（本人として通った）（断り）の 3 つで、クラス 1〜3 が 1 対 1 に取る。配備は学び側とまなびばの 2 つで、まなびば側をクラス 4 が取る。述語は「すべて載せて返す」なので、1 つの応答についてヘッダの集合の全要素を見れば尽きる（集合の正本は実装の応答の組み立て。R-102）。
- **境界の扱い**: 載せる／載せないの切れ目は無く（どの応答にも載る）、境界は応答の種類の側にしか無い。
- **検証しない**: ヘッダの値が外部の基準を満たすか（NFR-001 の計測が見る）。応答の本文の中身（この文はヘッダだけを述べる）。
- **参照先**: `tests/server/app.test.ts::セキュリティヘッダ`、`tests/server/protection.test.ts::セキュリティヘッダ（公開・認証の要る経路の両方）`、`tests/server/repay_UC-017_guard_api_boundary.test.ts::REQ-259 セキュリティヘッダ`（学び側の本人として通った応答）、`tests/portal/repay_UC-017_guard_api_boundary.test.ts::REQ-259 セキュリティヘッダ`（まなびばの認証を要さない・本人・断りの応答）。本番の応答は `scripts/check_portal_api.py::check_security_headers` が system suite で見る。
