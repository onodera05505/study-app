# REQ-256

> 学び側とまなびばが受け持たない /api の経路への要求を受けたとき、見つからないことを日本語の理由を 1 つ添えて断り、本人として呼ばれたかどうかで断りを変えない。

## 検証方針

- **分割クラス**:
  - `#unknown-path-anonymous` — 本人と分からない要求が、学び側の受け持たない /api の経路を呼ぶ
  - `#unknown-path-authenticated` — 通るトークンを添えた要求が同じ経路を呼ぶ（断りが変わらない）
  - `#unknown-path-portal` — まなびばの受け持たない /api の経路を呼ぶ
  - `#unknown-path-no-signing-secret` — トークンの署名の秘密が無い配備が、受け持たない /api の経路を呼ばれる（設定が無いことによる断りに変わらない）
  - `#unknown-path-unresolved-key` — 学びの key が与えられていない、または登録簿に無い配備が、受け持たない /api の経路を呼ばれる（設定が無いことによる断り（REQ-354）に変わらない）
- **尽きている根拠**: 経路は（受け持つ）（受け持たない）の 2 つで、受け持つ側は各 UC の operation が持つ。受け持たない側を分ける軸は「本人として呼ばれたか」の 2 値だけで、文が「断りを変えない」と言うのはこの 2 つの比較そのもの（クラス 1・2）。配備は学び側とまなびばの 2 つで、まなびば側をクラス 3 が取る。学び側の配備はさらに設定が（そろう）（署名の秘密が無い）（学びの key が解決できない）で分かれ、後の 2 つがこの経路に別の断りを差し込める位置にあるのでクラス 4・5 が取る。
- **境界の扱い**: クラス 1 は認証の前置きが掛かる /api 配下を匿名で呼び、断りが 401 に変わらないことを見る（前置きの外側にある /api/auth/* 配下は匿名でも断りが変わりようがないので、クラス 1 の入力には取らない）。受け持つ経路の一覧の正本はサーバの経路の定義（R-102）。
- **検証しない**: /api の外の経路（画面の静的ファイルと SPA の受け口）— 断りではなく画面を返す経路で、この文の射程外。断りの文言そのもの（実装が正本。R-102）。
- **参照先**: `tests/server/app.test.ts::失敗の形`、`tests/server/protection.test.ts::知らない経路と想定していない例外`、`tests/server/signing_secret.test.ts::受け持たない /api の経路は設定の不足では断らない（UC-017）`、`tests/server/repay_UC-017_guard_api_boundary.test.ts::REQ-256 受け持たない /api の経路`（`#unknown-path-unresolved-key`）、`tests/portal/repay_UC-017_guard_api_boundary.test.ts::REQ-256 受け持たない /api の経路`（まなびば）。
