# UC-017 学びとまなびばの要求の受け口を一様に守る

## 概要

学び側とまなびばが、届いた要求を本人と分かるかどうかで振り分け、断るときはどの配備でも同じ形で断り、
内部の事情を明かさないことを、どの学びのどの経路でも一様に満たす。配信した本番が守られていることの土台で、
個々の経路の内容は各 UC が持つ。

## 事前条件

- 学び側とまなびばが本番に配備され、それぞれ配備ごとのデータの保存先に結びついている
- 利用者の端末が、学び側の要求に添えるトークン、またはまなびばの要求に添えるセッションを持ちうる（発行は UC-013 の範囲）
- 適用される業務規則: BR-001, BR-002, BR-014

## 主シナリオ

1. システムが、学び側とまなびばへの要求を受け取り、添えられたトークンまたはセッションが通るかを確かめる → BR-001
2. システムが、要求の本文が決められた形を満たすかを確かめる
3. システムが、本人と分かった要求だけを処理に進め、その本人の応答を返す
4. システムが、返すどの応答にも定められたセキュリティヘッダを載せる
5. システムが、認証を要さない死活確認には、データの保存先を引かずに生きていることを示す応答を返す
6. システムが、断るときは断りの理由に当たる形で返し、内部の事情を明かさない → BR-002
7. システムが、断りと届かなかった要求を、画面で日本語の 1 文として利用者に伝える → BR-014

## 例外系の走査（4 分類）

| 軸 | 該当ステップ | 導出 |
| --- | --- | --- |
| 権限 | 1・3 | 本人と分からない要求には認証を要する応答を返さず、要求された変更も行わない → REQ-255（BR-001）。どの学びのどの経路でも同じ断りで、断りの応答にもセキュリティヘッダが載る → REQ-259 |
| 不変条件違反 | 2 | 決められた形を満たさない本文は処理に進めず、どの項目が満たされていないかが分かる日本語で断る → REQ-257 |
| 並行性 | 1 | 要求の途中でトークンやセッションが通らなくなる（期限が過ぎる・管理者の再設定で消される）→ 表 1 の 3 行目（REQ-255）。画面側の扱いは UC-013 の範囲 |
| 外部依存 | 3・5・7 | 処理の途中でデータの保存先などが応答しない → REQ-258（BR-002）。死活確認はデータの保存先に依らない → REQ-260。知らない経路への要求 → REQ-256。要求そのものが届かない → REQ-262 |

## 事後条件

- 成功時: 学び側とまなびばが、本人と分かった要求にだけ認証を要する応答を返しており、断りはどれも日本語の 1 文として利用者に伝わり、どの応答にも内部の事情が出ておらず定められたセキュリティヘッダが載っている。死活確認はデータの保存先の状態に依らず生きていることを示す
- 失敗時: いかなる状態変更も残っていない（部分適用なし。断った要求は本人の記録も学びのデータも変えない）
