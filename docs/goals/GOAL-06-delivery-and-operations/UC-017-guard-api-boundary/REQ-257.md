# REQ-257

> 要求の本文が決められた形を満たさないとき、学び側とまなびばはその本文を処理に進めず、どの項目が満たされていないかが分かる日本語の理由を添えて断る。

## 検証方針

- **分割クラス**:
  - `#not-json` — 本文が JSON として読めない
  - `#field-missing` — 契約が `required` に挙げる項目が本文に無い
  - `#wrong-type` — 項目の値が契約の型でない
  - `#out-of-range` — 項目の値が契約の形・長さ・範囲の外
  - `#not-processed` — 断った本文は処理に進まない（保存先を引く段に届かない）
  - `#reason-names-the-field` — 断りの理由が、満たされていない項目を日本語で指し、スキーマの英語の文言を出さない
- **尽きている根拠**: 本文は（JSON として読めない）（読めるが項目が無い）（項目の型が違う）（型は合うが範囲の外）（すべて決めの内）の 5 つに分かれ、最後だけが各 UC の成功側の要件の領域で、残り 4 つをクラス 1〜4 が 1 対 1 で取る。断ったときの観測は「進まないこと」と「理由の形」の 2 点（クラス 5・6）。
- **境界の扱い**: 範囲の両端の値そのものは各 operation の `request` が持つ（R-102）。断る側の端をクラス 4 が取り、通る側の端は各 UC の成功側の要件。
- **検証しない**: 項目ごとの文言の正確な語（利用者に見える文は別の検査が見る。R-102）。認証を要する経路で通るものが無く本文も形を満たさない要求の先後 — 先に立つのは認証の断りで、持ち主は REQ-255（`#precedes-body-check`）。署名の秘密が無い配備で本文も形を満たさない要求の先後 — 先に立つのは配備に設定が無いことによる断りで、持ち主は REQ-274（本文を取る認証を要さない経路はトークンを発行する 3 本だけなので、この配備ではこの文の対象になる入力が無い）。
- **参照先**: `tests/server/protection.test.ts::本文のスキーマ検証`（理由が項目を指すこと）、`tests/server/repay_UC-017_guard_api_boundary.test.ts::REQ-257 決められた形を満たさない本文の断り`（学び側。認証を要する変更の経路での 4 つの崩れ方と、認証を要さない発行の経路が断った本文でまなびばを呼ばないこと）、`tests/portal/repay_UC-017_guard_api_boundary.test.ts::REQ-257 決められた形を満たさない本文の断り（signIn）`（まなびば。4 つの崩れ方と、断った本文が保存先に届かないこと）。
