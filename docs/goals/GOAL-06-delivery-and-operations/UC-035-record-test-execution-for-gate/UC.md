# UC-035 テストを回して実行の記録を書き出し、どのテストからも動かないコードを門で見つけられるようにする

## 概要

運用者がテストを回し、システムが画面・API・共有コード・道具のどれがテストから動いたかを 1 つの実行の記録に書き出すことで、どのテストからも動かないコードを門で見つけられるようにする（ADR-0015）。

## 事前条件

- 手元の作業環境に、配信しようとする版のソースとテストがそろっている

## 主シナリオ

1. 運用者が、テストを回す
2. システムが、テストを 1 回回し、同じプロセスで動いたコードと、テストが子プロセスで回した道具の、動いた行と呼ばれた関数を記録する
3. システムが、テストが写しの置き場で回した道具の記録を写し元のファイルの記録に直し、今回の実行の分だけを 1 つの実行の記録に書き出す
4. 運用者が、書き出された実行の記録を門に渡す

## 状態 × イベント表

| テストと道具の状態 \ イベント | テストを回す |
| --- | --- |
| テストが道具をリポジトリの置き場から子プロセスで回す | REQ-590, REQ-591 |
| テストが道具を写しの置き場へ写して子プロセスで回す | REQ-590, REQ-591 |
| 前に回したときの実行の記録が残っている | REQ-592 |
| 道具の記録を取る環境を作れない | REQ-593 |
| 打ち切られたか書けなかった子プロセスが、読めない記録を残している | REQ-610 |
| 同じファイルが、テストと同じプロセスの記録と子プロセスの記録の両方に載る | REQ-666 |

## 例外系の走査（4 分類）

| 軸 | 該当ステップ | 導出 |
| --- | --- | --- |
| 権限 | 1 | なし（手元の作業環境で、ソースとテストを読める運用者だけが使う） |
| 不変条件違反 | 2・3 | 写しで回した道具が写し元のファイルとして載らないと、動いた道具が動いていないと数えられる → REQ-590／記録を取ることで道具の出す物が変わると、テストの確かめが変わる → REQ-591／前の実行の分が混ざると、今回動いていないコードが動いたと数えられる → REQ-592／片方の記録で呼ばれた関数が、もう片方の記録で呼ばれていないと載ると、動いた関数が動いていないと数えられる → REQ-666 |
| 並行性 | 2 | なし（記録は 1 回の実行のテストすべての分を合わせて書き出す） |
| 外部依存 | 1・2 | 道具の記録を取る環境を作れない → REQ-593／打ち切られたか書けなかった子プロセスが読めない記録を残す → REQ-610 |

## 事後条件

- 成功時: 運用者が、今回のテストの実行で動いた画面・API・共有コード・道具の行と関数が、写し元のファイルとして載った実行の記録を門に渡せる
- 失敗時: 記録を取る環境を作れなかった理由が示され、テストの実行が失敗で終わっている

## 要件

### REQ-590
- pattern: Event-driven
- status: active

> 運用者がテストを回したとき、システムは、テストが子プロセスで回した道具の動いた行と呼ばれた関数を、写しの置き場で回した道具も写し元のファイルの行と関数として実行の記録に載せ、写し元に同じファイルが無い物は載せない。

#### 検証方針

- **分割クラス**:
  - `#repo-python-tool` — 置き場から回した Python の道具は、動いた行と呼ばれた関数が載り、動かなかった関数とその行は動いていないと載る
  - `#repo-shell-tool` — 置き場から回したシェルの道具は、動いた行が載り、通らなかった行は動いていないと載る
  - `#repo-node-tool` — 置き場から回した Node の道具は、動いた行と呼ばれた関数が載り、動かなかった関数は呼ばれていないと載る
  - `#copied-tool-as-original` — 写しの置き場で回した道具は、写し元のファイルの行と関数として載り、写しのパスでは載らない
  - `#place-via-link` — 置き場をリンクを含むパスで渡しても、置き場から回した Python と Node の道具の動いた行が写し元のファイルとして載る
  - `#copy-only-not-listed` — 写し元に同じファイルが無い道具は、記録に載らない
- **尽きている根拠**: 道具の種類（Python・シェル・Node。記録の取り方が種類ごとに違う）ごとに置き場から回す場合を 1 つ、写しで回す場合を写し元がある・無いで 2 つ置く。置き場の渡し方（リンクを解いたパス・リンクを含むパス）で、写し元のファイルの見分けが変わらないことを 1 つ置く
- **境界の扱い**: 置き場は、`#place-via-link` のほかはリンクを解いた本当のパスで渡す。小さな置き場を記録つきで回す 1 回は、ほかの担当のテストと並べて数秒〜十数秒だった。上限は 1 回 240 秒、1 テスト 300 秒（並べたときの遅れに 10 倍以上の余裕を持たせる）
- **検証しない**: シェルの道具の関数（シェルの記録は行だけを取る）。写しで回すシェルと Node の道具（写し元への直し方は道具の種類によらず同じ文が掛かるので、Python で見る）。同じファイルの節が記録に 2 つ出るか（文は 1 つのファイルに 1 つの節を求めていない。2 つの節の動いた行は合わせて読み、呼ばれた関数の載り方は REQ-666 が決める）

### REQ-591
- pattern: State-driven
- status: active

> 実行の記録を取っているあいだ、テストが回す道具の標準出力・標準エラー・終了の状態・書き出すファイルは、記録を取らずに回したときと同じである。

#### 検証方針

- **分割クラス**:
  - `#python-tool-same` — Python の道具の標準出力・標準エラー・終了の状態・書き出すファイルは、記録の有無で同じ
  - `#shell-tool-same` — シェルの道具の標準出力・標準エラー・終了の状態・書き出すファイルは、記録の有無で同じ
  - `#node-tool-same` — Node の道具の標準出力・標準エラー・終了の状態・書き出すファイルは、記録の有無で同じ
- **尽きている根拠**: 記録の取り方が道具の種類ごとに違うので、種類ごとに 1 つ置き、文が挙げる 4 つを 1 つのテストでまとめて比べる
- **境界の扱い**: 記録なしは、同じ置き場の同じテストを vitest でそのまま回した物と比べる。小さな置き場を記録つきで回す 1 回は、ほかの担当のテストと並べて数秒〜十数秒だった。上限は 1 回 240 秒、1 テスト 300 秒（並べたときの遅れに 10 倍以上の余裕を持たせる）
- **検証しない**: 0 でない終了の状態の値ごとの違い（道具は 0 でない値を 1 つずつ返し、値によって記録の取り方は変わらない）

### REQ-592
- pattern: Event-driven
- status: active

> 運用者がテストを回したとき、システムは実行の記録に今回の実行で動いた分だけを書き出し、前に回したときの分を残さない。

#### 検証方針

- **分割クラス**:
  - `#previous-run-not-kept` — 前の実行で回した道具を今回のテストが回さないと、今回の記録ではその道具は動いていない
- **尽きている根拠**: 前の実行の分が残る形は、前の実行の記録が今回に混ざることだけで、前にだけ動いた道具の行で見る
- **境界の扱い**: 同じ置き場を 2 回回し、2 回目の前にその道具を回すテストを外す。小さな置き場を記録つきで回す 1 回は、ほかの担当のテストと並べて数秒〜十数秒だった。上限は 1 回 240 秒、1 テスト 300 秒（並べたときの遅れに 10 倍以上の余裕を持たせる）
- **検証しない**: 前の実行の記録を消せない場合（UC の表で導いていない）

### REQ-593
- pattern: Unwanted behaviour
- status: active

> 運用者がテストを回すときに、Python の道具の記録を取る環境を作れないとき、システムはその理由を 1 行で示して、テストの実行を失敗で終える。

#### 検証方針

- **分割クラス**:
  - `#venv-uncreatable` — Python の記録の環境を作れない置き場を渡すと、理由を 1 行で示して、失敗で終える
- **尽きている根拠**: 文の条件は 1 つで、環境の置き場の途中がファイルで作れない場合で見る
- **検証しない**: 環境は作れたが道具の記録を取る部品を入れられない場合（ネットワークに出る形になるので回さない）

### REQ-610
- pattern: Unwanted behaviour
- status: active

> 運用者がテストを回すときに、打ち切られたか書けなかった子プロセスが読めない記録を残したとき、システムはその記録を飛ばして、テストの実行をそれでは失敗にせず、飛ばした数を 1 行で示す。

#### 検証方針

- **分割クラス**:
  - `#unreadable-raw-skipped` — 生の記録の置き場に読めない記録（Node と Python）があっても、それを飛ばし、成功で終え、飛ばした数を 1 行で示す
- **尽きている根拠**: 文の条件は 1 つで、Node と Python の読めない記録を同時に置き、合わせた数で見る
- **境界の扱い**: 読めない記録は、置き場のテストが記録つきで回るときに、子に渡る生の記録の置き場へ壊れたファイルを書いて作る。飛ばした数を示す行は、読めない記録の無い同じ実行に無かった 1 行と読む。小さな置き場を記録つきで回す 1 回は、ほかの担当のテストと並べて数秒〜十数秒だった。上限は 1 回 240 秒、1 テスト 300 秒（並べたときの遅れに 10 倍以上の余裕を持たせる）
- **検証しない**: シェルの読めない記録（シェルの生の記録は 1 つのファイルに追記する形で、どれが読めない 1 件かを文が決めていない）

### REQ-666

- pattern: Event-driven
- status: active

> 運用者がテストを回したとき、システムは同じファイルの同じ行で始まる関数を 1 つの関数とみなし、今回のテストの実行のどれかの記録でその行で始まる関数が呼ばれていれば、その行で始まる関数を実行の記録で呼ばれていないとは載せず、どの記録でも呼ばれていない行で始まる関数は呼ばれていないと載せる。

#### 検証方針

- **分割クラス**:
  - `#called-in-one-record-not-uncalled` — テストと同じプロセスで呼ばれ、子プロセスの記録では 0 回の関数が、実行の記録で呼ばれていないと載らない
  - `#same-line-functions-called-together` — 同じファイルの同じ行で始まる 2 つの関数のうち片方だけが呼ばれると、実行の記録ではどちらも呼ばれていないと載らない
  - `#uncalled-in-both-stays-uncalled` — 同じファイルが 2 つの記録に載るとき、どちらの記録でも呼ばれない名前つきの関数（呼ばれた関数と別の行で始まる）は、実行の記録で呼ばれていない（0 回）と載る
- **尽きている根拠**: 文の条件は、同じ始まりの行の関数がどれかの記録で呼ばれる場合と、どの記録でも呼ばれない場合の 2 つ。呼ばれる側は、同じ関数が 2 つの記録に名前の違いで載る場合と、1 つの行で始まる別の関数の場合の 2 つ。呼ばれない側は、呼ばれた関数と別の行で始まる関数で見る
- **検証しない**: 呼ばれた回数の値（文は呼ばれたか呼ばれていないかだけを決める）
