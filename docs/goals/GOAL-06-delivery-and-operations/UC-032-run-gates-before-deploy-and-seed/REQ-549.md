# REQ-549

> 運用者がソースの門を回したとき、パスワードの記録を作る計算量が配備先の実行環境の上限の内にあり、画面のコードに、取得する一覧か取得しない手元の一覧かを問わず状態を空の一覧で始める箇所が無ければ、システムは通したことを示して成功で終える。

## 検証方針

- **分割クラス**:
  - `#within-limit-clean-client` — パスワードの記録を作るコードがプロジェクトの今のコードの写しで、画面のコードの置き場に状態を空の一覧で始める箇所が無いとき
  - `#clean-client-same-written-forms` — 画面のコードが、REQ-551 の書き方のクラスと同じ形（返す関数で渡す・型を後ろに添える・型引数を複数の行や入れ子で書く・名前空間から呼ぶ）で、状態を空でない一覧や取得前を表す値で始めるとき
- **尽きている根拠**: 文の通る条件は 2 つの AND で、どちらかが欠けるときは REQ-550・REQ-551 が持つ。通る入力は意味の上では 1 つの同値クラスだが、REQ-551 が書き方ごとに止める箇所を置くので、同じ書き方で空の一覧でない値を渡す入力を境界の隣として別のクラスに置く（書き方だけを見て止める誤り、たとえば初期値を関数で渡す形をすべて止める誤りを見分ける）。
- **境界の扱い**: 計算量の上限の内は、プロジェクトの今のパスワードの記録を作るコードの写しで作る（今の計算量で作った記録はまなびばが照合に使っており、上限の内にある）。画面のコードの置き場は、取得する一覧を取得前を表す値で始める画面と、一覧でない値を空で始める画面で作る。書き方の隣のクラスは、1 つの画面に REQ-551 の書き方を 1 つずつ並べ、どれも空でない一覧か取得前を表す値で始める。
- **検証しない**: 計算量がちょうど上限のとき（上限の値の正本は門の実装の定数で、テストから引くと実装を読むことになる。上限の値は文書に書かない）。通したことを示す文言の形（文と契約が決めていない）。
- **参照先**: `tests/server/UC-032_registry_and_source_gates.test.ts::ソースの門は、計算量が上限の内で空の一覧で始める箇所が無ければ通す（UC-032）`
