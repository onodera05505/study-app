# REQ-551

> 運用者がソースの門を回したときに、画面のコードに、取得する一覧か取得しない手元の一覧かを問わず状態を空の一覧で始める箇所があれば、システムはその箇所をすべて挙げて失敗で終える。

## 検証方針

- **分割クラス**:
  - `#one-site` — 画面のコードの置き場に、取得する一覧の状態を空の一覧で始める箇所が 1 つあるとき
  - `#all-sites-listed` — 2 つのファイル（1 つは下のディレクトリ）に合わせて 3 箇所あるとき、3 箇所をすべて挙げる
  - `#annotated-line-still-fails` — 箇所の行に印や注記のコメントを書き添えても、止めて挙げる（行ごとの例外は無い。ADR-0010）
  - `#hook-module-site` — 画面のコードの置き場の、画面の部品でない `.ts` のファイル（取得を受け持つ関数）にある箇所
  - `#local-list-site` — 取得の結果を入れない、取得しない手元の一覧の状態を空の一覧で始める箇所が 1 つあるとき（取得する一覧の箇所は無い）
  - `#lazy-initializer-site` — 初期値を、空の一覧を返す関数で渡す箇所（`useState<T[]>(() => [])`）が 1 つだけあるとき
  - `#type-asserted-site` — 型を空の一覧の後ろに添えて渡す箇所（`useState([] as T[])`）が 1 つだけあるとき
  - `#multiline-type-argument-site` — 型引数を複数の行に分けて書いた箇所（`useState<` 改行 `T[]` 改行 `>([])`）が 1 つだけあるとき
  - `#nested-type-argument-site` — 型引数の中に別の型引数を入れ子にした箇所（`useState<Array<T>>([])`）が 1 つだけあるとき
  - `#namespaced-call-site` — 状態を作る関数を名前空間から呼ぶ箇所（`React.useState<T[]>([])`）が 1 つだけあるとき
- **尽きている根拠**: 箇所の数（1 つ・複数）と置き場の中の位置（同じファイル・下のディレクトリ）を 2 クラスで押さえ、行に書き添えた物で結果が変わらないこと（ADR-0010）と、画面のコードのファイルの種類（部品と部品でない `.ts`）を別に置く。文は一覧を取得するかどうかを問わないと決めているので、取得しない手元の一覧の箇所だけがある入力を別のクラスに置く（取得する一覧の箇所だけを止める誤りを見分ける）。文は「空の一覧で始める」を書き方で分けないので、箇所の書き方を 3 つの軸に分け、軸の値ごとに 1 クラスを置く: 状態を作る関数の呼び方（素の名前は既存のクラス、名前空間から呼ぶ形は `#namespaced-call-site`）、型引数（無し・1 行の単純な型は既存のクラス、複数の行は `#multiline-type-argument-site`、入れ子は `#nested-type-argument-site`）、初期値の渡し方（空の一覧をそのまま渡す形は既存のクラス、返す関数で渡す形は `#lazy-initializer-site`、型を後ろに添える形は `#type-asserted-site`）。軸ごとに見落とし方が別なので（1 行の照合・角かっこの対応・初期値の式の読み方）、1 つのクラスに畳まない。書き方のクラスはどれもその箇所だけを置いた入力にし、終了の値だけでも見落としを見分けられるようにする。パスワードの側は通る写しを渡し、失敗が画面の側から来ることを分ける。
- **境界の扱い**: 取得する一覧の箇所は `useState` の初期値を空の一覧にして、同じ部品の中で取得の結果を入れる形で作る（型引数あり・なしの両方）。取得しない手元の一覧の箇所は、同じ初期値で取得の結果を入れない形で作る。書き方のクラスは手元の一覧の箇所と同じ画面の形で、初期値の書き方だけを変える。挙げたことは、出力の 1 行にそのファイルの名前とその行の番号がそろって出るかで見る。複数の行に分けた箇所は、`useState` を書いた行の番号で見る。書き添える物は、これまで例外の印だった `// 空で開始可` と、ほかの道具の除外の書き方で作る。通す側の対の入力（同じ書き方で空でない値や取得前の値で始める画面）は REQ-549 が持つ。
- **検証しない**: 空の一覧を `useState` 以外で持つ書き方（文の「始める箇所」がどの書き方を指すかを一意に読めない）。空の一覧を別の名前に置いてから渡す形（`const empty: T[] = []` のあと `useState(empty)`）と、関数の本体を文の並びで書いて空の一覧を返す形（`() => { return [] }`）と、一覧を作る呼び出しで空にする形（`Array()`・`new Array()`）: 初期値が空の一覧かはプログラムの流れや呼び出しの意味を読まないと決まらず、そのときに挙げる行が名前を置いた行か `useState` の行かも文が決めない（問いとして返した）。
- **参照先**: `tests/server/UC-032_registry_and_source_gates.test.ts::ソースの門は、状態を空の一覧で始める箇所をすべて挙げて止める（UC-032）`
