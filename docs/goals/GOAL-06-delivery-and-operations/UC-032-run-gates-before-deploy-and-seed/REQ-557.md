# REQ-557

> 運用者が流した投入が保存先に通ったとき、システムは流したあとの保存先を投入と突き合わせ、突き合わせが通ったときだけ完了を示して成功で終える。

## 検証方針

- **分割クラス**:
  - `#reconciled-completes` — 投入が通り、突き合わせも通る入力（投入のあとに突き合わせを回し、成功で終わる）
  - `#mismatch-fails` — 投入は通ったが、突き合わせが食い違いを示す入力（失敗で終わる）
  - `#reconciles-target-storage` — 流した先が本番か手元かで、突き合わせが見る保存先がそれに合う（手元へ流したときだけ手元を見る指定を付ける）
- **尽きている根拠**: 突き合わせの結果は通る・食い違いの 2 つに尽き、見る保存先は流した先の 2 つに尽きる。突き合わせの形は UC-027 の verifySeedRemote が持つ。
- **検証しない**: 完了を示す文言。食い違いの種類ごとの入力（UC-027 の verifySeedRemote の範囲）。食い違いのあとに流した投入と控えが残ること（手続きは保存先を巻き戻す操作を持たず、偽の保存先では観測の足しにならない）。
- **参照先**: `tests/server/UC-032_seed_procedure.test.ts::UC-032 配備と投入の前に門を回し、通らない物を本番に出さない（投入の手続き）`（土台は `tests/server/UC-032_fixture.ts`。本番と手元の保存先は偽の SQLite、流す前の投入の検査・突き合わせ・控えの道具は決めた終了の状態で返す包み）
