# REQ-562

> 運用者がロードマップ型の学びを配信するときに、本番の保存先で学ぶ順を持つ論点のうち回の無い論点が 1 つでもあるか、保存先から論点の回を読めなければ、配備の手続きは回の無い論点の数か読めないことと先に回す手続きを示し、その学びを配信しないまま失敗で終える。

## 検証方針

- **分割クラス**:
  - `#round-missing` — ロードマップ型の学びで、学ぶ順を持つ論点のうち 1 つにだけ回が無い入力（配信しないまま失敗で終わる）
  - `#rounds-unreadable` — ロードマップ型の学びで、本番の保存先から論点の回を読めない入力（同上）
  - `#missing-count-shown` — ロードマップ型の学びで、学ぶ順を持つ論点のうち複数に回が無く、学ぶ順を持たず回も無い論点もある入力（学ぶ順を持つ論点のうち回の無い論点の数を示す）
- **尽きている根拠**: 回の状態は、すべてある（REQ-561）・無い物がある・読めない、の 3 つに尽きる。「1 つでも」の境界として 1 つだけ欠ける入力を置く。示す数は、1 つだけ欠ける入力では出力の中のほかの数と見分けられないので、欠ける数を出力に出にくい数にした入力で別に見る。学ぶ順を持たない論点の回の欠けを数に入れる誤りを見分けるため、学ぶ順を持たず回も無い論点を足す。
- **境界の扱い**: 示した数は、出力の中に前後が数字でない 10 進の数として、学ぶ順を持つ論点のうち回の無い論点の数が出るかで見る。学ぶ順を持たない回の無い論点まで数えた数は出ないことを見る。
- **検証しない**: 先に回す手続きの文言（手続きの名前を文が決めていない）。示す数の書き方（10 進の数のほかの形を文が決めていない）。
- **参照先**: `tests/server/UC-032_deploy_gates.test.ts::UC-032 配備と投入の前に門を回し、通らない物を本番に出さない（学び側の配備の手続き）`（土台は `tests/server/UC-032_fixture.ts`。門と描画の検査は決めた終了の状態で返す包み、本番の保存先は偽の SQLite）
