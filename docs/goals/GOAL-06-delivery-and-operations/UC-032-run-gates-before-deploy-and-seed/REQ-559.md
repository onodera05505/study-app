# REQ-559

> 運用者が学び側を配信するときに、配備先にログインしているアカウントがプロジェクトの決めた配備のアカウントと違うか、ログイン中のアカウントを確かめられなければ、配備の手続きはログイン中のアカウントと決めたアカウントを示し、その学びを配信しないまま失敗で終える。

## 検証方針

- **分割クラス**:
  - `#other-account` — 配備先に決めた配備のアカウントと違うアカウントでログインしている入力（両方のアカウントを示し、配信しないまま失敗で終わる）
  - `#account-unverifiable` — ログイン中のアカウントを確かめられない入力（決めたアカウントを示し、配信しないまま失敗で終わる）
- **尽きている根拠**: ログイン中のアカウントは、決めたアカウント（REQ-561 の正常の入力）・違うアカウント・確かめられない、の 3 つに尽きる。
- **検証しない**: 決めた配備のアカウントの値そのもの（正本は `scripts/pages_projects.json`）。確かめられないときに示す文言。
- **参照先**: `tests/server/UC-032_deploy_gates.test.ts::UC-032 配備と投入の前に門を回し、通らない物を本番に出さない（学び側の配備の手続き）`（土台は `tests/server/UC-032_fixture.ts`。門と描画の検査は決めた終了の状態で返す包み、本番の保存先は偽の SQLite）
