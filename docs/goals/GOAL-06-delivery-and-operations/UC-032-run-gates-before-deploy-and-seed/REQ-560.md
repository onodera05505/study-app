# REQ-560

> 運用者が学び側を配信するときに、その学びの本番の保存先に当たっていない構造の変更があるかそれを確かめられないか、ソースの門・その学びの登録簿の門・文書の索引の門・実データの描画の検査のどれかが止めたなら、配備の手続きはその学びを配信しないまま失敗で終える。

## 検証方針

- **分割クラス**:
  - `#unapplied-migration` — 本番の保存先に当たっていない構造の変更が 1 つある入力（配信しないまま失敗で終わる）
  - `#migrations-unverifiable` — 本番の保存先の構造の変更を確かめられない入力（同上）
  - `#source-gate-stops` — ソースの門が止める入力（同上）
  - `#registry-gate-stops` — その学びの登録簿の門が止める入力（同上。門にはその学びを渡す）
  - `#docs-index-gate-stops` — 文書の索引の門が止める入力（同上）
  - `#render-check-stops` — 実データの描画の検査が止める入力（同上）
- **尽きている根拠**: 文が挙げる止める理由は、構造の変更（当たっていない・確かめられない）と 4 つの門・検査に尽き、1 つずつ止めてほかは通す。全部通る側は REQ-561 の正常の入力が覆う。門・検査がどの入力で止めるかは各門の契約と要件（UC-032 の REQ-546〜551・UC-027 の checkRender）が持つ。
- **検証しない**: 門・検査が止める中身ごとの入力（各門の要件の範囲）。2 つ以上が同時に止める入力。門を回す順。
- **参照先**: `tests/server/UC-032_deploy_gates.test.ts::UC-032 配備と投入の前に門を回し、通らない物を本番に出さない（学び側の配備の手続き）`（土台は `tests/server/UC-032_fixture.ts`。門と描画の検査は決めた終了の状態で返す包み、本番の保存先は偽の SQLite）
