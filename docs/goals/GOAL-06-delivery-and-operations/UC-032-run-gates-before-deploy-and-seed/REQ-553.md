# REQ-553

> 運用者が投入を流すときに、流す先の保存先に当たっていない構造の変更があるか、それを確かめられなければ、システムは控えも投入もせずに失敗で終える。

## 検証方針

- **分割クラス**:
  - `#unapplied-migration` — 流す先の保存先に当たっていない構造の変更が 1 つある入力（控えも投入もせず失敗で終わる）
  - `#migrations-unverifiable` — 流す先の保存先に構造の変更が当たっているかを確かめられない入力（同上）
  - `#other-storage-not-target` — 流す先でない保存先にだけ当たっていない構造の変更がある入力（それでは止めずに流す先へ投入する）
- **尽きている根拠**: 流す先の保存先の構造の変更の状態は、全部当たっている（REQ-555・557 の正常の入力）・当たっていない物がある・確かめられない、の 3 つに尽きる。文の「流す先の」を、流す先でない保存先の状態で止めないことで見分ける。本番・手元の 2 つの列は各クラスの中で両方を回す。
- **検証しない**: 当たっていない構造の変更の数が 2 つ以上の入力（1 つと同じ扱いで、境界は 1）。断ったときの文言と示す手順。
- **参照先**: `tests/server/UC-032_seed_procedure.test.ts::UC-032 配備と投入の前に門を回し、通らない物を本番に出さない（投入の手続き）`（土台は `tests/server/UC-032_fixture.ts`。本番と手元の保存先は偽の SQLite、流す前の投入の検査・突き合わせ・控えの道具は決めた終了の状態で返す包み）
