# REQ-555

> 運用者が門の通った投入を流すとき、システムは流す先が本番の保存先のときだけ投入の前にその保存先の控えを取り、控えが取れなければ投入せずに失敗で終える。

## 検証方針

- **分割クラス**:
  - `#remote-backup-before-seed` — 門の通った投入を本番へ流す入力（本番のその学びの保存先の控えを取ってから、本番の保存先へ投入する）
  - `#local-no-backup` — 門の通った投入を手元の保存先へ流す入力（控えを取らずに手元の保存先へ投入する）
  - `#backup-fails` — 門の通った投入を本番へ流し、控えが取れない入力（投入せず失敗で終わる）
- **尽きている根拠**: 流す先は本番・手元の 2 つで、本番では控えが取れる・取れないの 2 つに分かれる。控えは控えの道具か保存先の書き出しのどちらで取っても数え、取れないときはどちらも失敗させる。
- **検証しない**: 控えの中身と置き場所（控えの道具の範囲）。
- **参照先**: `tests/server/UC-032_seed_procedure.test.ts::UC-032 配備と投入の前に門を回し、通らない物を本番に出さない（投入の手続き）`（土台は `tests/server/UC-032_fixture.ts`。本番と手元の保存先は偽の SQLite、流す前の投入の検査・突き合わせ・控えの道具は決めた終了の状態で返す包み）
