# REQ-561

> 運用者が学び側を配信するとき、配備の手続きは、資格対策の学びなら回の確かめは見る物が無いとして通し、ロードマップ型の学びなら本番の保存先で学ぶ順を持つ論点のすべてに回があることを確かめてその論点の数を示して通す。

## 検証方針

- **分割クラス**:
  - `#qualification-no-round-check` — 資格対策の学びで、門がすべて通る入力（回を確かめる物が無いとして配信する）
  - `#roadmap-all-rounds` — ロードマップ型の学びで、学ぶ順を持つ論点のすべてに回があり、門がすべて通る入力（その論点の数を示し、門がすべて通ったあとに配信する）
- **尽きている根拠**: 学びの種類は資格対策・ロードマップ型の 2 つに尽き、ロードマップ型の回の欠け・読めないは REQ-562 が覆う。
- **検証しない**: 論点の数を示す文言（数そのものが出力にあることだけを見る）。版の印・配備の道具・配信物に結ぶ保存先（UC-016 の範囲）。
- **参照先**: `tests/server/UC-032_deploy_gates.test.ts::UC-032 配備と投入の前に門を回し、通らない物を本番に出さない（学び側の配備の手続き）`（土台は `tests/server/UC-032_fixture.ts`。門と描画の検査は決めた終了の状態で返す包み、本番の保存先は偽の SQLite）
