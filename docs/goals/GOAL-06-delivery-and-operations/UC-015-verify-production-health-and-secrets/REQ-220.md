# REQ-220

> 本番の検査が結果を返すとき、見た配備と項目に問題が 1 つ以上あれば、全体を失敗として返す。

## 検証方針

- **分割クラス**:
  - `#one-problem-overall-fail` — 問題が 1 つだけでも全体を失敗として返す
  - `#problems-listed` — 失敗の結果に、足りなかった配備と項目の名前がすべて挙がる
  - `#fail-from-any-item-kind` — 死活確認・入口の画面・秘密の名前のどの項目の問題でも、等しく全体が失敗になる
  - `#no-state-change` — 失敗を返しても本番の状態が何も変わっていない（検査は読むだけ）
- **尽きている根拠**: 入力は「問題の件数」と「問題の種類」の 2 軸。件数は 0 件（REQ-216）と 1 件以上に尽き、1 件以上の側をこの要件が受け持つ。種類は UC の表の 3 つの項目に尽き、どれでも結果が同じなのでまとめて 1 クラス。失敗時の事後条件（部分適用なし）は件数と独立なので別に立てる。
- **境界の扱い**: 0 件と 1 件の隣接。0 件の側は REQ-216 の `#all-pass-overall-pass`。
- **検証しない**: 出力の文言と並び（OQ-119）。問題の挙げ方の中身（REQ-217・REQ-218・REQ-221・REQ-222）。
- **参照先**: 単体には無い（結果の返し方は標準出力と終了状態で、契約に表せない。OQ-119）。本体は `scripts/check_sso_prod.sh`（system suite なので `@covers` を持たない）＝全クラス未被覆。
