# REQ-224

> 運用者が新しい版を配信したとき、システムはその版を見分ける版の印を配信物に書き出す。

## 検証方針

- **分割クラス**:
  - `#first-release` — まだ印が無い（一度も配信していない）状態で新しい版を配信した入力（配信物に版の印が置かれる）
  - `#after-previous` — 前の版の印がある状態で新しい版を配信した入力（前の印と見分けられる値に置き換わる）
- **尽きている根拠**: UC.md の表「配信物に置かれた版の印」の「新しい中身の版を配信する」列は、印の状態 2 つ（まだ印が無い／前の版の印がある）で尽きる。書き出せなかった側は REQ-226 の範囲。
- **検証しない**: 配信物の置き場と配信そのものの成否（配備の 1 本道が持つ。ADR-0002）。印に入れる値の作り方（機械可読な値なのでコードが正本。R-102）。
- **参照先**: `tests/server/repay_UC-016_deploy_procedure.test.ts::UC-016 配備の手続き（偽の配備の道具と組み立ての道具で回す）`（リポジトリの影の根で `scripts/deploy-pages.sh` を、固定した版の位置に置いた偽の配備の道具と偽の組み立ての道具で回し、配信に渡された配信物の `version.json` を偽の道具の記録で見る。土台は REQ-225・226・351・352 と共有する。保証点は ADR-0007）
