# REQ-351

> 運用者が学び側またはまなびばを配信するとき、配備の手続きはプロジェクトが固定した版の配備の道具で配信する。

## 検証方針

- **分割クラス**:
  - `#learning-uses-pinned-tool` — 学び側の配備の手続き（`scripts/deploy-pages.sh`）を回した入力（配信に使われた配備の道具がプロジェクトの固定した版である）
  - `#portal-uses-pinned-tool` — まなびばの配備の手続き（`scripts/deploy_portal.sh`）を回した入力（配備の設定を組む場所がリポジトリの外でも、使われた配備の道具がプロジェクトの固定した版である）
- **尽きている根拠**: 配備の手続きは学び側とまなびばの 2 本に尽き、どちらも観測は「使われた道具が固定した版か」の 1 つ。
- **検証しない**: 固定した版の値（R-102。値の SSOT は `package.json` と `package-lock.json` の wrangler）。配信そのものの成否（配備先が持つ。ADR-0002）。配備の手続きを迂回して道具を直に呼ぶ経路（保証点の外。ADR-0007）。
- **参照先**: `tests/server/repay_UC-016_deploy_procedure.test.ts::UC-016 配備の手続き（偽の配備の道具と組み立ての道具で回す）`（固定した版の位置に置いた偽の道具と、PATH と npx の取りに行く先に置いた別の版の偽の道具を分け、配信に使われた道具を記録で見る）
