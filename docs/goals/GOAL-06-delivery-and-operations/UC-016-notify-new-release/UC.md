# UC-016 配信した新しい版を、開いたままの画面に知らせる

## 概要

運用者が新しい版を配信したとき、前の版を開いたままの利用者の画面に新しい版があることを知らせ、利用者が読み直しを選んだときだけ新しい版に入れ替わる。運用者は、配信した版が使っている人に届いたことを画面の知らせとして確かめられる。

## 事前条件

- 運用者（ACT-03）に配備の権限がある
- 利用者（ACT-01）が権限のある学びの画面を使える（学びに入る筋は GOAL-08 の範囲）
- 版の印は認証を要らずに取れる配信物として置かれる
- 配備の道具（wrangler）と組み立ての道具は、プロジェクトが版を固定して入れている
- 適用される業務規則: BR-041（横断の候補は下の BR候補 マーカー）

## 主シナリオ

1. 利用者が学びの画面を開く
2. システムが最初の版の印を 1 回だけ取りに行って覚える
3. 運用者が新しい版を配信する
4. 配備の手続きが、プロジェクトが固定した版の配備の道具で、その版を見分ける版の印を書き出した配信物を出す
5. 利用者が画面を移る
6. システムが版の印を取り直し、覚えている印と見比べる
7. システムが新しい版の知らせを出す
8. 利用者が読み直しを選ぶ
9. システムが画面を読み直し、新しい版の内容を出す

## 例外系の走査（4 分類）

| 軸 | 該当ステップ | 導出 |
| --- | --- | --- |
| 権限 | 3・4・8 | なし（理由: 配信できるのは配備の権限を持つ運用者だけで、その権限は配備の仕組みが持ち、画面側に分岐が無い。版の印は認証を要らずに取れる配信物で、知らせと読み直しは利用者の権限に依らない） |
| 不変条件違反 | 2・4・6 | 版の印が読めない形で置かれていたときは取れなかったものとして扱う → 表「画面が覚えている最初の版の印」の「取り直せない」列（REQ-232）。覚えた最初の印は画面を開いている間 1 つで、重ねて取り直して上書きしない → REQ-227。印を書き出せないまま版を出さない → REQ-226 |
| 並行性 | 2・5・6 | 見比べの間隔と画面の移りが重なって最初の印を同時に求めたときも、取りに行くのは 1 回 → REQ-227。最初の印を覚えていない状態で画面の移りと見比べの間隔の取り直しが重なり、別々の印が取れたときも、先に返った印が最初の印で、後に返った印はそれを上書きしない → REQ-233。見比べのさなかにさらに次の版が配信されたときは、取り直した印との違いで判定する → 表「画面が覚えている最初の版の印」2 行目（REQ-231）。同じ利用者が画面を複数開いているときは画面ごとに独立して覚え、片方で読み直しても他方の知らせは残る → 表「新しい版の知らせ」2 行目（REQ-234） |
| 外部依存 | 2・3・4・6・9 | 配備の道具の固定した版が入っていない → REQ-352（別の版に倒さない）。版の印を取りに行けない（通信の失敗・配信物に印が無い） → REQ-232、開いたときに取れなかった → REQ-233。版を見分ける元の値が読めないときも、配信の時点で前の版と見分けられる印になる → REQ-225。読み直した先がまだ前の版のまま返るときの扱いは未決 → 表「新しい版の知らせ」2 行目の `?` |

## 事後条件

- 成功時: 利用者が新しい版の内容を見ており、読み直す前に画面が覚えていた集計は捨てられて新しい版で取り直されている。運用者は、配信した版が開いたままの画面に届いたことを知らせと読み直しの結果として確かめられる
- 失敗時: いかなる状態変更も残っていない（部分適用なし。版の印を書き出せなければその版は本番に出ず、知らせが出ても利用者が読み直しを選ぶまで入力は失われない）
