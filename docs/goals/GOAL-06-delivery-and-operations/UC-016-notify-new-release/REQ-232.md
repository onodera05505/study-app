# REQ-232

> 版の印を取り直せなかったときは、システムは新しい版が無いものとして扱い、新しい版の知らせを出さない。

## 検証方針

- **分割クラス**:
  - `#refetch-fails-without-remembered` — 最初の印を覚えていない状態で取り直しも失敗した入力（知らせを出さない）
  - `#refetch-fails-while-remembered` — 最初の印を覚えている状態で取り直しが失敗した入力（覚えている印を保ったまま知らせを出さない）
  - `#malformed-stamp` — 配信物に印が無い・印が読めない形の入力（印が無いものとして扱い、知らせを出さない。契約 `fetchVersionStamp` の `noStamp`）
- **尽きている根拠**: UC.md の表「画面が覚えている最初の版の印」の「版の印が取り直せない」列は、覚えている／覚えていないの 2 行で尽きる。取り直せない理由は通信の失敗と印が読めないことの 2 つで、契約 `fetchVersionStamp` はどちらも印が無いものとして返す（OQ-118）ので、理由ごとの観測は 1 つに畳まれる。
- **検証しない**: 失敗の種類の区別（契約が `errors: []` で失敗を「印が無い」に畳む。OQ-113）。取り直しの再試行（要件は知らせを出さないことまでを言う）。
- **参照先**: `tests/client/version.test.ts::新しい版の検知（UC-016）`（`#refetch-fails-while-remembered`・`#malformed-stamp` は未被覆）
