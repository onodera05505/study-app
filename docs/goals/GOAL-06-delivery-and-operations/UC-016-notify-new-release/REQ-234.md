# REQ-234

> 新しい版の知らせが出ている間、システムは利用者が読み直しを選ぶまでその画面に知らせを出し続ける。

## 検証方針

- **分割クラス**:
  - `#notice-persists-across-navigation` — 知らせが出たまま画面を移った入力（知らせが残る。UC.md の表「新しい版の知らせ」2 行目）
  - `#notice-per-window` — 同じ利用者が画面を複数開き、片方で読み直した入力（他方の画面の知らせは残る。UC.md 例外系の走査「並行性」）
- **尽きている根拠**: 表「新しい版の知らせ」2 行目で知らせが残り続ける列は「画面を移る」で、別の画面での読み直しが並行性の走査から加わる。「見比べの間隔が過ぎる」列は同じ表で REQ-235 が持ち、「利用者が読み直しを選ぶ」は REQ-236 が持つので、残る 2 つでこの要件の入力が尽きる。
- **境界の扱い**: 知らせが出たあとに取り直した印が最初の印に戻った（配信が前の版へ戻った）ときも、知らせは消さずに残す（`#notice-persists-across-navigation` の代表値に含める）。
- **検証しない**: 知らせが出続ける時間の長さ（要件は読み直しを選ぶまでを言い、時間を決めていない）。
- **参照先**: `tests/client/repay_UC-016_update_bar.test.tsx::新しい版の帯（UC-016）`（`#notice-persists-across-navigation`）、`tests/client/repay_UC-016_version_lib.test.ts::最初の印の保ち方（UC-016）`（`#notice-per-window`。窓は module の実体で表し、読み直しは module の作り直し）
