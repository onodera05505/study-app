# REQ-406

> 端末にトークンがある（通るかどうかを問わない）まま使える使い捨てコードを持って学びの入口へ戻ったとき、学び側は前のトークンを端末に残さずにそのコードの本人のトークンに入れ替え、以後の要求と添える名前をその本人のものにする。

## 検証方針

- **分割クラス**:
  - `#valid-token-replaced` — 端末に通るトークン（別の本人）があるまま、使えるコードを持って学びの入口へ戻った状態（端末のトークン・ヘッダーの名前・以後の要求に添えるトークンが、すべてコードの本人のものになり、前のトークンは端末に残らない）
  - `#invalid-token-replaced` — 端末に通らないトークン（期限が過ぎた・形を成さない）があるまま、使えるコードを持って戻った状態（同じく入れ替わる）
- **尽きている根拠**: 文の条件は「トークンがある（通るかどうかを問わない）」で、UC.md の表の「トークンがある（通る）」と「トークンはあるが通らない」の 2 行がそのまま 2 クラス。通らない側の理由（期限・壊れ）は値の変種。観測は文の述語の（端末に残すトークン）（以後の要求）（添える名前）の 3 つで、同じ入力の観測なので分けない（R-1105）。
- **境界の扱い**: 前のトークンとコードの本人が同じ人の場合は、入れ替えても観測が変わらないので `#valid-token-replaced` の代表（別の本人）が強い側を取る。
- **検証しない**: コードを換えたあとに本人の記録を作るか引き継ぐか（REQ-191・REQ-192）。端末がトークンを保存できない場合（UC.md の表で `?`）。
- **参照先**: `tests/client/UC-013_token_on_return.test.tsx` の describe「UC-013 トークンがある端末が使えるコードを持って戻る（REQ-406）」。
