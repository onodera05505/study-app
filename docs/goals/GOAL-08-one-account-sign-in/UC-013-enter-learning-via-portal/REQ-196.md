# REQ-196

> 学び側は、通るトークンを伴う要求をそのトークンが指す本人の要求として扱い、返す内容とその要求で積む記録を同じ本人のものにそろえる。

## 検証方針

- **分割クラス**:
  - `#request-carries-token` — トークンがある端末の要求がそのトークンを運び、無い端末の要求は運ばない状態
  - `#same-person-in-response-and-records` — 返す内容と、その要求で積む記録が同じ本人の物にそろっている状態
- **尽きている根拠**: 「本人の要求として扱う」を外から観測できるのは（要求がトークンを運ぶ）と（応答と記録の本人がそろう）の 2 面。トークンが通るかどうかの判定そのものは、通らない場合を別の要件（REQ-194・REQ-197 の前提）が受け持つ。
- **検証しない**: トークンの形式・署名の方式・期限の長さ（実装を置き換えても要件の文は変わらないので要件にならない。R-401。値の正本はコード。R-102）。
