# REQ-274

> トークンの署名の秘密が与えられていない配備では、学び側はトークンを発行せず、どの発行の経路でも、配備に設定が無いことに当たる形で断る。

## 検証方針

- **分割クラス**:
  - `#exchange-refused` — 署名の秘密が無い配備に、まなびばから戻った使い捨てコードの交換が来た状態
  - `#password-login-refused` — 同じ配備に、学び側のパスワードでのログインが来た状態
  - `#register-refused` — 同じ配備に、学び側の登録が来た状態
  - `#signing-secret-present-not-refused` — 署名の秘密が与えられている配備では、同じ 3 つの経路が設定の不足では断られない（条件の外側の境界）
- **尽きている根拠**: トークンを発行する経路は契約の `signInWithCode`・`signInWithPassword`・`register` の 3 つで尽きる（クラス 1〜3）。配備の側は署名の秘密が（無い）（ある）の 2 値で、ある側の端をクラス 4 が取る。まなびばの場所と共有秘密の有無はこの要件の条件に入らないので、クラスを割らない。
- **境界の扱い**: 断る側と断らない側の切れ目は「配備に署名の秘密が与えられているか」だけで、秘密の値そのものは観測しない。設定の項目の名前の正本は配備の設定（R-102）。
- **検証しない**: 断りの本文が設定の不足の中身（どの秘密が足りないか）を明かさないこと（BR-002 側の検査＝`REQ-206#same-text-as-other-not-configured` が見る）。開発と検査で秘密を環境から渡す手当て（運用で、外から観測できない）。
- **参照先**: `tests/server/signing_secret.test.ts` の describe「署名の秘密が無い配備ではトークンを発行しない（UC-013）」
