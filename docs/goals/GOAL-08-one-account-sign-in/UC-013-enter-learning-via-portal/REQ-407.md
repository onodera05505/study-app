# REQ-407

> 端末にトークンがあるまま、使い捨てコードが無いか換えられないまま学びの入口へ戻った場合、学び側は端末のトークンを捨ても入れ替えもしない。

## 検証方針

- **分割クラス**:
  - `#no-code-keeps-token` — 端末にトークンがあるまま、コードを持たずに学びの入口へ戻った状態（換えに行かず、端末のトークンはそのまま）
  - `#exchange-refused-keeps-token` — 端末にトークンがあるまま、換えられないコード（使用済み・権限無し・まなびばに届かない）を持って戻った状態（換えに行ったうえで、端末のトークンはそのまま）
- **尽きている根拠**: 文の条件「コードが無いか換えられない」は、換えに行く前に決まる側（コードが無い）と、換えに行って断られる側の 2 つで尽きる。断りの種類（401・403・502）は契約の `signInWithCode` の errors の値の変種。
- **検証しない**: 断られたときの画面の旨と理由（REQ-193）。前のトークンが通るかどうかの別（文が条件にしない。表の 2 行は同じ観測で、通る側を代表に取る）。
- **参照先**: `tests/client/UC-013_token_on_return.test.tsx` の describe「UC-013 トークンがある端末がコード無し・換えられないまま戻る（REQ-407）」。
