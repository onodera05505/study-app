# REQ-566

> ログインした学び側の画面で認証の形の問い合わせが失敗したら、画面はまなびばへの導線を出さないだけにし、画面のほかの部分は出す。

## 検証方針

- **分割クラス**:
  - `#reason-failure` — ログインした画面の認証の形の問い合わせが、本文に理由を添えた失敗の応答で返った入力（導線も理由も出さず、画面のほかの部分は出る）
  - `#no-answer-failure` — ログインした画面の認証の形の問い合わせが答えを返さずに終わった入力（届かない、または失敗の状態で本文が読めない・理由が無い）
- **尽きている根拠**: 文の入力は問い合わせの失敗で、画面に渡りうる中身は「理由がある」か「何も無い」かの 2 つに尽きる。理由つきの失敗は、REQ-261 がこの要件を「その失敗を示さないと決めた要件」に挙げるので、理由を出さないことまで見る点で答えの無い失敗と分ける。答えの無い失敗は、届かないことと失敗の状態で本文が読めないことのどちらでも画面が何も得ない点で同じクラスで、テストは両方の実例を置く。問い合わせが成功して導線が出る画面は REQ-205・REQ-190 の範囲、トークンの無いログイン画面での失敗は REQ-525 の範囲。
- **検証しない**: 画面のほかの部分の並びと見た目（観測は、ホームのおすすめの論点・本人の名前・上部メニューの行き先が出ていることで行う。どの部分を持つかは各 UC の要件が決める）。まなびばへの導線は、登録簿のまなびばの場所に向いた導線と文言に「まなびば」を持つ導線の両方が無いことで見て、導線の置き場は見ない。
- **参照先**: `tests/client/UC-013_logged_in_auth_config_failure.test.tsx::UC-013 ログインした画面で認証の形の問い合わせが失敗したとき`
