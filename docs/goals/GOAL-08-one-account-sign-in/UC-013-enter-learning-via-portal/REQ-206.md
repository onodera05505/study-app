# REQ-206

> まなびばの場所はあるが共有秘密が与えられていない配備では、学び側は使い捨てコードを換えに行かず、トークンも渡さず、学び側のパスワードでのログインにも戻さずに断る。

## 検証方針

- **分割クラス**:
  - `#secret-missing-refused` — 共有秘密が無い配備で、まなびばを呼ばずに断られ、トークンも渡らない状態
  - `#no-fallback-to-password` — 同じ配備で、学び側のパスワードでのログインに戻されない状態
  - `#same-text-as-other-not-configured` — 同じ断り（秘密が与えられていないことに当たる 1 つの code と状態）を返すもう一方の配備（署名の秘密が無い）と本文が等しく、足りない秘密を名指ししない状態（BR-002）
- **尽きている根拠**: この配備で起こりうるのは（まなびばを呼ぶか）（トークンを渡すか）（パスワードの経路に戻すか）の 3 面で、前の 2 つは断りで止まる 1 つの観測にまとまる。断り自体は（状態と code）（本文）の 2 面で、本文を分ける軸は「どの秘密が足りないか」の 2 値（共有秘密／署名の秘密）だけで、クラス 3 がその 2 つの比較そのものを取る。
- **検証しない**: 断りの本文の文言そのもの（実装が正本。R-102。足りない秘密で変わらないことはクラス 3 が見る）。
- **参照先**: `tests/server/app.test.ts::SSO のコード交換（学び側。UC-013）`、`tests/server/signing_secret.test.ts::設定が無いことによる断りは足りない秘密で変わらない（UC-013）`
