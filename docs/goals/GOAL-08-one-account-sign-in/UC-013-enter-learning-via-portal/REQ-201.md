# REQ-201

> 共有秘密が合わない、または添えられていない呼び出しで使い捨てコードを換えに来たとき、まなびばはコードの状態にかかわらず断り、本人のメールも名前も渡さず、コードを使用済みにしない。

## 検証方針

- **分割クラス**:
  - `#wrong-secret` — 合わない共有秘密を添えた呼び出しの状態
  - `#no-secret` — 共有秘密を添えていない呼び出しの状態
  - `#refused-before-code-state` — コードが使用済み・期限切れでも、共有秘密の側で先に断られること（契約の errors の順序。R-1207）
  - `#code-not-consumed` — 断ったコードが使用済みになっていない状態
- **尽きている根拠**: 共有秘密は（合う）（合わない）（無い）の 3 つしかなく、合う場合は REQ-200・REQ-202・REQ-203 が受け持つ。残る 2 つを `#wrong-secret`・`#no-secret` が取り、「コードの状態にかかわらず」は隣の条件と同時に満たす入力（`#refused-before-code-state`）で確かめる。
- **検証しない**: 断りの本文（BR-002 が形を決め、秘密の有無で文を変えないことは REQ-206 のクラス `#same-text-as-other-not-configured` が見る）。
