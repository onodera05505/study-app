## 2026-09-29 以後の要求の流れを型に（本人「要件の書き直し → 製造とテスト設計を独立に → 毎回 ID の機械検査」）
- 入口 Skill `/develop`（`.claude/skills/develop/SKILL.md`）: 分類 → 要件を書く（新規は draft、バグ修正は `.trace-gate/work.json` に対象 REQ を宣言）→ 承認 → `implementer` と `test-author` を別コンテキストで並行 → `npm test` → 切り分け → active にしてコミット
- 担当の型: `implementer`（テストを書かない。契約＝公開関数の外形を報告に返す）、`test-author`（要件の文面と契約だけ。実装を読まない。**Bash を持たない**＝実行して期待値を実装に寄せられない。中央 `reports/106`）
- 書き込みの門 `write_gate`（PreToolUse。ユーザー設定に配線、`traceconfig.json` のある PJ だけ）: `src/`・`portal/src/`・`tests/`・検査スクリプトへの Write/Edit は、`docs/spec.yaml` に未コミットの差分があるか `.trace-gate/work.json` の REQ 宣言（実在する ID だけ）があるときだけ通す。変異テスト: 宣言なし→止まる／実在 REQ 宣言→通る／存在しない REQ→止まる／spec に差分→通る／docs へ→通る／tests への Edit→止まる／traceconfig の無い PJ→通る、を確認
- これで「要件を書かずに製造が始まる」「実装した文脈でテストを書く」「ID の無い実装やテストで終える」の 3 つが、規則ではなく機械で止まる。中央の型（手順 8）と `setup_project.sh --trace`（agents・skill も複製）に反映
