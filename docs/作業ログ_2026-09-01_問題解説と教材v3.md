## 進め方で効いたこと

- **試作 1 バンドルずつ → 親が中身を読む → 手本として全件へ**。IP は最頻出 2 論点（OSS・IT ガバナンス）、AP は稼働率・アローダイアグラム・サブネットマスクで試作
- **解説を先に書き、そのあと教材を削る**を同じ担当にやらせた。何を教材から外してよいかを担当自身が判断できるので抜けが出ない
- 用語集は「誰かの誤答 term」で解決するので、担当をまたぐ `[[用語]]` は最後まで警告のまま残ることがある。最終的に残った 8 語（IP）だけ `glossary_overrides.json` に書いた
- 誤答 `term` は `topics.json` の表記に合わせさせた（「この論点を学ぶ →」が付く）。副作用で `リスク対応（リスク回避，…）` のような長い表記が本文に出るので、表示側で末尾の（…）を落とす
- 担当が本文の `[[用語]]` を解決できないと判断して素の文字に戻す挙動が散見された。壊れないので容認

## 落とし穴

- **本人から「用語ポップが見つからない」と報告（反映直後）。** 原因は `Markdown.tsx` の行内パーサが `**…**` を先に丸ごと太字にしていて、
  `**[[用語]]**` の形（教材の「混同しやすい用語」はほぼこれ。IP 93%・AP 88%）では `[[…]]` が文字のまま出ていたこと。
  太字の中身をもう一度パーサに通す形に直した。**教訓: 表示側は実データの代表的な書き方（太字の中の用語、表のセルの中の用語）で
  jsdom 描画まで確かめてから反映する。** API の JSON に `[[` が入っていることの確認だけでは足りなかった。
  → 2026-09-02、これを常設の門にした: `bash scripts/check_render.sh ip|ap`（`deploy-pages.sh` がビルド前に自動で回す）
- `check_explanations.py --bundle expl_01` は argparse の前方一致で `--bundles`（ディレクトリ）に化け、**突合が黙って 0 件になる**。引数なしで全体を走らせる
- `[[デジタル署名（署名鍵，検証鍵）]]` のように IPA 句読点を含む論点名を教材本文で `[[ ]]` にすると、`check_materials.py` の句読点検査に引っかかる。本文は短い表記にする
- 頻度順に束ねると先頭バンドルが 8 論点で 85 問になった。`--max-questions 28` で区切る（担当の出力量を超える）
- Python 3.9 で日本語入りの作業スクリプトが `Non-UTF-8` で落ちることがある。先頭に `# -*- coding: utf-8 -*-`
