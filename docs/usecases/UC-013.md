## 前提条件
- 利用者が画面を開いたままにしている
- 配信のたびにビルドの印が更新される

## 基本の流れ
1. 開発側が新しい版を配信する。システムはビルドのたびに、コミットの短い ID と時刻を持つ版の印を静的ファイルとして出す
2. 利用者が画面を開く。システムは版の印を 1 回だけ取りに行き、その値を最初の印として覚える
3. 利用者が画面を移る。システムは版の印を取り直して最初の印と見比べ、5 分おきにも同じ見比べをする
4. 版が違っている。画面は上部に「新しい版があります。」の帯と「更新」ボタンを出し、自動では読み直さない
5. 利用者が「更新」を押す。画面は読み直して新しい版になる

## 例外の流れ
E1. 3 で版の印が取れない（通信の失敗）。システムは帯を出さない
E2. 2 で最初の印が取れなかった。システムは次に取れた値を最初の印にし、その回は帯を出さない

## 事後条件
- 読み直すまで利用者の入力は失われない
- 読み直した後は、画面が覚えていた集計も捨てられ、新しい版の内容で取り直される
