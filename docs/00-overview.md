# 概要

## 解決する課題

何かに特化した学び（資格・分野・職種・入社先の業務）について、**何が必要かの定義・学ぶ順・教材**が、
学ぶ人の手元にそろわない。市販のテキストは「テキストとしての完成度」を優先するため、
合格や実務までの最短経路にはならない。

資格対策では、公開された試験問題に紐づく件数がそのまま学習の優先順位になる（出題頻度＝重要度）。
資格以外の学びにはその信号が無いため、優先の信号を学びごとに定める必要があり、
そこがこの仕組みの中心の課題。生成した教材には正解表が無いので、誤りを学ぶ人へ出さないことも課題に含む。

測れている現状: 公開されている 29 回のうち取り込みは 11 回と 18 回、論点に教材がそろっている割合は 100%。

方向（測り方と閾値を置かないので、要件にはしない）:

- 運用にかかる費用は、無料の枠に収める
- 気軽に使えることを重んじるので、手元のスマホからでも使える

## 全体の方針

プロジェクト全体で検証しない範囲と、その理由。範囲ごとの要件の側の記録は、各要件の検証方針の「検証しない」にある。

- **本番相当の配備でだけ観測できる振る舞い（本番の検査 UC-015、受験履歴の本人の資源だけ REQ-097、フィードバックの保存と上限 REQ-159/161）**: 検査本体は `scripts/check_sso_prod.sh`・`scripts/check_api.py`・`scripts/check_portal_api.py`（system suite）で、`@covers` を持てない。単体は実体のある D1 を要する。ローカルの D1 で回すサーバ経路の検査（`check_api.sh ip`・`check_portal_api.sh`）は push 前の検査（`.githooks/pre-push`）が回し、共有の置き場の検査は回さない（手元の配備が要る。UC-044）。本番に対してだけ回す `check_sso_prod.sh` は配信のあとに運用者が回す
- **seed の投入の手続き側の決まり（BR-029〜033）**: 本番の D1 に流すシェルの手続きで、`tests.dirs` も `tests.system` も届かない。保証点は `scripts/seed_remote.sh`。配備の手続き（版の印 REQ-224〜226、配備の道具の版 REQ-351・352）は偽の道具に差し替えて回す単体テストが見るので、この行に入れない
- **2 つの配備をまたぐ観測（アカウントを削除したあとも学び側の本人の記録が実際に残っていること。REQ-171 は、まなびばが学び側の本人の記録に触る操作を持たないことまでを担保する）**: まなびばと学び側は別配備で、片方の単体からは観測できない
- **端末をまたぐ観測（端末の記憶は端末をまたがない BR-012）**: 単体テストは 1 つの端末の記憶しか持たない
- **実データの中身に依る並び（次に学ぶのおすすめ順 REQ-042/043、同一内容の畳み方の全件）**: 単体は小さな偽データで形だけを見る。全件は `scripts/check_render.sh`・`check_seed.py`・`check_api.py` が本番相当で見る
- **まなびば側の単体の観測（UC-011・UC-014 の全クラス、UC-013 のまなびば側）**: `tests/portal/` は想定外の失敗の 1 ファイルだけで、まなびばの API を単体で回す土台が無い（返済計画 Phase 7）
- **見た目（理解度の色、帯や印の形）**: 見た目の正本は実装と人の目（OQ-86）。描画の全件検査は `scripts/check_render.sh`
- **実装の選択そのもの（トークンの形式と署名の方式、新しく作るパスワードの記録の作り方と計算量の値）**: 実装を差し替えても要件の文は変わらない（R-401）、値の正本はコード（R-102）。外から観測できる側は要件のクラスが持つ: 通らないトークンの断りと期限は REQ-289（BR-044）、パスワードの記録の照合・不一致・配備先の上限は REQ-290（BR-039）、配備された版が作った記録を今のコードで照合し続けることは REQ-290 の `#persist-v1-compat`（形の正本は `contracts/fixtures/` の見本。R-1202）、見比べの間隔の長さは REQ-230。決定の記録は ADR-0002
- **検査用の配備での本物のまなびばとの往復（`scripts/check_api.py` が使う学び側の配備）**: 検査用の配備にはまなびばの場所として手元の SSO の偽物を与え、検査の本人はその偽物が換えた使い捨てコードからだけ作る（学び側のパスワードの経路はどの配備にも無い。REQ-204）。本物のまなびばとの往復は本番の検査（UC-015）だけが見る
- **実機の読み上げソフトでの聞こえ方（教材の図の説明文が 1 回だけ届くこと REQ-427、ヘッダーが縮むときに本文の先頭へ移したフォーカスの読み上げ REQ-431・432）**: 単体は jsdom で読み上げに届く名前と結び付きの数だけを見る。figure の名前を figcaption から取るか、移したフォーカスから先頭を読み直すかは読み上げソフトごとに違い、手軽に確かめる手段が無いので確かめない（本人 2026-11-11）

## やらないこと（Out of Scope）

- 市販テキストのような体系的網羅。出題実績のある論点を、頻度順に潰す立場を採る
- 学びをまたぐ統計と書き出し。管理はアカウントと権限の付け外しに閉じる
- フィードバックへその場で自動に応答すること。溜めて、改善に回す
- 教材の見せ方を比べる試験（A/B）
- 試験問題の PDF をそのまま画面に埋め込むこと（公開元の利用条件で禁じられている）
- その学びの種類が持つ作り手の確かめ（資格対策の学びは教材の門、ロードマップを持つ学びは教材の門と学習者役の測定）を経ずに、生成した教材と問題を利用者へ出すこと
- 他の運営者への提供と収益化。公開範囲を所有者が権限を与えた人より広げる決定が先
