# 不変条件と門 — 「壊してはいけないこと」を、何が守っているかの対応表

**書いた日: 2026-09-10。** 社用側のプロトコル層にある ADR の「強制方法」表
（不変条件を設ける決定は、それを機械で守る門を必ず明記する。無ければ散文の願いにすぎない）の型を持ち帰ったもの。
CLAUDE.md の「設計の中核」「忘れやすい落とし穴」は散文で、**どれが機械で守られていて、
どれが人の注意頼みかが見えなかった。** ここで一覧にして、門の無い行をそのままバックログにする。

運用の決まり:

- 不変条件を1つ足したら、この表に行を1つ足す（門が無くてもよい。「無し」と書く）
- 門を作ったら状態を更新する。**わざと壊して落ちることを見るまでが実装**（検査観点カタログ 原則 5）
- 表が名指しするスクリプトの実在は `python3 scripts/check_docs.py` が見る（deploy-pages.sh が自動で回す）。
  消したり改名したりしたらこの表も直す
- 状態の語: **あり**＝機械で止まる ／ **一部**＝止まる範囲と人任せの範囲がある ／
  **手順**＝スクリプトはあるが実行は人の判断 ／ **無し**＝文書と注意だけ

## バックログ（状態が「無し」「手順」「一部」の行）

門を足すなら、効果と手間の比で上から:

1. **O1 + O2**: seed 投入を `scripts/seed_remote.sh <試験>` のような1本にして、中で backup → check_seed → `--remote` 付き execute → 投入後 SELECT を順に回す。O1・O2・「投入後の SELECT」が同時に門になる
2. **O5**: `check_api.py` か tsc の前段で `ITERATIONS <= 100000` を assert する（数行）
3. **D11**: クライアント側は `grep -rn "useState<[^>]*\[\]>(\[\])" src/client` が空であることを check_render.sh に足す
4. **O4**: secret put のラッパーを作って直後に deploy-pages.sh を呼ぶ
