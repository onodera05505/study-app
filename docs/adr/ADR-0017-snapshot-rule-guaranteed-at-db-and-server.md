# ADR-0017 出題時スナップショットの決まりは、持つことを DB、読むことをサーバで保証する

## Context

BR-020 は「採点と振り返りは、出題した時点の内容で行う」と決めている。この決まりは 2 つの事柄から成る。出題の行が出題時スナップショットを必ず持つことと、採点と振り返りがそのスナップショットを読むこと。前者は出題の表の制約で、後者は学び側のサーバの採点と振り返りの経路で強制できる。

規約（R-704）は、複数の箇所で強制できるルールについて、どの箇所を除くと正しさが壊れるかで保証の SSOT を決め、記録することを求めている。

## Decision

- **スナップショットを持つことの保証の SSOT は、出題の表の制約とする**（スキーマ正本 `src/server/db/schema.ts`）。制約を除くと、サーバを通らない書き込み（投入・移行）がスナップショットの無い出題の行を作れる。制約が効くことは、規則に反する行を DB に直に入れて断られるテスト（`@covers BR-020`）で確かめる。
- **採点と振り返りがスナップショットを読むことの保証の SSOT は、学び側のサーバの採点と振り返りの経路とする。** DB の制約は、どの値を読んで採点するかを決められない。サーバの経路を除くと、あとで直した問題データで過去の結果が変わる。確かめるのは、BR-020 を引く要件のテスト。
- BR-020 の `enforced_at` は、この 2 か所を書く。

## Consequences

- よい: 決まりのどちらの半分も、除くと壊れる箇所が 1 つに決まる。
- よい: DB の側はサーバを通らない書き込みにも効く。
- 悪い: 決まり 1 つに保証点が 2 つあり、片方だけ見ても全体は分からない。

## 却下した選択肢

- **サーバだけで保証する**: 投入や移行の書き込みがスナップショットの無い行を作っても止まらない。
- **DB だけで保証する**: 制約は行が値を持つことしか見られず、採点がその値を使うことを保証できない。
