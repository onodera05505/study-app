# ADR-0012 断りの種類の名前 — 実装が出す名前の出所を 1 つのファイルにし、受け口ごとの載せ方を決める

## Context

断りの種類の名前（`docs/_shared/components.yaml` の `errorCodes`）は、契約の `errors` と実例にだけあり、実装は状態の番号と理由の文、道具の多くは終了の状態と文しか出さない。状態の番号が同じで種類が違う断り（見つからない断りと、設定が無い断り）、終了の状態が同じで種類が 2 つ以上ある道具の操作、JSON の本文を持たない断り（まなびばの入口の平文の断り、ログイン画面や一覧へ戻す断り）は、外から種類を見分けられない。

契約の実例を実装に当てる確かめ（UC-033）は、失敗例を名前で照らす。R-703 は、実装のエラーコードが `errorCodes` に含まれること（C7）と、`errorCodes` のコードがどれかの契約で使われること（C24）を求め、確定した契約の自分の持ち物の操作に `errors` がある間、`traceconfig` の `contract` を「無い」と宣言することを認めない（C26）。

実装は 3 つの受け口に分かれる。学び側とまなびばの API（TypeScript）、画面の端末の記憶を読み書きする操作（TypeScript）、作り手と運用者が手元で回す道具（Python とシェル）。道具のうち 8 本は、止まるとき標準出力に `{"error": {"code", "reason"}}` の形を出している。本人は 2026-11-18 に、実装に名前を持たせること、利用者の画面の文と見た目を変えないことを決めた（BR-064）。

## Decision

- **名前の出所は `src/shared/error-codes.json` の 1 ファイル。** 実装が出す名前はこのファイルにある物だけで、TypeScript の実装はこのファイルを import し、道具はこのファイルを読む。名前の文字列を、出す場所ごとに書かない。`traceconfig` の `contract.error_source` はこのファイルを指す。意味と状態の番号の対応は、これまでどおり `errorCodes` が持つ（このファイルは名前の一覧だけを持つ）。
- **API の断り（JSON の本文）は、本文の `code` に名前を持つ。** 共有の形 `ErrorBody` は理由の文 `error` と名前 `code` の 2 つを持つ。どの経路にも同じ形で立つ断り（ADR-0011）も同じ形で持ち、それぞれに当てる名前は `errorCodes` の説明が持つ（ADR-0011 の Context が並べる 2 つのうち、`INTERNAL` は想定していない失敗の名前で、受け持たない経路の断りは `NOT_FOUND`）。
- **JSON の本文を持たない断りは、応答のヘッダ `X-Error-Code` に名前を持つ。** 平文の本文と戻り先の URL は変えない。JSON の本文を持つ断りには、このヘッダを付けない（名前は 1 か所に 1 つ）。
- **道具は、契約の `errors` に当たって止まるとき、標準出力に `{"error": {"code", "reason"}}` の形を出し、0 でない終了の状態で終える。** 既にこの形を出している 8 本にそろえる。
- **端末の記憶を読み書きする操作は、書けない・読めないとき、名前を持つ失敗を呼んだ側に渡す。** 画面の側がそれを受けて、今の扱い（覚えないだけにする・値が無いとして進む）を続ける。
- **UC-033 の境界は、ADR-0008 の読みに重ねて `transport: local-store`・`owned: false` で読む。** 受け渡しの行の形は harness の contract-run が決めるので、写しとして持つ。

## Consequences

- よい: 名前を足す・変えるときに直す場所が、`errorCodes`（意味）とこのファイル（出す名前）の 2 つで済み、ずれは C7・C24 が止める。
- よい: 状態の番号や終了の状態が同じ断りを、契約の実例で名前ごとに確かめられる。
- 悪い: まなびばは学び側の断りを組み立てる所（`src/server/lib/`）を通して、道具はじかに、`src/shared/` のこのファイルを読むので、学び側と別の配備・別の言語の実装が 1 つのファイルに結ばれる。置き場を動かすと 3 つの受け口を同時に直すことになる。
- 悪い: 名前の載せ方が、JSON の本文・ヘッダ・標準出力・投げる失敗の 4 通りになる。確かめの受け渡し役は 4 通りを読み分ける。
- 変わる: ADR-0001 の Consequences が書く「エラーコードの語彙とコードの `{error}` の文は機械で突き合わされない（C7 skip）」は、次の版の検査の宣言（`traceconfig.next.json` の `contract.error_source`）では当たらなくなる。今の門の宣言（`traceconfig.json`）は検査の切り替えまで変えないので、それまで C7・C24 を回すのは次の版の検査だけ。
- 悪い: C7 が見るのはこのファイルの中の名前だけで、実装がこのファイルを通さずに文字列で名前を書くことは止めない。審査の担当と、契約の実例の確かめ（違う名前は実例と合わない）が見る（R-901）。

## 却下した選択肢

- **名前を実装に持たせず、状態の番号と終了の状態から受け渡し役が名前を推し量る**: 同じ番号・同じ終了の状態に 2 つの種類が乗る所で決められず、推し量りの表が契約の写しになる（R-101 に反する）。
- **名前の一覧を TypeScript と Python に 1 つずつ持つ**: 出所が 2 つになり、`contract.error_source` が 1 つのファイルしか指せないので片方が検査の外に出る。
- **JSON でない断りの名前を戻り先の URL に付ける**: 利用者のアドレス欄に名前が見え、画面の見た目を変えないという決定に反する。
- **平文の断りを JSON の本文に変える**: ブラウザで開いた利用者に見える本文が変わる。
- **すべての断りにヘッダを付け、本文には足さない**: 共有の形を変えずに済むが、画面の側が本文から名前を読めず、道具と形がそろわない。
