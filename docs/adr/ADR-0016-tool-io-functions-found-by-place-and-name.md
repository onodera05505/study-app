# ADR-0016 道具の中の読み書きの関数は、印でなく置き場と名前で引く

## Context

原本 harness は、実装のコードに仕様の ID を指す印（`@implements`・`@operation`）を書かず、機械も読まない（`.claude/rules/comments.md`）。仕様と実装の対応は、テストの実行の記録（ADR-0015）と入口の一覧（ADR-0014）で確かめる。

ADR-0013 は、道具の中の読み書きの操作（契約の `transport: local-store`・`direction: outbound`・`owned: true`）の関数が直上に `@operation` を持ち、関数のあるファイルを注釈の行から引くと決めている。印と契約の操作の対応を保証する検査は無いので、この引き方には拠り所が無い。

関数の名前（操作名を snake_case にした物）は、ユースケースをまたぐと同じ物がある（同じ読み書きを 2 つの門がそれぞれ持つ）。名前だけでは 1 つに決まらない。読み書きの操作は、「その操作を持つユースケースの道具のファイルを先に、無ければ部品の置き場」の順で引くと、すべて 1 つに決まる。

## Decision

- **道具の中の読み書きの操作の関数は、次の順で引く。** ①その操作を持つユースケースの契約の、道具を回す操作（`direction: inbound`）の入口のファイル（入口の規則と `scripts/entry_names.json` で決まる。ADR-0014）の最上位。②そこに無ければ、部品の置き場 `scripts/lib/` のファイルの最上位。関数の名前は、操作名を snake_case にした物。
- **引いた先は 1 つとする。** 同じユースケースの道具のファイル 2 つ以上に、同じ名前の最上位の関数を置かない。`scripts/lib/` の中でも同じ名前の最上位の関数を 2 つ置かない。
- **関数に `@operation` を書かない。** コードに残っている印は読まず、触った範囲で消す。
- **ADR-0013 は置き換えない。この記録は ADR-0013 に重ねる。** ADR-0013 の決めのうち、関数が直上に `@operation` を持つこと・`@operation` を 1 か所に置くこと・ファイルを注釈の行から引くことは、この記録の決めが先に立つ。ほかの決め（1 操作に 1 つの関数、引数と返り値の形、失敗の渡し方、道具がこの関数を通して読み書きすること）はそのまま。

## Consequences

- よい: 規約（印を書かない）と入口の規則が食い違わない。
- よい: 関数の引き方が契約と置き場だけで決まり、実装を読まずに導ける。
- 悪い: 「引いた先は 1 つ」は機械では止まらない。審査の担当が見る（R-901）。
- 悪い: 印がコードに残っている間、読まれない行がある。

## 却下した選択肢

- **印を残し、規約の例外にする**: 機械が読まない印に入口の規則が寄りかかる。印がずれても止まらない。
- **操作からファイルへの表を持つ**: 操作ごとの表は契約の写しになる（R-101・R-1204）。
- **名前だけで引く**: ユースケースをまたいで同じ名前の関数があり、1 つに決まらない。
