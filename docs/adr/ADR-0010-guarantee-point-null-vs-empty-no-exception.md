# ADR-0010 保証点 — 「取得前と結果が空を区別する」（BR-015）は応答と画面の両方で守り、画面側の検査に行ごとの例外を置かない

## Context

ADR-0006 は、BR-015「一覧・集計・進行中のテストの案内は、取得前と結果が空を区別して示す」の保証点を、応答側の検査（`scripts/check_api.py`）と画面側の検査（`scripts/check_source.py`）の両方に置いた。そのとき画面側には、行に印を書けばその行を検査から外す例外を認めた。

その後に 2 つのことが決まった。紐づきと検査に例外を作らない（R-804。コードに書く例外の印を持たない）。本人の決まりとして、除外の印は存在させず、提案もしない。画面と入口のソースで、この印を使っている行は 1 つも無い。

## Decision

保証点は ADR-0006 と同じく、応答側と画面側の両方とする（非対称が立たないため）。応答側は `scripts/check_api.py` の空の一覧の検査、画面側は `scripts/check_source.py` の、取得する一覧を空の一覧で始める箇所の検査が守る。どちらか一方を外した変更は差し戻す。

画面側の検査は、行ごとの例外を持たない。取得する一覧を空の一覧で始める箇所は、すべて挙げて止める。空の一覧で始めたい一覧がある場合は、印で外さず、取得前を表す値で始める形に直す。

## Consequences

- よい: 事故の再発を 2 層で止める形は変わらない。
- よい: 検査を素通りさせる書き方がソースに残らない。門の結果が、印の有無でなくコードの形だけで決まる。
- 悪い: 取得しない手元の一覧を空で始める書き方が、検査の読み方に当たると止まる。その行は書き方を変える必要がある。
- 悪い: 同じ規則の検査が 2 か所にあり、片方の緩和に気づきにくい点は ADR-0006 のまま残る。

## 却下した選択肢

- **行ごとの例外の印を残す**: 使っている行が無く、残す理由が無い。印があると、止まった行を直さずに印で通す道が開く。
- **応答側だけ、または画面側だけを保証点にする**: ADR-0006 が却下した理由（片方が正しくても、もう片方が崩れれば同じ誤表示が出る）がそのまま当たる。
