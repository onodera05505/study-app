## 前提条件
- まなびばに本人のアカウントがあり、対象の学びの権限（grants）が付いている
- 学び側の本番環境に SSO_PORTAL_URL と SSO_SECRET が設定されている

## 基本の流れ
1. 利用者が学び側の画面を開く。端末にトークンが無いので、画面はどの画面の代わりにもログイン画面を出し、まなびばへ誘導する（パスワード欄は無い）
2. 利用者がまなびばのログイン画面でメールとパスワードを入れる。まなびばは認証し、Cookie を発行する
3. まなびばは学びの一覧を出し、画面は本人のアカウントと権限を読んで、権限のある学びだけ「開く」にする
4. 利用者が「開く」を押す。まなびばは権限を確かめて使い捨てコードを発行し、学び側へリダイレクトする
5. 学び側の画面がコードを受け取り、学び側サーバに渡す
6. 学び側サーバはまなびばでコードを交換する。まなびばはコードの 1 回性・期限・共有秘密・権限を確かめ、メールと名前を返す
7. 学び側サーバは users をメールで見つけるか作り、学び側のトークンを発行して返す
8. 画面はトークンを端末に保存し、以後の API 呼び出しに付ける
9. 画面はヘッダーに、保存したトークンから読んだ本人の名前を出す（画面の読み直しを待たない）

## 例外の流れ
E1. 2 でメールかパスワードが違う。まなびばは 401 を返し、文言でメールの有無を漏らさない
E2. 4 で対象の学びの権限が無い。まなびばは denied を返しコードを発行しない。未ログインならまなびばのログイン画面へ送り、戻り先はサーバが組む
E3. 6 でコードが使用済み・期限切れ、または共有秘密が違う。まなびばは拒否する（秘密違いは 403）。学び側はまなびばに届かなければ 502、秘密が未設定なら 503 を返す
E4. 本番で学び側の従来のパスワードログインや登録が呼ばれる。学び側は 404 を返し、認証の設定は sso・portal・app だけを返す
E5. 8 の後、トークンが期限切れになり API が 401 を返す。画面はトークンと前回の続きを捨て、ログイン画面で 1 度だけ期限切れを伝える

## 事後条件
- 学び側の users に本人の行がある（パスワード列は sso）
- 端末にトークンがあり、以後の API 呼び出しが本人として通る
