## 前提条件
- 画面が学び側の API を呼んで表示を組んでいる

## 基本の流れ
1. 利用者が画面を操作し、画面が API を呼ぶ。画面は失敗を message・status・body を持つ 1 つの型で受け取る
2. API が失敗を返す。画面は本文の {error}（日本語）を message にして投げ、そのまま画面に出せるようにする

## 例外の流れ
E1. 2 で通信そのものが成立しない（電波が無い・オフライン）。画面は status を持たない日本語の固定文で投げる

## 事後条件
- 画面は失敗の理由を日本語で出せ、status で場合分けできる
