# 検証方針（全体）

各要件の検証方針は要件ファイル（`docs/goals/**/REQ-nnn.md` の `## 検証方針`）に同居する（R-1002）。
この文書はプロジェクト**全体**で検証しない範囲のみを持つ。各 UC の担当が報告した範囲を集め、単体テストで観測できない理由を 1 行ずつ書く。範囲ごとの要件側の記録は各 REQ の `検証しない` と `参照先` にある。

## 検証しない範囲（全体）

| 範囲 | 理由 |
| --- | --- |
| 本番相当の配備でだけ観測できる振る舞い（本番の検査 UC-015、受験履歴の本人の資源だけ REQ-097、理解度の記録の永続と本人のみ REQ-034/035/037、フィードバックの保存と上限 REQ-159/161） | 検査本体は `scripts/check_sso_prod.sh`・`scripts/check_api.py`・`scripts/check_portal_api.py`（system suite）で、`@covers` を持てない。単体は実体のある D1 を要する |
| 配備の手続き側の決まり（版の印 REQ-224〜226、seed の投入 BR-029〜033） | シェルの手続きで、`tests.dirs` も `tests.system` も届かない。保証点は `scripts/deploy-pages.sh`・`scripts/seed_remote.sh`（ADR-0007） |
| 2 つの配備をまたぐ観測（アカウントを削除しても学び側の記録は消えない REQ-171） | まなびばと学び側は別配備で、片方の単体からは観測できない |
| 端末をまたぐ観測（端末の記憶は端末をまたがない BR-012） | 単体テストは 1 つの端末の記憶しか持たない |
| 実データの中身に依る並び（次に学ぶのおすすめ順 REQ-042/043、同一内容の畳み方の全件） | 単体は小さな偽データで形だけを見る。全件は `scripts/check_render.sh`・`check_seed.py`・`check_api.py` が本番相当で見る |
| まなびば側の単体の観測（UC-011・UC-014 の全クラス、UC-013 のまなびば側） | `tests/portal/` は想定外の失敗の 1 ファイルだけで、まなびばの API を単体で回す土台が無い（返済計画 Phase 7） |
| 見た目（理解度の色、帯や印の形） | 見た目の正本は実装と人の目（OQ-86）。描画の全件検査は `scripts/check_render.sh` |
| 機械可読な定数の値そのもの（見比べる間隔、PBKDF2 の反復回数、トークンの形式） | 値の正本はコード（R-102）。テストに `// 仕様外:` の印（OQ-124・139） |
