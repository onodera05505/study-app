## なぜ漏れたのか（3つの構造的な理由）

### 1. 検証スクリプトは「AI の成果物」しか見ていない

`scripts/check_*.py` は5本あるが、対象はすべて AI（分担エージェント）が作ったものだった。

| スクリプト | 何を検証するか | 対象 |
| --- | --- | --- |
| `check_answerability.py` | 抽出テキストだけで解けるか | AI の読み取り |
| `check_answerability_materials.py` | 教材だけで解けるか | AI の執筆 |
| `check_classified.py` | 分類の網羅・分野の一致 | AI の分類 |
| `check_materials.py` | 教材の記法・字数・カバレッジ | AI の執筆 |
| `check_material_coverage.py` | v2 書き直しでの情報落ち | AI の執筆 |

この設計は「**担当の自己申告は当てにならない**」という実際の失敗から来ていて、
そこは正しい。だが裏を返すと、**スクリプトが生成したデータは疑われていない**。

今回壊れていた `citation` と `exam_label` は、AI が書いたものでも原本から
読み取ったものでもなく、**`build_seed.py` が組み立てた文字列**だった。
だからどの検証にも引っかからなかった。

### 2. パイプラインの最終段（seed 生成 → D1 投入）が無検証

読み取り → 分類 → 教材 までは各段に検証がある。しかし:

```
data/*.json  →  [build_seed.py]  →  seed.sql  →  [wrangler d1]  →  本番 DB
                                   ↑ ここから先に検証が一切ない
```

`seed.sql` の中身を見るスクリプトも、投入後の DB を見るスクリプトも無い
（`scripts/` 20本のうち、DB に触れるのは `build_seed.py` と `deploy-pages.sh` だけ）。
**投入が成功したこと**は確認していたが、**入った中身が正しいこと**は
確認していなかった。

### 3. 目視確認で見つけにくい場所にある

CLAUDE.md には「**画面の確認は毎回やる**」とあり、実際そうしていた。それでも漏れた。

- 出典はログインしないと見えない（`TopicDetail.tsx` と `Result.tsx` のみ）
- しかも問題を開いた先の**小さい灰色の文字**（`.citation` は `0.78rem` / `--muted`）
- 「動くか」を見に行くと目に入らない種類の情報

実際、この件は**ユーザーの目視確認も通り抜けた**。見落としを責めても再発は防げない。
**目視に頼らない検証**が要る。

## 同じ穴から出そうなもの（2件とも対応済み）

今回の調査で見つけた同種のリスク。どちらも 2026-08-29 に手当てした。

### A. `modified`（原文改変フラグ）→ 2026-08-29 に実装した

スキーマにこうあるのに、この列を読む箇所が `src/` に1つも無かった。
`build_seed.py` は常に `False` を入れ、UPSERT の更新対象にも入っていなかった。

```
/** 原文を改変した場合に立てる。立っていれば表示側で「一部改変」を併記する。 */
```

**スキーマのコメントどおりに実装した。** 何を「改変」とするかの線引きはこうした。

| | 例 | 扱い |
| --- | --- | --- |
| 記号や構造を**別の表記に置き換えた** | 上付き文字を `2^10`、オーバーラインを `¬`、横線の分数を `1/216`、空欄を `［ a ］`、選択肢の組合せ表を `a：… ，b：…` | **改変**（フラグを立てる） |
| 本文の**文言は原文のまま** | 行の折り返しを繋いだ、ルビや下線を `notes` に移した | 改変ではない |

判定は `build_seed.py` の `MODIFICATION_MARKS` と `is_modified()`。抽出仕様
（`scripts/prompts/extract_questions.md`）が指示している変換と対応させてある。
**仕様に変換を足したら、こちらにも足すこと。**

該当したのは IT パスポート 60/1,100問、応用情報 30/880問。
表示は3画面（受験中 `Session`・結果 `Result`・論点詳細 `TopicDetail`）で、
出典のうしろに「（一部改変）」と続ける。

### B. UPSERT の更新列漏れ（`exam_label` と同じ形）

`exam_label` を直したときに全テーブルを機械的に調べた結果:

| テーブル | UPDATE されない列 | 実害 |
| --- | --- | --- |
| `past_questions` | `users.name` 以外は解消 | `exam`/`number` は id から決まるので更新不要。`modified` は A で追加した |
| `users` | `name` | 管理ユーザ名を変えても反映されない。実害は小さいので残してある |
| `syllabus_items` `topics` | なし | — |

**この検査は `check_seed.py` が毎回やる。** 列を増やしたときの書き足し忘れを拾う。

## 実装したもの（2026-08-29）

### `scripts/check_seed.py`

seed.sql を投入する**前**に中身を見る。上に挙げた5つを全部やる。

```bash
python3 scripts/build_seed.py --data data/ap
python3 scripts/check_seed.py --data data/ap    # ここで止まれば投入しない
npx wrangler d1 execute study-app-ap-db --env ap --remote --file=data/ap/seed.sql
```

出典の試験名を意図的に間違えた seed を食わせて、880件を検出して終了コード1 で
落ちることを確認済み（＝今回のバグは、これがあれば初回で止まっていた）。

### `build_seed.py` の引数2つを `--data` から決めるようにした

どちらも「渡し忘れると壊れる」形だったので、渡さなくても正しくなるようにした。

| 引数 | 前 | 後 |
| --- | --- | --- |
| `--exam-name` | 既定が `ITパスポート試験` 固定 | `--data` から引く。未知なら**エラーで止まる** |
| `--out` | 既定が `data/ip/seed.sql` 固定 | `<data>/seed.sql` |

### `deploy-pages.sh` の案内文

`--exam-name` 抜きの案内が事故の元だったので直し、`check_seed.py` を挟む形にした。

## 実装して分かったこと（重要）

**`check_seed.py` を書いて最初に流した瞬間、別の事故が見つかった。**

`data/ip/seed.sql` の中身が**応用情報のデータ**になっていた（5回・400問・80問ずつ、
なのに出典は「ITパスポート試験」）。原因は `--out` の既定値が `data/ip/seed.sql` 固定で、
`build_seed.py --data data/ap` を `--out` 無しで実行したときに上書きしていたため
（2026-08-28 19:44）。

**このファイルを `study-app-db --remote` に流していたら、IT パスポートの本番 DB に
応用情報の問題400問が「ITパスポート試験」の出典で混入していた。** 幸い流す前に見つかった。
seed を再生成して復旧済み（11回・1,100問）。

教訓が2つある。

- **出力先を固定値にしない。** 入力（`--data`）が変わったのに出力先が変わらない設計は、
  取り違えを黙って起こす。しかもファイルは上書きされるだけでエラーにならない
- **検査は書いた瞬間から効く。** 「来週テストしよう」と先送りせず作ってよかった。
  想定していたバグ（出典）ではなく、想定していなかったバグが最初に釣れた

## この記録を読む人へ

- **「手順書に注意書きを足す」で終わらせない。** 今回の根本原因は
  「`--exam-name` を渡し忘れると壊れる」設計だった。注意書きは既にあったが、
  `deploy-pages.sh` の案内文自体が渡し忘れた形だったので、毎回再発していた。
  渡さなくても正しくなるか、渡さなければ止まるようにするのが正しい
- **投入の成功と中身の正しさは別。** `Executed 2444 queries` は
  「SQL が通った」以上のことを言っていない
- **スクリプトは両試験で共通。** 片方で見つけた不具合は、たいていもう片方にもある。
  直したら両方の seed を作り直して投入すること（`modified` の追加でもそうした）
