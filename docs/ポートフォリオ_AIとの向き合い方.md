# ポートフォリオ説明資料 — AI にどう任せ、何で確かめ、何を自分で決めたか

提出物: このリポジトリ（https://github.com/onodera05505/study-app）と、稼働中のアプリ（入口 https://manabiba-5oz.pages.dev）。
審査用のアカウント（まなびばのログイン情報）は応募フォームで別途お伝えします。権限は IT パスポートと応用情報の 2 つです。
作業はすべて Claude Code（親に Fable、担当に Opus）で行い、個人のプロジェクトです。業務のデータは含みません。

## 1. 何を・なぜ作ったか

資格試験（IT パスポート・応用情報・基本情報）と資格でない学び（就活・マーケティング・マッサージ・経済・会話術）を、
**同じコード・別データ・別配備**で出している学習アプリ群です。「論点に紐づく過去問の件数＝出題頻度＝重要度」という一点のためにデータ構造を組み、
頻出論点から潰す最短合格経路を出します。身内と友人が使う前提で、入口「まなびば」が認証と権限を持ち、学び側は 9 対象です。

作った理由は 2 つです。自分と周りが試験に受かること。そして **コーディングエージェントに開発とコンテンツ生成の両方を任せたとき、
どこまで仕組みで品質を保てるか**を、本番で使われるものを題材に確かめることです。

| 規模（2026-11-02 時点） | 値 |
| --- | --- |
| 本番の対象 | 8（＋配備待ち 1） |
| 問題・論点 | 過去問 2,940 問・論点 1,619 件、ロードマップ 302 単位・確認問題 604 問。全件に教材と解説 |
| コード | TypeScript 約 6,500 行（Hono / React / D1）、Python のスクリプト（取り込み・検査）、担当エージェントの型 12 |
| 仕様 | GOAL 7・UC 16・REQ 276・BR 36・ADR 7・用語集 105 語 |

| 期間 | 2026-08-23 から 21 作業日、323 コミット |

## 2. AI にどう任せたか

- **親と担当を分ける。** 会話の親（Fable）は仕様・実装・テストを書かず、状態の更新・分担・門・記録だけを持ちます。実作業は担当（Opus）に型（`.claude/agents/`）で渡します。型には「仕様書を最初に読む」「正解表を読まない」「検証コマンド」を畳み込み、呼び出しには回ごとの可変部分だけを書きます。
- **決まりは指示に直書きせず仕様書に書く。** 担当への指示に決まりを 3 行以上書いていたら仕様書が足りない信号と決め、`scripts/prompts/*.md` に落としてから「読め」で渡します。これを決める前は、図の説明文の決まりが 8 体の指示に直書きされ、次の生成に効きませんでした（中央の報告書 134）。
- **仕様が先、承認が先。** 要求は 質問／バグ修正／仕様変更 に分けてから動き、仕様変更は UC（状態 × イベント表）と REQ（EARS 1 文、1 要件 1 か所のコード）に写して承認を得てから、implementer と test-author を**別コンテキストで並行**させます（test-author は実装を読みません）。
- **量は波で出す。** 基本情報 400 問は読み取り 20 体・検証 10 体・分類 15 体・執筆 40 体・図 5 体を 10 体ずつの波で 1 日で通しました（`docs/作業ログ_2026-10-05_基本情報.md`）。

## 3. 出力をどう確かめたか（実際にあった 5 件）

1. **「データが壊れている」という報告は 8 回中 7 回が誤報でした。** 信じて直すと正しいデータを壊すので、原本の画像と照合してから直す決まりにしました。8 回目は本物で（選択肢に答えが漏れていた）、「毎回確認する」が正しい結論です。一般論を根拠にした指摘ほど原本に当たる価値がありました（PPM の軸の件。`docs/落とし穴.md` の「検証で『データが壊れている』と報告されたら」）。
2. **出典が全 880 問で誤ったまま数か月動いていました。** `Executed N queries` は SQL が通ったとしか言っていない、投入が成功することと中身が正しいことは別、という教訓から `check_seed.py`（出典・年度ラベル・回ごとの件数・図の実在）と `verify_seed_remote.py`（投入後に DB から SELECT して突き合わせ）を門にしました（`docs/作業ログ_2026-08-29_出典表示の修正.md`）。
3. **担当の自己申告は当てになりません。** 67 体で教材を書き直したとき、担当していない論点番号を完了報告してきた例が複数ありました（中身は正しかった）。以後、報告文ではなく成果物を機械で突き合わせます（`scripts/check_*.py` 16 本と描画・API・本番の検査 5 本）。基本情報では、ファイルの存在で完了を判じて途中の状態を掴んだので、入力バンドルの識別子が出力に全部揃うことを見るようにしました。
4. **用語ポップが全滅したのに単体テストは緑でした。** 太字の中の `[[用語]]` が文字のまま出ていたのを、実データ全件を jsdom で描いて DOM を見る `check_render.sh` でデプロイ前に止めるようにしました。スクリプト検証を素通りする不具合は他にも 2 件あり、それでも人がログイン後の画面を見ることを残しています。
5. **reviewer の阻止はゼロになるまで直します。** 実装と別コンテキストの reviewer が反例つきで「阻止」を出し、親は 1 slice につき 2 巡まで回します。機械判定に落とせない指摘は `docs/verification/DEFERRED.md` に 1 行ずつ残し、縮む方向にしか動かしません。直近の例は「409 直後の状態が仕様の文に無い」「時間切れの境界（残り 0 ちょうど）が REQ 間で割れている」でした。

## 4. 判断を仕組みに落としたもの（ハーネス）

| 層 | 実体 |
| --- | --- |
| 指示 | `CLAUDE.md`（地図。三分類・設計の中核）と、そこから引く `docs/作業の進め方.md`（分担の原則）・`docs/落とし穴.md`、`.claude/rules/`（文書の規約 R-101〜R-1207、コメントは今の仕様だけ）、`.claude/agents/` 12 型、`.claude/skills/`（`/develop`・対象の追加・フィードバック） |
| フック | PreToolUse: UC の phase が実装／検証で REQ が全部 active・契約が fixed でないと `src/` に書けない。Stop: spec-lint → trace-check → typecheck → test が通るまで終われない。pre-commit・pre-push・CI が同じ検査 |
| トレーサビリティ | コードに `@implements REQ-nnn`、テストに `@covers REQ-nnn#class`。未返済は `.trace-baseline.json` に持つ。移行時に 529 件を一度に記録してから 494 件まで返済し、**縮む方向にしか動かさない**（育てるのは本人の許可制で、許可した 2 回は返済計画に件数を書いた） |
| 不変条件 | `docs/不変条件と門.md` に 38 行。「どのスクリプトが守っているか」まで書き、門の無い行はバックログ |
| 記録 | ADR 7 本、未決は `OPEN-QUESTIONS.md`（184 件）、トラブルの報告書はプロジェクトに 27 枚・中央に 154 枚。解決したら報告書を 1 枚還し、次の作業の着手前に症状の語で引く |
| 権限 | 破壊的な操作（`rm`、本番 D1 の DELETE）は許可リストに入れず毎回確認。秘密は Pages の secret のみ、リポジトリに置かない |

自分で決めたことの例: 「仕様が絶対の正解。どの要件にも当たらないコードは除外ではなく要件を書いてから実装する」「検査を通すためだけの空のテストやタグは禁止」「押せないのがまずいなら押せる、意味が無いなら消す、畳めるなら畳む」。決めたら同じ作業で 仕様書・門・前提の決定行・手戻り台帳 の 4 か所に書きます。

## 5. 募集要項の 3 軸に対する自己評価

- **① AI を活用した開発**: 上の 2〜4 がそのまま答えです。生成されたコードの評価・検証・改善を、人の目ではなく門に落とすことに時間を使いました。
- **② Web アプリを世に出す**: Hono と React、Cloudflare Workers と D1 で 8 対象が稼働中です。認証は 1 か所（まなびば）に寄せ、API は全部トークン必須、SQL はパラメータ、CSP と HSTS、秘密は環境の secret。本番の経路で脆弱性診断を行い、残る課題（ログインの回数制限）も記録しています（`docs/作業ログ_2026-09-25_脆弱性診断.md`）。
- **③ クラウドの IaC**: ここは弱い所です。Pages と D1 は wrangler と shell スクリプト（`bootstrap_personal.sh`・`finish_remote.sh`）で再現できる形にしていますが、Terraform や CDK は使っていません。AWS や GCP の本番運用の経験もこのプロジェクトにはありません。

## 6. 読み取った内容を「事実／推測／要確認」に分けると
