## 追記（同日）— 最初の改善フェーズ（1 件）

投入から約 1 時間で mkt に 1 件（鎌田さん、10:46。画面の添付なし）。Skill `improve-from-feedback` の手順どおりに回した最初の実例。
1. `fetch --every` → 1 件。分類して `mark --status triaged`
2. 分類: (a)「戻った後に進捗が反映されない。更新すると反映」＝**バグ**（brain 24: 構造としてキャッシュした `/fields` `/categories` に理解した数が混ざっていた。理解度を変えた直後に捨てる）
   (b)「学習した後に画面を戻るのがやりづらい」＝**使いやすさ**（教材の末尾に「一覧に戻る」「ホームへ」）
   (c)「解説で『◯◯の取り違え』と無理やり言っている」＝**内容側**（誤答の理由の型を 1 つに固定していた。仕様書を「混同／見落とし／計算」の 3 型にし、担当 3 体で 139 行を書き直し）

4. `finish_remote.sh mkt` で再投入（画面の修正は itc / ip / ap にもデプロイ）→ `mark --status done`。fetch → done まで約 2 時間

**分かったこと**: 学習者役 3 周で出なかった指摘が 3 つとも出た。(a)(b) は学習者役がパック（ファイル）で読むので画面の不具合は原理的に見つけられない。
(c) は 3 周とも「誤答の解説がある」ことを褒めていて、型の単調さには気づかなかった。**本人以外の利用者 1 人のフィードバックは、学習者役 3 周と別の層の欠陥を出す。**
