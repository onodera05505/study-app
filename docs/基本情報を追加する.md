# 基本情報技術者試験（科目A）を追加する

応用情報と**同じコードベース・別データ・別デプロイ**で運用する（`docs/応用情報を追加する.md` の型をそのまま使う）。
対象のキーは `fe`、データは `data/fe/`、Pages は `fe-am-study`、画面の名は「基本情報 科目A 最短合格」。

## 何を対象にするか（本人の決定 2026-10-05）

- **科目A（旧午前）だけ。** 科目B（アルゴリズム・擬似言語・セキュリティの長文）は 4 択の仕組みに乗らないので扱わない
- 素材は IPA が公開する**旧午前の問題冊子と解答例**。公開は平成 21 年度春期〜令和元年度秋期の 22 回（各 80 問）。
  令和 2 年度から CBT になり問題は非公開（科目A はサンプル問題だけ）。範囲と中身は今の科目A とほぼ同じ
- **最新 5 回（`2019r01a`・`2019h31h`・`2018h30a`・`2018h30h`・`2017h29a`）で先に本番へ出し、その後 5 回ずつ平成 22 年度春期までの 10 年分（20 回）へ**
- 模試（全範囲からの構成）は**今の科目A に合わせて 60 問・90 分・60%（36 問）**。通し受験（回をそのまま）は原本どおり 80 問。
  分野比は過去問の比（問 1〜50 テクノロジ、51〜60 マネジメント、61〜80 ストラテジ）を 60 問に割った テクノロジ 38・マネジメント 7・ストラテジ 15
- 教材・問題解説・図・分類の仕様は応用情報と同じ（`scripts/prompts/*.md`。担当には最初に読ませる）

## 流れ

`docs/回を追加する手順.md` を `--data data/fe` で回す。登録は `python3 scripts/new_target.py fe --kind exam …`（手で `targets.json` を足さない）。

| 工程 | コマンド・担当 |
| --- | --- |
| 登録 | `new_target.py fe --kind exam` → `targets.json`・`pages_projects.json`・`wrangler.jsonc` の `env.fe`・`.env.fe`。D1 は `npx wrangler d1 create study-app-fe-db` で先に作り ID を `env.fe` に |
| PDF 取得 | `python3 scripts/fetch_pdfs_ap.py --exam fe --exams 2019r01a 2019h31h 2018h30a 2018h30h 2017h29a` |
| 正解表と分野 | `python3 scripts/extract_answer_keys_ap.py --data data/fe`（各回 80/80 を確かめる。0 ならスキャン画像。手で読んで `answer_keys_manual.json`） |
| シラバス | `python3 scripts/parse_syllabus_ap.py --data data/fe` |
| ページ画像化 | `python3 scripts/render_pages.py --data data/fe <回>` |
| 読み取り → 検証 → 分類 → 論点 → 解説＋教材 v3 → 図 | 担当（`extract-questions`・`verify-answers`・`classify-questions`・`write-explanations`・`crop-figures`。教材は v2 を飛ばして `write-explanations` が v3 を書く）。5 回で約 90 体 |
| seed と投入 | `python3 scripts/build_seed.py --data data/fe` → `bash scripts/seed_remote.sh fe --local` → `bash scripts/bootstrap_personal.sh fe`（人。D1・Pages・secret）→ `bash scripts/finish_remote.sh fe` |
| 配備後 | `bash scripts/check_sso_prod.sh`・`bash scripts/check_api.sh fe`。まなびばの学びの一覧に `fe` を出す |

## 落とし穴（応用情報の物に加えて）

- **令和 2 年度以降の回は無い。** 年度ページを辿っても `_fe_am_` が出ないのは置き場の変更ではなく非公開。探し続けない
- 平成 21 年度の 2 回は現行シラバスとずれが大きい。10 年分（平成 22 年度春期まで）を目標にし、それより前は目標外
- **新しい対象の初回は論点マスタが無い。** 最初の 2 回を分類して `build_topics.py` でマスタを作り、残りの回はそれを照合先に分類する（同名の論点が分野をまたいだら補足つきの別名にする。例: 機械学習（AI 技術）／機械学習、キャパシティプランニング／容量・能力管理）
- **教材 v2 を飛ばして v3 を直接書く。** 新しい対象には v2 が無いので `build_explanation_bundles.py` をそのまま回し（教材欄は null）、`write-explanations` が解説と教材 v3 を同時に書く。教材執筆の波を 1 つ省ける
- **執筆は 10 体ずつの波で、成果物はバンドルの (topic_id, term) との完全一致で機械確認する。** ファイルが在るだけでは途中（4 論点を Write した直後）の可能性がある
- `syllabus_index.json`（分類バンドルが読む）は `parse_syllabus_ap.py` が `syllabus.json` と同時に出す。ap の時代は一回限りの生成物だった
- 論点名や本文に `|` を含む語（BNF など）は explanation に素の縦棒を書くと表に化ける（描画検査が拾う）。「縦棒の記号」のように語で書く
