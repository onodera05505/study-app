# 過去問の回を追加する手順

公開されている29回のうち、まだ取り込んでいない回を足すときの手順。
新年度が公開されたとき（毎年4月頃）も同じ流れで足せる。

**この手順は繰り返し実行できるように作ってある。** 論点 ID は固定されているので、
回を追加して出題頻度の順位が変わっても、ユーザーの理解度や執筆済みの教材は
別の論点を指したりしない。

---

## 0. 前提

```bash
pip install pymupdf
```

`data/pdfs/` に PDF が無い場合は先に取得する。既にあるものはスキップされる。

```bash
python3 scripts/fetch_pdfs.py
```

回の識別子は PDF のファイル名から `_ip_qs.pdf` を除いたもの。例: `2022r04`, `2019h31h`。
一覧は `ls data/pdfs/*_qs.pdf` で確認できる。

---

## 1. ページを画像にする

```bash
python3 scripts/render_pages.py 2022r04
```

問題冊子はスキャン画像でテキストを持たないため、ページを画像として書き出す。
`data/pages/2022r04/p001.png …` ができる。

---

## 2. 画像から問題を読み取る

ページを **11〜12ページずつ**に分けて、ビジョンモデルに読ませる。冊子が52ページなら
5分割が目安。担当者ごとに `data/extracted/2022r04/chunk_01.json` … へ書き出させる。

**読み取りの仕様は [`scripts/prompts/extract_questions.md`](../scripts/prompts/extract_questions.md) に固定してある。**
各担当に必ず最初にこれを読ませること。読ませないと、句読点や箇条書きの扱いが
担当ごとにばらつく（実際に令和6年度で起きた）。

分割時の注意:

- 問題の見出し「問N」が担当範囲にあるものだけを出力させる
- 選択肢が次ページに続く場合は次ページも読んでよい、と伝える
- 最後の担当には「付録ページと奥付には問題が無い」と伝える

---

## 3. 結合・正規化・構造検証

```bash
python3 scripts/merge_questions.py 2022r04
```

100問そろっているか、選択肢が4つあるか、図表の整合が取れているかを見る。
表記の揺れ（全角ピリオドなど）はここで自動的に直る。チャンク間で流儀がずれていれば
警告が出るので、内容を確認する。

---

## 4. 読み取り品質を測る

抽出したテキスト**だけ**を渡して問題を解かせ、正解表と突き合わせる。
50問ずつ2分割で担当させ、`data/answers/2022r04/batch_01.json` … へ書き出させる。

担当者には次を厳守させること。**守られないと検証の意味が無くなる。**

- `data/answer_keys.json` を読まない（正解表）
- `data/pages/` の画像を読まない（元画像）
- Web 検索をしない

```bash
python3 scripts/check_answerability.py 2022r04
```

正答率が低い問題、および「テキストだけでは解けない」と申告された問題は、
読み取りが壊れている可能性が高い。該当ページを確認する。

---

## 4.5 図を切り出す

図として描かれている問題（ブロック図・アローダイアグラム・擬似言語など）は、
原本から画像を切り出して表示する。表や擬似言語以外の「図」だけが対象で、
表は文章の書き起こしのままにする。

対象の見つけ方は、`figure_description` に「箱」「矢印」「分岐」などの語が入っていて、
かつ Markdown の表になっていないもの。`build_seed.py` が未切り出しのものを警告に出すので、
まず一度 `build_seed.py` を流して警告を見るのが早い。

対象が分かったら、担当にページ画像を読ませて**図の矩形領域の座標**（ページに対する
比率 0〜1）を出させ、`data/figures/boxes_<exam>.json` に書かせる。問題文や選択肢は
含めず、ラベルや凡例は含める。切り出して目視確認させると精度が上がる。

```bash
# --boxes にディレクトリを渡すと boxes*.json を全部読む（統合ファイルへの写し忘れが起きない）
python3 scripts/crop_figures.py --boxes data/ip/figures --pdf-dir data/ip/pdfs --out public/figures/ip
```

`public/figures/<試験>/<exam>-q<N>.png` ができる。Vite のビルドで `dist/` にコピーされ、
Workers Assets から配信される。

> **出力先は必ず試験ごとに分ける。** IT パスポートと応用情報には**同じ試験 ID がある**
> （令和2年度10月＝`2020r02o`）。平置きにすると同じ問番号でファイル名がぶつかり、
> 後から切り出したほうで上書きされる。実際 `2020r02o-q55` がぶつかって、IT パスポートの
> 画面に応用情報の課金グラフが出ていた（[`作業ログ_2026-08-31_図の取り違えと管理者アカウント.md`](作業ログ_2026-08-31_図の取り違えと管理者アカウント.md)）。
> `check_seed.py` が `/figures/<試験>/` 以外の URL を検出して止める。

## 5. シラバス項目と論点に分類する

50問ずつ2分割で担当させ、`data/classified/2022r04/batch_01.json` … へ書き出させる。

**分類の仕様は [`scripts/prompts/classify_questions.md`](../scripts/prompts/classify_questions.md) に固定してある。**

```bash
python3 scripts/build_topics.py
```

論点マスタが作り直され、出題頻度が再計算される。ここで見るべきもの:

- **統合候補** — 「アジャイル」と「アジャイル開発」のような表記揺れ。同一と判断したら
  `data/topic_aliases.json` に足して再実行する。別物なら足さない
- **項目の判断が割れた論点** — 多数決で決まるが、割れた事実が出るので確認する
- **新規に採番** — 新しく現れた論点の数。この分だけ教材の執筆が必要になる

---

## 6. 新しい論点の教材を書く

追加後にどの論点の教材が欠けているかを調べる。

```bash
python3 scripts/check_materials.py
```

教材が無い論点だけを 8論点ずつのバンドルにまとめる。

```bash
python3 scripts/build_material_bundles.py --missing
```

`data/material_bundles/bundle_NN.json` が出る。1バンドルを1担当に渡す。
出力先は `data/materials_v2/bundle_NN.json`。

**執筆の仕様は [`scripts/prompts/write_materials.md`](../scripts/prompts/write_materials.md) に固定してある。**
担当には必ず最初に読ませること。1バッチ8論点を超えると出力量オーバーで落ちるので増やさない。

バンドルを作り直すと既存の `data/material_bundles/` を消すので、
**実行中の担当が読んでいるファイルを上書きしない**。やり直すときは `--out` で別名にする
（過去に上書きして担当範囲がずれた事故がある）。

書き上がったら再度検証する。過去問の原文を写している箇所があれば言い換える。

```bash
python3 scripts/check_materials.py
```

---

## 6.5 問題解説を書く（2026-09-01 から）

問題ごとの解説（正解の根拠＋誤答ア〜エが何の用語の説明か）を書く。
誤答のケアは教材ではなくここで行う方針（[`scripts/prompts/write_question_explanations.md`](../scripts/prompts/write_question_explanations.md)）。
誤答の 1 行はそのまま用語のポップ（`[[用語]]`）の中身になる。

```bash
# 解説がまだ無い問題を持つ論点だけを 8 論点ずつ束ねる
python3 scripts/build_explanation_bundles.py --data data/ip --missing --out data/ip/explanation_bundles_r15
```

1 バンドルを 1 担当（型 `write-explanations`）に渡す。担当は解説を `question_explanations/expl_NN.json` に書き、
続けて同じ論点の教材を `materials_v3/expl_NN.json` に書き直す（新しい論点なら v2 を飛ばして v3 で書いてよい）。

```bash
python3 scripts/check_explanations.py --data data/ip
python3 scripts/check_materials.py --data data/ip
```

`build_seed.py` が解説と用語集（`glossary`）を seed に含める。用語集は全解説の誤答行から自動生成される。

## 7. DB に反映する

**先に migrations を当てる。** seed は今のスキーマの列を INSERT するので、未適用の migrations がある D1 には流せない
（`seed_remote.sh` と `deploy-pages.sh` は先頭で `d1_migrations.sh check` を回し、未適用があれば止まる。不変条件 D26）。

```bash
bash scripts/d1_migrations.sh ip apply --local   # ローカル D1 に未適用を当てる
bash scripts/d1_migrations.sh ip apply           # 本番（当てる前にバックアップ。未適用が無ければ何もしない）
python3 scripts/build_seed.py --data data/ip
bash scripts/seed_remote.sh ip --local     # まずローカルでリハーサル
bash scripts/seed_remote.sh ip             # 本番: check_seed → backup → --remote 投入 → 投入後の突き合わせ
```

UPSERT なので、**学習の進捗と受験履歴は消えない**。

`seed_remote.sh` が `check_seed.py`・`backup_d1.sh`・`--remote` 付きの投入・
`verify_seed_remote.py`（入った件数と代表値を seed と突き合わせる）を順に回し、
どれか1つ落ちれば止まる。**wrangler を直に叩かない**（2026-09-10〜）。
**`check_seed.py` を飛ばさない。** 出典の試験名・年度ラベル・回ごとの問題数・
図の画像の実在・UPSERT の更新列漏れを見る。ここを飛ばしたために、応用情報の
全880問が誤った出典を出したまま数か月動いていた
（[`懸念_表示データに検証が無い.md`](懸念_表示データに検証が無い.md)）。

回を足したら **`exam_labels.json` に年度ラベルを足す**のを忘れない。無い回は
`2022r04h` のような内部コードが出典とセッション名にそのまま出る（検査で止まる）。

## 8. 動作を確認する

```bash
bash scripts/check_render.sh ip   # 描画検査（デプロイ時にも自動で走る）
bash scripts/check_api.sh ip      # API 検査（ローカルに 8788 を立てて形・認証・件数を見る）
npm run build
npx wrangler dev                  # .dev.vars に JWT_SECRET が要る（無いとログインが 503。雛形 .dev.vars.example）
```

追加した回が「過去問実践」の一覧に出ること、新しい論点に解説が付いていることを見る。
描画検査は新しい教材・解説を jsdom で実際に描いて、`[[用語]]` や図・表が
画面で壊れていないかを見る（データ側の検査とは別物。詳細は `scripts/lib/check_render.tsx` の先頭）。
