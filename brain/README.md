# brain — インシデント報告書の置き場（センターブレイン・このプロジェクト固有分）

**2層構造の片方**: 別プロジェクトでも再発しうる共通事例は `~/.claude/brain/`（README あり）、
このリポジトリのデータ・画面・運用でしか起きないものがここ。迷ったら
「リポジトリ名を伏せて読んでも意味が通るか」——通るなら共通側へ。

**トラブル・不具合・原因不明のエラーに当たったら、作業を始める前にまず `INDEX.md` を読む。**
過去に同じ症状を踏んでいれば、原因究明をやり直さずに済む。これがこの仕組みの目的
（調査のやり直し＝トークンと時間の二重払い、を無くす）。

## 置いてあるもの（2026-09-14 に中央の setup_project.sh で配線を揃えた）

- `INDEX.md` → `reports/NN_*.md`: **トラブル**。症状で引く。当時の事実として凍結（追記のみ）
- `APPROACHES.md` → `approaches/*.md`: **このプロジェクト固有の作業の型**。作業の種類で引く。生きた手順。
  値・実例・固有名を持つものはここ、リポジトリ名を伏せても通じる型は中央（`~/.claude/brain/approaches/`）
- `PREMISES.md`: **未決・本人の指示・開始時の質疑応答**。着手前に毎回読む。決定と制約は `CLAUDE.md` に集約する（2 か所に書かない）
- `TEMPLATE.md` / `TEMPLATE_APPROACH.md`: 書式

## 使い方（読む側）

1. `INDEX.md` を読む（1事例=1行。ここだけなら数百トークン）
2. 症状が一致する行があれば、その報告書**だけ**を開く
3. 無ければ普通に調査する。**解決したら報告書を書いて還す**（下記）

## 使い方（書く側）— ブレインを育てる

未知のトラブルを解決したら、その場で1枚書く。あとでまとめて書こうとすると書かれない。

- `reports/NN_短い名前.md` に **1インシデント=1ファイル**。番号は既存の最大+1
- 書式は `TEMPLATE.md`。**30行以内**を目安に、症状→原因→対処→再発防止の順
- `INDEX.md` に1行足す: `| NN | 症状の一言（検索に引っかかる言葉で） | ファイル名 |`
- 同じ症状を再び踏んだら、新規作成ではなく既存の報告書に「再発: 日付・場所」を追記する
  （再発する事例＝門が要る事例、が浮かび上がる）

## 書式の原則

- **症状から書く**（原因からではなく）。次に踏む人が知っているのは症状だけ
- 原因は1文で言い切る。対処は「何をしたら直ったか」を再現できる具体さで
- 再発防止に「今はどの門・ルールで防いでいるか」を書く（無ければ「無し」と正直に）
- 詳細な経緯が別文書にあるならリンクで済ませ、ここには要点だけ

## 他の文書との役割分担

- `CLAUDE.md` の落とし穴 = **作業前に全員が読む予防リスト**（厳選・常時ロード）
- `brain/` = **症状が出てから引く索引**（網羅・オンデマンド）。落とし穴に昇格させるほど
  頻繁でないものも全部ここに入れる
- `docs/作業ログ_*` = 経緯の一次資料。brain はそこへの入口
