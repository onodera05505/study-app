# 01. 応用情報の全 880 問が「ITパスポート試験」の出典を出していた（数か月）

- **日付/場所**: 2026-08-29 発覚 / `build_seed.py` → seed.sql → 本番 D1（応用情報）
- **症状**: 過去問の出典が `出典：2022r04h ITパスポート試験 問1`。中身は応用情報の問題。
  問題文・選択肢・正解は正しく、**壊れていたのは表示用の文字列だけ**。
  11回ぶん・数か月にわたって本番に出ていたのに誰も気づかなかった（IPA の利用条件で出典表示は必須）。
- **原因**: 3つ重なっていた。①`build_seed.py --exam-name` の**既定値が `ITパスポート試験` 固定**で、
  手順書にも `deploy-pages.sh` の案内文にも渡す記載が無かった（構造的に毎回間違う）
  ②`data/ap/exam_labels.json` に6回分が無く、`labels.get(exam, exam)` のフォールバックで
  内部コード `2022r04h` がそのまま出ていた ③UPSERT の更新列に `exam_label` が無く、
  ラベルを足しても既存行が変わらなかった（→ 共通 13）。
- **対処**: 欠けていた年度ラベルを追加。`--exam-name` と `--out` を **`--data` から決める**
  （未知のディレクトリならエラーで止まる）。UPSERT に `exam_label=excluded.exam_label` を追加。
  seed を作り直して投入（UPSERT なので進捗・受験履歴は無事）。
- **再発防止**: **`scripts/check_seed.py`（投入前の門）**が出典の試験名・年度ラベル・回ごとの
  件数・UPSERT の更新列漏れを見る。意図的に壊した seed で 880 件を検出して exit 1 することを確認済み。
  手順書は `build_seed.py → check_seed.py → wrangler d1 execute` の順に固定。
- **教訓**: **「手順書に注意書きを足す」で終わらせない。** 渡し忘れると壊れるものは、
  渡さなくても正しくなるか、渡さなければ止まるようにする。
- **事前の質問**: 同じ生成スクリプトで複数の系統（試験・データセット）を扱うとき、系統ごとの出力先と識別名を何から決めるか（入力ごとに分けるか、固定の既定値を持つか）（→ approaches/本番データ投入の1本道.md 〔q: per-dataset-defaults〕）（2026-09-15 変換）
