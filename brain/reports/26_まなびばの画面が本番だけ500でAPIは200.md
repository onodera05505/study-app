# 26. まなびばの画面（/・app.js・style.css）が本番だけ 500。API は 200 のままで、門も SSO の一巡も通っていた

- **日付/場所**: 2026-09-17 / `portal/src/index.ts`（Pages の `_worker.js`）、本番 manabiba-5oz.pages.dev
- **症状**: 本人「マッサージ見れませんよ」。まなびばを開くと `Internal Server Error`。`/api/health`・`/api/learnings`・`/sso/start` は正常。ログ（`wrangler pages deployment tail <deployment-id>`）は `TypeError: Can't modify immutable headers. at setHeaders … at secureHeaders2`
- **原因**: 残りのパスを `c.env.ASSETS.fetch(c.req.raw)` の応答そのままで返していた。ASSETS の応答はヘッダーが変更不可で、Hono の `secureHeaders` がヘッダーを足そうとして例外になった。ローカルの wrangler dev では変更可能なので再現せず、SSO の本番反映のデプロイから壊れていた
- **対処**: `const res = await c.env.ASSETS.fetch(c.req.raw); return new Response(res.body, res)` で写してから返す → `deploy_portal.sh`。/・app.js・style.css が 200、セキュリティヘッダーも付くことを確認。本番のブラウザでログイン→msg のホームまで通した
- **再発防止**: `scripts/check_sso_prod.sh` が、まなびばの /・app.js・style.css と各学びの / の 200 を見る（これまでは health の API だけ）
- **アプローチへの反映**: 無し（この PJ の門の穴。中央の型に当たる語が無かった（grep: 静的ファイル, immutable headers））
- **事前の質問**: 聞いても防げない（理由: 環境の癖。ローカルでは再現しない。防ぐのは「本番の門は API だけでなく画面の入口も見る」で、門に入れた）
- **詳細**: `docs/作業ログ_2026-09-17_SSO.md` の追記
- **検索語**: Internal Server Error, Can't modify immutable headers, secureHeaders, ASSETS.fetch, まなびば 500
