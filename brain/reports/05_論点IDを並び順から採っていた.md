# 05. 論点 ID を並び順から採っていた（回を追加すると進捗と教材が別の論点を指す）

- **日付/場所**: 2026-08-23 / `topics.json` と教材・進捗の紐づけ（本番前に発見）
- **症状**: 発現前に気づいた設計の欠陥。`topics.json` は**出題頻度の降順**で並ぶため、
  回を追加して順位が変わると **ID が別の論点を指す**。利用者の理解度（`progress`）も
  執筆済みの教材も、まとめて別の論点にぶら下がる。
- **原因**: ID を並び順から採番していた。
- **対処**: **照合キーごとに採番した ID を `data/topic_ids.json` に残し、一度振った ID は
  使い回さない**方式に変更。採番時点の並び順と一致していたので、執筆済みの教材はそのまま使えた。
- **再発防止**: `data/topic_ids.json` が正。CLAUDE.md「設計の中核」に
  「**論点 ID は並び順から採ってはいけない**」と明記。実際に回を追加した際、
  既存 ID は据え置きで新規だけ採番されることを毎回確認している（291→385→456→532 …）。
- **事前の質問**: 利用者の記録がぶら下がる単位の ID を何から採るか（並び替えで指す先が変わらない形か）。元データから消えた ID を投入のたびにどう扱うか（→ approaches/本番データ投入の1本道.md 〔q: unit-id-lifecycle〕）（2026-09-15 変換）
- **詳細**: [`docs/作業ログ_2026-08-23.md`](../../docs/作業ログ_2026-08-23.md)「設計上の欠陥を2つ修正」
- **検索語**: topic_ids.json, 論点 ID 固定, 並び順から採番, 出題頻度順, 進捗がずれる
